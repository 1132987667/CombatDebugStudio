## 修正点（与 spec 不同的地方）

### 修正 1：测试 Mount 方式 —— ref callback

**spec 原文**：
```ts
const app = createApp({ render: () => h(BattleVisualEffects, { ref: vfxRef }) })
```

**问题**：Vue 3.2.x 中 `h()` 传递 `Ref` 对象作为 `ref` 不一定自动解包（Vue 3.4+ 才稳定）。该项目的 Vue 版本是 `^3.2.47`。

**改为**：
```ts
const app = createApp({
  render: () => h(BattleVisualEffects, { ref: (el) => { vfxRef.value = el } }),
})
```

### 修正 2：fakeCard DOM 清理

**spec 原文**：`fakeCard` 创建的 div 直接 `appendChild` 到 body，无清理逻辑。

**补充**：在 `afterEach` 中统一移除所有 fakeCard 创建的 DOM 元素。实现方式：`fakeCard` 改成 track 模式。

### 修正 3：CSS 动画时长注释准确化

**spec 原文**（P1 映射表脚注）：
```
`1400/1600` 是"战斗节奏可压缩、但伤害数字必须让人看清"的可读性保障，与 `dmg-pop 1.4s` / `heal-rise 1.6s` 绑定。
```

**补充说明**：`shield-rise` CSS 动画时长也是 1.4s（1400ms），但 JS 常量为 `SHIELD_NUM_TTL_MS = 1450`（多了 50ms 缓冲）。注释中应明确指出这一点。同时 `hex-flash` CSS 动画 0.9s > JS 移除时长 `b * 0.5`，这是原版就有的行为，已在常量旁加注释。

## 代码质量、健壮性、正确回收 —— 深度审查报告

### 代码质量

**Spec 已覆盖**：
- `setRemove` 泛型化 `any → Ref<T extends { id: number }>`
- `VFX_COLORS` 类型收窄：`Record<string, Record<string, string>>` → `Record<VfxColorType, { bg: string; glow: string }>`
- 删除重复的 `sparkColors`（与 `VFX_COLORS` 完全重复）
- 移除未使用的 `nextTick` 导入
- 所有 `setRemove` 调用方类型安全（`skillNames`/`impacts`/`healAuras`/`shieldHexes`/`dmgNums` 都满足 `{ id: number }`）

**无需额外处理**：`timeouts` 数组 → `pendingTimers` Set 不仅是重命名，更是类型增强（Set 的 `forEach`+`delete` 防重复注册）。

### 健壮性 —— 边界 case 验证

| 场景 | 行为 | 结论 |
|---|---|---|
| `document.getElementById('visual-effects-root')` 返回 null | 函数静默 return（`showProjectile`/`createSpark`/`spawnIceShatterParticles` 均有守卫） | 安全 |
| `nextId` 单会话自增 | 不可能溢出 | 无需处理 |
| `impactStyle` 非法值（如 `'nonexistent'`） | `switch` 落空，`case` 无默认 → body 为空（slash/shockwave 无 JS 粒子） | 安全，且负面清单明确不做静默回退 |
| `VFX_COLORS[colorType]` 找不到 | `?? VFX_COLORS.fire` 兜底 | 安全 |
| `CardPos.el` 字段 | 保留在 `CardPos` 类型中，`defineExpose` 暴露 `cardElements`，调用方可直接访问 | 向后兼容 |

### 正确回收 —— 原版问题与 Spec 修复

**原版未追踪的定时器（Spec 全部改为 `later()`）**：

| 位置 | 原版 | 卸载后 |
|---|---|---|
| `setRemove` 内部 | 追踪到 `timeouts[]` | ✅ 清除 |
| `spawnExplosionParticles` 的 `setTimeout(fn, 650)` | **未追踪** | ❌ 残留 → ✅ `later()` |
| `spawnIceShatterParticles` 的 2 处 `setTimeout` | **未追踪** | ❌ 残留 → ✅ `later()` |
| `spawnShadowParticles` 的 `setTimeout(fn, 850)` | **未追踪** | ❌ 残留 → ✅ `later()` |
| `showScreenShake` 的 `setTimeout` | **未追踪** | ❌ 残留 → ✅ `later()` |
| `showHealAura` 的 `setTimeout` | **未追踪** | ❌ 残留 → ✅ `later()` |
| `showProjectile` 的 `rAF(step)` | **未追踪** | ❌ 残留 → ✅ `nextFrame()` |

**竞态分析 —— 卸载发生在光弹飞行 rAF 途中**：

```
onUnmounted()
  ├─ pendingFrames.forEach(cancelAnimationFrame)   ← 清除待处理 rAF
  ├─ pendingTimers.forEach(clearTimeout)            ← 清除待处理定时器
  ├─ cardElements.clear()
  └─ #visual-effects-root 被 DOM 移除
       └─ proj, trail, 粒子等全部子节点自动移除
```

corner case：若 `step()` 正在执行且 `t < 1`，会调用 `nextFrame(step)` 向已清理的 `pendingFrames` 添加新 id。但该新 rAF 回调触发时 `proj.isConnected === false`，立即 return。**无泄漏，无 DOM 操作。**

**WAAPI 动画（`Element.animate`）**：

粒子/闪光通过 `spark.animate()` 播放动画。这些 `Animation` 对象未显式 `cancel()`，但元素被 DOM 移除后浏览器自动终止动画，GC 回收 detached 元素时一起回收。**无需额外处理。**

**尾迹清理 —— 双路径验证**：

```
trail 创建 → later(removeChild, 600) → pendingTimers
  ├─ 若卸载先到：timer 被 clearTimeout，trail 随 root 一起被 DOM 移除
  └─ 若 600ms 先到：回调执行，parentNode 存在则移除
```
两种路径都安全。

### 结论

三个维度核心风险已被 P2 阶段完全覆盖，无需在 spec 基础上额外补充。

## 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| `createApp` mount 在 jsdom 下的稳定性 | 低 | 已验证：jsdom 支持 `getElementById`、`appendChild`、`getBoundingClientRect` |
| `Element.animate` 在 jsdom 中不存在 | 低 | 已在 `beforeEach` 中打桩 |
| `performance.now` 与 fake timers 的联动 | 低 | P0 时序用例刻意不依赖 `performance.now`；光弹轨迹由打桩后的 rAF 短路 |
| 派生值与历史魔数不一致 | 低 | P0 9 个用例按毫秒级断言，值恒等由机器证明 |
