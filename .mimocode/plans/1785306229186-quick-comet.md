## 阶段二（target-resolver 修改，合为一次 PR）

### 2.1 `src/domain/skill/target-resolver.ts` — 新增参数

**函数签名**（第 23-28 行）追加可选参数：
```typescript
threatManager?: ThreatManager,
formationRowLookup?: (side: ParticipantSide, seatIndex: number) => 'front' | 'back' | null,
frontProtectionLookup?: (side: ParticipantSide) => boolean,
```

**逻辑变更**：
1. 在 `faction === 'enemy'` 过滤后（第 46 行之后）、strategy switch 之前：
   - 若 `threatManager` 存在，检查 `getTauntTarget(candidates)`（嘲讽者标签 `buff_taunt`）→ 有则直接返回
   - 若无嘲讽，检查 `threatManager.getHighestThreatTarget` → 有则返回
2. `FRONT`/`BACK` 策略（第 74-77 行）：当 `formationRowLookup` 存在时，按行定位
3. 前排保护逻辑：在 `FIRST`/`RANDOM` 等默认策略中，若 `frontProtectionLookup(enemySide)` 为 true 且前排存活，过滤后排

### 2.2 `src/domain/skill/PassiveSkillManager.ts` — 不传递

`triggerPassives()`（第 209 行）中的 `resolveSkillTargets` 调用不移传阵型/嘲讽参数（被动技能不受前排保护 — 设计文档 M1 显式声明）。

- (C2) `fieldEffectManager` 和 `formationManager` 直接 `new`，不经过 DI

- `initialize(allyParticipants, enemyParticipants, sceneId?)`
- 在第 546 行 `distributeAuras` 之后，插入：

  - 阵型应用：`if (allyFormation)` → `formationManager.applyFormation`
  - 阵型应用后 `allParticipants.forEach(p => p.recalcAll())` + `battleData.turnOrder = this.turnManager.createTurnOrder(...)`
- 在 `damageCalculator.setConfig` 处（第 297-301 行）注入 `fieldElementalModifier` 回调

#### `runEndConditionCheck()`（第 941-965 行）— 改为核心
```typescript
// 1. 先结算待处理的死亡（drainPendingDeaths）
```

#### `processTurnInternal()`（第 632-885 行）— 追加：
- 回合开始阶段（第 665 行后）：`fieldEffectManager.triggerPeriodic('turn_start')`
- 第 676 行后：`reviveTracker.tickCooldowns()`
- 回合结束阶段（第 800 行后）：`fieldEffectManager.triggerPeriodic('turn_end')` + `fieldEffectManager.tick()` + `threatManager.tickDecay()`

#### `resetBattle()`（第 1026-1032 行）改为：

### 3.2 `BattleExecutor.ts` 改造

#### 构造函数（第 98-105 行）新增参数：
```typescript

private readonly threatManager?: ThreatManager,
```
- 可选参数，向后兼容

#### `pendingDeaths` 机制 — 新增属性 + 方法：
```typescript
private pendingDeaths: Array<{deadId: string; killerId: string; battle: BattleData}> = []

drainPendingDeaths(): Array<{deadId: string; killerId: string; battle: BattleData}> {
  const deaths = [...this.pendingDeaths]
  this.pendingDeaths = []
  return deaths
}
```

#### 3 处 ON_DEATH/ON_KILL 改为 `pendingDeaths.push()`：

| 位置 | 行号 | 改动 |
|---|---|---|
| `handleHitAttack()` | L1197-1214 | `if (!target.isAlive())` → `pendingDeaths.push({deadId: target.id, killerId: source.id, battle})` |
| `selectAndExecuteSkill()` pendingDamages 循环 | L677-694 | 同上 |
| `executeAction()` 非 SKILL 路径 | L1775-1794 | 同上 |

#### `applyDamageToTarget()`（第 997-1012 行）追加仇恨生成：
```typescript
if (this.threatManager) {
  const targetHasTaunt = this.buffSystem.hasBuffWithTag(target.id, 'taunt')
```

#### `selectAndExecuteSkill()` 中 `damageToken` 应用处追加仇恨：

#### `selectTarget()`（第 1332-1352 行）改为嘲讽+仇恨优先：

#### 复活结算（`selectAndExecuteSkill` 末尾，第 740-754 行前）：

```typescript
    this.reviveTracker.recordRevive(revivedId, (action.extra.reviveParams as ReviveStepParams).cooldown ?? 0)
    this.passiveSkillManager.triggerPassives(
```

### 3.3 `SkillExecutor.ts` — 新增 REVIVE case

**`executeStep()` switch（第 119 行后）新增**：
```typescript
case SkillStepType.REVIVE:
```

**新增 `executeRevive()` 方法**：
- 检查 `target.isAlive()` → 存活则跳过
