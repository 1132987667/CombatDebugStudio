## 问题四：`generateCommandsForTurn()` 占位伤害

### 4.1 现状

```ts
// BattleSystem.ts:1504-1515
const targetId = this.selectCommandTarget(battle, participant)
if (targetId) {
    const damage = Math.floor(Math.random() * 20) + 10  // ← 伪造值 10~29
    commands.push({
        type: 'APPLY_DAMAGE',
        payload: { targetId, amount: damage, sourceId: participantId },
    })
    // ponytail: 简化版 — 仅生成基础伤害命令
}
```

标注 `ponytail: 简化版`，与 `BATTLE_CONSTANTS.DEFAULT_ATTACK_DAMAGE_MIN=10 / MAX=20` 匹配，说明是早期的临时简化。

### 4.2 影响

- 自动战斗/命令模式生成的伤害完全脱离角色属性和技能配置
- `APPLY_DAMAGE` 命令驱动 Store reducer 直接扣血，绕过伤害计算管线（无防御减免、暴击、元素修正等）

### 4.3 修改方案

**策略**：最小可行改进——使用 `participant.getRandomAttackDamage()` 替换占位值，该方法是 `BattleParticipantImpl` 已有的实例方法，基于角色真实的 `minAttack/maxAttack` 属性取随机值。

**文件**：`src/domain/battle/BattleSystem.ts`

```ts
// 替换生成伤害的占位逻辑（约 8 行变更）
const targetId = this.selectCommandTarget(battle, participant)
if (targetId) {
    // ★ 使用参与者真实攻击属性计算伤害，替代占位随机数
    // NOTE: getRandomAttackDamage 基于 minAttack/maxAttack 属性，
    //       已纳入属性修饰符和配置值，比固定随机数更贴近实际伤害。
    //       完整的伤害计算管线（防御减免/暴击/元素修正）需后续通过
    //       DamageCalculator 接入 command 流程。
    const damage = participant.getRandomAttackDamage()
    commands.push({
        type: 'APPLY_DAMAGE',
        payload: { targetId, amount: damage, sourceId: participantId },
    })
}
```

### 4.4 不做什么

- 不引入 `DamageCalculator` 完整管线（防御/暴击/元素）——第三阶段 command 模式与现有 `BattleExecutor.executeParticipantAction` 是两套并行的路径，完整接入需大规模重构命令系统，超出本次硬编码清理范围
- 不改动 `BattleCommand` 类型或 Store reducer

### 4.5 验证要点

- 角色 `minAttack=50, maxAttack=80` 时，命令生成器产生的 `APPLY_DAMAGE.amount` 在 50~80 区间内
- 现有自动战斗流程不受影响（`processTurnInternal` 走 `executeParticipantAction`，不经过 `generateCommandsForTurn`）
- `npm run typecheck && npm run test` 无回归

## 问题五：`PassiveSkillManager.evaluateCondition()` 硬编码阈值

### 5.1 现状

```ts
case 'source_has_debuff_count_3':
    return source.getBuffInstanceIds().length >= 3   // ← 固定阈值 3
case 'source_energy_high':
    return source.getAttribute('currentEnergy') / maxEnergy > 0.9  // ← 固定 0.9
case 'source_turn_gt_5':
    return (context?.currentTurn ?? 0) > 5            // ← 固定 5
case 'source_turn_mod_5':
    return (context?.currentTurn ?? 0) % 5 === 0      // ← 固定模 5
```

条件名与阈值绑定（`_3`、`_gt_5`、`_mod_5`），不同被动无法复用同一条件名但使用不同阈值。JSON 配置中确实使用了这些条件名：

```json
{ "condition": "source_has_debuff_count_3" }
{ "condition": "source_energy_high" }
```

### 5.2 修改方案

**策略**：参数化——`PassiveSkillConfig` 新增 `conditionParams` 字段，`evaluateCondition` 从 params 读取阈值。旧条件名作为别名保持兼容。

#### 文件 1：`src/domain/skill/PassiveSkillManager.ts`

##### 5.2.1 新增接口字段（约 3 行）

```ts
export interface PassiveSkillConfig {
  // ... 现有字段 ...
  conditionParams?: Record<string, number | string | boolean>  // ★ 新增
}
```

##### 5.2.2 修改 `shouldTriggerPassive()` 传递 params（约 5 行）

```ts
if (
  config.condition &&
  !this.evaluateCondition(config.condition, entity, contextTarget, context, config.conditionParams)
)
  return false
```

##### 5.2.3 修改 `evaluateCondition()` 签名与实现（约 20 行变更）

```ts
private evaluateCondition(
  condition: string,
  source: BattleEntity,
  target?: BattleEntity,
  context?: PassiveTriggerContext,
  params?: Record<string, number | string | boolean>,  // ★ 新增
): boolean {
  try {
    switch (condition) {
      // ... 已有条件不变 ...
      case 'source_has_debuff_count':
      case 'source_has_debuff_count_3': {  // 旧名兼容别名
        const threshold = (params?.count as number) ?? 3
        return source.getBuffInstanceIds().length >= threshold
      }
      case 'source_energy_high': {
        const threshold = (params?.ratio as number) ?? 0.9
        return (
          source.getAttribute('currentEnergy') /
            Math.max(1, source.getAttribute('maxEnergy')) >
          threshold
        )
      }
      case 'source_turn_gt': {
        const threshold = (params?.turn as number) ?? 5
        return (context?.currentTurn ?? 0) > threshold
      }
      case 'source_turn_mod': {
        const mod = (params?.mod as number) ?? 5
        return (
          (context?.currentTurn ?? 0) % mod === 0 &&
          (context?.currentTurn ?? 0) > 0
        )
      }
      // 旧名保持兼容
      case 'source_turn_gt_5':  return (context?.currentTurn ?? 0) > 5
      case 'source_turn_mod_5': return (context?.currentTurn ?? 0) % 5 === 0 && (context?.currentTurn ?? 0) > 0
      default: ...
    }
```

#### 文件 2：JSON 配置（增量更新，可选）

不强制修改现有 JSON。旧条件名 `source_has_debuff_count_3` 等作为别名继续工作。新建被动时推荐新格式：

```json
{
  "condition": "source_has_debuff_count",
  "conditionParams": { "count": 3 }
}
```

### 5.3 验证要点

- 旧条件名（`source_has_debuff_count_3` 等）不加 `conditionParams` 时按原阈值工作（向后兼容）
- 新条件名 + `conditionParams` 可配置不同阈值
- `npm run typecheck && npm run test` 无回归

### 5.4 最小测试

```ts
it('source_has_debuff_count 从 params 读取阈值', () => {
  const source = { getBuffInstanceIds: () => ['a','b','c'] } as any
  // params.count = 3 → true, params.count = 4 → false
  expect(manager['evaluateCondition']('source_has_debuff_count', source, undefined, undefined, { count: 3 })).toBe(true)
  expect(manager['evaluateCondition']('source_has_debuff_count', source, undefined, undefined, { count: 4 })).toBe(false)
  // 向后兼容：无 params 时默认 3
  expect(manager['evaluateCondition']('source_has_debuff_count_3', source)).toBe(true)
})
```
