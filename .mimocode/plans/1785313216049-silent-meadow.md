# 修复 BattleReplayManager 的 8 个空壳事件处理器

## 修改清单

### 文件 1: `src/domain/battle/replay/BattleReplayManager.ts`

1. **新增导入**:
   - `type { IDomainEventBus }` from `@/domain/port/IDomainEventBus`
   - `{ battleLogManager }` from `@/infrastructure/adapters/logging`

2. **构造函数变更**: 新增可选 `eventBus?: IDomainEventBus` 参数，保存到私有字段 `eventBus`。
   - Phase 1 不发射动画事件，仅注入备用。
   - `eventBus` 字段保留，供 Phase 2 使用（需注入 mitt eventBus 而非 triggerEventBus）。

3. **`startReplay()` 变更**: 在方法开始时调用 `battleLogManager.setAutoCleanup(false)`，防止长战斗日志被截断。

4. **`stopReplay()` 变更**: 在 `resetReplayState()` 后调用 `battleLogManager.setAutoCleanup(true)`，恢复日志自动清理。

5. **8 个 handler 替换** — 每个 handler 移除 `console.log`，改为调用 `LoggerProvider.logger.addBattleLog(...)`:
   - `handleActionReplay`: 输出 sourceId→targetId、damage/heal 信息，category 根据伤害/治疗/普通切换
   - `handleTurnStartReplay`: 系统日志，标注第 N 回合开始 + 行动者
   - `handleTurnEndReplay`: 系统日志，标注回合结束
   - `handleBattleStartReplay`: 系统日志 "战斗开始"
   - `handleBattleEndReplay`: 状态日志，标注胜利者（**不**调用 `stopReplay()`）
   - `handleBuffAddReplay`: 状态日志，targetId + buffId
   - `handleBuffRemoveReplay`: 状态日志，targetId + instanceId
   - `handleBuffUpdateReplay`: 状态日志，remainingTurns / stacks 信息

### 文件 2: `src/infrastructure/di/Container.ts`

6. **`BattleReplayManager` 注册变更**: 从 `container.register(...)` 改为 `container.registerFactory(...)`，工厂中传入 `triggerEventBus`：

   ```ts
   // 改前:
   container.register('BattleReplayManager', new BattleReplayManager())

   // 改后:
   container.registerFactory('BattleReplayManager', () => {
     return new BattleReplayManager(triggerEventBus)
   }, true)
   ```

### 验证步骤

- 运行 `npm test` 确认无回归
- 确认类型检查通过: `npm run typecheck`
- 手工验证思路：启动开发服务器，录制一场战斗，回放时日志面板应出现带有 `[回放]` 前缀的条目（回合开始/结束、战斗开始/结束、动作、Buff 变化）
