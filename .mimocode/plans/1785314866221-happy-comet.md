## 缺陷 1（P1）：Path B 被动触发频次改变 — `pendingDamages` 聚合丢失

**严重度：P1**

### 根因

原 `selectAndExecuteSkill` 的被动触发循环（行 684-726）使用 `pendingDamages` 数组，**每个目标只触发一次** `ON_HIT`/`DAMAGE_TAKEN`，传入的是 `skillAction.damage`（整次技能行动的汇总伤害）。

设计文档的 After 代码改为遍历 `damageToken.getEntries()`，每一条 entry 调用一次 `settleDamage`。对于多步骤技能（2 步各造成 50 伤害），场景变化：

| 维度 | 原行为 | After 行为 |
|---|---|---|
| `takeDamage` | 2 次 (50+50) | 2 次 (50+50) ✅ |
| `ON_HIT` 触发 | **1 次 (damage=100)** | **2 次 (damage=50, 50)** ❌ |
| `DAMAGE_TAKEN` | **1 次 (damage=100)** | **2 次 (damage=50, 50)** ❌ |

### 触发条件

仅针对多步骤技能对**同一目标**造成多次伤害的场景。单步骤技能不受影响。

### 修复方向

保持 `pendingDamages` 的按目标聚合逻辑，在 `selectAndExecuteSkill` 中先按 target 聚合 damageToken entries，然后每个目标调用一次 `settleDamage`。或者在遍历 `damageToken.getEntries()` 时按 target.id 聚合后统一调用。

## 缺陷 2（P1）：Path D `onDamageRequest` 回调共享代码导致 DAMAGE_TAKEN 重复发射

**严重度：P1**

### 根因

`onDamageRequest` 回调（BattleSystem.ts 行 435-550）在三个分支**之后**有共享的后续逻辑：

```
三个分支：
  ├─ percentDamage > 0  → target.takeDamage()  // 仍然需要事件+被动
  ├─ percentDamage < 0  → target.heal()         // 治疗路径，不走 settleDamage
  └─ damage > 0         → target.takeDamage()   // → 改为 settleDamage

共享后续逻辑（行 502-545）：
  ├─ eventBus.emit(DAMAGE_ANIMATION)         // 三个分支都要
  ├─ emitTriggerEvent(DAMAGE_TAKEN, ...)     // ← 固定伤害分支通过 settleDamage 已经发射了！
  ├─ ALLY_DAMAGE_TAKEN / ALLY_FATAL_DAMAGE  // 三个分支都要
  └─ passiveSkillManager.triggerPassives(DAMAGE_TAKEN) // ← 固定伤害分支通过 settleDamage 已经触发了！
```

如果只是简单将固定伤害分支替换为 `settleDamage` 调用，共享代码仍然会执行，导致 **DAMAGE_TAKEN 事件和被动触发重复执行**。

### 修复方向

需要让共享逻辑感知到当前分支是否已经通过 `settleDamage` 处理过。方案：
1. 将固定伤害分支完全独立出去，让共享逻辑只对 `percentDamage > 0` 分支执行
2. 或者在固定伤害分支设置一个 flag，共享逻辑判断后跳过

推荐方案 1：重构 `onDamageRequest` 为：
```
if (percentDamage > 0) {
  // 百分比伤害：保持原有逻辑（takeDamage + 事件 + 动画 + 被动）
} else if (percentDamage < 0) {
  // 百分比治疗：保持原有逻辑（heal + 事件）
} else if (damage > 0) {
  // 固定伤害：走 settleDamage（内部处理事件 + 被动 + pendingDeaths）
  // 然后只保留 DOT 特有逻辑（DOT记录/日志/动画/队友事件）
}
```

## 缺陷 3（P2）：设计文档关于 `emitTriggerEvent` 的 `currentTurn` 描述不准确

**严重度：P2**

设计文档第六节表格说 `emitTriggerEvent` 缺失 `currentTurn`，但实际代码中 `emitTriggerEvent` 方法（BattleSystem.ts 行 254）使用 `this.battleData.currentTurn` 作为默认值：

```typescript
currentTurn: context.currentTurn ?? this.battleData.currentTurn,
```

所以事件上下文中**并不缺失** `currentTurn`。正确的差异点在于：

| 差异 | `emitDamageTakenEvent` | `emitTriggerEvent` (Path D) |
|---|---|---|
| `extra.isCritical` | ✅ 传入 | ❌ 缺失（始终无暴击标记） |
| `sourceId` | `source.id` | `''`（无来源） |

`isCritical` 缺失是真实差异，但 `currentTurn` 不是。
