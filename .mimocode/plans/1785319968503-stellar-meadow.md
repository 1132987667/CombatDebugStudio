# 领域层反向依赖重构方案（修正版 · 目标 95 分）

> 原方案（自评 95 分）评估得分 78 分，存在 BattleManager 遗漏、内部构造模式未考虑、ISP 描述偏差等问题。本修正版在原方案基础上完善细节、补齐遗漏，目标 95+。

## 一、对原方案的纠正

| 原方案问题 | 影响 | 本版处理 |
|------------|------|---------|
| 遗漏 `BattleManager.ts` | 6 而非 5 个领域文件存在反向依赖 | 纳入 `BattleManager`，完整覆盖 6 个文件 |
| 子管理器内部 `new` 模式未考虑 | `BattleAnimationManager`/`LifecycleManager` 通过 `BattleSystem` 构造函数内部 `new` 创建，注入 `uiEventPort` 不会自动传递 | `BattleSystem` 接收 `IUIEventPort` 后在构造函数中转发给子管理器 |
| ISP 描述偏差 | `IDomainEventBus` 已仅用于领域事件；UI 事件走独立 `eventBus`（mitt），非 ISP 违规，是 DIP 违规 | 修正描述：问题本质是 DIP 违规，IUIEventPort 是对策；保留方案结构 |
| `UIEventBus` 注册位置不明确 | `container.register('UIEventBus')` 未指定放在哪个函数 | 明确放在 `initializeContainer()` 最上方 |
| UI 层迁移一刀切 | 不同文件 evnetBus 使用模式不同 | 逐文件指定迁移策略 |
| `DebugGate` 消费者未追踪 | 有 4 个外部文件引用 `debugGate` | 列出所有使用方，说明如何处理 |
| `BattleParticipantImpl` 静态 setter 未提及 | 与方案批评的模式同类 | 注明：因使用 `triggerEventBus`（领域事件），不属于本方案范围，但作为已知问题记录 |
| `BattleEventManager` 角色未说明 | 订阅了 mitt eventBus 事件，新架构中需调整 | 明确迁移策略 |

## 四、分阶段实施计划

### Phase 0：新建端口定义（无破坏性）

**新建 `src/domain/port/IUIEventPort.ts`**：
```typescript
/**
 * UI 事件端口 — 领域层向 UI 层发射通知的最小化接口
 *
 * 设计原则：
 * - 仅包含 emit，不包含 on/off（领域层不订阅 UI 事件）
 * - 与 IDomainEventBus（领域内部事件，含 on/off/emit）彻底分离
 * - 符合 ISP：领域层只需要发射能力，不需要订阅能力
 * - 符合 DIP：领域层定义接口，基础设施层实现
 */
export interface IUIEventPort {
  emit(event: string, payload?: unknown): void
}
```

**新建 `src/infrastructure/adapters/event/UIEventBus.ts`**：
```typescript
import mitt, { type Emitter } from 'mitt'
import type { BattleEvents } from '@/domain/battle/type/BattleEventType'
import type { IUIEventPort } from '@/domain/port/IUIEventPort'

export class UIEventBus implements IUIEventPort {
  private emitter: Emitter<BattleEvents>

  constructor() {
    this.emitter = mitt<BattleEvents>()
  }

  emit(event: string, payload?: unknown): void {
    this.emitter.emit(event as keyof BattleEvents, payload as any)
  }

  /** 供 UI 层订阅使用（BattleManager.on/off、Vue 组件） */
  getEmitter(): Emitter<BattleEvents> {
    return this.emitter
  }
}
```

#### 2.1 `DebugGate.ts` — 构造函数注入 + 废弃单例

```typescript
import type { IUIEventPort } from '@/domain/port/IUIEventPort'
// 移除: import { eventBus } from '@/main'

export class DebugGate {
  enabled = false
  waitingPhase: string | null = null
  private _resolve: (() => void) | null = null

  constructor(private readonly uiEventPort: IUIEventPort) {}

  setEnabled(v: boolean): void {
    this.enabled = v
    this.uiEventPort.emit(BattleEventCodes.DEBUG_TOGGLE, { enabled: v })
    if (!v) this.nextStep()
  }

  async waitIfNeeded(phase: string): Promise<void> {
    if (!this.enabled) return
    this.waitingPhase = phase
    this.uiEventPort.emit(BattleEventCodes.DEBUG_PAUSE, { phase })
    return new Promise((resolve) => { this._resolve = resolve })
  }

  nextStep(): void {
    this.waitingPhase = null
    const resolve = this._resolve
    this._resolve = null
    resolve?.()
    this.uiEventPort.emit(BattleEventCodes.DEBUG_PAUSE_RESUME)
  }

  isWaiting(): boolean { return this._resolve !== null }
}

// 废弃全局单例：export const debugGate = new DebugGate()
// 改成 DI 容器管理：container.resolve<DebugGate>('DebugGate')
```
