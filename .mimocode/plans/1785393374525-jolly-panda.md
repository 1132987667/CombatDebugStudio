# 修复计划：4 个严重 Bug

## 概述

修复报告中的 4 个严重问题，涉及 3 个文件，每处改动均为 1-10 行以内的外科手术式修改。

---

## 问题 4：多护盾叠加时 `onRemove` 过度扣减

**文件**: `src/domain/buff/atomic/effects/ShieldEffect.ts`

**根因**: `onRemove` 用完整 `_shieldAmount` 扣减全局 `shieldValues`，但该全局值可能已被 `takeDamage` 消耗，导致多减。

**改动**: 第 48 行，扣减时取 `Math.min(shieldAmount, current)`：

```typescript
// 改前:
buffSystem.setShieldValue(ctx.characterId, Math.max(0, current - shieldAmount))

// 改后:
const deduction = Math.min(shieldAmount, current)
buffSystem.setShieldValue(ctx.characterId, current - deduction)
```

## 问题 5：`onTick` 始终传入 `turn = 0`

**文件**: `src/domain/buff/BuffSystem.ts` + `src/domain/battle/BattleSystem.ts`

**根因**: `updatePerTurn` 没有接收 `currentTurn` 参数，内部 `onTick` 调用硬编码 `0`。

**改动 1** — `BuffSystem.ts` 第 975 行：
```typescript
// 改前:
public updatePerTurn(characterId: string): void {
  instance.script.onUpdate(instance.context, 0)
  effect.handler.onTick?.(instance.context, effect.params, 0)

// 改后:
public updatePerTurn(characterId: string, currentTurn: number = 0): void {
  instance.script.onUpdate(instance.context, currentTurn)
  effect.handler.onTick?.(instance.context, effect.params, currentTurn)
```

**改动 2** — `BattleSystem.ts` 第 922 行：
```typescript
// 改前:
this.buffSystem.updatePerTurn(participant.id)

// 改后:
this.buffSystem.updatePerTurn(participant.id, battle.currentTurn)
```

注意：`instance.script.onUpdate` 的第二个参数是 `deltaTime`（毫秒）而非回合数。**不修改 `onUpdate` 的传参**，保持 `0` 或传入 `currentTurn` 效果相同（均为非零数值，实际无脚本依赖此值做精度计算）。这里采取保守方案：只传给 `onTick`，`onUpdate` 保持 `0` 不变。

## 问题 6：`_inDamageCallback` 布尔守卫误杀合法并发触发

**文件**: `src/domain/battle/BattleSystem.ts`

**根因**: 布尔守卫一旦进入就拒绝所有嵌套调用，反伤等合法触发被静默丢弃。

**改动**: 第 441-448/565 行，布尔标志替换为深度计数器：

```typescript
// 改前:
let _inDamageCallback = false
// ...
if (_inDamageCallback) return
_inDamageCallback = true
// ... finally:
_inDamageCallback = false

// 改后:
let _damageCallbackDepth = 0
const MAX_DAMAGE_CALLBACK_DEPTH = 3
// ...
if (_damageCallbackDepth >= MAX_DAMAGE_CALLBACK_DEPTH) {
  LoggerProvider.logger.addDebugLog(
    `伤害回调嵌套深度超过上限(${MAX_DAMAGE_CALLBACK_DEPTH})，丢弃`,
    { level: LogLevel.WARN },
  )
  return
}
_damageCallbackDepth++
// ... finally:
_damageCallbackDepth--
```

## 问题 7：`LIMITED` 满层刷新时不触发 `onStackChange`

**文件**: `src/domain/buff/BuffSystem.ts`

**根因**: `addBuff` 的 `LIMITED` 分支中，`newStacks > maxStacks` 时仅调用 `refreshBuff`，未通知 `effectPlan` 原语。

**改动**: 在 `refreshBuff` 后补充 effectPlan 通知代码（与非满层分支一致）：

```typescript
// 在 this.refreshBuff(target.id, currentTurn) 之后、this.triggerAttributeChange 之前插入:
const buffResolved = this.scriptRegistry.getResolvedBuffConfig(buffId)
if (buffResolved?.effectPlan) {
  for (const effect of buffResolved.effectPlan) {
    effect.handler.onStackChange?.(target.context, effect.params, maxStacks)
  }
  const effectLines = buffResolved.effectPlan
    .map((e) => e.handler.getEffectLines?.(target.context, e.params) ?? [])
    .flat()
  if (effectLines.length > 0) {
    target.effectLines = [
      ...(target.script.getEffectLines?.(target.context) ?? []),
      ...effectLines,
    ]
  }
}
```
