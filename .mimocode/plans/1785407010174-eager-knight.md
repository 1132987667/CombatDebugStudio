### Step 2: 核心逻辑重写（BuffSystem.ts）

**2a. `addBuff` 路径判定重写（L639-L683 替换）**

替换 L639-L683 的现有代码。当前代码在 L639-643 执行 `script.onApply`，L661-683 执行 effectPlan 或旧路径。改为：

```
// 代替 L639 的 const applyResult = BuffErrorBoundary.wrap...
// 先在 L635 之后、脚本调用之前做路径判定：

const buffResolved = this.scriptRegistry.getResolvedBuffConfig(buffId)
const hasScript = script !== NOOP_BUFF_SCRIPT  // 真实脚本
const hasEffectPlan = buffResolved?.effectPlan && buffResolved.effectPlan.length > 0

// 检查有无配置效果（attributes/immunities/aura/controlType）
const hasConfigEffects = !!(
  resolvedConfig.attributes ||
  (resolvedConfig.immunities && resolvedConfig.immunities.length > 0) ||
  resolvedConfig.aura ||
  (resolvedConfig.controlType && resolvedConfig.controlType !== ControlType.NONE)
)
const isTrackPassive = buffId.startsWith('_track_passive_')
const hasTriggersOnly = !hasScript && !hasEffectPlan && !hasConfigEffects &&
  (resolvedConfig.triggers?.length ?? 0) > 0

let path: 'A' | 'B' | 'C' | 'D'
if (hasScript) path = 'A'
else if (hasEffectPlan) path = 'B'
else if (hasConfigEffects) path = 'C'
else if (isTrackPassive || hasTriggersOnly) path = 'D'
else {
  // PATH ERROR
  this.logger.addDebugLog(`[BuffSystem] 配置错误: ${buffId} 无脚本、无 effectPlan、无配置效果，拒绝施加`, { level: 'ERROR' })
  return ''
}

// Path A: 脚本驱动
if (path === 'A') {
  buffContext.variables.set('_stacks', buffInstance.currentStacks)
  const applyResult = BuffErrorBoundary.wrap(() => { script!.onApply(buffContext) })
  if (applyResult === null) {
    this.buffInstances.delete(instanceId)
    BuffContextPool.return(buffContext)
    this.logger.addDebugLog(`[BuffSystem] onApply 失败，已回滚: ${buffId} → ${characterId}`, { level: 'WARN' })
    return ''
  }
  buffInstance.effectLines = script!.getEffectLines?.(buffContext) ?? []
}
// Path B: effectPlan 驱动
else if (path === 'B') {
  for (const effect of buffResolved!.effectPlan) {
    BuffErrorBoundary.wrap(() => { effect.handler.onApply(buffContext, effect.params) })
  }
  buffInstance.effectLines = buffResolved!.effectPlan
    .map(e => e.handler.getEffectLines?.(buffContext, e.params) ?? []).flat()
}
// Path C: 纯配置
else if (path === 'C') {
  this.applyAttributeModifiers(characterId, instanceId, buffId)
  this.applyBuffImmunities(characterId, buffId)
  // aura 仅在 effectPlan 不含 AuraEffect 时执行
  const hasAuraEffect = buffResolved?.effectPlan?.some(e => e.type === AtomicEffectType.AURA) ?? false
  if (!hasAuraEffect) this.applyBuffAuraModifiers(characterId, instanceId, buffId)
  buffInstance.effectLines = []
}
// Path D: 纯标记 / trigger-only
else {
  buffInstance.effectLines = []
}
```

注意：`resolvedConfig` 在第 451 行构造，路径判定要在其之后。

**2b. `removeBuff` 路径判定互斥（L917-L929 替换）**

当前执行 BOTH：
```typescript
// L917-919: script.onRemove (always)
BuffErrorBoundary.wrap(() => { instance.script.onRemove(instance.context) })
// L921-929: effectPlan.onRemove (always)
const buffResolved = this.scriptRegistry.getResolvedBuffConfig(instance.buffId)
if (buffResolved?.effectPlan) { for (const effect of buffResolved.effectPlan) { ... } }
```

改为互斥判定：
```typescript
// 路径判定（与 addBuff 对称）
const buffScript = this.scriptRegistry.get(instance.buffId)
const hasScript = buffScript !== null && buffScript !== NOOP_BUFF_SCRIPT
const buffResolved = this.scriptRegistry.getResolvedBuffConfig(instance.buffId)
const hasEffectPlan = buffResolved?.effectPlan && buffResolved.effectPlan.length > 0

if (hasScript) {
  // PATH A: 脚本 onRemove
  BuffErrorBoundary.wrap(() => { instance.script.onRemove(instance.context) })
} else if (hasEffectPlan) {
  // PATH B: effectPlan onRemove
  for (const effect of buffResolved!.effectPlan) {
    BuffErrorBoundary.wrap(() => { effect.handler.onRemove(instance.context, effect.params) })
  }
}
// PATH C/D: 无回调
```

**2c. `updatePerTurn` 路径判定互斥（L1001-L1011 替换）**

当前执行 BOTH script.onUpdate + effectPlan.onTick。改为互斥：
- `hasScript` → 仅 `script.onUpdate`
- `hasEffectPlan` → 仅 `effectPlan[].onTick`

注意：Path D 的 buff（`_track_passive_` 或 trigger-only）不需要更新。路径判定与 addBuff/removeBuff 对称。

**2d. `refreshBuff` 路径判定互斥 + effectPlan onRefresh（L978-L993 替换）**

当前仅 `script.onRefresh`。改为：
- `hasScript` → `script.onRefresh` + `script.getEffectLines`
- `hasEffectPlan` → `effectPlan[].onRefresh` + 从 effectPlan 生成 effectLines

注意：需要把 `currentTurn` 注入到 context（与 updatePerTurn 对称）。

## 关键设计决策

1. **Path A 判定条件**：`script !== NOOP_BUFF_SCRIPT`（真实注册的脚本）而不是 `script !== null`。NOOP 是占位符，不应触发脚本路径。

2. **hasConfigEffects 的判定**：仅检查 `attributes`/`immunities`/`aura`/`controlType`，不包括 `triggers`。Trigger-only 走 Path D。

3. **`updatePerTurn` 的 Path D 行为**：Path D 的 Buff 不需要更新循环，路径判定后直接跳过（走回合递减和过期移除即可）。

4. **`isSelfContained` 的语义变更**：改为严格模式（仅 `selfContained === true`），不再因有效 effectPlan 而被视为自包含。这在 Path 系统中是安全的，因为 effectPlan 现在由 Path B 独立管理，不再需要 `isSelfContained` 做保护。

5. **不清理 `ponytail:` 标签**：本次只改核心逻辑，存量注释标记留待以后统一清理。
