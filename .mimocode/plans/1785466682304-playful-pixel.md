# 回合标签状态前置 + RoundNarrativeRenderer 死代码砍伐（合并方案）

## 目标

1. 删除 `RoundNarrativeRenderer` 中旧管道死代码（12 个未使用方法 + HpTracker + 3 个接口 + 相关 import）。
2. 回合标签从"事后遍历推断"改为"**主循环状态前置收集**"：直接消费 `meta.kill`/`role: 'sub'` 显式语义，O(N)，回合切换时即得标签；`meta.roundTag` 作为显式默认值保留。
3. 顺带激活击杀/暴击高亮：action 块的 `result` 不再恒为 undefined。

**设计取舍**：不采纳"引擎 BattleSystem 统计 + 快照挂 roundTag"方案——它动引擎、diff 大，且快照被 showStatus 过滤时会丢标签；主循环收集天然免疫该问题，改动收敛在渲染器一个文件。

## 背景（已查证）

- `meta.roundTag` 显式通道（`battle-log.ts:92`）存在但全项目无一处填充；后处理循环（311-327）用 `inferRoundTag` 推断结果**覆盖**显式标签。
- `inferRoundTag` 的 `hasLethal` 恒 false（action 块无 lethal 字段）→ '致命保护!' 是死分支 → **连同 lethal 概念一并删除**（`meta.lethal` 全项目无写入方）。
- action 块 `result: undefined`（221 行）→ 击杀/暴击动作行无高亮；`meta.kill` 由引擎显式写入（`BattleExecutor.ts:634`，写在 action 日志而非 sub 日志）。
- 旧管道方法（buildBlocks/renderBlock/renderSnapshot/computeSummary/renderBattleSummary/detectTurnAnnotation/renderBattleHeader/renderRoundHeader/renderSystemBlock/renderTurnSeparator/isFatal 等）仅被彼此调用，`renderEntries` 不触碰。
- `tests/` 目录零引用这些方法，无需同步测试。

**renderEntries 改造（状态前置）**：
- 新增状态：`currentRoundBlock`、`roundHasKill`、`roundSubCount`（替代 162 行 `roundTag` 局部变量）
- 新增 `flushRound()`：应用标签并重置（含在 `flushAll()` 内，保证最后回合标签落地）：
  ```ts
  const flushRound = () => {
    if (currentRoundBlock) {
      if (roundHasKill) currentRoundBlock.tag = '击杀!'
      else if (roundSubCount > 3) currentRoundBlock.tag = '多重触发'
      currentRoundBlock = null
      roundSubCount = 0
      roundHasKill = false
    }
  }
  ```
- 回合切换处：`ROUND` 块创建时 `tag: meta.roundTag`（显式默认值），并记录 `currentRoundBlock`
- 主循环 switch 之前收集（O(N)）：
  ```ts
  if (meta.role === BattleLogMetaRole.ACTION && meta.kill) roundHasKill = true
  else if (meta.role === BattleLogMetaRole.SUB) roundSubCount++
  ```
- **删除 311-327 后处理推断循环**
- ACTION 分支 `result: undefined` → `result: this.buildResult(e.meta)`；`kill: meta.kill === true` 字段删除（见 battle-log.ts）

**buildResult 裁剪复活**（只输出 sub 行没有的高亮，避免与 sub 行重复伤害数值；样式 `log-crit/log-lethal/log-kill` 已存在）：
```ts
private buildResult(meta: BattleLogMeta): LogSegment[] | undefined {
  if (!meta.crit && !meta.lethal && !meta.kill) return undefined
  const segs: LogSegment[] = []
  if (meta.crit) segs.push({ text: '★ 暴击! ', classStr: 'log-crit' })
  if (meta.lethal) segs.push({ text: ' — 致死!', classStr: 'log-lethal' })
  if (meta.kill) segs.push({ text: ' ✦ 击杀!', classStr: 'log-kill' })
  return segs
}
```
（`meta.lethal` 无写入方，致死段暂不触发，属正常降级；buildResult 的 `BattleLogMeta` inline import 保留或提升为顶层 import）

## 已知降级边界（接受）

- showStatus 开关（`BattleLog.vue:219` 按 `category!=='status'` 过滤）滤掉 STATUS 类 action 日志时，该回合"多重触发"统计可能偏低（击杀日志 category=DAMAGE 不受影响）——开关语义即降噪，可接受
- '致命保护!' 标签随 lethal 死分支一并删除（`meta.lethal` 无写入方，从未触发过）
