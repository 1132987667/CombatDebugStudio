# Task Spec: 太初道枢资深用户改进建议（基于真实代码库）

## Goal
以"太初道枢战斗系统资深业务专员（QA 主管）"身份，基于本仓库（CombatDebugStudio：回合制战斗引擎 + Vue3 可视化调试沙盒）的**真实实现**，产出客观、具体、可落地的改进建议。每条建议包含「场景描述 → 当前问题 → 改进建议」，至少 5 条有深度，覆盖操作效率 / 功能缺失 / 易用性 / 性能与稳定性 / 数据与报表 / 协作与集成 / 其他 中的多数类别，最后给出一个"杀手级"功能并说明原因。

## Scope（范围内）
- 探索 src/presentation 四大产品化模块：封神榜（数据编定）、唤灵台（阵容战斗）、演劫台（实战对局）、昊天镜（战局分析：事件流回放工作台 + 调试工作台、条件断点、分支 diff、存档导入导出）
- 探索 src/infrastructure（日志 LogCollector/LogParser、事件总线）、configs（JSON 数据）、documents（需求/审查文档中的已知缺陷）
- 产出建议必须以代码库真实功能/缺口为证据（file:line 引用），避免空泛套话

## Non-goals（范围外）
- 不修改任何代码（纯建议产出）
- 不评价代码质量本身（如命名、架构），只从用户视角谈产品功能
- 不做跨模块 UI 截图/视觉审查

## Success criteria（成功标准）
1. 每条建议可追溯到真实代码证据（grep/read 验证过存在或缺失）
2. 至少 5 条深度建议，格式统一为 场景描述 → 当前问题 → 改进建议
3. 覆盖 ≥ 4 个输出要求中的类别
4. 杀手级功能建议有明确理由和落地路径
5. 最终交付：完整建议报告（回复正文 + 存档 .reasonix/autoresearch/<id>/deliverable/）

## Verification gates
- 每条建议引用到的"现状"需 grep/read 验证（存在某功能 / 确实缺失某功能）
- 交付前通读一遍，确认无虚构功能、无空泛表述

## Iteration direction plan
- Iter 1: 建立状态 + 摸清仓库结构（done）
- Iter 2: 昊天镜模块深度调查（事件流回放 / 断点 / diff / 存档 IO / 断言统计）——explore 子代理 + 自读关键文件
- Iter 3: 日志/事件/断言基础设施调查（LogCollector/LogParser/eventBus/seed 随机种子）
- Iter 4: 封神榜 / 唤灵台 / 演劫台 + configs 数据调查
- Iter 5: documents 已知缺陷与需求文档核对（不重复报告已规划内容，或标注"已规划"）
- Iter 6: 合成建议清单（每项带证据）→ 验证证据 → 撰写交付报告
