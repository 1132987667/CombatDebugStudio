# 多仓库建造改造计划

## Context

当前行囊是**单仓库 + 格子扩容**模型：`packStore.storage: StorageSlot[]` 一个扁平数组，容量=数组长度（12 起步、每次 +6、上限 36），用金钱扩容（[packStore.ts](file:///d:/4-softworkspace/java/CombatDebugStudio/src/presentation/stores/packStore.ts#L1072-L1127)）。

斗战西游是刷宝游戏，物品量大且品类混杂，单仓库无法分类收纳。需求：**仓库可用材料建造多座（上限 5 座、成本递增），不同物品放不同仓库**。

已确认决策：
- 交付范围 = 文档 + 代码
- 设定文档写入 `documents/演劫台/修改意见.md`（UTF-8 带 BOM）
- 建造口径 = 材料递增，上限 5 座
- 每座仓库**独立扩容**（各自 12→36，沿用金钱扩容档位）
- 提供**仓库间直接转移**（新增 store 方法与交互），不只靠背包中转

## 一、数据模型（src/presentation/stores/packStore.ts）

采用**嵌套 warehouses[]**（每座仓库持有自己的 slots），而非给扁平数组加 warehouseId：
- 容量 = 该仓 `slots.length`，建造/扩容/改名天然局部，不污染全链路
- 迁移只需把旧 `storage` 包裹一次

```ts
/** 仓库（多座，可建造 / 改名；每座独立格子） */
export interface Warehouse {
  /** 稳定 id（改名、排序不变；首仓固定 'wh_main'） */
  id: string
  /** 展示名（可改） */
  name: string
  /** 格子列表，长度即该仓容量 */
  slots: StorageSlot[]
}
```

store 状态（替换 L287 `storage`）：
- `warehouses = ref<Warehouse[]>([])`
- `activeWarehouseId = ref('wh_main')`
- `activeWarehouse = computed(() => warehouses.value.find(w => w.id === activeWarehouseId.value) ?? warehouses.value[0])`
- `storageCapacity = computed(() => activeWarehouse.value?.slots.length ?? 0)`（语义变为「当前仓」）
- `warehouseFull = computed(...)`：当前仓无空位；**作为「是否还能存入」的单一来源**，替换 PackItemCard/PackItemDetail 中内联的 `pack.storage.some(...)`
- `warehouseCount / maxWarehouseCount / canBuildWarehouse` computed

`buildFromConfigs()`（L507）改为生成首仓：`{ id:'wh_main', name:'主仓库', slots: storageCells.map(...) }`（映射逻辑不变）。

## 二、存档迁移（v6 → v7）

- 抽 `const PACK_SNAPSHOT_VERSION = 7`，消除 interface L198 与 flush L341 的版本双写
- `PackRuntimeSnapshot`：`storage` → `warehouses: Warehouse[]` + `activeWarehouseId: string`
- `flush()`（L340-366）序列化 `warehouses`/`activeWarehouseId`
- `load()`（L403 附近）：
  - `snap.warehouses` 存在 → 直接还原（含 id/name/slots，字段用 `??` 兜底）
  - 否则 `snap.storage` 存在（v6 及更早）→ 包裹成 `[{ id:'wh_main', name:'主仓库', slots: snap.storage }]`，`activeWarehouseId='wh_main'`
  - 兜底：为空时建一座空首仓；`activeWarehouseId` 无效时回退 `warehouses[0].id`
  - **幂等**：仅当 `snap.warehouses` 缺失才包裹；v7 落盘后恒不再触发

## 四、store 方法改造

```ts
/** 下一座仓库建造成本（已满 5 座返回 null） */
function buildCost(): XiyouRecipeMaterial[] | null
/** 建造新仓库：上限 → 材料 → 扣料 → 新建；返回是否成功 */
function buildWarehouse(): boolean
/** 切换当前操作仓库 */
function switchActiveWarehouse(id: string): boolean
/** 重命名仓库（trim 非空） */
function renameWarehouse(id: string, name: string): boolean
/** 仓库间整格直接转移（目标仓找首个空位；满则拒绝） */
function transferWarehouseItem(fromId: string, slotIdx: number, toId: string): boolean

// 既有方法加默认仓参数，默认 = 当前仓（旧调用点行为不变）
function moveToStorage(itemId: string, warehouseId?: string): boolean
function moveToInventory(slotIdx: number, warehouseId?: string): boolean
function expandCost(warehouseId?: string): number
function expandStorage(warehouseId?: string): boolean
```

- `buildWarehouse` 校验顺序：① 座数 ≥ maxCount → toast「仓库已达上限（5 座）」；② 逐条比对 `inventory[id] ?? 0 < count` → toast 缺料明细，**不扣**；③ `removeItem` 扣料；④ push 新仓（空 baseSlots 格）并 `activeWarehouseId` 指向它；`scheduleSave()` + toast。新仓 id 用 `wh_<时间戳/随机>`（仿 `newInstanceId()`）
- `expandStorage(warehouseId?)`：按**该仓** `slots.length` 算档位，`MAX_STORAGE=36` 为该仓上限
- 新增 `newWarehouseId()` 工具；导出 `PACK_SNAPSHOT_VERSION`、`MAX_STORAGE`
- 导出项（L1489 附近）：删 `storage`；加 `warehouses / activeWarehouse / activeWarehouseId / warehouseCount / maxWarehouseCount / canBuildWarehouse / warehouseFull / switchActiveWarehouse / renameWarehouse / buildWarehouse / buildCost / transferWarehouseItem`，保留并复用既有 `storageCapacity / moveToStorage / moveToInventory / expandCost / expandStorage`
