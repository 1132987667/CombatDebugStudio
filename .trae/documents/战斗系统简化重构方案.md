# 战斗系统简化重构方案：移除多战斗支持

## 一、重构目标

- 消除不必要的多战斗并发支持，将系统简化为**单战斗实例**模型
- 降低代码复杂度，提升可维护性、可读性和性能
- 消除因多战斗状态管理混乱导致的各种潜在错误
- 保持向后兼容，确保现有功能正常工作

---

## 二、核心设计变更

1. **移除 battles 映射表**：不再同时管理多个战斗实例
2. **消除 battleId 参数污染**：所有方法不再需要 battleId 参数
3. **简化状态管理**：将当前战斗数据直接作为类的核心状态
4. **动画队列去 ID 化**：不再按战斗 ID 隔离，直接管理当前战斗的动画

### 第二阶段：实现类修改

#### 3.3 修改 `GameBattleSystem` 类 (`src/core/BattleSystem.ts`)

##### 3.3.1 属性调整

| 原属性 | 新属性 | 说明 |
|--------|--------|------|
| `private battles = new Map<string, BattleData>()` | 移除 | 不再需要多战斗映射 |
| `private curBattleData: BattleData` | `private battleData: BattleData` | 直接存储当前战斗数据 |
| `private curParticipantsInfo: BattleParticipant[]` | 移除 | 数据可从 battleData.participants 获取 |
| `private animationState = new Map<string, {...}>()` | `private animationQueue: Array<...>` | 单战斗无需 Map 隔离 |
| `private turnProcessingLocks = new Map<string, boolean>()` | `private isProcessingTurn = false` | 单战斗使用布尔值即可 |

##### 3.3.2 构造函数调整

- 保留依赖注入构造函数
- 初始化时创建默认 battleData

##### 3.3.3 方法签名修改

所有带 battleId 参数的方法改为无参：

```typescript
// 修改前
public async processTurn(battleId: string): Promise<void>
public async endBattle(battleId: string, winner: ParticipantSide): Promise<void>
public getBattleState(battleId: string): BattleState | undefined
public startAutoBattle(battleId: string): void
public stopAutoBattle(battleId: string): void

// 修改后
public async processTurn(): Promise<void>
public async endBattle(winner: ParticipantSide): Promise<void>
public getBattleState(): BattleState | undefined
public startAutoBattle(): void
public stopAutoBattle(): void
```

##### 3.3.4 移除多战斗相关方法

- `getAllBattles()` - 移除
- `getActiveBattles()` - 移除
- `clearCompletedBattles()` - 移除
- `findBattleByParticipant()` - 移除
- `getBattleData(battleId)` - 改为无参 `getBattleData()`
- `getBattleStatus(battleId)` - 改为无参 `getBattleStatus()`
- `getRoundState(battleId)` - 改为无参 `getRoundState()`
- `isBattleInState(battleId, state)` - 改为 `isBattleInState(state)`
- `isBattleEnded(battleId)` - 改为 `isBattleEnded()`
- `isBattleInProgress(battleId)` - 改为 `isBattleInProgress()`

##### 3.3.5 内部方法修改

所有内部使用 `this.battles.get(battleId)` 或 `this.battles.get(battleId)!` 的地方改为直接使用 `this.battleData`。

需要修改的方法列表：
- `processTurnInternal(battleId)` → `processTurnInternal()`，内部直接使用 `this.battleData`
- `recordBattleAction(battleId, action)` → `recordBattleAction(action)`
- `addBattleAction(battleId, action)` → `addBattleAction(action)`
- `syncBattleStateUpdate(battleId)` → `syncBattleStateUpdate()`
- `syncBattleLog(battleId, logEntry)` → `syncBattleLog(logEntry)`
- `cleanupAnimationState(battleId)` → `cleanupAnimationState()`
- `isAnimationPlaying(battleId)` → `isAnimationPlaying()`
- `triggerAnimationAndWait(battleId, ...)` → `triggerAnimationAndWait(...)`
- `processAnimationQueue(battleId)` → `processAnimationQueue()`
- `cleanupBattleTimers(battleId)` → `cleanupBattleTimers()`

##### 3.3.6 自动战斗相关

- 移除 `getBattleDelay(battleId)` 方法，改为使用 `this.battleData`
- 自动战斗定时器 ID 存储在类属性 `private autoBattleTimerId?: symbol`

## 五、注意事项与风险

1. **状态清理**：战斗结束后需调用 `resetBattle()` 才能开始新战斗
2. **并发安全**：定时器回调中应确保当前战斗仍然活跃
3. **动画队列清空**：战斗结束时必须清空动画队列
4. **事件监听解绑**：外部组件需在战斗结束后取消监听
5. **向后兼容**：IBattleSystem 接口变更会影响所有实现类
