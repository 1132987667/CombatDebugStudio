# 战斗文本不显示排查指南

## 背景

项目是一个 Vue 3 + TypeScript 战斗模拟系统。战斗中的伤害数字、技能名称、治疗数字等视觉文本已经有完整的代码实现（CSS 动画飘字、事件驱动），但在实际战斗中不显示。

## 排查目标

找到从"战斗逻辑计算出伤害"到"屏幕出现浮动数字"这条链路中，哪一个环节断开了。

## 完整链路

```
BattleSystem.processTurnInternal()
  → BattleExecutor.executeParticipantAction() / handleHitAttack()
  → BattleAnimationManager.triggerDamageAnimationAndWait(targetId, damage, ...)
  → eventBus.emit(BattleEventCodes.DAMAGE_ANIMATION, data)       ← 发射事件
  → battleStore.handleDamageAnimationEvent(data)                  ← 接收事件
  → setAnimationState('damage', data)                             ← 写入响应式状态
  → BattleField.vue watch(store.animationState, { deep: true })   ← 监听变更
  → visualEffectsRef.value?.showDamageNum(targetId, damage, crit) ← 显示浮动数字
  → dmgNums.push() → 模板渲染浮动数字
```

## 检查步骤（按优先级从高到低）

### 第 1 步：检查动画事件是否被发射

在浏览器控制台中搜索这些日志关键字或添加断点：

- 在 `BattleAnimationManager.ts` 的 `triggerAnimationAndWait()` 方法中，`eventBus.emit(animation.type, animation.data)` 这一行是否被执行？
- `animation.type` 是否为 `'damage-animation'`（即 `BattleEventCodes.DAMAGE_ANIMATION`）？
- 确认实际走的是哪个执行路径：
  - **新路径**：`BattleExecutor.handleHitAttack()` → 调用 `animationManager.triggerDamageAnimationAndWait()`
  - **旧路径**：`ActionExecutor.processAttack()` → **不触发任何动画事件**
  - **命令路径**：`BattleSystem.generateCommandsForTurn()` → **也不触发任何动画事件**

> 关键问题：用户点击"执行回合"时，调用的是哪一个路径？如果是 `processTurnAsCommands()` 命令路径，那动画事件永远不会被发射。

### 第 2 步：检查 Store 层是否收到了事件

- 在 `battleStore.ts` 的 `handleDamageAnimationEvent` 中加 `console.log`，确认它被调用
- 检查 `events` Map 中 `BattleEventCodes.DAMAGE_ANIMATION` 是否已正确注册
- 检查 `battleManager.value.on()` 是否在正确的 `eventBus` 实例上注册（确认 `eventBus` 导入来源一致）
- ⚠️ **关键竞态风险**：Store 创建时 `battleManager.value` 已经是正确的实例吗？`container.resolve()` 返回的是单例吗？是否有其他地方调用了 `initializeBattleManager(newInstance)` 导致新实例没有注册事件？

### 第 3 步：检查 animationState 是否被写入

- 在 `battleStore.ts` 的 `setAnimationState()` 中加 `console.log`，确认 `animationState.damage = data` 执行后值是否正确
- 检查 `setTimeout` 清除动画的延迟时间（`getAnimationDuration()` 返回值），是否太短导致 Vue 来不及响应？

### 第 4 步：检查 BattleField.vue 的 watch

- 确认 `watch(store.animationState, ...)` 的回调是否被触发
- 当 `state.damage` 不为 null 时，确认 `visualEffectsRef.value` 不为 null
- 检查 `visualEffectsRef` 对应的 `<BattleVisualEffects ref="visualEffectsRef" />` 是否在模板中渲染
- 检查是否有条件渲染（`v-if`）导致组件被销毁

### 第 5 步：检查 BattleVisualEffects 的 DOM 渲染

- 在 `showDamageNum()` 方法中加日志，确认 `cardCenter()` 返回有效坐标
- 检查 `cardElements` Map 中是否已有目标角色的 HTMLElement（卡片是否已注册）
- 在浏览器 Elements 面板检查 `#visual-effects-root` 是否存在
- 检查 CSS：`.battle-visual-effects` 的 `z-index: 1000` 和 `.floating-num` 的 `z-index: 1100` 是否被覆盖？
- 检查父容器是否有 `overflow: hidden` 或 `display: none`

### 第 6 步：检查控制台错误

- 是否有任何 JavaScript 运行时错误阻断执行流？
- BattleAnimationManager 的队列处理是否抛出异常（`isAnimationPlaying` 卡在 true 导致后续动画被阻塞？）

## 可能的原因汇总

1. **走的是旧路径/命令路径，不发射动画事件** — 最常见原因
2. `visualEffectsRef` 未挂载或为 null
3. 卡片 DOM 注册时序问题，`cardCenter()` 返回 null
4. Store 的 eventBus 注册与发射端不是同一个实例
5. CSS 被覆盖（z-index、overflow、display）
6. 动画队列卡死
