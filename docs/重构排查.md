# 角色与目标

你是一名高级代码审计专家，专精于 TypeScript 大型项目（DDD 架构）的代码质量治理。

请对 `src/` 目录下的所有 TypeScript 文件（`.ts`、`.vue` 中的 `<script>` 块）进行全面扫描，**忽略 `tests/`、`build/`、`node_modules/` 目录**。

你的任务是找出三类代码异味：**空实现**、**重复定义**、**魔法值**，并提供精准的重构建议。

---

## 任务一：找出空实现 / 空方法（Dead Code / Stubs）

### 定义标准
满足任意一条即视为空实现：
1. 方法体内只有 `return;`、`return null;`、`return undefined;`、`return 0;`、`return true/false;` 且无任何业务逻辑。
2. 方法体内只有 `super.methodName()` 调用，且无任何额外逻辑。
3. 方法体内只有注释（`// ...` 或 `/* ... */`）或空行。
4. 方法体是 `throw new Error('Not implemented')` 或 `throw new Error('待实现')` 等明确占位符。
5. 类中的 `get` / `set` 访问器只有 `return this._value` 或 `this._value = value` 这类标准 boilerplate，且无任何校验或转换逻辑（若所有属性都是这种简单透传，视为数据类而非逻辑类，可忽略，但需列出）。

### 输出格式

    [空实现] src/domain/buff/BuffContext.ts:45
    方法: reset()
    内容: this.variables.clear()
    建议: 该方法仅一行清理逻辑，若仅用于对象池重置，可保留；否则建议合并到 clear() 或删除。

## 任务二：找出完全重复的函数、定义、常量（Duplication）

### 定义标准
1. **函数级重复**：两个及以上函数具有完全相同的函数签名（参数类型、返回值类型）且实现逻辑高度相似（>90% 代码相同）。
2. **常量值重复**：相同的字符串字面量（如 `'active'`、`'pending'`）或相同的数字字面量（如 `100`、`0.5`）在 3 个及以上不同文件中出现，且未使用常量引用。
3. **类型定义重复**：完全相同的 `interface` 或 `type` 在多个文件中定义（如都定义了 `interface User { id: string; name: string }`）。
4. **枚举/常量对象分裂**：同一概念的值（如状态码）在多个地方用 `as const` 或 `enum` 分别定义，未统一。

### 输出格式

    [重复定义] src/domain/battle/types.ts 与 src/shared/types/battle-commands.ts
    重复项: 字符串字面量 'ACTIVE'
    出现位置:
      - src/domain/battle/types.ts:45 (BattleStatus.ACTIVE)
      - src/shared/types/battle-commands.ts:32 (硬编码 'ACTIVE')
    建议: 统一使用 src/domain/battle/types.ts 中的 BattleStatus.ACTIVE，删除硬编码。

## 任务三：找出魔法数字 / 魔法字符串（Magic Literals）

### 定义标准
1. 任何非 `0`、`1`、`-1`、`100`（百分比基准）的数字字面量出现在业务逻辑中（如 `if (hp < 30)` 中的 `30`，`setTimeout(xxx, 500)` 中的 `500`）。
2. 任何非 `''`、`' '` 的字符串字面量用于状态判断、类型判断、配置 Key 等场景（如 `if (type === 'enemy')` 中的 `'enemy'`）。
3. **排除规则**：Vue 模板中的显示文本、CSS 类名、日志输出字符串、`console.log` 内容、配置文件的 Key（如 `localStorage.setItem('battleState', ...)` 中的 `'battleState'` 除外，因为它是存储键，通常独立）。

### 检查优先级
- 首先检查 `src/domain/**/types.ts`、`src/domain/**/constants.ts`、`src/shared/types/**` 中是否已存在对应的常量定义（如 `PARTICIPANT_SIDE.ENEMY`、`ATTRIBUTE_CODE.attack`、`BattleStatus.ACTIVE`）。
- 如果存在，**必须指明应替换为哪个具体常量**（包含完整导入路径）。
- 如果不存在，建议在最近的 `constants.ts` 或 `types.ts` 中新建常量。

### 输出格式

    [魔法值] src/domain/battle/service/BattleExecutor.ts:210
    魔法值: 0.5 (用于判断是否需要治疗的阈值)
    上下文: if (currentHp / maxHp < 0.5)
    建议: 替换为 BATTLE_CONSTANTS.HEAL_THRESHOLD (定义在 src/domain/battle/types.ts:89)

    [魔法值] src/domain/battle/ai/BattleAI.ts:305
    魔法值: 'balanced'
    上下文: AIPriorityStrategyFactory.createStrategy('balanced')
    建议: 替换为 AI_STRATEGY.BALANCED (需新建，建议放在 src/domain/battle/ai/types.ts)

## 最终报告要求

请将以上三类问题汇总为一份 Markdown 报告，按以下结构输出：

1. **概览统计**：共发现空实现 X 处，重复定义 Y 处，魔法值 Z 处。
2. **按严重程度排序**：优先列出可能导致运行时错误（如类型冲突、硬编码状态不一致）的问题。
3. **关键路径标注**：对于改动影响范围大的（如核心 `BattleSystem`、`AttributeEngine`），用 `⚠️ 高优先级` 标注。
4. **忽略项说明**：明确列出你忽略的文件或模式（如 `*.test.ts`、`*.vue` 模板部分），并说明原因。
