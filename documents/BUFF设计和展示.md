## 一、设计原则定义

> **“全文本语义驱动”**
>
> 战斗 UI 严格遵循纯文本信息架构，所有状态变化、属性修正、Buff 效果**完全通过中文字词、数字、标点和排版层级来表达**，不使用任何图标或图形符号。通过字体粗细、颜色和缩进构建信息层级。

**允许使用的符号仅限于**：`↑` `↓` `%` `∞` `【】` `（` `）` `+` `-` `>` `<` `=` `/` `：`

## 二、核心格式规范

### 2.1 基础格式

```
【属性名称】↑/↓数值（条件）（剩余回合）
```

### 2.2 完整示例

```
攻击↑30%（3回合）
防御↓15%（3回合）
伤害↑40%（残血）（未激活）
速度↓20%（中毒）（2回合）
【眩晕】（1回合）
```

### 2.3 排版规则

| 类型        | 颜色 | 字重      | 示例                           |
| ----------- | ---- | --------- | ------------------------------ |
| 增益        | 青色 | 加粗      | **攻击↑30%（3回合）**          |
| 减益        | 红色 | 常规      | 防御↓15%（3回合）              |
| 控制        | 品红 | 加粗      | **【眩晕】（1回合）**          |
| 永久        | 灰色 | 常规      | 攻击↑5%（永久）                |
| 条件-未激活 | 灰色 | 常规      | 伤害↑40%（残血）（未激活）     |
| 条件-已激活 | 青色 | 加粗+闪烁 | **伤害↑40%（残血）（已激活）** |

## 七、响应规则

### 7.1 标签排序

1. 控制状态排最前
2. 剩余回合短的排前
3. 已激活条件增益优先于未激活
4. 增益优先于减益

### 7.2 折叠策略

- 核心属性超过 5 条时，折叠为 `+N`
- 点击 `+N` 展开全部

### 7.3 动画反馈

- 增益添加：青色文字从右滑入
- 减益添加：红色文字从左滑入
- 层数变化：数字跳动
- 剩余1回合：文字闪烁
- 移除：文字渐出消失
- 条件激活：灰色→青色切换，持续 0.3 秒高亮

## 十、设计规范总结

| 维度         | 规范                                                           |
| ------------ | -------------------------------------------------------------- |
| **图标**     | 无                                                             |
| **允许符号** | `↑` `↓` `%` `∞` `【】` `（` `）` `+` `-` `>` `<` `=` `/` `：`  |
| **颜色**     | 增益=青色，减益=红色，控制=品红，永久=灰色，条件=灰色/青色切换 |
| **字重**     | 增益加粗，减益常规，控制加粗                                   |
| **属性名**   | 2-4个中文字，使用标准术语                                      |
| **格式**     | `属性↑数值（条件）（回合）`                                    |
| **合并**     | 同属性合并显示，悬停拆解来源                                   |
| **排序**     | 控制优先→快到期优先→增益优先                                   |
| **折叠**     | 超过5条折叠为 +N                                               |

## 十一、一句话概括

> **将每个 Buff 拆解为“属性↑/↓数值”标签，用纯中文、颜色和排版表达一切，增益为青、减益为红、控制为品红，完全不用图标。**完善该小型回合制战斗游戏 buff 设计

这份纯文本驱动的 Buff 设计方案已经具备了极高的完成度和清晰的逻辑架构。为了让方案在实际游戏开发中更落地，且能覆盖更复杂的战斗机制，建议从以下 五个维度 进行补充和完善：
十二、特殊机制的文本化表达
除了常规的属性增减和控制，游戏中的常见特殊机制也需严格遵循纯文本规范：
机制类型 文本表达示例 说明
持续伤害 (DOT) 每回合损失 50 气血（3回合） 明确扣减数值与来源
持续回复 (HOT) 每回合回复 30 气血（3回合） 明确回复数值与来源
吸血 造成伤害回复 15% 气血（3回合） 区分造成伤害与回复
反伤 受到伤害反弹 20%（2回合） 明确触发条件（受击）
无敌 免疫所有伤害（1回合） 避免使用盾牌图标，直接文字声明
复活 死亡时回复 30% 气血（永久） 附加触发条件
驱散/净化 每次行动前移除 1 个减益（3回合） 将机制转化为条件描述
综合示例（流血状态）：
【流血】（3回合）
● 每回合损失 30 气血（3回合）
● 移动时额外损失 10 气血（3回合）
十三、交互与覆盖规则（文本反馈）
当 Buff 发生刷新、覆盖、免疫时，需要通过简短的文字浮动提示反馈给玩家，避免玩家产生“为什么Buff消失了”的疑惑：
交互情况 浮动文字反馈 颜色
高级覆盖低级 【狂战士】已升级 青色
同名刷新时间 【中毒】时间刷新 红色
触发免疫 【眩晕】免疫 灰色
触发净化/驱散 【中毒】已移除 绿色
达到叠加上限 【复仇】已达上限 黄色
十四、时机与回合表达的细化
回合制游戏中，Buff 的生效时机不一定都在回合开始/结束，需要通过限定词在文本中明确：
时机类型 表达规范 示例
常规持续 （N回合） 攻击↑30%（3回合）
仅本回合 （本回合） 速度↑50%（本回合）
下次行动前 （行动前） 受到伤害↑20%（行动前）
永久持续 （永久） 气血上限↑500（永久）
触发后消失 （1次） 下次攻击必定暴击（1次）
即刻生效 无后缀，仅飘字 回复 200 气血
说明：当 Buff 是“下次攻击触发”时，不占用回合数，而是用“次”来计数：
【蓄力一击】（1次）
● 下次攻击伤害↑100%（1次）
十五、敌方与多单位极简模式
在遭遇多个敌人时，如果每个敌人都完整展示文本会导致 UI 溢出。需要为非聚焦单位设计一套极简压缩语法：
省略“回合”二字：直接用数字表示。
省略“属性”二字：使用单字代表属性（攻/防/速/命/闪）。
省略“未激活”：未激活的条件Buff不显示，仅在激活时显示。
折叠层数：用 xN 表示。
对比示例：
主角/精英怪（完整态）：
【中毒】 速度↓10% 防御↓15% +2
杂兵/群怪（极简态）：
【中毒(2)】 速↓10% 防↓15%
多层流血（极简态）：
流血x3 速↓15%
十六、排版与可读性规范
纯文本 UI 最忌讳排版错乱，必须建立严格的 CSS/文本格式规范：
等宽数字：所有数值必须使用等宽数字，避免 100 和 111 宽度不同导致抖动。
符号间距：↑ ↓ 与文字之间不加空格，与数字之间不加空格；（ 前加一个半角空格。
正确：攻击↑30% （3回合）
错误：攻击 ↑ 30%（3回合）
色盲安全：考虑到红绿色盲玩家，除了颜色，必须保留 ↑（增益）和 ↓（减益）作为形状区分。
行高与对齐：展开面板中的 ● 符号必须垂直对齐，属性名（如“攻击力”）必须左对齐，数值必须右对齐或紧跟属性名对齐。
完善后的总结
通过补充以上五点，该设计方案不仅解决了“Buff 效果如何展示”的问题，还解决了：
特殊机制怎么写（DOT/HOT/吸血等）
Buff 交互怎么提示（覆盖/免疫/净化）
生效时机怎么表达（回合/次数/下次行动）
复杂战局怎么不挡视野（极简压缩模式）
视觉排版怎么不乱（等宽/对齐/色盲安全）
至此，这是一套可以直接交付给前端开发和战斗系统策划执行的完整纯文本战斗 UI 规范。
