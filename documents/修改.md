# 修改方案：Buff 数据所有权归一化

## 核心原则

> **`BattleEntity` 不持有 `buffs` 数组，所有 buff 增删查改走 `BuffSystem`。**
> Buff 数据仅存在于 `BuffSystem` 的 `private buffInstances` 中，实体通过 `getBuffInstanceIds()` / `hasBuff()` 委托查询。

---

## 第一步原理分析

| 层面 | 现状 | 结论 |
|------|------|------|
| 数据所有权 | `BuffSystem.buffInstances` 是唯一持有者 ✅ | OK |
| 实体查询 | `BattleParticipantImpl` 通过 `buffQuery` 委托 ✅ | **但 `setBuffQuery` 从未被调用，查询永远返回空数组 ❌** |
| 接口定义 | `BattleEntity` 无 `buffs` 字段 ✅ | 但 `hasBuff` 声明了两次（177/198行） |
| 添加入口 | `SkillExecutor.executeBuff` / `executeControl` 调用 `buffSystem.addBuff` ✅ | OK |
| 回合格子 | `BattleSystem.processTurn`(531行) 调用 `buffSystem.updatePerTurn` ✅ | OK |
| 到期移除 | `updatePerTurn` 内部到期自动 `removeBuff` ✅ | OK |
| 战斗清理 | `BattleLifecycleManager.endBattle/resetBattle` 调 `clearAllBuffs` ✅ | OK |
| 触发存根 | `dealDirectDamage` / `healTarget` 是空函数 | 经查配置无触发使用，**不动** |
| 被动系统 | `PassiveSkillManager` 用 `hasBuff` 查询 ✅ | OK |
| AI 威胁计算 | 用 `getBuffInstanceIds().length` ✅ | OK |
| UI 展示 | `ParticipantPanel` / `BattleDashboard` 用 `getBuffInstanceIds()` ✅ | OK |
| 快照/回放 | `ParticipantSnapshot.buffs` 是序列化拷贝 | **不动** |
| 配置数据 | `GameDataProcessor` 的 `CharacterStats.buffs` 是静态配置数据 | 类型提升 `any[]` → `BuffBrief[]` |
| Mock 实体 | 已实现 `getBuffInstanceIds` / `hasBuff` ✅ | OK |

## 改动清单（3 个文件）

### Step 0 — 修复初始化漏洞（+1行）

**文件：** `src/domain/battle/BattleSystem.ts`

`setModifierProvider` 被调用了，但 `setBuffQuery` 没有被调用。因 `BuffSystem` 同时实现了 `IModifierProvider` 和 `BuffQuery`，只需在初始化时也设置 `buffQuery`。

```diff
// 第298行附近
if (participant instanceof BattleParticipantImpl) {
  participant.setModifierProvider(this.buffSystem)
+ participant.setBuffQuery(this.buffSystem)
}
```

**后果如果不修：** `getBuffInstanceIds()` 永远返回空数组，AI 认为所有角色没有 buff，被动技能 `source_has_buff` 条件永远为 false。

---

### Step 1 — 删接口重复声明（-1行）

**文件：** `src/domain/battle/types.ts`

```diff
-  hasBuff(buffId: string): boolean    // 第198行，与第177行重复
```

第177行已有 `hasBuff(buffId: string): boolean`，第198行是死代码。

---

### Step 2 — Trigger 存根仅加注释（0行生产代码改动）

**文件：** `src/domain/buff/BuffSystem.ts`

`dealDirectDamage` / `healTarget` 是空函数存根。经查：
- `buffs.json` 中所有 trigger 的 `scriptId` 都是自定义 ID（如 `block_damage_percent`），无直接使用 `deal_damage` / `heal`
- `skills_new.json` 的 `deal_damage` / `apply_buff` 是技能步骤类型，走 `SkillExecutor` 流程，与触发器无关

**结论：** 当前无人调用，只追加注释说明，不改代码。

```diff
+ // ponytail: 当前无配置触发 deal_damage/heal 存根。后续如有灼烧/中毒等每回合触发器需要实现，
+ // 应通过 BattleSystem 注册的 onAttributeChange 回调委托到 BattleParticipantImpl.takeDamage。
```

---

### Step 3 — 提升 GameDataProcessor 类型安全

**文件：** `src/shared/utils/GameDataProcessor.ts`

`CharacterStats.buffs` 是 `any[]`，改为明确类型：

```diff
+ interface BuffBrief {
+   id: string
+   isPositive?: boolean
+   isDebuff?: boolean
+ }

  // CharacterStats 中
- buffs?: any[]
+ buffs?: BuffBrief[]
```

`calculateStatBonus` 和 `calculateDamageBonus` 的硬编码 `n*10` 逻辑保留——这是纯静态预览计算，不在本次范围。
