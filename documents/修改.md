## 二、架构决策（原《修改2.md》核心，已全部落地）

### 2.1 路径定义（`BuffSystem.addBuff`，`BuffSystem.ts:621-676`）

```
① 解析配置（4 级回退链）→ ② 免疫检查 → ③ 叠加规则 → ④ 路径判定 → ⑤ 执行
路径判定（互斥）：
  hasScript（registry 中脚本存在）      → PATH A：脚本驱动（脚本全权负责效果）
  hasEffectPlan（effectPlan 非空）      → PATH B：原子效果驱动
  executionMode='marker'/'triggerOnly' → PATH D：纯标记 / 仅触发器（取代 _track_passive_ 前缀豁免）
  三者皆否                            → PATH ERROR：记 ERROR 日志，回滚已创建的实例与 context
                                          （`buffInstances.delete` + `BuffContextPool.return`，`BuffSystem.ts:644-645`），拒绝施加
正交组件（两条路径共享）：触发器注册、ON_APPLY 事件、buffAppliedCallback、triggerAttributeChange
```

### 2.2 核心规则

| 规则 | 说明 |
|------|------|
| 脚本优先 | 有脚本走 PATH A，不执行 effectPlan、不执行 JSON attributes |
| effectPlan 兜底 | 无脚本时走 PATH B（`BuffConfigResolver` 从 JSON `effects[]` 生成） |
| 无则报错 | 既无脚本也无 effectPlan/triggers → 配置错误，加载时 `validateBuffConfigs` 抛错 / 运行时拒绝施加 |
| 互斥 | 一个 Buff 实例生命周期内只走一条路径，`addBuff` 时确定 |
| 脚本自管 | 脚本路径下，脚本通过 `context.addModifier()` 自行管理修饰符，框架不代劳 |

### 2.3 已删除的概念

`NOOP_BUFF_SCRIPT` 常量、`isSelfContained()` 方法（2026-07-30+ 最终删除）、`applyAttributeModifiers()`、`applyBuffImmunities()`、`applyBuffAuraModifiers()`、`addBuff`/`removeBuff` 中护盾硬编码处理、JSON 旧字段（`attributes`/`controlType`/`immunities`/`aura` 不再被解析器识别，须显式 `effects[]`）。

### 2.4 对称路径

`removeBuff`（PATH A 脚本 onRemove / PATH B effectPlan onRemove，统一错误边界，`isActive=false` 前置 + `finally` 清理）、`updatePerTurn`（PATH A onUpdate / PATH B onTick，注入 `context.currentTurn`）、`refreshBuff`（PATH A onRefresh / PATH B effectPlan onRefresh）——全部对称且带错误边界。

### 2.5 迁移策略

脚本是第一公民，不强制迁移到 effectPlan。新增 Buff 规范：简单属性/控制/免疫/光环/DOT/HOT 走 PATH B（JSON `effects[]`）；复杂逻辑（递增、衰减、成长、自残、刷新叠加、周期治疗）走 PATH A 脚本。

## 四、2026-07-30+ 追加修复（对照当前代码新发现）

### 追加-1（重要）：4 个脚本映射键与 BUFF_ID 不匹配 → 脚本从未注册

**问题**：`scripts/index.ts` 的 `buffScripts` 映射键使用短名（`mountain_god`/`poison`/`berserk`/`shield`），而 `BuffScriptLoader` 按 `v.BUFF_ID === buffId` 精确匹配，脚本类的静态 `BUFF_ID` 均为 `buff_*` 全名 → 匹配失败 → **MountainGodBuff、PoisonDebuff、BerserkBuff、ShieldBuff 四个脚本从未被加载注册**。

**影响**（修复前）：
- `buff_berserk` 无任何 JSON 配置 → `addBuff` 直接拒绝，**狂暴 Buff 完全无法施加**
- `buff_poison` / `buff_shield` / `buff_mountain_god` 静默回退 PATH B（JSON effects/triggers 兜底），脚本的复杂机制（递增伤害、护盾恢复/刷新增强、每秒治疗、自残）从未生效

**修复**：映射键改为 BUFF_ID 全名（`buff_mountain_god`/`buff_poison`/`buff_berserk`/`buff_shield`），并清理 JSON 中的兜底配置（`buff_poison` 删 triggers 防双伤害、`buff_shield`/`buff_mountain_god` 删 effects/onAdd），description 同步为脚本实际效果。

**配套适配**：`BuffScriptLoader.loadScripts()` 是异步的、晚于 `BuffScriptRegistry` 构造，故构造时 `validateBuffConfigs` 的 `hasScript` 只能基于**静态脚本清单**（`buffScripts` 映射键，即 BUFF_ID 全名）判断，而非当时仍为空的注册表——否则清理 JSON 兜底配置后，有脚本的 Buff 会在构造时被误判为"无脚本无效果"而抛错。

### 追加-2：`isSelfContained` 死方法删除

PATH 判定改用 `script !== null` 后该方法无任何调用方，已删除。

### 追加-3：P3-4 修复

`BuffContext.initialize` 不再重复 `variables.clear()`（池化路径由 `ObjectPool.reset()` 保证，borrow 的 validate 校验为空）。
