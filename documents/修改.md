您指出的问题非常关键。当前 `BattleParticipantImpl` 的构造函数声明为 `data: BattleParticipantImpl`（自引用类型错误），且内部直接手写对象字面量初始化 `AttributeValue`，确实会导致类型不安全、状态不一致以及脏标记流控失效。

为保证架构严谨性，建议采用 **标准 DTO 接口 + 工厂函数封装 + 职责分离** 的方式进行重构。以下是完整修复方案：

### 🔧 核心问题定位

1. **构造函数类型错误**：`constructor(data: BattleParticipantImpl, ...)` 应为初始化数据接口。
2. **手动拼装 `AttributeValue`**：易遗漏 `dirty`、`modifiers` 等关键字段，破坏脏标记流控契约。
3. **外部调用耦合**：`enemyToParticipant` 直接传入散列数值，缺乏统一初始化契约。

### ✅ 重构方案

#### 2. 重构 `BattleParticipantImpl` 构造函数与 `initAttribute`

```typescript
// src/core/battle/BattleParticipantImpl.ts
import {
  createAttributeValue,
  AttributeCodes,
  type IModifierProvider,
} from '@/types/attribute'
import type { ParticipantInitData } from '@/types/battle'

export class BattleParticipantImpl implements BattleEntity {
  // ... 其他字段声明保持不变

  /**
   * 构造函数
   * @param data - 标准初始化数据 DTO
   * @param modifierProvider - 修饰符提供者（可选，通常为 BuffSystem）
   */
  constructor(data: ParticipantInitData, modifierProvider?: IModifierProvider) {
    this.id = data.id
    this.name = data.name
    this.level = data.level
    this.type = data.type
    this.team = data.team
    this.buffs = []
    this.skills = data.skills ?? {}
    this.skillCooldowns = new Map()

    if (modifierProvider) {
      this._modifierProvider = modifierProvider
    }

    // 统一通过工厂函数初始化属性，确保结构一致且触发脏标记
    this.initAttribute(AttributeCodes.MAX_HP, data.maxHealth)
    this.initAttribute(AttributeCodes.HP, data.currentHealth ?? data.maxHealth)
    this.initAttribute(AttributeCodes.MAX_ENERGY, data.maxEnergy ?? 100)
    this.initAttribute(AttributeCodes.ENERGY, data.currentEnergy ?? 25)
    this.initAttribute(
      AttributeCodes.ATK,
      (data.minAttack + data.maxAttack) / 2,
    )
    this.initAttribute(AttributeCodes.MIN_ATK, data.minAttack)
    this.initAttribute(AttributeCodes.MAX_ATK, data.maxAttack)
    this.initAttribute(AttributeCodes.DEF, data.defense)
    this.initAttribute(AttributeCodes.SPD, data.speed)
    this.initAttribute(AttributeCodes.CRIT_RATE, data.critRate ?? 10, true)
    this.initAttribute(AttributeCodes.CRIT_DMG, data.critDamage ?? 125, true)
    this.initAttribute(
      AttributeCodes.DMG_REDUCTION,
      data.damageReduction ?? 0,
      true,
    )

    // 标记所有属性为脏，确保首次 getAttributeValue 时触发 AttributeEngine 计算
    this.markAllDirty()
  }

  /**
   * 内部属性初始化方法（封装 AttributeValue 创建逻辑）
   */
  private initAttribute(
    attr: AttributeCodes,
    baseValue: number,
    isPercentage: boolean = false,
  ): void {
    // 使用工厂函数替代手写对象字面量，严格遵循类型契约
    const attrObj = createAttributeValue(baseValue, baseValue, {
      isPercentage,
      dirty: true, // 新建属性默认标记为脏，首次读取时触发 recalc
      modifiers: [],
    })
    this.attributes.set(attr, attrObj)
  }

  // ... 其余方法保持不变
}
```

#### 3. 规范 `GameDataProcessor.enemyToParticipant` 调用方式

```typescript
// src/utils/GameDataProcessor.ts
import { container } from '@/core/di/Container'
import { BuffSystem } from '@/core/BuffSystem'
import { PARTICIPANT_SIDE, type ParticipantSide } from '@/types/battle'
import type { ParticipantInitData } from '@/types/battle'
import type { Enemy } from '@/types/enemy'
import { BattleParticipantImpl } from '@/core/battle/BattleParticipantImpl'

export class GameDataProcessor {
  // ... 其他方法

  /**
   * 将 Enemy 转换为 BattleParticipantImpl
   * 职责：仅负责数据映射与实例化，不直接操作 AttributeValue 内部结构
   */
  static enemyToParticipant(
    enemy: Enemy,
    type: ParticipantSide = PARTICIPANT_SIDE.ENEMY,
    modifierProvider?: IModifierProvider,
  ): BattleParticipantImpl {
    const buffSystem =
      modifierProvider ?? container.resolve<BuffSystem>('BuffSystem')
    const passiveSkills = this.getSkillByIds(enemy.skills?.passive)
    const passiveModifierTemplates = this.buildPassiveModifiers(passiveSkills)

    // 1. 构造标准初始化 DTO
    const initData: ParticipantInitData = {
      id: `${type}_${enemy.id}_${Date.now()}`, // 建议后续替换为稳定 ID 生成器
      name: enemy.name,
      type,
      team: type,
      level: enemy.level,
      maxHealth: enemy.stats.health,
      currentHealth: enemy.stats.health,
      maxEnergy: 100,
      currentEnergy: 25,
      minAttack: enemy.stats.minAttack,
      maxAttack: enemy.stats.maxAttack,
      defense: enemy.stats.defense,
      speed: enemy.stats.speed,
      critRate: 10,
      critDamage: 125,
      damageReduction: 0,
      skills: {
        small: this.getSkillByIds(enemy.skills?.small),
        passive: passiveSkills,
        ultimate: this.getSkillByIds(enemy.skills?.ultimate),
      },
    }

    // 2. 实例化参与者（内部自动创建 AttributeValue 并标记 dirty）
    const participant = new BattleParticipantImpl(initData, buffSystem)

    // 3. 注入被动技能修饰符
    const modifierStack = buffSystem.getModifierStack(participant.id)
    if (modifierStack) {
      for (const template of passiveModifierTemplates) {
        modifierStack.addModifier({
          buffInstanceId: `passive_${participant.id}_${template.id}`,
          attribute: template.targetAttribute,
          value: typeof template.value === 'number' ? template.value : 0,
          type: template.type,
        })
      }
      // 触发脏标记，确保后续 getAttributeValue 重新计算
      participant.markAllAttributesDirty()
    } else {
      console.warn(
        `[GameDataProcessor] 无法获取参与者 ${participant.id} 的修饰符堆栈`,
      )
    }

    return participant
  }
}
```

### 📐 架构优势说明

| 改进点                            | 解决的问题                                          | 架构收益                                                 |
| :-------------------------------- | :-------------------------------------------------- | :------------------------------------------------------- |
| **引入 `ParticipantInitData`**    | 消除构造函数自引用类型错误，明确外部传参契约        | 接口即文档，杜绝散列参数传递导致的字段遗漏               |
| **`initAttribute` 封装工厂调用**  | 替代手动拼凑 `{ value, base, dirty... }` 对象字面量 | 结构统一、类型安全，严格遵循 `createAttributeValue` 规范 |
| **`dirty: true` 默认注入**        | 新建属性未标记脏状态，首次读取跳过计算              | 完美衔接脏标记流控，避免“缓存未更新”导致的数值错误       |
| **`enemyToParticipant` 职责收敛** | 原方法混合了属性创建、修饰符注入、类型转换          | 符合单一职责原则，数据映射与状态计算彻底解耦             |

### ⚠️ 迁移注意事项

1. **全局搜索替换**：将历史代码中 `new BattleParticipantImpl({ ... })` 中直接传入 `BattleParticipantImpl` 类型引用的地方，全部改为 `ParticipantInitData`。
2. **ID 稳定性**：示例中使用了 `Date.now()` 生成 ID，若战斗回放或状态快照依赖稳定标识，建议替换为 `Counter` 或基于场景/敌人ID的哈希生成器。
3. **响应式绑定**：Vue 组件中务必通过 `computed(() => participant.getAttributeValue(AttributeCodes.HP))` 缓存引用，避免模板内频繁调用方法触发重复计算。

按此方案调整后，属性初始化将完全符合类型契约，脏标记流控可稳定运行，且后续扩展新属性时只需在 `initAttribute` 调用链中增加一行即可。如需提供 `Counter` 稳定 ID 生成器实现或 Vue 绑定优化示例，请告知。
