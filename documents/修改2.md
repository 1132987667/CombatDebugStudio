# 架构决策修正：脚本优先，effectPlan 兜底，无则报错

## 一、您的判断完全正确——effectPlan 无法覆盖所有脚本

我逐一审阅了全部 20 个脚本类和 8 个原子效果，结论如下：

### 1.1 能力缺口实证

| 脚本 | 需要的能力 | 现有原子效果能否覆盖 | 缺口 |
|------|-----------|-------------------|------|
| `PoisonDebuff` | 伤害随时间**递增**（`damageMultiplier^stacks`） | `DotEffect` 只做固定值/百分比 × 层数 | ❌ 无递增机制 |
| `StrongPoisonDebuff` | 同上 + 攻击/速度双减 | 同上 | ❌ |
| `DefenseUpBuff` | 防御值随时间**成长**（`growthRate` 每秒） | `ModifierEffect` 只在 onApply 设一次值 | ❌ 无成长机制 |
| `StoneSkinBuff` | 减伤+速度惩罚**同步增强** | 无 | ❌ 无协调增强 |
| `CritDamageReductionDebuff` | 减益随时间**衰减恢复** | 无 | ❌ 无衰减机制 |
| `HitReductionDebuff` | 同上 | 无 | ❌ |
| `SpeedReductionDebuff` | 同上 | 无 | ❌ |
| `BerserkBuff` | 每 N 回合**自残** + 刷新时**叠加增强** | 无 `SelfDamageEffect`，无刷新叠加 | ❌ |
| `ShieldBuff` | 护盾**每秒恢复** + 刷新时**增加上限** | `ShieldEffect` 无恢复/刷新逻辑 | ❌ |
| `HealOverTime` | 刷新时**治疗量递增** | `HotEffect` 无刷新递增 | ❌ |
| `MountainGodBuff` | 修饰符 + **每秒治疗** | `HotEffect` 按回合不按秒 | ❌ 时间模型不匹配 |
| `MountainChildBuff` | 修饰符 + 每秒治疗 + **自然之力增强** | 无 | ❌ |

**可覆盖的**（简单修饰符/控制）：`AttackUpBuff`、`SpeedUpBuff`、`DodgeUpBuff`、`StunDebuff`、`GuardianBuffs`（18 个）——共约 21 个。

**不可覆盖的**：12 个脚本涉及递增、衰减、成长、自残、刷新叠加、实时计时等机制，**当前 8 个原子效果无一能表达**。

### 1.2 根本原因

`IAtomicEffect` 接口只有 4 个生命周期钩子：

```typescript
onApply(ctx, params)      // 施加
onRemove(ctx, params)     // 移除
onTick?(ctx, params, turn) // 每回合
onStackChange?(ctx, params, newStacks) // 层数变化
```

而 `IBuffScript` 有：

```typescript
onApply(ctx)       // 施加
onRemove(ctx)      // 移除
onUpdate(ctx, dt)  // 每帧/每回合（可访问 getElapsedTime）
onRefresh(ctx)     // 刷新（可叠加增强）
```

`onRefresh` 和基于实时时间的 `onUpdate` 是原子效果**结构性缺失**的能力。不是"加个参数"能解决的——需要新增原子效果类型或扩展接口。

## 二、正确的架构：严格二择一 + 失败即报错

### 2.1 路径定义

```
┌─────────────────────────────────────────────────────────────┐
│                    addBuff(buffId) 入口                      │
│                                                             │
│  ① 解析配置（4 级回退链，不变）                                │
│  ② 路径判定（严格二择一）：                                    │
│                                                             │
│     script = registry.get(buffId)                           │
│     effectPlan = registry.getEffectPlan(buffId)             │
│                                                             │
│     if (script && script !== NOOP)                          │
│         → PATH A: 脚本驱动（脚本全权负责效果）                  │
│     else if (effectPlan && effectPlan.length > 0)           │
│         → PATH B: effectPlan 驱动（原子效果负责效果）           │
│     else                                                    │
│         → PATH ERROR: 抛异常，拒绝施加                        │
│                                                             │
│  ③ 正交组件（两条路径共享）：                                   │
│     - 触发器注册                                              │
│     - ON_APPLY 事件                                          │
│     - buffAppliedCallback                                   │
│     - triggerAttributeChange                                │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心规则

| 规则 | 说明 |
|------|------|
| **脚本优先** | 有脚本就走脚本，**不执行 effectPlan**，不执行 `applyAttributeModifiers` |
| **effectPlan 兜底** | 无脚本时走 effectPlan（含 `BuffConfigResolver` 从 JSON 自动生成的） |
| **无则报错** | 既无脚本也无 effectPlan → 配置错误，`addBuff` 返回空串并记录 ERROR 日志 |
| **互斥** | 一个 Buff 实例在生命周期内只走一条路径，`addBuff` 时确定，不可切换 |
| **脚本自管** | 脚本路径下，脚本通过 `context.addModifier()` 自行管理修饰符，框架不代劳 |

### 2.3 删除的概念

| 删除项 | 原因 |
|--------|------|
| `NOOP_BUFF_SCRIPT` | 不再需要"有配置无脚本"的占位——无脚本则必须有 effectPlan |
| `isSelfContained()` | 不再需要区分"自包含/非自包含"——脚本路径下脚本始终自管 |
| `applyAttributeModifiers()` | 脚本自管修饰符；effectPlan 由 `ModifierEffect` 管 |
| `applyBuffImmunities()` | effectPlan 由 `ImmunityEffect` 管；脚本路径由脚本自管 |
| `applyBuffAuraModifiers()` | effectPlan 由 `AuraEffect` 管；脚本路径由脚本自管 |
| `addBuff` 第 713-718 行护盾后处理 | 脚本/`ShieldEffect` 自管 |
| `removeBuff` 第 929-938 行护盾回收 | 脚本/`ShieldEffect` 自管 |

### 3.2 走 PATH B（effectPlan）的 Buff

`buffs.json` 中**无对应脚本**的条目，由 `BuffConfigResolver` 自动生成 effectPlan：

| 来源 | 自动生成规则 |
|------|------------|
| JSON 有 `attributes` | → `ModifierEffect` |
| JSON 有 `controlType` | → `ControlEffect` |
| JSON 有 `immunities` | → `ImmunityEffect` |
| JSON 有 `aura` | → `AuraEffect` |
| JSON 有 `effects[]` | → 按 `type` 映射到对应原子效果 |
| `effects.json` 中的条目 | → `ModifierEffect`（已有转换逻辑） |

### 3.3 必须报错的情况

| 场景 | 处理 |
|------|------|
| `buffId` 在 `buffs.json` 中无条目，且无注册脚本 | `addBuff` 返回 `''`，记录 ERROR |
| `buffId` 有 JSON 条目但无 `attributes`/`effects`/`controlType`/`immunities`/`aura` 任何字段 | `BuffConfigResolver` 生成空 effectPlan → 报错 |
| `_track_passive_` 前缀的运行时追踪 Buff | 特殊豁免：允许空 effectPlan（仅用于被动技能追踪，无实际效果） |

## 四、代码修改方案

### 4.1 `BuffSystem.addBuff` — 路径判定重写

```typescript
public addBuff(
    characterId: string,
    buffId: string,
    config: Partial<BuffConfig> = {},
    currentTurn: number = 0,
    context?: StepExecutionContext,
    parentInstanceId?: string,
): string {
    // ① 解析配置（不变）
    const resolvedConfig = this.resolveBuffConfig(buffId, config)

    // ② 免疫检查（不变）
    if (this.isImmune(characterId, resolvedConfig)) return ''

    // ③ 叠加规则处理（不变）
    // ... REFRESH / LIMITED / INDEPENDENT 逻辑 ...

    // ④ 路径判定（核心变更）
    const script = this.scriptRegistry.get(buffId)
    const hasScript = script && script !== NOOP_BUFF_SCRIPT
    const buffResolved = this.scriptRegistry.getResolvedBuffConfig(buffId)
    const hasEffectPlan = buffResolved?.effectPlan && buffResolved.effectPlan.length > 0

    if (!hasScript && !hasEffectPlan) {
        // ★ PATH ERROR：既无脚本也无 effectPlan
        // 豁免：运行时追踪 Buff
        if (!buffId.startsWith('_track_passive_')) {
            this.logger.addDebugLog(
                `[BuffSystem] 配置错误: ${buffId} 既无脚本也无 effectPlan，拒绝施加`,
                { level: LogLevel.ERROR },
            )
            return ''
        }
    }

    // ⑤ 创建实例（不变）
    const instanceId = `${characterId}_${buffId}_${currentTurn}_${this.instanceIdCounter.next()}`
    const buffContext = BuffContextPool.borrow(characterId, instanceId, resolvedConfig, this)
    const buffInstance: BuffInstance = { /* ... */ }
    this.buffInstances.set(instanceId, buffInstance)

    // ⑥ 执行路径（互斥）
    if (hasScript) {
        // ─── PATH A：脚本驱动 ───
        const applyResult = BuffErrorBoundary.wrap(() => {
            buffContext.variables.set('_stacks', buffInstance.currentStacks)
            script!.onApply(buffContext)
        })
        if (applyResult === null) {
            // onApply 失败 → 回滚
            this.buffInstances.delete(instanceId)
            BuffContextPool.return(buffContext)
            return ''
        }
        buffInstance.effectLines = script!.getEffectLines?.(buffContext) ?? []
        // ★ 不执行 applyAttributeModifiers / applyBuffImmunities / applyBuffAuraModifiers
        // ★ 不执行 effectPlan
    } else if (hasEffectPlan) {
        // ─── PATH B：effectPlan 驱动 ───
        for (const effect of buffResolved!.effectPlan) {
            BuffErrorBoundary.wrap(() => {
                effect.handler.onApply(buffContext, effect.params)
            })
        }
        buffInstance.effectLines = buffResolved!.effectPlan
            .map((e) => e.handler.getEffectLines?.(buffContext, e.params) ?? [])
            .flat()
    }
    // else: _track_passive_ 豁免，无效果执行

    // ⑦ 正交组件（两条路径共享，不变）
    if (resolvedConfig.triggers?.length) {
        this.registerTriggersForInstance(instanceId, resolvedConfig.triggers, characterId)
    }
    this.triggerAttributeChange(characterId)
    this.eventBus.emit(BattleTriggerPhase.ON_APPLY, { /* ... */ })
    if (this.buffAppliedCallbackEnabled) {
        this.onBuffApplied?.(characterId, buffId)
    }

    return instanceId
}
```

### 4.2 `BuffSystem.removeBuff` — 对称路径

```typescript
public removeBuff(instanceId: string, options?: { silent?: boolean }): boolean {
    const instance = this.buffInstances.get(instanceId)
    if (!instance || !instance.isActive) return false

    // ★ 第一步标记，防止重入
    instance.isActive = false

    try {
        // 父→子索引清理（不变）
        if (instance.parentInstanceId) { /* ... */ }

        // ★ 路径判定（与 addBuff 对称）
        const script = this.scriptRegistry.get(instance.buffId)
        const hasScript = script && script !== NOOP_BUFF_SCRIPT
        const buffResolved = this.scriptRegistry.getResolvedBuffConfig(instance.buffId)
        const hasEffectPlan = buffResolved?.effectPlan && buffResolved.effectPlan.length > 0

        if (hasScript) {
            // PATH A：脚本 onRemove
            BuffErrorBoundary.wrap(() => {
                instance.script.onRemove(instance.context)
            })
        } else if (hasEffectPlan) {
            // PATH B：effectPlan onRemove（★ 加错误边界）
            for (const effect of buffResolved!.effectPlan) {
                BuffErrorBoundary.wrap(() => {
                    effect.handler.onRemove(instance.context, effect.params)
                })
            }
        }
    } finally {
        // ★ 统一清理（始终执行）
        this.unregisterTriggersForInstance(instanceId)
        this.buffInstances.delete(instanceId)

        const modifierStack = this.getModifierStack(instance.characterId)
        modifierStack.removeModifier(instanceId)
        for (const [charId, stack] of this.modifierStacks) {
            if (charId !== instance.characterId) {
                stack.removeModifier(instanceId)
            }
        }

        BuffContextPool.return(instance.context)
        this.rebuildCharacterImmunities(instance.characterId)
        this.cascadeRemoveChildren(instanceId, instance.characterId)

        if (!options?.silent) {
            this.triggerAttributeChange(instance.characterId)
        }
    }
    return true
}
```

### 4.3 `BuffSystem.updatePerTurn` — 对称路径

```typescript
public updatePerTurn(characterId: string, currentTurn: number = 0): void {
    const toRemove: string[] = []
    let hasNonExpiredChange = false

    this.buffInstances.forEach((instance) => {
        if (!instance.isActive || instance.characterId !== characterId) return

        const script = this.scriptRegistry.get(instance.buffId)
        const hasScript = script && script !== NOOP_BUFF_SCRIPT
        const buffResolved = this.scriptRegistry.getResolvedBuffConfig(instance.buffId)
        const hasEffectPlan = buffResolved?.effectPlan && buffResolved.effectPlan.length > 0

        if (hasScript) {
            // PATH A：脚本 onUpdate
            BuffErrorBoundary.wrap(() => {
                instance.script.onUpdate(instance.context, currentTurn)
            })
        } else if (hasEffectPlan) {
            // PATH B：effectPlan onTick（★ 加错误边界）
            for (const effect of buffResolved!.effectPlan) {
                BuffErrorBoundary.wrap(() => {
                    effect.handler.onTick?.(instance.context, effect.params, currentTurn)
                })
            }
        }

        // 回合递减（两条路径共享）
        if (instance.duration === -1) return
        instance.remainingTurns--
        if (instance.duration > 0 && instance.remainingTurns <= 0) {
            toRemove.push(instance.id)
        } else {
            hasNonExpiredChange = true
        }
    })

    toRemove.forEach((id) => this.removeBuff(id))
    if (hasNonExpiredChange) this.triggerAttributeChange(characterId)
}
```

### 4.5 `BuffConfigResolver` — 有脚本时不生成 effectPlan

```typescript
resolve(raw: Record<string, any>): ResolvedBuffConfig {
    // ★ 如果此 buffId 有注册脚本，不生成 effectPlan
    // 脚本路径下脚本全权负责，effectPlan 不执行
    const hasScript = this.scriptRegistry?.has(raw.id) ?? false
    const effectPlan = hasScript ? [] : this.buildEffectPlan(raw)

    return {
        ...this.buildBaseConfig(raw),
        effectPlan,
    }
}
```

## 五、`refreshBuff` 的路径对称

当前 `refreshBuff` 只调用 `script.onRefresh`，不通知 effectPlan。需要补充：

```typescript
public refreshBuff(instanceId: string, currentTurn: number): boolean {
    const instance = this.buffInstances.get(instanceId)
    if (!instance || !instance.isActive) return false

    const script = this.scriptRegistry.get(instance.buffId)
    const hasScript = script && script !== NOOP_BUFF_SCRIPT
    const buffResolved = this.scriptRegistry.getResolvedBuffConfig(instance.buffId)
    const hasEffectPlan = buffResolved?.effectPlan && buffResolved.effectPlan.length > 0

    if (hasScript) {
        BuffErrorBoundary.wrap(() => {
            instance.script.onRefresh(instance.context)
        })
        instance.effectLines = instance.script.getEffectLines?.(instance.context) ?? []
    } else if (hasEffectPlan) {
        // ★ effectPlan 无 onRefresh 等价物，用 onStackChange 近似
        // 长期方案：在 IAtomicEffect 接口中增加 onRefresh
        for (const effect of buffResolved!.effectPlan) {
            BuffErrorBoundary.wrap(() => {
                effect.handler.onStackChange?.(
                    instance.context, effect.params, instance.currentStacks
                )
            })
        }
    }

    instance.startTurn = currentTurn
    instance.remainingTurns = instance.duration
    return true
}
```

## 七、迁移策略

### 7.1 不迁移脚本

**脚本是第一公民，不强制迁移到 effectPlan。** 12 个复杂脚本保留原样。

### 7.2 可选迁移

21 个简单脚本（`AttackUpBuff`、`GuardianBuffs` 等）**可以**迁移到 effectPlan（删除脚本类，在 `buffs.json` 中用 `attributes` 字段），但**不强制**。迁移后走 PATH B，不迁移走 PATH A，两者都合法。

### 7.3 新增 Buff 的规范

| 场景 | 推荐路径 |
|------|---------|
| 简单属性加减 | PATH B：JSON `attributes` → 自动生成 `ModifierEffect` |
| 控制/免疫/光环 | PATH B：JSON `controlType`/`immunities`/`aura` |
| DOT/HOT | PATH B：JSON `effects: [{type: "dot", ...}]` |
| 复杂自定义逻辑 | PATH A：编写 `IBuffScript` 子类 |
| 需要 `onRefresh`/`onUpdate` | PATH A：只有脚本有这些钩子 |

### 7.4 未来扩展

如果后续需要让更多脚本迁移到 effectPlan，需要新增原子效果：

| 新原子效果 | 覆盖能力 |
|-----------|---------|
| `GrowthEffect` | 修饰符值随回合递增 |
| `DecayEffect` | 修饰符值随回合衰减 |
| `SelfDamageEffect` | 每 N 回合对自身造成伤害 |
| `RefreshStackEffect` | 刷新时叠加增强 |
| `PeriodicHealEffect` | 每回合治疗（基于回合而非实时时间） |

但这些是**可选扩展**，不是迁移前提。脚本路径始终可用。
