## 二、P0 — 静默失效 Bug 修复

### 2.1 ATTRIBUTE_CODE 硬编码字符串收窄

**问题**：`BuffContext.addModifier` 和 `BaseBuffScript.addModifier` 的参数类型为 `string`，
编译器无法拦截拼写错误。4 个 Buff 脚本使用了不在 `ATTRIBUTE_CODE` 中的字符串字面量，
modifier 写入孤立键，`recalcAttribute` 永远找不到，效果静默失效。

**修复**：

| 文件 | 改动 |
|------|------|
| `BuffContext.ts:69` | `addModifier(attribute: string` → `ATTRIBUTE_CODE`，移除 `as` 强制转换 |
| `BaseBuffScript.ts:43` | `addModifier(attribute: string` → `ATTRIBUTE_CODE` |
| `CritDamageReductionDebuff.ts` | 3 处 `'CRIT_DAMAGE'` → `ATTRIBUTE_CODE.critDamage` |
| `HitReductionDebuff.ts` | 3 处 `'HIT_RATE'` → `ATTRIBUTE_CODE.hit` |
| `DodgeUpBuff.ts` | 1 处 `'dodgeRate'` → `ATTRIBUTE_CODE.dodge` |
| `MountainChildBuff.ts` | 3 处 `'NATURE_POWER'` → `ATTRIBUTE_CODE.attackBonus` |

**边界转换**（JSON 配置层）：

| 文件 | 改动 |
|------|------|
| `ModifierEffect.ts` | 增加 `attr as ATTRIBUTE_CODE` 转型，标记 JSON 边界 |
| `BuffTemplate.ts` | `getAffectedAttributes()` 返回类型 `name: string` → `ATTRIBUTE_CODE` |

### 2.2 BattleData.battleState 改为必填

**问题**：`BattleData.battleState` 是可选字段（`BattleStatus?`），但 `BattleState.battleState` 是必填，
`convertToBattleState()` 使用 `!` 断言。所有消费方假设它存在，但类型系统不保证。

**修复**：
- `types.ts:656`：`battleState?: BattleStatus` → `battleState: BattleStatus`
- `BattleState.ts:43`：移除 `!` 断言

## 四、P2 — 契约对齐

### 4.1 EffectType 拆分 + ControlType 数组 Bug 修复

**最大 Bug**：`EffectType` 和 `ControlType` 都使用了 `...ControlKind` 展开，
但 `ControlKind` 是 `StatusCode[]`（数组），`{ ...array }` 产生的是**数字键** `{ 0: 'stun', 1: 'silence' }`，
导致 `EffectType.STUN` / `ControlType.STUN` 等 30+ 处引用全部编译失败（预存错误）。

**修复**：

```typescript
// 新增 StepEffectType — 14 个合法步骤类型
export const StepEffectType = { DEAL_DAMAGE, HEAL, APPLY_BUFF, MODIFY_ATTRIBUTE,
  GAIN_ENERGY, REMOVE_DEBUFF, CLEANSE, SHIELD, REFLECT, DRAIN, REVIVE, CUSTOM, STUN, SILENCE }

// 新增 ActionResultType — 10 个结果分类类型
export const ActionResultType = { DAMAGE, HEAL, BUFF, DEBUFF, MISS, CRITICAL, STATUS, SHIELD, DRAIN, REFLECT }

// EffectType 保留为向后兼容的合并重导出（不含 ...ControlKind）
export const EffectType = { ...StepEffectType, ...ActionResultType, ...预留占位值 }

// ControlType 从 ...ControlKind 改为显式声明
export const ControlType = { NONE, STUN, SILENCE, FREEZE, SLEEP, BIND, ...15 个控制类型 }
```

- `SkillStep.type` 从 `EffectType` 收窄为 `StepEffectType`
- `EffectType` 标 `@deprecated`，逐步迁移到 `StepEffectType` / `ActionResultType`

### 4.2 `void statsVersion` Hack 替换

**问题**：`useParticipantStats.ts` 中 10 处 `void participant.statsVersion` 用副作用语句
建立 Vue 响应式依赖，意图隐晦。

**修复**：改为 `watchEffect` + `statsVersionRef` 模式：

```typescript
const statsVersionRef = ref(0)
watchEffect(() => { statsVersionRef.value = participant.statsVersion })

const currentHealth = computed(() => {
  statsVersionRef.value  // 显式依赖
  return getFormatted(ATTRIBUTE_CODE.currentHealth)
})
```

### 4.3 LoggerProvider 安全化

裸静态字段改为 `setLogger`/`get logger` getter 模式，未初始化时抛清晰 Error。

### 4.4 BuffConfig aura 不安全转型修复

`getBuffAuraConfig()` 中 `as BuffAuraConfig` 改为显式对象映射 + 边界类型转换。
同时发现 `getBuffAuraConfig` 和 `distributeAuras` 均是死代码（光环系统已迁移到 effectPlan）。

### 4.5 convertSkillConfigToSkill 消除 `!` 断言

`config.skillType!` → `config.skillType ?? SkillType.SMALL`

### 4.6 js 计算器共用逻辑提取

新建 `calculation-utils.ts`，包含 3 个共享函数：

| 函数 | 用途 |
|------|------|
| `processExtraValues()` | extraValues 遍历，`resolveAttr` 回调处理特殊属性 |
| `processTargetModifiers()` | targetModifiers 目标属性修正 |
| `resolveAttributeValue()` | 属性值解析（含 customResolvers hook） |

`DamageCalculator` 和 `HealCalculator` 已迁移使用共享函数。
