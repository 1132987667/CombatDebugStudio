## 一、既有问题（非本次修改引入，建议后续处理）

### 1.1 触发器 scriptId 静默失效（7 处 Buff）

**问题**：`buffs.json` 中引用的 5 个触发器 scriptId 未在 `src/domain/buff/triggers/index.ts` 的
`TRIGGER_SCRIPTS`（15 项）注册。`BuffSystem.registerTriggersForInstance` 回调内
`this.triggerScripts.get(trigger.scriptId)` 为 `undefined` 时**静默跳过**，无任何日志。

**未注册的 scriptId**：`bonus_damage`、`energy_absorb`、`grant_extra_action`、`dot_damage`、`regen_resource`

**受影响的 Buff**（7 处触发器不会触发）：

| Buff | 引用的 scriptId |
|------|----------------|
| `guardian_buff_eye_for_eye` | 待核对 |
| `guardian_buff_backwater_armor` | 待核对 |
| `buff_extra_action` | `grant_extra_action` |
| `buff_liuxue` | `bonus_damage`（疑） |
| `buff_zhongdu` | `dot_damage`（疑为 `deal_dot_damage` 笔误） |
| `buff_lingfu` | `regen_resource`（疑） |
| `buff_zaisheng` | `energy_absorb`（疑） |

> 注：具体 Buff→scriptId 对应关系以 `configs/buffs/buffs.json` 的 `triggers[].scriptId` 为准。

**建议**：核对各 Buff 的意图——`dot_damage` 若是笔误改配置；其余补齐 `TRIGGER_SCRIPTS` 实现或移除无效触发器。

### 1.2 SpeedUpBuff.ts 死类

`src/domain/buff/scripts/SpeedUpBuff.ts`（BUFF_ID=`buff_speed_up`）未在 `scripts/index.ts` 的
`buffScripts` 映射导出，**从未注册**；且其内部使用 `MULTIPLICATIVE 0.2` 旧小数语义
（与全项目"PERCENTAGE 值为百分数"的新约定冲突）。`buffs.json` 中该 id 为数据驱动
（+5 ADDITIVE），无功能影响。**建议**：删除死类或改造后注册。

### 1.3 LogTooltipResolver.formatModifierValue 残留 ×100

`src/application/projection/LogTooltipResolver.ts` 的 `formatModifierValue` 仍按"小数"语义
`value * 100` 格式化 aura modifiers。数据已迁移为百分数（10 = 10%），且 `config.aura`
旧字段全库 0 条——该分支是死代码。**若未来启用 aura 分支会显示错 100 倍**。**建议**：删除或改为直接输出。

### 1.4 validateBuffConfigs 的脚本注册时序

`BuffScriptRegistry.validateBuffConfigs` 在构造函数中执行，此时脚本尚未注册 →
`hasScript` 恒为 `false`。当前 guardian 18 条靠"JSON 配置与脚本双重定义"绕过校验；
**若未来新增"仅脚本"（无 JSON 配置）条目会被误杀**。**建议**：校验延后到脚本加载后，
或显式区分"注册表脚本 + JSON 配置"两套来源。

### 1.5 participantMapper 的 perStack 语义

`participantMapper.buildBuffRawItems` 合并多个 MODIFIER 效果的 attributes 后统一 `× stacks`，
`perStack: false` 时语义丢失。当前 66 个 modifier 效果全部 `perStack: true`，无实际影响。
**建议**：提取 attributes 时保留 perStack 标志。

### 1.6 动态 Buff 的 triggers phase 未归一化

`BuffConfigResolver` 仅对 JSON 配置的 `triggers[].phase` 归一化；运行时动态创建的 Buff
（调用方传入 `config.triggers`）若使用旧风格名（`ON_TURN_START`）会注册到错误事件名，
触发器静默失效。当前无动态 Buff 携带 triggers，无实际影响。**建议**：在 `BuffSystem.registerTriggersForInstance`
入口统一归一化（复用 `OLD_PHASE_NAME_MAP`）。

### 1.7 BattleReplayManager / BattleFacade 回放死路径

`BattleReplayManager.startReplay` 与 `BattleFacade.startReplay` 全库无调用方
（`BattleReplay.vue` 自实现播放逻辑）。**建议**：确认后删除或接入。

## 二、本次修改引入的新约定（维护注意事项）

1. **属性值格式**：`buffs.json` / `effects.json` 的 `attributes` 值必须为
   `{ value: number, type: 'PERCENTAGE' | 'ADDITIVE' }`（PERCENTAGE 的 value 为百分数，
   如 `20` 表示 +20%）。非法键名/格式由 `validateBuffConfigs` 在加载时 **throw**（构建失败）。

2. **polarity 必填**：每条 Buff 配置必须声明 `polarity`（positive/negative/neutral/mixed），
   缺失时由 `BuffConfigResolver` 从 controlType/tags 推导，推导失败 throw。

3. **phase 统一枚举值**：`triggers[].phase` 只接受 `BattleTriggerPhase` 枚举值
   （旧风格 `ON_TURN_START` 等由 `BuffConfigResolver.normalizePhase` 归一化，未知值 throw）。

4. **脚本注册**：新增 Buff 脚本必须在 `src/domain/buff/scripts/index.ts` 的 `buffScripts`
   映射登记（`BuffScriptLoader` 只遍历该映射，不再扫描目录）。

5. **执行模式**：动态创建的 marker Buff（无脚本、无 JSON 配置）必须显式传
   `executionMode: 'marker'`，不再有 `_track_passive_` 前缀豁免。

6. **回放事件元数据**：`ReplayBattleEvent.data` 由录制端写入 `category` 与 `severity`，
   回放/渲染层直接读取，不做数值猜测。

7. **一次性迁移脚本保留**：`scripts/tools/migrate_buff_attributes.cjs`、
   `migrate_effects_json.cjs`、`migrate_aura_values.cjs` 记录了字符串→对象格式的迁移规则，
   未来配置维护可参考其转换语义（乘数→百分数、小数→百分数）。
