# 数值精度规范

> 状态：生效中（2026-09-29 立项）。约束战斗数值的**小数位数**与**浮点尾数**在域内状态、日志文本、UI 三处的表现口径。

## 1. 为什么要立这条规范

调试面板日志出现过这样一行：

```
[敌方]桃林守卫 受到 28 点伤害  119.80000000000001 → 91.80000000000001
```

`119.80000000000001` 不是显示 bug 的偶发结果，而是一类通用问题的表象：**百分比类效果（属性 × 系数）在 IEEE-754 二进制浮点下必然产生十进制尾数**（`0.1 + 0.2 === 0.30000000000000004`）。这类尾数一旦进入状态，就会顺着你没预料到的每条路径泄漏：

| 泄漏面 | 后果 |
|--------|------|
| 日志 / 悬浮明细文本 | 玩家看到一串无意义数字，可读性归零 |
| 气血条宽度、overkill 计算 | 比较用 `>` / `<=` 在边界上行为不确定 |
| 快照与回放对比 | `===` 判定"值没变"失效，产生脏事件 |
| 存档 | 尾数被持久化，跨版本对账困难 |

只在报错的那一处补 `toFixed` 是打地鼠。本规范定义**口径**，并把它钉在两个单源上。

## 2. 口径：谁允许几位小数

| 数值 | 小数位上限 | 保证方式 |
|------|-----------|----------|
| 气血（`currentHealth` / `maxHealth`） | **1 位** | 域内量化（写入即量化） |
| 能量（`currentEnergy` / `maxEnergy`） | **1 位** | 域内量化（写入即量化） |
| 伤害 / 治疗 | 1 位（实际多为整数） | 引擎各乘区结算 `floor`，源头 `extraValues` 已量化 |
| 其余属性（攻击、暴击率、减免% …） | 2 位 | 属性重算 `round(value, 2)`，沿用既有行为 |
| 百分比展示（配置里的 0~1 比率 ×100） | 2 位 | 显示层 `formatDisplayNumber(n, 2)` |
| 属性面板主值（六维 + 进阶属性面板行） | 1 位 | 显示层 `formatDisplayNumber(n, 1)`，四舍五入 |

**属性面板主值为什么是 1 位、为什么四舍五入（2026-09-30 裁定）**：存储/计算保留 2 位（上表），展示是投影——
面板压到 1 位去视觉噪音，悬浮明细仍走 2 位可对账。取整方向曾考虑向上取整（ceil），否决：
ceil 偏差恒定为正，六维直接进战斗公式（速度先手、命中/闪避对抗），「面板过线、战斗不过线」的错觉
恰好被 ceil 最大化；四舍五入误差 ±0.5 且无方向偏好，是可对账的最小误差方案。若未来要选「有保证」的
方向，那是 floor（显示 ≤ 实际，显示能过线实际必过线），不是 ceil。取整语义单源在
`formatDisplayNumber(n, 1)`，禁止调用方内联 `Math.round` / `toFixed(1)` / `Math.ceil`。

已接入面板主值口径的显示位：昊天镜 `RoleAttrsPanel`、唤灵台 `BattleDashboard` 角色监控、
演劫台 `characterAttrs`（`attrText` / `hpText` / `energyText`，BattleRoster 与修行 CharacterPanel 共用）。
战斗卡片的当前血量（`ParticipantCard`、`displayHp`）是 HUD 口径，取整显示，不在本行约束内。

精度位数常量单源：`src/shared/utils/math.ts` 的 `COMBAT_PRECISION`（= 1）。
受它约束的属性码集合单源：`src/domain/attribute/types.ts` 的 `VITAL_ATTRIBUTE_CODES` / `isVitalAttribute()`。

**禁止**在调用方各自内联 `1` / `2` / `toFixed(2)` 表达同一语义——哨兵值与精度口径必须单源，否则漂移只是时间问题。

## 3. 双层防线

### 第 1 层：域内不变量（治本）

浮点尾数不该进状态。量化点选在**唯一写入口**，而不是每个调用方：

- `ParticipantStats.setAttributeValue()` —— 运行时状态量（气血 / 能量当前值）的唯一写入口。
  `takeDamage` / `heal` / `gainEnergy` / `spendEnergy` / `setAttribute` 全部经过它，
  因此只需在此处 `round(value, COMBAT_PRECISION)`，新增调用方自动受约束。
- `ParticipantStats.recalcAttribute()` —— 公式派生值（`maxHealth` / `maxEnergy`）的写入口，
  对 vital 属性用 `COMBAT_PRECISION`，其余属性保持 2 位。
- `processExtraValues()`（`src/domain/skill/calculation-utils.ts`）—— `属性 × 系数` 是尾数的产地，
  在源头量化后，伤害链每一步的 `before` / `after` 与描述文本全部自然干净，
  无需去 `DamageCalculator` 的二十多处 `description` 模板里逐个包格式化。

### 第 2 层：显示边界清洗（兜底）

中间量（减免前原始伤害、各乘区 before/after）本来就允许是浮点，它们在进入文本前统一清洗：

```ts
formatDisplayNumber(119.80000000000001)      // '119.8'
formatDisplayNumber(0.1 + 0.2)               // '0.3'
formatDisplayNumber((1 / 3) * 100, 2)        // '33.33'
```

实现要点（`src/shared/utils/math.ts`）：

- 用 `Number(n.toPrecision(12))` 折回人类预期的十进制值，**不用 `toFixed`**——
  `toFixed` 是"定长补零"语义，会把 `119.8` 写成 `119.80`，也会截断真实精度。
- 量级 ≥ 1e15 时原样输出：12 位有效数字反而会砍掉大数的有效位。
- `NaN` / `Infinity` 原样输出，不抛异常。

已接入的显示边界：

| 位置 | 覆盖内容 |
|------|----------|
| `BattleLogProjector` | 攻击/技能 action 与 result sub、气血变化箭头、回合态势快照 |
| `EffectRenderer` | 伤害/治疗/吸血/反伤/护盾文本与 HP 箭头 |
| `calculation-utils.describeCalculation` | 技能公式描述（`100% 攻击力`、`等级×5`） |

## 4. 新增数值或显示时怎么做

1. 它是气血 / 能量类状态量吗？→ 把属性码加进 `VITAL_ATTRIBUTE_CODES`，写入走 `setAttributeValue`，不要绕过。
2. 要往日志 / 悬浮 / 浮字里插一个数？→ 用 `formatDisplayNumber()`，不要 `${value}` 裸插，也不要 `Math.round`（后者会把 `119.8` 藏成 `120`，与 HP 箭头自相矛盾）。
3. 新增了乘区或加成？→ 结算完就把该中间量量化，别指望显示层救。
4. 改精度位数？→ 只改 `COMBAT_PRECISION`，并同步本文件与 `tests/unit/numeric-precision.test.ts`。
5. 属性面板上显示一个属性主值？→ `formatDisplayNumber(n, 1)`（口径见 §2 表「属性面板主值」行），
   不要 `Math.round` / `toFixed(1)` / 裸插 `${value}`——浮点尾数与 2 位存储值会原样上屏。

## 5. 回归锁

`tests/unit/numeric-precision.test.ts` 覆盖：

- `formatDisplayNumber` 的尾数清洗、`maxDecimals` 截断、`0` / 负数 / 大数 / `NaN` / `Infinity` 边界；
- 气血与能量的量化不变量（直接写入、累加、`takeDamage` / `heal` 往返、上限经百分比修饰符重算）；
- `processExtraValues` 在源头掐断尾数（单条与多条累加）；
- 症状级回归：`projectSkillLog` 喂入 `hpBefore = 119.80000000000001`，断言日志文本为 `119.8 → 91.8` 且不含 6 位以上小数。

`tests/unit/presentation/character-attrs-display.test.ts` 锁面板主值口径：

- 87.54 → `87.5`（排除 ceil）、97.56 → `97.6`（排除 floor）——把四舍五入语义钉死；
- `sixAttrVal` 保留计算精度不取整（面板与存储同源对账）；
- 气血 / 法力文本最多 1 位小数。

`tests/unit/presentation/player-attributes.test.ts` 的流派树乘区用例锁快照存储口径 2 位（`round(x, 2)`，非 `Math.round`）。
