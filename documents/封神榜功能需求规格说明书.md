## 1. 模块概述

### 1.1 定位与使命

封神榜是**游戏数据的编定与管理系统**，定义「这个世界里存在什么」。所有被唤灵台、演劫台使用的角色、技能、Buff、敌人、场景、阵型、材料，均在此处确立。模块使命：

1. **定义**：提供完整的增删改查能力，编定一切游戏法则；
2. **守护**：保证数据完整（引用、数值、唯一性），杜绝坏数据流入战斗；
3. **供给**：以统一、只读的异步 API 向其他模块供数，保证数据源唯一；
4. **留痕**：支持数据导入导出、版本迁移与操作日志，数据可备份、可追溯。

### 1.2 在太初道枢闭环中的位置

```
┌────────────┐  数据访问 API（只读）   ┌────────────┐
│   封神榜    │ ──────────────────────→ │   唤灵台    │
│ （数据根源） │                        │ （阵容战斗） │
└────────────┘                        └─────┬──────┘
      ▲                                     │ 战斗记录
      │                                     ▼
      │  调参反馈                    ┌────────────┐
      └──────────────────────────── │   昊天镜    │
                                    │ （战斗分析） │
                                    └────────────┘
      ┌────────────┐                        ▲
      │   演劫台    │ ───────────────────────┘
      │ （游戏模块） │
      └────────────┘
```

- 封神榜数据流向唤灵台 / 演劫台（只读消费）；
- 唤灵台 / 演劫台的战局产出战斗记录进入昊天镜；
- 昊天镜的分析结论回流封神榜调参，形成闭环。

### 1.3 数据存储形态与演进

| 阶段 | 存储形态 | 说明 |
| ---- | -------- | ---- |
| 现状 | `configs/` 静态 JSON | 技能/敌人/场景/阵型/材料/效果等数据以配置文件内置于仓库，构建时载入 |
| 目标 | IndexedDB 数据表 | 数据迁入浏览器持久化存储，通过封神榜后台界面 CRUD，实时生效 |

存储层已具备基础：`IndexedDbStorage`（`src/infrastructure/adapters/storage/IndexedDbStorage.ts`）实现 `IPersistentStorage` 端口（`set/get/remove/keys/clear/keysByField/getStats`），当前 DB 版本 1，含 `recordings`、`snapshots` 两个 store。封神榜的数据表将作为新增 store 扩展进入同一 DB（见 5.3 版本迁移）。

## 3. 数据实体管理（基础 CRUD）

> 统一约定：所有实体均含 `id`（唯一标识）、`updatedAt`（最近修改时间戳）。CRUD 均为异步操作，写操作成功后递增全局 `dataVersion`（见 6.2）。

### 3.1 角色管理

**功能描述**

- 创建 / 编辑 / 删除角色：维护基础属性、成长曲线、可用技能列表、所属阵营与元素；
- 批量导入 / 导出角色数据；
- 复制角色为模板快速新建（见 7.3）。

**数据字段**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识，如 `hero_001` |
| name | string | 名称 |
| level | number | 等级（1–99） |
| stats | object | 基础属性：气血、能量、最小/最大攻击、防御、速度、暴击率、暴击伤害、命中率、闪避率、免伤率 |
| growth | object | 成长曲线：每级基础属性增量（可选） |
| skillIds | string[] | 可用技能 ID 列表 |
| faction | string | 所属阵营 / 元素（可选，扩展数据引用） |
| energyInit | number | 初始能量（默认 30） |

**联动方式**：唤灵台 / 演劫台通过角色 ID 异步拉取完整角色数据，转换为参战者（现状经 `GameDataProcessor.enemyToParticipant`）组成阵容。

**现状对照**：角色编辑对话框（`CharacterEditor.vue`）已支持属性编辑、Buff 注入、重置；当前角色与敌人共用 `configs/enemies/` 数据域，独立角色数据域待建立。

### 3.2 技能管理

**功能描述**

- 管理技能定义：标识、名称、类型、能量消耗、威力系数、效果集合、目标规则、冷却回合；
- 支持效果组合：一个技能可挂载多个状态 / Buff，并配置概率与持续回合；
- 支持主动技能（小技能 / 大技能·终极技能）与被动技能。

**数据字段**（对齐 `configs/skills/` 现有结构）

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识 |
| name | string | 名称 |
| type | string | 主动小技能 / 主动大技能 / 被动 |
| energyCost | number | 能量消耗（小技能 50、大技能 150；被动无消耗） |
| cooldown | number | 冷却回合（默认 2 / 5） |
| selector | object | 目标规则：阵营（敌方/友方）、策略（首目标/随机/全体等）、数量 |
| steps | object[] | 步骤编排：造成伤害 / 施加 Buff / 治疗 / 召唤等，含伤害计算配置（基础值 + 属性比率）与效果参数（指向 Buff ID、概率、持续回合） |
| description | string | 描述 |

**联动方式**：战斗模块根据技能 ID 查询步骤列表，按步骤类型与效果中的 Buff ID 实时计算伤害、治疗与状态施加，并将每一步写入战斗日志。

**现状对照**：`configs/skills/`（主动 + 被动）已按此结构建模，由 `battleService.loadSkillConfigs()` 载入；缺后台 CRUD 界面。

### 3.3 状态与 Buff 管理

**功能描述**

- 统一管理所有可施加的增益 / 减益 / 控制效果（如攻击提升、中毒、眩晕、护盾）；
- 每个状态 / Buff 定义：标识、名称、极性（增益/减益）、类别、叠加规则、每回合效果（属性修正公式、持续伤害等）、持续回合、图标引用；
- 支持**效果链**：某 Buff 到期或触发时，可自动施加另一个 Buff。

**数据字段**（对齐 `configs/effects/` 与 `configs/buffs/` 现有结构）

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识，如 `buff_atk_up` |
| name | string | 名称 |
| polarity | string | positive（增益）/ negative（减益） |
| category | string | attribute / aura / dot / hot / shield / control / immunity / trigger 等 |
| duration | number | 持续回合（-1 为永久） |
| maxStacks | number | 最大叠加层数 |
| stackRule | string | 叠加规则：替换 / 叠加 / 独立 |
| effects | object[] | 效果列表：属性修正公式（目标属性 + 修正类型 + 值）、持续伤害/治疗（公式 + 间隔）、控制、免疫、光环 |
| chain | object[] | 效果链：到期或触发时自动施加的 Buff 及概率（可选） |
| icon | string | 图标资源引用（可选） |

**联动方式**：战斗逻辑在 Buff 施加、回合开始 / 结束时查询角色的所有 Buff 定义（由封神榜提供），合并计算属性、判定触发效果，并将变化记录进战斗日志；效果链在 Buff 到期 / 触发时自动施加后续 Buff。自包含 Buff 脚本（`domain/buff/scripts/`）通过静态 `CONFIG` 与框架注册，同样纳入本管理范围。

**现状对照**：`configs/effects/` + `configs/buffs/` + Buff 脚本三源并存，效果已实现原子化（`domain/buff/atomic/effects/`）；缺统一后台管理与效果链配置界面。

### 3.4 属性与公式管理

**功能描述**

- 定义游戏中的一级属性（攻击、防御、速度、气血等）与二级属性（暴击率、暴击伤害、命中率、闪避率、免伤率）；
- 管理属性计算规则（如「基础伤害 = 随机(最小攻击~最大攻击) × 修正系数」「最终伤害 = 基础伤害 × (1 − 目标防御 × 0.01)」）与属性上限（如暴击率 0–100%）；
- 支持自定义公式，通过表达式引擎动态解析（可先以"预设公式 + 参数表"实现，表达式引擎为增强项）。

**联动方式**：昊天镜可通过查询公式定义反推伤害计算是否符合预期，用于调试与平衡性分析。

**现状对照**：伤害/治疗计算器（`DamageCalculator`、`HealCalculator`）与属性系统（`domain/attribute/`）已内嵌公式，全局参数（`configs/params/`）含平衡性系数；公式以代码形式存在，未数据化。

### 3.5 扩展数据管理（敌人 / 场景 / 阵型 / 预设阵容 / 材料）

**功能描述**

- **敌人**：属性、技能组、掉落物（材料 / 消耗品 + 概率）；
- **场景**：背景描述、多难度敌人编组、所需等级、通关奖励（经验 / 金币）；难度编组支持两种形态——直接列敌人（`enemyIds`），或引用预设阵容（`lineupId`，含角色 + 阵型），二者二选一、`lineupId` 优先；
- **阵型**：站位布局（前排 / 后排）、阵型增益 Buff、前排保护规则；
- **预设阵容**：角色组合 + 阵型绑定 + 阵营（我方 / 敌方）+ 用途标签，作为"一队人"的整体定义，供场景难度引用（敌方）与唤灵台一键布阵（我方）；
- **材料与消耗品**：稀有度、描述、使用效果（如恢复气血）。

> 注：阵营 / 元素克制关系已独立为 [3.7 阵营与元素克制管理](#37-阵营与元素克制管理)。

**预设阵容数据字段**（对齐 `configs/lineups/lineups.json` 现有结构）

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识，如 `lineup_001` |
| name | string | 阵容名称 |
| description | string | 用途说明 |
| side | string | ally（我方）/ enemy（敌方） |
| formationId | string | 绑定阵型 ID（引用 `configs/formations/`） |
| roles | object[] | 角色编组：`seatIndex`（站位索引，对应阵型 slots）+ `roleId`（引用角色/敌人数据） |
| tags | string[] | 用途标签（均衡 / 防守 / 试炼等） |

**联动方式**：演劫台按场景配置推进关卡、按敌人掉落表结算战利品；场景难度引用预设阵容时，由阵容展开为参战者（角色按 `side` 归队、按阵型落位）；唤灵台参战面板可从预设阵容一键布阵。

**现状对照**：`configs/enemies/`、`configs/scenes/`、`configs/formations/`、`configs/materials/`、`configs/lineups/`（预设阵容示例）已全部建模（含掉落概率、难度、奖励、阵型增益、阵容编组）；场景管理对话框（`SceneManagementDialog.vue`）支持保存 / 加载 / 删除场景；场景难度引用预设阵容（`lineupId`）的读取逻辑与后台界面待接入；阵营元素克制关系待建模（见 [3.7](#37-阵营与元素克制管理)）。

### 3.6 装备管理

**功能描述**

- 管理装备定义：部位、基础属性加成、百分比加成、穿戴等级门槛、阵营限制；
- 装备不独立存在，需挂载到角色身上生效（后续由演劫台/唤灵台穿戴装配）。

**数据字段**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识，如 `weapon_001` |
| name | string | 名称 |
| slot | string | 部位：weapon / armor / accessory |
| rarity | number | 稀有度（1–5 星） |
| stats | object | 属性加成：`{ attribute, modifierType, value }[]`——基础属性（气血/攻击/防御/速度）或百分比加成（如攻击 +8%） |
| requiredLevel | number | 穿戴等级门槛（可选） |
| factionRestriction | string | 阵营限制（可选，如仅火系） |
| description | string | 描述 |

**联动方式**：演劫台 / 唤灵台在装配装备时，将装备 `stats` 并入角色的属性计算（参照 Buff 属性修正的合并管线），战斗开始后随战斗快照冻结。

**现状对照**：`configs/materials/materials.json` 已混入 3 件装备（`weapon_001 铁剑`、`armor_001 皮甲`、`accessory_001 速度之符`），但材料域仅含 `rarity/description`，无 `slot/stats/requiredLevel` 字段；装备应独立成域，从材料中剥离。

### 3.7 阵营与元素克制管理

**功能描述**

- 管理阵营/元素定义（火 / 水 / 木 / 土 / 金）与两两克制系数；
- 战斗模块读取克制表，按攻击方 vs 防御方阵营计算伤害/命中修正。

**数据字段**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| elements | object[] | 阵营元素定义：`id` + `name`（如 `fire` / 火） |
| matrix | object | 克制矩阵：`{ attackerId, defenderId, coefficient }[]`——如 `fire` 克 `wood`，系数 1.2 |
| defaultCoefficient | number | 无克制关系时的默认系数（通常 1.0） |

**联动方式**：`DamageCalculator` 在计算最终伤害时查询克制表；`HitCalculator` 可在命中阶段查询（克制可额外增加命中或闪避修正，按需）。

**现状对照**：角色/敌人已带 `faction`（火/水/木/土）字段，`domain/attribute/` 有克制查询的能力占位但无数据；`configs/` 无克制表，计算器未消费。此域是阵营属性从"装饰"变为"战斗机制"的前提。

### 3.8 成长曲线管理

**功能描述**

- 管理角色升级成长的曲线定义：每级基础属性增量、经验表；
- 角色字段 `growth` 引用曲线 ID，由曲线展开逐级属性，供演劫台养成。

**数据字段**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识，如 `growth_balanced` |
| name | string | 曲线名称（均衡型 / 攻击型 / 防御型 / 速度型） |
| perLevel | object | 每级增量：`{ 气血, 攻击, 防御, 速度 }` 等基础属性增量 |
| expTable | object | 经验表：`{ level, expRequired }[]`——升级所需经验（可选，演劫台养成用） |

**联动方式**：演劫台角色升级时按曲线 `perLevel` 累加基础属性；角色编辑器与参战面板可预览曲线推导结果（如"45 级属性"）。

**现状对照**：角色编辑对话框（`CharacterEditor.vue`）的成长曲线目前是硬编码枚举文本（均衡型/攻击型/防御型/速度型），无独立数据定义；角色类型契约含 `growth` 字段但未数据化。属性计算公式数据化（3.4）完成后，成长曲线与之配合可实现"逐级推导属性"。

### 3.9 掉落组管理

**功能描述**

- 管理掉落组定义：一组物品 + 各自掉落概率，供敌人/场景引用；
- 敌人 `drops` 可改为引用掉落组 ID，避免同组掉落反复维护。

**数据字段**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 唯一标识，如 `drop_flora` |
| name | string | 掉落组名称（如"花草系掉落"） |
| entries | object[] | 掉落条目：`{ itemId, probability }[]`——物品 ID（材料/消耗品）+ 掉落概率（0–100%） |

**联动方式**：演劫台战后按敌人所引用掉落组的 `entries` 结算战利品；健康检查校验条目引用的 `itemId` 必须存在于材料/装备表。

**现状对照**：掉落概率目前直接内嵌在 `configs/enemies/enemies.json` 的 `drops` 字段（如毒液囊 ×1 60%），尚未抽组。此域为演进项：场景/敌人增多、掉落需复用时再抽取，不提前强制迁移。

### 3.10 战斗规则参数管理

**功能描述**

- 集中管理战斗调参类参数：伤害倍率、暴击概率、默认冷却、Buff 上限等；
- 把散落在各对话框/计算器里的可调参数收拢为数据，昊天镜分析结论可直接落此。

**数据字段**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | string | 参数唯一标识，如 `damage_multiplier` |
| name | string | 参数名称 |
| value | number | 当前值 |
| range | object | 合法范围 `{ min, max }`（对应 4.2 数值范围约束） |
| description | string | 用途说明 |

**联动方式**：唤灵台 `BattleRulesDialog` 读取并临时覆盖参数；封神榜保存的值为默认值，战斗规则参数随战斗快照冻结。

**现状对照**：`configs/params/buff-global-params.json` 已含全局参数（Buff 上限、默认冷却、平衡性系数、校验/调试开关），但 `BattleRulesDialog` 中的伤害倍率/暴击概率等参数未纳入参数数据，仍散在对话框逻辑内。此域是把"调参"从代码收拢到数据的关键。

## 4. 数据完整性保障与校验

### 4.1 引用完整性检查

- **保存时校验**：保存角色时自动校验其 `skillIds` 中的技能 ID 是否存在；保存技能时校验 `steps` 所引用的 Buff / 效果 ID 是否存在；保存 Buff 时校验效果链引用的目标 Buff 存在；
- **全局健康检查**：一键扫描所有数据表，输出断裂引用报告（引用方 → 缺失 ID → 所属数据表），供批量修复。

### 4.2 数值范围约束

- 为属性配置合法范围（如暴击率 0–100%、能量 0–200、等级 1–99）；
- 保存时拦截非法数据并给出字段级错误提示。

### 4.3 重复与冲突检测

- 检测角色名、技能名、Buff 名是否唯一（可选开关）；
- ID 冲突时提示覆盖或换名。

**现状对照**：`src/shared/utils/schema-validator.ts` 已提供配置校验基础设施，可作为保存校验与健康检查的底座；范围约束与唯一性检测待建。

## 5. 数据导入导出与备份

### 5.1 JSON 完整数据包

- 一键将所有表数据导出为单个 JSON 文件（含元信息：`dataVersion`、导出时间、表清单），用于备份、版本回退或团队协作；
- 支持从 JSON 文件**全量导入**（覆盖）或**增量导入**（合并，ID 冲突按策略处理）。

### 5.2 选择性导出

- 仅导出角色、技能或某个数据子集（按表、按 ID 列表、按最近修改时间）。

### 5.3 数据库版本迁移

- 复用 IndexedDB 的 `version` 升级机制（`onupgradeneeded`）：数据结构变更时递增 DB 版本，执行迁移脚本（新增 store / 字段拆分 / 数据改写）；
- 现状已具备迁移先例：`migrateLegacyLocalStorage`（localStorage → IndexedDB，一次性迁移，`cds:idb-migration-v1` 标记幂等）；
- 封神榜数据表加入时：DB_VERSION 由 1 升级至 2，新增角色 / 技能 / Buff / 敌人 / 场景 / 阵型 / 预设阵容 / 材料等 store，并保留旧 store 数据。

## 6. 实时数据接口与联动机制

> IndexedDB 无法主动推送变更，因此以"版本戳 + 快照 + 只读 API"实现联动。

### 6.1 数据访问 API

- 对外暴露基于 Promise 的异步查询接口，如：

| 接口 | 说明 |
| ---- | ---- |
| `getActorById(id)` | 按 ID 取角色完整数据 |
| `getSkillList(ids)` | 批量取技能定义 |
| `getBuffDef(id)` | 取 Buff / 效果定义 |
| `getScene(id)` / `getEnemyList(ids)` | 场景与敌人编组 |
| `getLineup(id)` / `listLineups(filter)` | 预设阵容（角色组合 + 阵型 + 阵营） |
| `getEquipment(id)` / `listEquipment(filter)` | 装备（部位 + 属性加成） |
| `getElementMatrix()` | 阵营元素克制表 |
| `getGrowthCurve(id)` | 成长曲线（每级增量 + 经验表） |
| `getDropGroup(id)` | 掉落组（物品 + 概率） |
| `getBattleParam(id)` / `listBattleParams()` | 战斗规则参数（伤害倍率 / 暴击概率等） |
| `getDataVersion()` | 取当前全局数据版本号 |
| `listByTable(table, filter)` | 分页 / 筛选查询（辅助功能用） |

- 唤灵台、演劫台、昊天镜**只能通过这些 API 读取数据，不能直接操作 IndexedDB**，保证数据源唯一；
- 现状衔接：`GameDataProcessor`（`src/shared/utils/GameDataProcessor.ts`）已承担 configs 读取与实体转换，API 层在其上包一层 Promise 接口即可平滑演进。

### 6.2 版本戳与缓存刷新

- 封神榜维护全局数据版本号 `dataVersion`，任何写操作（增 / 删 / 改 / 导入）都递增；
- 唤灵台在初始化战斗时拉取当前版本号；战斗期间如需保证数据一致，可传入版本号要求提供对应快照；
- 若版本变化，战斗模块提示「数据已更新，是否重新载入」，避免用旧数据开新局。

### 6.3 战斗快照生成

- 战斗开始前，封神榜提供「数据快照」：将参战角色、技能、Buff 定义序列化为**不可变快照对象**，附带 `dataVersion`，随战斗初始数据存入战斗记录；
- **与昊天镜联动**：分析时直接读取该快照，确保显示的角色属性、技能效果与战斗发生时完全一致，避免后续数据修改导致分析失真；
- 现状衔接：IndexedDB 已有 `snapshots` store 与数据快照对话框（`DataSnapshotDialog.vue`），快照生成器在此基础上扩展覆盖全部战斗数据域。

### 6.4 数据监听器（可选）

- 利用 `BroadcastChannel`（或 `localStorage` 事件）在同源多标签页间广播数据变更，实现多窗口协同编辑时的同步刷新。

## 7. 辅助功能

### 7.1 数据搜索与筛选

- 按名称模糊搜索；按属性范围筛选角色；按技能类型筛选技能；按类别筛选 Buff——方便大规模数据管理。

### 7.2 最近修改与操作日志

- 记录每条数据的修改时间戳、操作类型（增 / 删 / 改），形成轻量级操作日志；
- 昊天镜可据此判断某场战斗所用数据在当时的状态（配合 6.3 快照还原）。

### 7.3 模板与复制

- 复制角色 / 技能 / Buff 作为新模板，快速创建相似数据，提高编辑效率。
