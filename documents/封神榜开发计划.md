## 1. 背景与目标

### 1.1 背景

太初道枢四大模块中，昊天镜已按独立模块目录落地完成；封神榜在 `BattleArena.vue` 中仍为占位 Tab（`src/presentation/views/BattleArena.vue:60`），顶部按钮收敛到"角色编辑 / 图鉴 / 场景管理"三个弹窗入口。

本期将封神榜完整落地为**游戏数据后台管理模块**：以 IndexedDB 为主存储，`configs/` 作种子，提供十二数据域 CRUD、数据完整性保障、导入导出备份、Promise 数据访问 API 与版本戳，覆盖规格说明书全部 P0/P1/P2 功能域。

### 1.2 目标

1. **数据层**：IndexedDB DB 版本 1→2，新增封神榜数据 store + meta（dataVersion / 操作日志 / 迁移标记），`onupgradeneeded` 迁移脚本保留旧 recordings/snapshots 数据；首次启动从 `configs/` 导入种子；
2. **后台界面**：按 Demo 蓝本落地——左侧数据域/系统功能导航 + 十二数据域列表（搜索/筛选/分页/批量操作）+ 编辑抽屉（校验提示）+ 数据包 / 健康检查 / 操作日志 / 属性公式 系统视图；
3. **完整性保障**：引用完整性检查（保存时拦截 + 全局健康检查报告）、数值范围约束、唯一性检测；
4. **数据接口**：Promise 数据访问 API + `dataVersion` 版本戳 + 战斗快照生成器 + **运行时数据源切换**（封神榜改动 → 战斗引擎可见，见 3.4 关键路径）；
5. **辅助功能**：JSON 导入导出（完整/选择性、覆盖/合并）、操作日志、模板复制、搜索筛选。

### 1.3 非目标（本次不做）

- 演劫台（游戏模块）开发；
- 表达式引擎动态解析公式（规格说明书 3.4 增强项，以"预设公式 + 参数表"落地）；
- 网络同步 / 多端联机；
- 战斗引擎内部同步读取路径异步化（引擎保持同步架构，经运行时数据源切换读最新数据，见 3.4）；
- 多标签页数据监听（BroadcastChannel，规格说明书 6.4 标注"可选"）——降级为 `TODO(P2)`，本期不做；
- 掉落组批量抽取（规格说明书 3.9 明示"不提前强制迁移"）——本期仅 schema 支持引用形态 + 健康检查校验；
- 阵营克制命中修正（HitCalculator 接入）——本期仅接 DamageCalculator，命中侧留 `TODO(P2)`；
- 属性与公式视图（FormulasView）——公式在代码中，仅做只读静态页，不做任何可写功能。

### 3.2 数据层

**IndexedDB v2**：`IndexedDbStorage.ts` 的 `DB_VERSION` 1→2，`onupgradeneeded` 新增 store；`IPersistentStorage.StorageStoreName` 由封闭联合类型扩展为开放（`string` 兼容或增补枚举）；`getStats()` 改为遍历全部 store。

| store | 数据域 | 种子来源 | 备注 |
| ----- | ------ | -------- | ---- |
| actors | 角色 | 待建（guardian 派生或空域） | 独立角色域，含 skillIds/faction/growth/energyInit |
| skills | 技能 | `configs/skills/*.json`（4 份合并） | 对齐现有结构，含 steps/selector |
| buffs | 状态与 Buff | `configs/buffs/` + `configs/effects/` | 合并效果定义，含 chain 效果链字段 |
| enemies | 敌人 | `configs/enemies/*.json` | 保留 drops（兼容内嵌与掉落组引用两种形态） |
| scenes | 场景 | `configs/scenes/scenes.json` | 难度编组支持 enemyIds / lineupId 二选一 |
| formations | 阵型 | `configs/formations/formations.json` | 含 slots/effects/frontProtection |
| lineups | 预设阵容 | `configs/lineups/lineups.json` | 角色编组 + 阵型 + 阵营 + tags |
| materials | 材料 | `configs/materials/materials.json` | 剥离 3 件装备 |
| equipment | 装备 | 从 materials 剥离 | 补 slot/stats/requiredLevel |
| elements | 阵营元素 | 新建种子（火/水/木/土/金 + 克制矩阵） | 含 matrix/defaultCoefficient |
| growth | 成长曲线 | 新建种子（均衡/攻击/防御/速度） | 含 perLevel/expTable |
| drops | 掉落组 | 新建种子（可选，不强制迁移内嵌 drops） | 含 entries[{itemId, probability}] |
| meta | 元数据 | — | dataVersion / 操作日志 / 迁移标记 |

**种子导入**：启动时（应用初始化）检查 meta 种子标记，未导入则把上述 configs 写入对应 store 并递增 `dataVersion`；幂等标记 `cds:fengshen-seed-v2`。configs 有 `updatedAt` 的按值写入，不含运行时字段。

### 3.4 数据流与运行时数据源切换（关键路径）

**问题**：`GameDataProcessor` 构建时静态 import configs（运行期不可变），战斗引擎（BattleSystem / BattleArena.initBattle）全程同步读它。若封神榜只写 IDB，引擎依旧读 configs——封神榜改动对战斗不可见，模块失去意义。**数据源切换是本模块成立的前提，列入 M0 关键路径。**

```
首次启动: configs/ ──种子导入──▶ IndexedDB(v2) ◀──写操作── 封神榜后台界面
                                      │  dataVersion 递增 + UIEventBus 广播
                 ┌────────────────────┴────────────────────┐
                 ▼                                          ▼
    GameDataApi（Promise 只读）                   BattleDataLoader（启动预载内存缓存）
    封神榜 / 唤灵台界面层                                经 GameDataProcessor 出口
                                                        战斗引擎同步读取
```

**IDataSource 抽象**：`GameDataProcessor` 持有的静态数据改由 `IDataSource` 接口提供（同步方法 `getEnemies/getSkills/getScenes/...`）：

- `ConfigDataSource`：现状静态 import configs（种子来源，兜底实现）；
- `IdbDataSource`：启动时由 `BattleDataLoader` 从 IDB 全量预载入内存缓存后按该接口提供（运行期权威源）。

**切换时序**：应用启动 → 种子导入 / 数据就绪 → `GameDataProcessor.setDataSource(IdbDataSource)` → `BattleArena` 的 `initBattle` / `loadSkillConfigs` 在就绪回调后执行。对现有同步调用方透明，改动集中在 `GameDataProcessor` 与启动编排。

- **界面层**：封神榜 / 唤灵台参战面板读 `GameDataApi`（Promise）；
- **引擎同步路径**：保持同步架构，经 `GameDataProcessor` 出口读已切换的数据源——"引擎所见即封神榜所存"；
- 战斗快照仍走现有 `snapshots` store，由 `SnapshotBuilder` 扩展覆盖装备/克制/规则参数冻结值。

### 3.5 字段 Schema 驱动（表单 / 校验 / 列配置 一份定义三用）

12 个数据域手写表单 + 校验是最大重复劳动，用一份字段 schema 收敛：

- `FieldSchema`：字段名 / 类型（text/number/select/multi/array）/ 必填 / 范围 min-max / 枚举 / 引用关系 / 列表列配置（宽度 / 格式化）；
- 同一份 schema 驱动：`FieldEditor` 表单渲染、`DataIntegrityService` 校验（数值范围 + 唯一性 + 引用完整性）、`DataTable` 列配置；
- 引用完整性声明式：`ReferenceRule { sourceField, targetTable }` 注册表（角色.skillIds→skills、技能.steps[].effectId|buffId→buffs、阵容.formationId→formations、阵容.roles[].roleId→actors|enemies、场景.difficulties[].lineupId→lineups、敌人.drops[].itemId→materials|equipment、装备.factionRestriction→elements、角色.growth→growth、掉落组.entries[].itemId→materials|equipment）；
- **删除保护**：删除实体前按 ReferenceRule 反查被引用关系，有引用则拦截（提示引用方）——与保存校验共享同一规则表；
- 先落地 3 个域（角色/技能/Buff）作为模板，校验通过后铺开其余域。

## 5. 验收标准

- **实体 CRUD**：十二数据域均可创建/编辑/删除/列表查询，写后 `dataVersion` 递增且操作日志记录；
- **引用完整性**：保存引用不存在 ID 被拦截；**被引用实体删除被拦截并提示引用方**；健康检查输出完整断裂引用报告（含掉落组 itemId、装备 factionRestriction、角色 growth、场景 lineupId）；
- **数值约束**：越界数值（如暴击率 150%）保存失败并提示字段与合法范围；
- **导入导出**：完整导出→清空→导入可还原；选择性导出只含所选子集；导入支持全量/增量与冲突策略；
- **版本迁移**：DB v2 迁移后旧 recordings/snapshots 完整保留；种子导入幂等；`dataVersion` 与快照可追溯；
- **数据 API**：界面层经 GameDataApi 读取；**引擎经数据源切换读到封神榜最新数据**（改一个角色、开战立即可见）；传入旧版本号时能提示数据已更新；
- **战斗快照**：战斗记录附带不可变快照（含装备/克制/规则参数冻结值），昊天镜回放显示与战斗发生时一致；
- **辅助功能**：搜索筛选、模板复制、操作日志、效果链配置、掉落组引用可用；
- **质量门禁**：每里程碑含测试任务（校验/健康检查/导入导出/版本戳/数据源切换对应 `tests/unit/` 用例）；结束 `npm run typecheck` + `npm run test` 全绿。

## 6. 风险与注意事项

| 风险 | 应对 |
| ---- | ---- |
| 数据源切换波及引擎调用方 | 改 `GameDataProcessor` 前盘点全部调用方（AGENTS.md 守则）；`IDataSource` 默认 ConfigDataSource 兜底，切换失败回退不阻塞启动 |
| 封神榜改动在战斗期间不生效 | 版本戳提示 + `BattleDataLoader` 重载仅在未开战时生效；战斗内数据经战斗快照（snapshots）冻结，符合"数据一致优先" |
| 角色域独立（现状与敌人共用 enemies） | 种子从 guardian 派生首批角色或空域启动，由后台建立；`enemyToParticipant` 保留供敌人路径 |
| 场景结构变更（enemyIds/lineupId）影响现有读取 | 兼容优先：lineupId 缺省回退 enemyIds，双形态解析；GameDataProcessor 显式导入 lineups |
| IndexedDB 迁移失败导致旧数据丢失 | 迁移脚本幂等（onupgradeneeded 判断 store 存在）+ 迁移前自动导出备份（数据包） |
| 封神榜 CRUD 与 configs 种子同步 | 首次启动导入种子后以 IDB 为准；configs 仅作种子源，改 configs 需重置种子标记或手工同步 |
| 装备/材料剥离导致既有引用断裂 | 种子剥离时同步改写 enemies drops 中的 itemId；健康检查兜底报告 |
| `StorageStoreName` 封闭类型扩散影响面 | 开放联合类型 + 类型别名兼容，调用方改点集中在 storage 适配层 |
| 大批量表单（12 数据域 schema）工作量大 | 字段 schema 一份定义三用（表单/校验/列配置，见 3.5）；先做 3 个域模板再铺开 |

## 7. 决策与待确认事项

**评审已定决策**：

1. 运行时数据源切换（IDataSource + BattleDataLoader 预载）为 **M0 关键路径**，封神榜改动必须对战斗引擎可见（§3.4）；
2. 字段 schema 一份定义三用（表单/校验/列配置），先落地 3 域模板（§3.5）；
3. 可砍项：多标签页监听、掉落组批量抽取、阵营克制命中修正、公式视图可写化（§1.3，均降级 `TODO(P2)` 或只读）；
4. 删除保护纳入校验服务（被引用实体删除拦截）；每里程碑带测试任务；
5. actors 种子默认从 `guardian_*` 敌人派生首批角色。

**待确认（开发中逐项对齐）**：

1. 唤灵台顶部「角色编辑 / 图鉴」弹窗是否并入封神榜（与昊天镜"调试控制归属唤灵台"同一类取舍），还是保留唤灵台侧？
2. BattleDataLoader 预载时机：应用启动全量预载（默认），还是战斗初始化前按需拉取？
3. actors 派生角色与 enemies 中 `guardian_*` 条目的关系：保留敌人形态（可作敌方/训练桩验证），角色侧独立 ID 与技能组由种子补齐。

> 开发节奏：按 M0 → M1 → M2 → M3 → M4 推进；每里程碑产出可运行增量，结束执行 `npm run typecheck` + `npm run test` + 手测。
