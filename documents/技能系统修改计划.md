## P2/ARCH-1：技能与 Buff 之间的双向通信接口（未实现）

**背景**：
当前 Buff → 属性变更（单向通过 `ModifierStack`），但 Buff 无法操作技能系统（如"获得强化状态后技能冷却减 1"）。技能系统也无法查询自身携带的 Buff 是否会影响技能行为。复核确认：`modifySkillCooldown` / `getSkillDamageModifier` / `isSkillSilenced` 均无任何实现或替代机制，问题依然存在。

**方案**：
在 `BuffSystem` 上暴露一个 `SkillBuffBridge` 接口，持有弱引用：

```typescript
interface SkillBuffBridge {
  modifySkillCooldown(characterId: string, skillId: string, delta: number): void
  isSkillSilenced(characterId: string): boolean
  getSkillDamageModifier(characterId: string, skillId: string): number
}
```

`BuffSystem` 在构造时接收桥接口，Buff 脚本通过 `context.getBridge()` 访问。

**影响文件**：
- `src/domain/battle/service/SkillBuffBridge.ts` — 新建
- `src/domain/buff/BuffSystem.ts` — 构造函数增加桥接口参数；BuffContext 增加 `getBridge()`
- `src/domain/buff/BuffContext.ts` — 新增桥引用
- `src/domain/buff/scripts/base/BaseBuffScript.ts` — 模板 `onApply/onRefresh` 可调桥方法
- `src/infrastructure/di/Container.ts` — 组装时传入桥实现

**延迟条件**：无功能需求驱动时可推迟到有具体 Buff 脚本需要调用桥时再做。（当前无任何 buff 脚本需要桥，YAGNI 判断下可长期搁置。）

## P2/UI-1：技能描述模板化 + 不可用原因反馈（部分实现）

**背景**：
- `SkillConfig.description` 仍是静态字符串，技能伤害为动态公式（如 `50+attack×1.2`）时描述只能手写；`configs/skills/` 下无任何模板语法。
- 不可用原因：领域层已实现——`ParticipantSkills.canExecuteSkill` 返回 `SkillAvailability { can, reason }`（`SkillBlockReason`：`energy` / `cooldown` / `controlled` / `silenced`）。**但 presentation 层没有任何消费点**，玩家在 UI 上仍只能看到"技能不可用"的布尔态，看不到原因。`detail?: string`（如"还需 2 回合冷却"）也未实现。

**剩余工作**：

1. **不可用原因反馈 UI 接线**：Store/composable 暴露当前技能 `SkillAvailability`，技能面板组件按 `reason` 展示不同文案与图标。

2. **`SkillAvailability` 增加 `detail`**：

```typescript
export interface SkillAvailability {
  can: boolean
  reason: SkillBlockReason
  detail?: string  // 如 "还需 2 回合冷却"（格式约定：冷却用中文 + 数值，能量用 `current/max`，控制用状态名）
}
```

3. **描述模板**：`SkillConfig` 支持 `{{damage}}` `{{heal}}` `{{extra.attack*ratio}}` 语法，加载时由 `GameDataProcessor` 替换为实际计算值。

**影响文件**：
- `src/domain/battle/type/types.ts` — `SkillAvailability` 增加 `detail` 字段
- `src/domain/skill/types.ts` — `SkillConfig.description` 支持模板语法
- `src/presentation/stores/battleStore.ts` 或新的 composable — 新增不可用原因的响应式状态
- `src/presentation/components/` — 技能面板组件展示不可用原因

**验证**：
- 现有 `canExecuteSkill` 领域测试保持绿灯（`detail` 为增量字段）
- 新增测试：描述模板渲染正确性
