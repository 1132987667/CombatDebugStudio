## 第一章 · 背景故事与叙事

### 1.1 核心命题

```text
一个无名者，在一条被篡改的路上，用"斗战"证明自己的存在。
```

### 1.2 时间线

```text
取经之后一千年。

一千年前：取经功成，悟空成佛，金箍棒化为十道碎片封入西行路。
一千年间：西行路从圣路变成商路，妖怪被逐入深山，百姓安居。
一千年后：封印松动。碎片共振。旧血苏醒。
```

### 1.3 六耳猕猴的残魂

```text
真假美猴王一役中，六耳猕猴被如来识破，被金箍棒打死。
但六耳猕猴的本体不是肉身，而是"听"——它能听见万物之心。
肉身可灭，"听"不可灭。

六耳猕猴的残魂化为无数碎片，散落在西行路上。
它寄生在沿途妖怪体内，用"妖气"感染它们（词缀系统的叙事来源）。
它收集战意、怨念、不甘，试图重塑肉身。

它的终极目标：
  不是取代孙悟空。
  而是证明"我比孙悟空更像孙悟空"。
  它要成为斗战胜佛。
```

### 1.4 主角设定

```text
姓名：玩家自定（默认"行者"）
年龄：十六七岁
身份：山脚村落的普通少年

开局：
  某夜，妖气席卷，妖怪屠村。
  主角的师父（村中唯一的武师）以命换命，击退妖怪，
  但主角的妹妹"小蝉"被妖怪掳走。

  师父临死前把一根断棒塞给主角：
  "这是……一位大圣留下的。
   棒断了，但意还在。
   你拿着它，往西走。
   走到头的地方，有你要找的答案。"

主角的动机链：
  前期（1-3关）：救人（被掳走的小蝉）→ 愤怒、焦急
  中期（4-7关）：发现阴谋（妖怪暴动不是偶然）→ 好奇、不安
  后期（8-10关）：拯救（不只是救一个人，是救所有被困的人）→ 责任、觉悟
```

### 1.5 主角与六耳猕猴的镜像关系

```text
六耳猕猴：想成为孙悟空。用"听"模仿一切，但没有自己的心。
主角：是孙悟空的碎片，但不是孙悟空。用"战"走出自己的路。

最终对决的意义：
  不是"打败坏人"。
  是"我不需要成为任何人，我只需要成为我自己"。
```

### 1.10 结局

```text
击败六耳，救出小蝉。妖气消散，西行路恢复平静。

小蝉："那你还拿着？"
主角："嗯。"

小蝉："接下来往哪走？"
主角看向远方。不是西天。不是回家的方向。是任何一个方向。
"随便。"

【完】
```

## 第二章 · 敌人体系

### 2.1 三类敌人来源

| 类型 | 说明 | 占比 | 命名格式 |
|---|---|---|---|
| 旧血后代 | 原西游记妖怪的子孙，继承血脉但不记得祖辈恩怨 | 60% | 「姓」+「辈」+「名」（如牛三·裂地） |
| 旧魂残影 | 一千年前被封印的妖怪残魂苏醒，记忆残缺 | 25% | 原名 + 「残」/「旧」/「影」 |
| 新生妖 | 一千年间因灵气异变而诞生的全新妖怪 | 15% | 「环境」+「形态」（如雾妖、岩精） |

### 2.2 词缀的叙事绑定

```text
词缀 = 妖气烙印。
六耳猕猴的残魂碎片散落在西行路上。
妖怪接触到碎片后，被"感染"，获得异常力量。
感染越深，词缀越强。

UI 表现：
  · 带词缀的敌人名字旁有一个墨点（轻度感染）
  · 三档/四档词缀怪的墨点变为朱红印章（深度感染）
  · 击败后战斗心经记录："妖气消散，[敌人名] 恢复清明。"
```

### 2.3 流派获取的叙事绑定

| 流派 | 获取关卡 | 获取方式 | 师父/来源 |
|---|---|---|---|
| 灵猴道 | 第 1 关 | 村中老猴传授 | "小猴子，跑得快不算本事。知道往哪跑，才是。" |
| 金行道 | 第 3 关 | 碎石岭铁匠铺遗物 | 刻着"金行"的铁片。"锐不是天赋，是千锤百炼。" |
| 磐石道 | 第 5 关 | 浊浪滩河底石碑 | 石碑上刻着两个字："不躲。" |

### 2.4 装备/丹药/任务的叙事绑定

```text
装备：不是"系统给你的"，是"你在路上找到的"。
  桃木剑："第一把武器，不需要好，需要趁手。"
  铁精甲："五百年前有人在这里打铁，打到一半就走了。"

丹药：洞府炼丹是"主角在路边搭了一个炉子"。
  "炉子会冷，但火不会灭。"

任务（西行志）：不是"任务列表"，是主角的"行路日志"。
  "第三日，碎石坡。打了一只山魈。它困了五百年，很生气。我理解。"
```

### 3.2 回合结算轴（不可乱序）

| 阶段 | 内容 | 挂载点 |
|---|---|---|
| Phase 1 回合开始 | 能量恢复、Buff 递减、DOT 结算 | 装备被动触发、丹药持续效果 |
| Phase 2 行动判定 | 控制判定、速度排序 | 装备速度加成、流派先手被动 |
| Phase 3 行动执行 | 技能释放、伤害结算 | 装备词条触发（暴击/连击） |
| Phase 4 行动后 | 被动触发、反击、吸血 | 套装效果、附魔触发 |
| Phase 5 回合结束 | 状态清理、能量结算 | 装备冷却递减 |

### 3.3 大招性价比设计

```text
核心原则：大招能量消耗高不是问题，大招性价比不足才是问题。

大招必须具备普攻和小技能无法替代的质变效果：
  · 100% 概率的控制（小技能最高 30%）
  · 护盾（无其他护盾来源）
  · 必暴（暴击率无法保证 100%）
  · 破防（无视 60% 防御，小技能最高 40%）
  · 5 回合持续强化（小技能最高 3 回合）
```

### 3.4 斩杀返还机制

```text
任何技能击杀目标时，返还该技能消耗能量的 30%。
  · 小技能击杀：返还 15 能量
  · 大招击杀：返还 45 能量

目的：鼓励玩家用技能终结敌人，大招击杀后加速下一次循环。
```

| **合计** | **40** | |

### 4.2 技能树结构

```text
每流派一棵技能树，分 3 个分支，每分支 4 层，共 12 个节点/流派。
3 流派 × 12 节点 = 36 个节点。
40 点技能点，节点消耗 1-5 点。
玩家大约可以点亮 15-20 个节点（约 40%-55%）。
不可能点满，必须取舍。
```

```text
前置关系：每个分支内，必须从第 1 层逐层点亮，不可跳层。
跨流派：允许。每个流派第 1 层无前置，可直接点亮。
大招解锁：消耗 5 点，且必须点亮同分支前 3 层。最多解锁 2 个大招。
小技能装备：技能树解锁的小技能可超过 2 个，但战斗中最多装备 2 个。
被动装备：最多装备 2 个被动。
大招装备：最多装备 1 个大招。
重置：消耗金钱 500 × 已分配点数。悟道丹获得的技能点重置后不返还。
```

### 5.5 装备最终属性公式

```text
装备基础属性 = 原始基础属性 × 品质系数 × (1 + 技艺等级 × 5%) × (1 + 强化等级 × 强化系数) × (1 + 星级 × 10%)

最终角色属性 = 角色基础属性 + 装备基础属性总和 + 装备词条固定值总和
然后：最终角色属性 × (1 + 装备百分比词条总和) × (1 + 附魔百分比效果总和) × (1 + 套装效果总和)
```

## 第六章 · 词缀系统

### 6.1 设计原则

```text
1. 词缀只作为敌人难度标签。
2. 词缀只做正面属性修正（增强敌人），不对敌人施加负面效果。
3. 概率/百分比属性（吸血率/反伤率/格挡率/连击率/反击率）作为词缀属性修正。
4. 有独立生命周期的持续效果（中毒DOT/护盾/控制/净化）交给 Buff 系统。
5. 五行攻击已删除（设计决策 D1b），五行词缀统一为五行抗性。
6. 天命词缀为 BOSS 专属，不参与随机。
7. 词缀数量随场景/爬塔层数递增。
```

## 第九章 · 开发路线图

### 9.1 总体策略

```text
垂直切片 → 横向扩展。
```

### 9.2 阶段划分

| 阶段 | 内容 | 周期 | 优先级 |
|---|---|---|---|
| 阶段零 | 确认当前状态，列出现状清单 | 半天 | — |
| 第一阶段 | 战斗闭环（选关→打怪→掉落→存档） | 1-2 周 | P0 |
| 第二阶段 | 成长闭环（升级→技能点→流派） | 1-2 周 | P0 |
| 第三阶段 | 装备闭环（制造→穿戴→强化） | 2-3 周 | P0 |
| 第四阶段 | 经营闭环（洞府：炼丹/炼器/药园） | 2 周 | P1 |
| 第五阶段 | 词缀与 BOSS | 1-2 周 | P1 |
| 第六阶段 | 任务与经济 | 1-2 周 | P1 |
| 第七阶段 | 内容扩展（10 关 + 爬塔） | 持续 | P2 |
| 第八阶段 | UX 打磨（全屏面板/水墨动效） | 持续 | P2 |

### 9.3 每阶段必做检查

```text
□ npm run typecheck 零报错
□ npm run test 全绿
□ node scripts/balance-check.cjs 通过（涉及数值时）
□ 手动跑一遍完整流程（从选关到结算）
□ 存档 → 刷新页面 → 恢复，状态一致
□ documents/演劫台/ 下对应文档已更新
```

### 9.4 核心原则

```text
1. 每阶段必须闭环。不允许"先搭 40 个面板壳子再说"。
2. 战斗引擎只消费不修改。所有游戏逻辑在 games/xiyou/ 内。
3. 数据走封神榜。configs 是种子，IndexedDB 是权威。
4. 数值一处定义。不写死在组件里，走 configs/params/。
5. 先跑通再优化。丑但能跑 > 漂亮但跑不通。
6. 每个纯函数写测试。掉落概率、品质判定、强化消耗、词缀生成。
```
