# 宠物与坐骑总览（反推验算）需求

> **状态**：2026-09-02 立项草案，待策划签字（阻塞项见 §八）。
> **载体**：封神榜 → 词条投放规则 → 新增「宠物与坐骑总览」Tab（与现有「装备总览」并列，不新建页面）。
> **一句话**：把「装备总览」这套规则反推器平行搬到宠物与坐骑上——输入 系统/子类型/等级/品阶，输出该配置下**可能产出的全部属性及数值区间**，并把策划命名表里的设计基准值自动对账，越界即报。

---

## 一、为什么要做

### 1.1 现状

| 侧 | 装备 | 宠物与坐骑 |
| --- | --- | --- |
| 词条数值曲线 | `affix_value_curve.equipment`，14 行 | `affix_value_curve.pet_mount`，14 行 |
| 子类型 → 可投放池 | `sub_type_groups` + `attribute_groups` + `affix_rows` | **无** |
| 核心属性系数 | `core_affix_ratio`（15 子类型） | **无** |
| 固定条 | `fixed_attributes` / `main_affix_pool` | **无** |
| 禁止规则 | `forbidden` | **无** |
| 反推验算入口 | 「装备总览」Tab | 「宠物与坐骑」Tab 只有一张可编辑的曲线表，**没有任何反推** |

即：宠物与坐骑的数值**只写了"每个属性给多少"，没写"谁能拿到、拿几条、和别的设计值对不对得上"**。策划改完曲线没有任何东西能告诉他结果是否自相矛盾。

### 1.2 已经能实测出来的问题（本工具存在的证据）

**发现 A：曲线自身闭合，反证满级 = 50 级。**
`pet_mount` 全部 14 行都满足 `base + perLevel × 49 ≈ full`（最大偏差 0.3，属四舍五入）。所以宠物与坐骑的成长段与装备同为 **50 级**，但 PRD 与配置里都没写死这个数——工具需要把它作为显式参数，并在不闭合时报警。

**发现 B：策划命名表的满级加成，有 2 处确定越出曲线包络。**
按 Lv.50 + 最高品阶（仙品 0.9~1.0）+ 浮动 50%~110% 取外包络，逐条核对 `数值策划完整方案.md` 的 5 坐骑 / 6 宠物命名表共 22 个设计基准值：

| 个体 | 设计值 | 所在属性行的 Lv.50 仙品包络 | 结论 |
| --- | --- | --- | --- |
| 赤焰狂狮 | 暴击伤害 +15% | `critDamage` ∈ [1.8, 10.9] | **超上限 4.1 个百分点** |
| 谛听 | 全属性 +5% | 按六维百分比 `attackBonus` 等 ∈ [6.2, 32.7] | **低于下限 1.2 个百分点**（若"全属性"另走一条通路则不成立，见 §八 Q1） |
| 其余 20 项 | — | — | 落在包络内 |

这两条是我手算出来的，一次性的、会随曲线改动而过期。工具要把它变成**每次改数都自动跑**的检查，这才是本需求的核心价值，而不是"再看一次表"。

**发现 C：8 个属性没有任何数值通路。**
`attribute_groups` 里出现、但 `pet_mount` 曲线没有行的属性共 8 个：`maxHealth`、`attack`、`defense`、`hitValue`、`dodgeValue`、`speed`（基础六维绝对值）、`vulnerability`、`shield`。装备侧六维走装备公式（`单位基数 × 等级 × 权重 × 转化系数`）所以有解；**宠物与坐骑没有自己的公式**，若哪天要投"气血 +300 点"这类绝对值，当前配置算不出来。命名表目前全是百分比，所以这不是已经爆掉的 bug，而是一条**必须显式定口径的边界**（§八 Q2）。

## 二、这是什么、不是什么

**是**：规则反推器 / 策划自检器。输入参数 → 按 `affix_rule` 算出可获得区间。不读任何已配置的宠物/坐骑实体。

**不是**：
- 不是引擎结算预览（引擎侧宠物/坐骑尚未参战，见 §六.4）；
- 不是宠物/坐骑编辑器——个体（筋斗云、灵明石猴…）的定义不在本工具内产出；
- 不做资质 / 成长率 / 升星 / 突破：PRD 未给宠物坐骑强化体系，`演劫台` 西游沙盒里的 `XiyouPet.growth` / `XiyouMount.aptitude` 是**运行时演示 mock，与数值策划口径无映射关系，禁止当作依据复用**；
- 不做独立被动的机制数值（触发条件、乘区结算在演劫台验证，本工具只显示"该条不参与数值反推"）。

| 类别 | 宠物 | 坐骑 |
| --- | --- | --- |
| A 基础属性 | 是（少量） | 是（速度、气血、防御为主） |

## 四、输入参数轴

装备侧是 5 轴（等级/类型/子类型/品阶/品质）。宠物坐骑侧**只凑得出 4 轴**，第 5 轴不该硬造：

| 轴 | 控件 | 取值 | 依据 |
| --- | --- | --- | --- |
| 系统 | TacticalSelect | 宠物 / 坐骑 | 两侧 A/B/C/D/F 供给不同，是两个规则集而非一个 |
| 等级 | NumericStepper 1~maxLevel | 1~50 | 发现 A 反证；`maxLevel` 从配置读，缺省 50 并提示 |
| 子类型 | TacticalSelect（随"系统"联动） | 宠物：金 / 木 / 水 / 火 / 土 / 无（6）；坐骑：待 §八 Q3 | 宠物命名表带五行列；坐骑类型表有 疾风马 / 玄龟 / 战虎 / 白象 |
| 品阶 | TacticalSelect | 沿用 `tier_weight` 五档 | 见 §八 Q4（命名表用的是 稀有/史诗/传说/仙品，与装备 凡/玄/地/天/仙 不同词表） |

**品质轴不做**：PRD 规定宠物/坐骑词条数固定为 2 + 3，不随品质增减，所以装备侧"品质 → 投放前 N 行"的机制在这里没有对应物。界面主语行直接写死条数（见 §六）。

## 五、数值通路：区间怎么算

### 5.1 唯一通路 = 曲线

```
单条词条下限 lo = min.base + min.perLevel × (L − 1)
单条词条上限 hi = max.base + max.perLevel × (L − 1)
```

`max` / `min` 两行不是"同一件东西的波动"，而是**同属性在不同个体/不同 roll 上的分布边界**：`min` 是最差可得、`max` 是最好可得。

### 5.2 区间口径：外包络

品阶权重在 `[tier.min, tier.max]` 内**每件随机取一次**，浮动在 `[float.min, float.max]` 内独立取值，故最终展示"可能拿到的最好与最差"：

```
可获得下限 = lo × tier.min × float.min
可获得上限 = hi × tier.max × float.max
```

不做期望值、不做中间分位——那是演劫台蒙特卡洛的事，本工具的结论必须一行内能说清。

### 5.3 舍入

百分比一律保留 **1 位小数**（现有曲线 `perLevel` 最小步长 0.02，取整会把低等级值抹平）。与装备侧一致。

### 5.4 完整算例（必须原样体现在界面悬浮推导里）

输入：宠物 · 火 · Lv.50 · 仙品，看「速度加成」：

```
行1 min: 6 + 0.16 × 49 = 13.84      行1 max: 15 + 0.3 × 49 = 29.7
下限 13.84 × 0.9(品阶min) × 0.5(浮动min) = 6.2
上限 29.7  × 1.0(品阶max) × 1.1(浮动max) = 32.7
→ 可获得区间 6.2% ~ 32.7%
```

推导串（`calc`）格式沿用装备侧：
`曲线 6+0.16×49 = 13.8 ~ 15+0.3×49 = 29.7，×0.9~1（品阶）×0.5~1.1（浮动）`

### 5.5 品阶 / 浮动取值缺省时的行为

工具**必须显示自己用了哪份配置**：

- `pet_mount` 有专属 `tier_weight` → 用它；
- 否则回落到装备 `tier_weight`，并在 warnings 里挂一条 `品阶权重沿用装备 tier_weight（pet_mount 未单独配置）`；
- 浮动同理（回落 `equip_formula.floatRange` = 0.5~1.1）。

静默回落是本工具要消灭的头号错误来源。

## 六、界面结构

复刻装备总览的骨架，类名与交互一并复用：

```
参数条（4 个下拉/步进器，不放进卡片）
├─ 左卡 6fr
│   ├─ 主语行：宠物 · 火 · Lv.50 · 仙品 · 词条 2 + 3 条
│   ├─ 分区① 核心属性（2 条基础属性词条）
│   ├─ 分区② 主要属性（3 条 B/C/D/F）
│   └─ 分区③ 独立被动（机制条，无数值 → 明确写"不参与数值反推"）
├─ 右卡 4fr（position: sticky）
│   └─ 点左卡任意池 → 列出池内全部候选属性及各自区间
└─ 底部「配置缺口」红色告警区
```

硬性交互要求（都是装备总览已经踩过并验证过的）：

1. **每个区间数值格可悬浮看推导**（`data-calc` + CSS 气泡，即时显示）。缺数据时推导串写"缺口原因"而不是空着。
2. 缺配置一律显式标红/标警，**绝不显示 0 或"—"**——把"没配"和"配了 0"混为一谈会让策划误判。
3. 可点击行 hover / pressed / 选中三态齐备，带 `aria-label` 与 `aria-pressed`，键盘 Enter/Space 可展开。
4. 参数条文案：`按当前投放规则反推一只宠物/一匹坐骑可产出的全部属性区间。数值为规则推算，非引擎结算，也不读取已配置个体。悬停数值可查看推导过程。`
5. 窄屏（≤1180px）双卡降为单列，与装备总览同一断点。

### 6.4 与引擎的对账（暂不做，留接口）

`types.ts` 的属性来源枚举已含 `'pet' | 'mount'`，「来源审计」页能按来源拆到属性。后续若宠物坐骑参战，本工具的区间结论应与来源审计的实测值对账——现阶段无数据，只在文档里占位，不写代码。

## 七、配置缺口与分阶段补齐

### P0 — 只读反推，不新增任何配置（可立即开工）

用现有 `affix_value_curve.pet_mount` + 装备 `tier_weight`/`floatRange`（按 §5.5 显示回落）：

- 输入 4 轴，输出**该曲线表覆盖的全部 56 个属性**在给定等级/品阶下的区间，按曲线行分组列出；
- 「核心 2 条 / 主要 3 条」的池尚不存在 → 左卡两区显示「未配置投放池」+ 提供"按曲线行全量浏览"的降级视图；
- 新增**曲线闭合校验**：逐行检查 `|base + perLevel × (maxLevel − 1) − full| ≤ 0.6`，不闭合直接进 warnings；
- 新增**量纲提示**：`energyInit`（初始能量）、`splash`（溅射）这类不是百分比的行，界面单位必须与曲线一致，不得统一显示 `%`。

P0 的产出物本身就有用：它能自动抓出发现 A / 发现 B 那类问题，不需要任何新配置。

### P1 — 补投放规则结构

在 `configs/equipment/affix-rule.json` 新增顶层块（与装备并列，**不与 `sub_type_groups` 混用**）：

```jsonc
"pet_mount_rules": {
  "max_level": 50,
  "float_range": { "min": 0.5, "max": 1.1 },   // 缺省则回落并提示
  "tier_weight": {},                            // 缺省则回落并提示
  "sub_types": {
    "pet":   [{ "id": "fire", "name": "火" /* … */ }],
    "mount": [{ "id": "swift", "name": "疾风马" /* … */ }]
  },
  "core_count": 2,
  "main_count": 3,
  "pools": {                                    // 子类型 → 池
    "pet:fire": {
      "core_pool":  ["attackBonus", "speedBonus"],
      "main_pool":  ["ATK-ADD", "critRate"],
      "passive":    { "name": "焚天", "note": "暴击时必挂灼烧；对灼烧目标伤害独立 +15%" }
    }
  },
  "forbidden": []
}
```

**接入前必读**：`seed.ts` 的 `buildAffixRule()` 历史上按字段白名单拷贝，新增顶层字段必须同步登记，否则被静默丢弃（已在 `完整项目说明.md` 留过警告）。现在走 `affixRuleDefaults()` 整份深拷贝，新字段自动带过——但 `AffixRuleConfig` 类型必须同步扩，否则 TS 层面看不见。

### P2 — 设计基准值对账

把命名表的 22 个满级加成落成 `design_anchors`（放 `pet_mount_rules` 内，不新建 JSON 文件），工具逐条判定落在包络内/外，界面单开一区列越界项：

```jsonc
"design_anchors": [
  { "name": "赤焰狂狮", "system": "mount", "quality": "传说",
    "attrs": [{ "attribute": "attackBonus", "value": 20 },
               { "attribute": "critDamage",  "value": 15 }] }
]
```

P2 是发现 B 的自动化版本，也是这套工具对"数值策划"最实的一笔。

## 十、验收标准
