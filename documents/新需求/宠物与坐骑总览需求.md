# 宠物与坐骑总览（反推验算）需求 —— 8.16 口径重写版

> **状态**：2026-09-06 重写。原 2026-09-02 草案的口径已被 8.16 PRD 推翻（见 §一），本版为现行权威口径。
> **载体**：封神榜 → 词条投放规则 → 「宠物与坐骑总览」Tab（与「装备总览」并列，不新建页面）。
> **一句话**：输入 系统/个体/等级/品阶/品质/资质/突破 七轴，按 `pet_mount_rules` 反推该配置下一只宠物/一匹坐骑**可能产出的全部属性及数值区间**；曲线闭合校验常驻，设计基准对账留接口。

---

## 一、为什么重写（旧版教训）

旧版（09-02 草案）按当时 PRD 抄了四条口径——词条固定 2+3 不随品质增减、唯一数值通路=曲线、不做资质/突破、不读取已配置个体——8.16 PRD《完整项目说明.md》§宠物与坐骑系统把四条全部推翻。封神榜界面显示「词条 2 + 3 条」就是照旧版实现的结果。

**本版立的两条规矩（防复发）：**

1. **数值口径只引用、不复抄**：一切数值结论写「见《完整项目说明.md》§宠物与坐骑系统」，本档不再誊抄表格。复抄必漂移——旧版抄的养成权重 60，新 PRD 已改 120，而 `seed.ts` 落地的还是 60（§八遗留 2）。
2. **手算结论不进文档，进工具**：发现 A（曲线闭合）、发现 B（基准值越界）这类结论会随改数过期，只保留方法，数值判定由工具每次自动跑。

旧版 §八 六个待确认问题的下落：Q4 品阶权重共用一套（PRD 明文✓）；Q6 浮动 50%~110%（公式段明文✓）；Q3 子类型 → **个体驱动**（2026-09-06 裁定）；品质门槛 → 以 2026-09-06 裁定表为准（品质 1~5，见 §三）；Q5 池按个体分（个体驱动后自然消解）；Q1「全属性 +5%」通路仍待定（§八遗留 3）。

## 二、这是什么、不是什么

**是**：个体驱动的规则反推器 / 策划自检器。读取 `configs/pets/pets.json`、`configs/mounts/mounts.json` 的 `weights`（主要 3 条权重分布）与 `trait`（特性文本），按 `pet_mount_rules` 算出给定七轴下的全部属性区间。

**不是**：
- 不是个体编辑器——个体在 configs 维护，本工具只读；
- 不是引擎结算预览（宠物坐骑尚未参战）；
- 不模拟资质/突破的养成过程——两者只是反推参数轴；
- 不做期望值 / 蒙特卡洛——那是演劫台的事，本工具结论必须一行内能说清。

## 五、数值通路

### 5.1 主要 3 条 = 六维公式（8.16 新通路，推翻旧版"发现 C"）

```
单位基数 = base_sap ÷ system_count ÷ total_weight ÷ max_level = 900 ÷ 2 ÷ 9 ÷ 50 = 1
属性值 = 单位基数 × 等级 × 个体权重 × 资质倍率(资质/400) × 突破倍率(1+Σbonus) × 转化系数
可获得区间 = 基准 × 品阶权重区间 × 浮动区间（外包络，与装备总览同口径）
```

算例：紫电骅（攻 4/命 2/速 1）Lv.10 仙品 资质 400 未突破：
攻击基准 = 1 × 10 × 4 × 2(转化) = 80 → 外包络 **[36, 88]**。
（PRD 原文示例 [30, 66] 是"品阶取上限 1.0"的简化口径；本工具与装备总览统一为品阶×浮动双外包络。）

### 5.2 附加行 = pet_mount 曲线

`lo = min.base + min.perLevel × (L−1)`，区间 = lo/hi × 品阶 × 浮动外包络，百分比保留 1 位小数（perLevel 最小步长 0.02，取整抹平低等级值）。

### 5.3 常驻校验（工具自动跑，不写死结论）

- 曲线闭合：`|base + perLevel × (max_level − 1) − full| ≤ 0.6`，不闭合进 warnings；
- 个体权重和 ≠ 主要权重和 7 → 进 warnings；
- 附加行→曲线行的池映射为草案 → 常驻 warning 提示待确认（§八遗留 1）。

## 六、界面结构

```
参数条（7 轴，不放进卡片）+ 个体一览表（当前系统全部个体：名称/分类/权重分布/特性，点击行选中）
├─ 左卡 6fr
│   ├─ 主语行：宠物 · 紫电骅 · Lv.50 · 仙品 · 品质 5（神）· 资质 400 · 词条 N 条（N 随品质实算）
│   ├─ 分区① 主要属性（3 条，公式区间 + 悬浮推导）
│   ├─ 分区② 特性（品质门槛不足时显示「品质 3 起投放」；达标显示个体 trait 文本，注明不参与数值反推）
│   ├─ 分区③ 附加行（4+1 行表格：行名 / 品质门槛 / 本品质是否生效）
│   └─ 底部「配置缺口」红色告警区
├─ 右卡 4fr（sticky）：点左卡任意行 → 该行全部候选属性及区间
```

硬性交互要求沿用装备总览已验证的一套：悬浮推导（`data-calc` 气泡）、缺配置显式标红绝不显示 0、行三态 + aria + 键盘可达、窄屏 ≤1180px 单列、参数文案注明「数值为规则推算，非引擎结算」。

## 七、配置结构

`affix-rule.json` 顶层新增 `pet_mount_rules`（与装备并列，不混用 `sub_type_groups`）：

```jsonc
"pet_mount_rules": {
  "max_level": 50,
  "float_range": { "min": 0.5, "max": 1.1 },
  "formula": { "base_sap": 900, "system_count": 2, "total_weight": 9, "main_weight_sum": 7 },
  "aptitude": { "min": 280, "max": 440, "cap": 500, "base": 400 },
  "breakthroughs": [ { "level": 10, "bonus": 0.1 }, { "level": 30, "bonus": 0.2 }, { "level": 50, "bonus": 0.3 } ],
  "rows": [
    { "id": "main", "nameAtk": "主要属性", "nameDef": "主要属性", "minQuality": 1 },
    { "id": "trait", "nameAtk": "特性", "nameDef": "特性", "minQuality": 3 },
    { "id": "side_all", "nameAtk": "ATK-ALL", "nameDef": "DEF-ALL", "minQuality": 4, "pool": { "ATK": ["ATK-ALL"], "DEF": ["DEF-ALL"] } },
    { "id": "l1", "nameAtk": "ATK-L1", "nameDef": "DEF-L1", "minQuality": 1, "pool": { "ATK": ["ATK-L2"], "DEF": ["DEF-L2"] } },
    { "id": "l3c", "nameAtk": "L3-通用", "nameDef": "L4-通用", "minQuality": 2, "pool": { "ATK": ["L3-通用"], "DEF": ["L4-通用"] } },
    { "id": "l3", "nameAtk": "ATK-L3", "nameDef": "DEF-L3", "minQuality": 3, "pool": { "ATK": ["ATK-L3"], "DEF": ["DEF-L3"] } },
    { "id": "all", "nameAtk": "ATK-ALL", "nameDef": "DEF-ALL", "minQuality": 4, "pool": { "ATK": ["ATK-ALL"], "DEF": ["DEF-ALL"] } }
  ]
}
```

- `rows[].pool` = 该行可抽属性池（**属性组码**，经 `attribute_groups` 展开，与装备侧 `affix_rows` 同构）。行名与现有组码逐字同源（`ATK-L1` 组即攻/命/速、`L3-通用`/`L4-通用`、`ATK-L3`/`DEF-L3`、`ATK-ALL`/`DEF-ALL` 全部现成），零发明；附加 L1 行引用 `ATK-L2`/`DEF-L2`（六维加成）为草案，待策划确认（§八遗留 1）；
- 个体数据（weights/trait）在 `configs/pets/pets.json`、`configs/mounts/mounts.json`，不入本块；
- `AffixRuleConfig` 类型同步扩 `pet_mount_rules?`；个体类型 `PetMountIndividual` 与读取口 `petIndividuals()/mountIndividuals()` 落在 `affix-rule-defaults.ts`（单一权威读取口，新字段经整份深拷贝自动带过）。

## 八、遗留与待确认（不阻塞本版功能）

1. **附加行→属性组池映射草案**：L1→`ATK-L2`/`DEF-L2`（六维加成）、L3-通用→`L3-通用`/`L4-通用`、L3→`ATK-L3`/`DEF-L3`、ALL（含主要区）→`ATK-ALL`/`DEF-ALL`。行名与组码逐字同源，仅"L1 附加对应 L2 组"一处是推断，确认前工具常驻 warning。
2. **养成权重 60→120**：`seed.ts` `system_budget` 宠物/坐骑现为 60，新 PRD 为 120；且新 PRD §18「合计 660」未随 120 更新（按 120 应为 780）。两处都需策划拍板后一起改，涉及演劫台预算联动，不在本版动。
3. **「全属性 +5%」（谛听类）通路未定**：折进六维百分比、单开曲线行、还是常驻光环独立乘区（旧 Q1）。
4. **configs 个体数少于 PRD 命名表**：宠物 6 只 / 坐骑以 configs 实有为准，PRD 命名表（坐骑 11+ 只）待补齐 configs。
5. **P2 设计基准对账**：把命名表满级加成落成 `design_anchors` 自动判越界（发现 B 的自动化），本版不做，接口留在这。

## 九、实现约束与复用点（沿用旧版，仍然有效）

| 约束 | 要求 |
| --- | --- |
| 不复制算法 | 主要 3 条复用参数化的 `resolveAttrRange`（公式通路，公式参数由 `pet_mount_rules` 构造，不再吃装备 `EquipFormulaConfig`）；附加行复用 `resolveCurveAttrRange(…, 'pet_mount', …)`；禁止新建 pet-mount-overview.ts 抄一遍 |
| 单一权威读取口 | `affix-rule-defaults.ts`；新 Tab 与「装备总览」共用同一份 `cfg`，自动继承「载入定稿」与漂移横幅 |
| 缺口显式化 | 缺曲线行 / 缺转化系数 / 未知品阶 / 权重和不对 → source none + calc 写明缺口原因，绝不静默为 0 |
| 量纲 | `energyInit`、`splash` 不以 % 呈现；百分比 1 位小数 |

**验收清单**：

1. 七轴任一变动，主语行与三区结论同步刷新；主语行词条数 = 3 主要 + 特性(品质≥3) + 主要 ALL(品质≥4) + 生效附加行数，随品质实算。
2. 品质 1 时特性 / ALL 行显示「品质 N 起投放」，不显示区间；品质 5 全部生效。
3. 主要 3 条走公式通路（source = formula），悬浮推导含 单位基数/等级/个体权重/资质×突破/转化/品阶/浮动 各行。
4. 附加行曲线区间与 §5.2 口径一致（外包络、1 位小数）。
5. 曲线闭合校验常驻：改坏 full → warnings 出现「不闭合」。
6. `npm run typecheck && npm run test` 通过；测试覆盖 §5.1 算例、品质门槛、闭合校验、权重和校验。
7. 只有在浏览器里实际看到个体列表、品质门槛与悬浮推导，才算交付（typecheck 不算）。
