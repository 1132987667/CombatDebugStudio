# 玩法主循环设计 —— 进入 · 寻敌 · 战斗 · 战利品 · 结算闭环

> **状态**：2026-09-06 立项设计。补全《完整项目说明.md》§24 关卡结构中"多场推进 + 小结算/大结算 + 中途撤离"的**玩家一局流程闭环**。
> **定位**：单局玩法骨架，与流派无关的通用流程；当前阶段数值验证以连击流阵容为主（见《需求调整历史.md》#9 裁定）。
> **对齐现状**：演劫台已实现 选关（降妖路引，30 关 × 5 区域，解锁链 + 三星）→ 进入场景 → 敌方全体（3 敌组 + 妖徒）编成**一场** 4v4 → 胜利一次性结算入包。本设计将其演进为 **§24 的多场循环结构**。

---

## 一、现状与差距

| 环节 | 现状（已实现） | 差距（本设计补全） |
|------|---------------|-------------------|
| 进入 | SceneTimeline「降妖路引」选关，currentScene 存档 | 关卡内节点序列概念缺失 |
| 寻找敌人 | 无（整关敌人一场全上） | 节点推进 + 敌情预览 + 局内最后调整 |
| 战斗 | BattleZen 完整（4v4 自动战斗） | 接入逐场推进流 |
| 收拾战利品 | 掉落 roll + 入包 + toast | 小结算面板 / 大结算汇总分层 |
| 循环 | 打完停在场景 | 继续推进 / 中途撤离 / 大结算 / 再战 |

**关键冲突裁定**：当前实现把 `scene.enemies`（3 敌组）+ `scene.yaotu` 合编为**同一场**战斗的 4 个敌方单位；§24 则规定关卡有 1~4 **场**战斗（小场小结算）。本设计采用 §24 口径：**场景 = 多场战斗的节点序列**，敌方单位按规则从敌组池编成（见 §三.4）。

## 二、一局流程总览（状态机）

```text
营地（演劫台主界面）
 │
 ├─ ① 玩家进入流程
 │    选场景(5大区域) → 选关卡(30关) → 战前准备 → 进入关卡
 │
 ├─ ② 寻找敌人（关卡内推进）
 │    推进 → 到达节点 → 敌情预览 → [开战 / 调整 / 撤离]
 │
 ├─ ③ 战斗（4v4 自动战斗，玩家零操作）
 │    ├─ 胜利 → ④ 收拾战利品 → 小结算面板
 │    │    ├─ 还有下一场 → 回 ②（可中途撤离）
 │    │    └─ 最后一场   → ⑤ 大结算
 │    └─ 失败 → 失败结算（已得保留，无惩罚）→ 回 ①
 │
 └─ ⑤ 战斗结束（大结算）
      整关汇总 → 首杀/星级/解锁 → [再次挑战] 或 [返回路引] → 回 ①
```

一局的**最小闭环**（关卡一/二，1 场）：进入 → 敌情预览 → 战斗 → 小结算即大结算 → 出口。
**完整闭环**（关卡三~五，2~4 场）：进入 → （预览 → 战斗 → 小结算 → 继续）× (N-1) → 关底战 → 小结算 → 大结算 → 出口。

## 三、① 玩家进入流程

### 3.1 步骤

1. **入口**：演劫台全屏态 →「降妖路引」（SceneTimeline / SceneMapDialog）。
2. **选场景**：5 大区域，按解锁链逐区域开放（`unlockCondition.sceneId` 链式解锁，现状沿用）。
3. **选关卡**：每区域 6 关（5 普通关 + 1 妖魁关）。关卡卡片展示：
   - 推荐等级（`levelRange`）、当前星数（`stars/maxStars`）、产出预览（`drops`）；
   - 通关状态：未解锁 / 已解锁未通 / 已通（星数）。
4. **战前准备**（全部为战前行为，局内不换人）：
   - 上阵 4 人（唤灵台养成结果）；
   - 站位 2×2（前排仇恨 +50、承伤 +10%；后排仇恨 -30、承伤 -10%，见 §6）；
   - 流派 BUILD（**当前阶段 = 连击流**：连击/风势/裂甲）；
   - AI 规则（§26 目标优先级）。
5. **确认进入** → 加载关卡节点序列，进入 ②。

### 3.2 关卡节点序列（核心新概念）

- **关卡 = 节点序列**，场数按 §24：关卡一 1 场 / 关卡二 1 场 / 关卡三 2 场 / 关卡四 3 场 / 关卡五 4 场（含妖徒）/ 妖魁关 4 场。
- **节点构造规则**：
  - 末节点固定为**关底战**：普通关 = `scene.yaotu`（妖徒）率队；妖魁关 = `bosses.json` 妖魁率队；
  - 前置普通节点从**本场景敌组池**（`scene.enemies`）+ **同区域前序场景敌组池**按序轮转取用，每场编成 3~4 个敌方单位凑成 4v4；
  - 场数为 1 的关卡 = 单节点关底战（即现状形态）。
- **逐场递进（妖气增幅）**：第 k 场战斗的敌方属性乘 `1 + 0.15×(k-1)`（封顶 +45%），制造关内递进压迫感。基准值待与《数值策划完整方案》对账后固化。
- 节点序列为**确定性配置**（不做随机地图），可复现、可调试——符合"轻策略 + 自动战斗"定位，不做自由走位探索（非目标：复杂战棋）。

## 四、② 寻找敌人（关卡内推进）

### 4.1 推进

- 队伍沿节点序列**自动推进**（进度条 + 当前节点序号 k/N），无手动寻路。
- **推进过渡时长：固定 3 秒**（基准值，进封神榜可调参；含进场/遇敌提示演出）。
- 到达战斗节点 → **敌情预览以非阻塞横幅并入推进演出**（推进 3 秒内展示敌方编成/妖气增幅/掉落倾向），推进结束**自动开战**——全自动循环，无手动等待模式（2026-09-06 裁定：自动战斗不需要玩家手动操作；「调整/撤离」保留为 HUD 随时可用的干预入口，不阻塞流程）。

### 4.2 敌情预览（非阻塞演出 + HUD 干预入口）

推进 3 秒内以横幅/侧栏展示敌方本场编成（≤4 单位）：名称、等级、类型（普通/精英/妖徒/妖魁）、妖气增幅层数、掉落倾向（主掉落）。**不等待玩家**，推进结束自动开战。

玩家干预入口（HUD 常驻，不阻塞流程）：

| 入口 | 行为 |
|------|------|
| **加速/跳过** | 跳过当前推进过渡或结算期剩余回血，立即进入下一段 |
| **调整** | 修改站位 / AI 规则（下一场生效，不换人不掉装备） |
| **撤离** | 触发中途撤离规则（见 §六.3），仅场数 ≥2 的关卡开放 |

## 五、③ 战斗

全部引用现行规则，本设计只约定流程接口：

- 4v4 自动战斗、速度排序、回合制（§5）；连击/风势/裂甲按 §14 与流派文档执行；
- 战斗中玩家**零操作**，由战前 AI 规则驱动（§26）；
- 胜负：一方全灭（§5）；
- 战斗结束回写主角气血/能量（现状已实现，跨场保留）——小场之间**不瞬时回满**，气血在小结算阶段按每秒 5% 缓回（见 §六.2），补给节点（§六.4）为长关额外手段。

## 六、④ 收拾战利品

### 6.1 掉落与拾取

- **自动拾取**：胜利即结算本场掉落 roll（`drops.json` 掉落组 + `scenes.json` drops 表），直接入包，配合飘字/toast 提示。**不设地上捡取动作**（自动战斗定位，无拾取交互）。
- 掉落品质按品质生成机制（附录A §八）；关卡产出索引见附录B 第九章掉落总表。

### 6.2 小结算（每场战后，非弹窗）

- **展示形态（2026-09-06 裁定）**：**不使用弹窗/模态战报**——以 HUD 内嵌区域非阻塞展示（掉落逐条飘出 + 血条流动），战斗画面保持在场。
- 本场经验 / 金钱滚动；
- 掉落列表（沿用现状色阶：主掉落青 / 次掉落灰 / 稀有金），掉落 roll 展示约 1~2 秒；
- 角色气血/能量状态一览（跨场保留的直观呈现）。

### 6.2.1 结算期缓回（战耗恢复裁定）

- **规则**：小结算期间，全员每秒回复 **10% 最大气血**、能量每秒 **+5**，**直到满值**；HUD 血条实时流动。
- **时间窗口**：自然时长 = 气血缺口 ÷ 10%/秒，**上限 10 秒**（从空血起算）；实战战后气血通常余 40%~70%，窗口约 3~6 秒。
- **不阻塞推进**：HUD「加速/跳过」随时可点，跳过剩余回复直接进入 ②。
- **自动推进**：默认等待全员回满（≤10 秒）再自动推进；阈值（如 ≥90%）可经封神榜配置。
- 数值（10%/秒、能量 +5/秒）为基准值，进封神榜调参，待与《数值策划完整方案》对账后固化。

### 6.3 中途撤离（场数 ≥2 的关卡）

- 小结算面板提供「继续推进 / 中途撤离」；
- **已结算小场的资源保留**（经验/金钱/掉落均已入包），未打的场不计，**无任何惩罚**；
- 撤离直接返回选关界面（①），关卡进度不保存（下次从头打）。

### 6.4 补给节点（长关调节，P1 可选）

关卡四/五（3~4 场）在第 2 场前插入一个**补给节点**：回复全体 30% 气血 / 能量 +25，或三选一临时增益。基准值待数值对账；P0 可先不做，仅保留节点位。

## 七、⑤ 战斗结束（大结算）

### 7.1 大结算面板（关底战胜利触发）

- **整关汇总**：本场次逐场经验/金钱累计、全部掉落清单（按品质排序）；
- **首杀标记**：妖徒/妖魁首杀奖励（对照附录A §八 品质出现场景：普通 Boss 首杀玄品、精英 Boss 首杀地品等）；
- **星级评定**（写入 `scene.stars`，取历史最高）：
  | 星 | 条件 |
  |----|------|
  | ★1 | 通关（击杀关底） |
  | ★2 | 全程无成员死亡 |
  | ★3 | 关底战 4 回合内结束 |
  - 基准规则，阈值可经封神榜调参；
- **成长结算**：升级提示、突破材料入手提示；
- **进度推进**：通关解锁下一关（`unlockCondition` 链式推进），区域末关通关解锁下一区域。

### 7.2 失败结算（简版）

- 关底战或任意一场战败：**本场已得资源保留**（入包即落袋），无惩罚；
- 返回选关界面；敌方状态重置。

### 7.3 出口

| 按钮 | 行为 |
|------|------|
| 再次挑战 | 重进同关（①，直接进入节点 1） |
| 返回路引 | 回选关界面（①） |

## 八、循环闭环

```text
一局结束（大结算）
 → 资源入包 → 洞府/唤灵台消耗（强化/升星/洗练/宠物坐骑养成，§18/§21/§22）
 → 变强 → 挑战更高关卡 → 碾压 → 再变强（§4 核心游戏循环）
```

本设计即 §4 核心循环「战前配置 → 自动战斗 → 获得经验/金钱/材料/装备 → 强化/突破/加点/调整流派 → 挑战更高层级」的**单局落地形态**。

## 九、节奏基准与单局时长

### 9.1 节奏基准汇总（均为基准值，进封神榜可调参）

| 环节 | 时长 | 说明 |
|------|------|------|
| 推进过渡（含敌情横幅） | **固定 3 秒** | 寻找敌人的移动/遇敌演出，结束自动开战 |
| 战斗 | 2~4 回合（普通 15~40 秒表现时长，按 §25 怪物击杀回合数） | 引擎现状，零改动 |
| 掉落 roll 展示 | 1~2 秒 | 小结算开场（HUD 内嵌，非弹窗） |
| 回血窗口 | **每秒 10% 最大气血，上限 10 秒**（实战约 3~6 秒） | 可点「加速/跳过」跳过 |
| 大结算 | 玩家自控阅读 | 无强制等待 |

### 9.2 单局时长估算

| 关卡 | 构成 | 估算总时长 |
|------|------|-----------|
| 关卡一/二（1 场） | 3 + 20~40 + ~6 | **约 30~50 秒** |
| 关卡三（2 场） | 2×(3+20~40) + 1×回血 3~10 | **约 50 秒~2 分钟** |
| 关卡四（3 场） | 3×(3+20~40) + 2×回血 | **约 1.5~3 分钟** |
| 关卡五/妖魁（4 场） | 4×(3+20~40) + 3×回血 + 大结算 | **约 2~4 分钟** |

单局 2~5 分钟、无强制等待（全程可跳过）、支持纯挂机循环——对齐 §2「战斗爽感 / 轻策略 / 轻肝度」目标。挂机刷一关的循环节拍 = 战斗 → 结算回血 → 推进，玩家全程可随时接管（调整/撤离/加速）。

## 十、实现对照与落地批次

| 批次 | 内容 | 依赖 |
|------|------|------|
| P0-1 | 节点序列状态机（RunState：选关/预览/战斗/小结算/大结算/撤离终态；scenes.json 扩展节点编排或按 §三.2 规则推导） | 无 |
| P0-2 | 敌情预览面板 + 调整/撤离入口 + 挂机 2 秒自动开战 | P0-1 |
| P0-3 | 小结算面板（逐场）+ **每秒 5% 缓回计时器**（可跳过，挂机等满）+ 跨场气血/能量保留 | P0-2 |
| P0-4 | 大结算面板 + 星级评定 + 首杀标记 | P0-3 |
| P1 | 补给节点、妖气增幅与缓回速率数值固化、挂机推进阈值配置 | 数值对账 |

**自检要求（随实现交付）**：P0-1 状态机配一个最小演示脚本（断言 1 场关与 4 场关的节点流转/撤离/失败路径）；P0-3 缓回配一个计时断言（缺口 40% → 8 秒回满、跳过立即生效）。

**实现要点**：
- `battle.ts` 的 `buildEnemyTeam` 按节点序列重构（当前为整场景合编）；
- `BattleZen` 战斗结束出口从"停在场内"改为"推进/结算/撤离"三态；
- 星级/首杀写入 scenes.json 与存档（save-bridge 已有场景字段通道）。
