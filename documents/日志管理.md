## 战斗日志管理系统需求规格说明书

### 1. 引言

#### 1.1 目的

本文档旨在详细定义基于 Vue3 + TypeScript 实现的战斗日志管理系统的功能、界面、数据及性能需求，为开发、测试及项目验收提供依据。

#### 1.2 范围

本系统为前端独立模块，负责实时记录、展示和筛选战斗中发生的各类事件，提供直观的日志视图，并支持浅色/暗色主题切换。

#### 1.3 术语表

- **日志条目**：记录一次具体事件的最小单元。
- **回合**：战斗中的一轮行动周期，日志按回合分组。
- **连续事件合并**：将同一来源对同一目标连续发生的同类事件合并为一条汇总日志。

---

### 2. 总体描述

#### 2.1 用户场景

- 玩家在战斗过程中实时查看战斗日志，了解战斗细节。
- 战斗结束后可回溯日志，分析战斗过程。
- 通过筛选快速聚焦特定类型的事件（战利品、系统、战斗）。

#### 2.2 假设与依赖

- 战斗逻辑与日志生成均在前端完成，日志数据由战斗系统实时推送。
- 不使用第三方UI组件库，样式完全自定义。
- 支持现代浏览器（Chrome、Firefox、Edge最新版）。

---

### 3. 功能需求

#### 3.1 日志展示

- **列表形式**：日志按时间顺序垂直排列，最新日志在底部（或顶部，需配置），支持滚动查看。
- **时间戳**：每条日志内部存储精确时间戳（用于排序），但界面不显示具体时间。
- **回合分组**：
  - 同一回合内的日志使用相同的背景色（浅色/暗色模式下有区别）或左侧缩进线条标识。
  - 回合切换时，在分组顶部显示“第 X 回合开始”的标识行。
- **事件合并**：
  - 对同一来源（如“张三”）对同一目标（如“李四”）连续造成的多次同类型事件（如普通攻击、暴击）进行合并。
  - 合并后显示格式示例：“张三对李四连续造成5次伤害（共320点）”，并可展开查看每次详情（展开功能暂不实现，但保留数据结构）。
  - 合并规则：
    - 事件类型相同（如均为“伤害”）
    - 来源和目标相同
    - 中间无其他类型事件打断
    - 连续发生（按时间顺序相邻）
- **颜色标识**：
  - 我方角色名称：绿色（#2ecc71 浅色 / #27ae60 暗色）
  - 敌方角色名称：红色（#e74c3c 浅色 / #c0392b 暗色）
  - 伤害数值：红色（#e74c3c）
  - 治疗数值：绿色（#2ecc71）
  - 暴击数值：黄色（#f1c40f）
  - 技能名称：统一使用蓝色（#3498db 浅色 / #2980b9 暗色）
  - 其他文字（如“闪避”、“添加buff”等）：默认文本色
- **回合数统计**：在日志区域顶部显示当前战斗的总回合数（实时更新）。

#### 3.2 事件类型与内容

系统需记录并展示以下事件类型，每种类型有对应的文本模板：

| 事件类型   | 模板示例                                                      | 说明                                                 |
| ---------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| 战斗开始   | 战斗开始                                                      | <br />                                               |
| 战斗结束   | 战斗结束，结果：胜利/失败                                     | <br />                                               |
| 回合开始   | 第3回合开始                                                   | 作为分组标识                                         |
| 回合结束   | 第3回合结束                                                   | 可选，若需明确回合边界                               |
| 角色进场   | \[角色名] 进入战场                                            | 角色名按敌我颜色                                     |
| 角色倒下   | \[角色名] 倒下了                                              | <br />                                               |
| 普通攻击   | \[攻击方] 对 \[目标] 发动普通攻击，造成 \[数值] 点伤害        | 数值颜色为伤害红；若暴击则额外标注“暴击！”且数值变黄 |
| 暴击       | \[攻击方] 对 \[目标] 造成暴击！\[数值] 点伤害                 | 单独事件或合并到攻击中，根据设计选择                 |
| 闪避       | \[目标] 闪避了 \[攻击方] 的攻击                               | <br />                                               |
| 释放小技能 | \[施法者] 释放 \[技能名称]，对 \[目标] 造成 \[数值] 点伤害    | 技能名称用技能色                                     |
| 释放大招   | \[施法者] 释放大招 \[技能名称]，对全体敌人造成 \[数值] 点伤害 | 技能名称用技能色                                     |
| 添加buff   | \[目标] 获得 \[buff名称]，持续 \[X] 回合                      | buff名称用技能色，显示持续回合                       |
| debuff扣血 | \[目标] 受到 \[debuff名称] 影响，损失 \[数值] 点气血          | 数值用伤害红，可注明来源                             |
| buff加血   | \[目标] 受到 \[buff名称] 恢复，获得 \[数值] 点气血            | 数值用治疗绿                                         |
| 获得物品   | \[角色] 获得 \[物品名称] x \[数量]                            | <br />                                               |
| 打开宝箱   | \[角色] 打开宝箱，获得 \[物品列表]                            | <br />                                               |
| 获得战利品 | 战斗胜利，获得 \[物品列表]                                    | <br />                                               |

> **建议**：为避免日志过长，可对连续同类事件合并后显示汇总信息，并在数据结构中保留原始事件列表以便未来扩展。

#### 3.3 筛选功能

- **筛选方式**：提供三个按钮（标签样式），分别对应“战利品”、“系统”、“战斗”，按钮之间用竖线“|”分隔。
- **筛选逻辑**：
  - 点击“战利品”：只显示与物品、宝箱、战利品相关的事件。
  - 点击“系统”：只显示战斗开始/结束、回合开始/结束、角色进场/倒下等系统类事件。
  - 点击“战斗”：只显示攻击、技能、buff、闪避等战斗交互事件。
  - 默认显示全部日志。
  - 支持多选？目前设计为单选（三个互斥），但可考虑扩展为多选（如按钮组支持多选）。建议先实现单选，后续按需调整。
- **筛选状态**：被选中的按钮高亮显示。

#### 3.4 清空日志

- 提供一个“清空日志”按钮，点击后清空当前日志列表，并重置回合计数。

#### 3.5 主题切换

- 支持浅色和暗色两种主题，通过全局切换（如顶部开关）改变颜色变量。
- 颜色变量需按上述规范定义，确保在不同主题下可读性。

### 4. 数据需求

#### 4.1 日志数据结构

建议采用以下 TypeScript 接口定义：

```typescript
// 日志条目基础接口
interface LogEntry {
  id: string // 唯一ID，可使用 uuid 或时间戳+随机数
  timestamp: number // 时间戳（毫秒），用于排序
  round: number // 所属回合数
  type: LogType // 事件类型（用于筛选）
  category: 'loot' | 'system' | 'combat' // 筛选分类
  content: string // 渲染用的纯文本（或使用模板+数据，见下）
  rawData?: any // 原始数据，用于扩展（如合并事件的详情）
  mergeKey?: string // 用于合并的键值（如 "source_target_type"）
}

// 事件类型枚举（可根据需要扩展）
type LogType =
  | 'combatStart'
  | 'combatEnd'
  | 'roundStart'
  | 'roundEnd'
  | 'enter'
  | 'die'
  | 'normalAttack'
  | 'critical'
  | 'dodge'
  | 'skill'
  | 'ultimate'
  | 'buffAdd'
  | 'debuffDamage'
  | 'buffHeal'
  | 'itemGet'
  | 'chestOpen'
  | 'lootGet'

// 为支持结构化数据，可定义更具体的接口，例如：
interface AttackLogData {
  source: string
  target: string
  value: number
  isCritical?: boolean
  skillName?: string
}
```

**合并事件建议**：\
在生成日志时，若检测到符合合并条件的事件，可将其合并为一条特殊日志，其 `content` 为汇总文本，并在 `rawData` 中存储子事件列表。例如：

```typescript
{
  id: 'merged-xxx',
  timestamp: 1680000000000,
  round: 3,
  type: 'normalAttack',
  category: 'combat',
  content: '张三 对 李四 连续造成 5 次伤害（共 320 点）',
  rawData: {
    events: [/* 原始事件数组 */],
    source: '张三',
    target: '李四',
    totalDamage: 320,
    count: 5
  }
}
```

#### 4.2 数据流

- 战斗系统每产生一个事件，调用日志模块的 `addLog(entry)` 方法。
- 日志模块内部维护一个响应式数组 `logs`，并处理合并逻辑（可在添加时检查上一条日志是否可合并）。
- 筛选和清空操作基于该数组进行过滤或重置。

### 5. 界面需求

#### 5.1 布局

- 日志区域占据独立面板，高度固定或可调整，内部滚动。
- 顶部工具栏包含：
  - 回合数统计：显示“当前回合：X”
  - 筛选按钮组：“战利品 | 系统 | 战斗”
  - “清空日志”按钮
  - 主题切换开关（图标或文字）

#### 5.2 样式细节（浅色/暗色示例）

- **浅色主题**：
  - 背景色：#f8f9fa
  - 文字默认色：#2c3e50
  - 回合分组背景色：#ecf0f1（交替或仅标识行）
  - 按钮边框：#bdc3c7
- **暗色主题**：
  - 背景色：#2c3e50
  - 文字默认色：#ecf0f1
  - 回合分组背景色：#34495e
  - 按钮边框：#7f8c8d

具体颜色值可在实现时定义 CSS 变量，便于切换。

#### 5.3 交互

- 日志条目不支持点击展开详情（按需求）。
- 筛选按钮点击立即更新视图。
- 清空日志按钮需二次确认？目前无要求，可直接清空，但为避免误操作可增加简单确认弹窗（可选）。

---

### 6. 非功能需求

#### 6.1 性能

- 单场战斗日志条目数预估不超过 1000 条，无需虚拟滚动，但需保证渲染流畅。
- 合并连续事件可有效减少条目数。
- 使用 `keyed` 列表渲染，避免不必要的 DOM 更新。

#### 6.2 可维护性

- 日志数据结构清晰，类型定义完整。
- 颜色、文本模板等配置化，便于修改。
- 合并逻辑独立为可配置模块。

#### 6.3 兼容性

- 遵循 Vue3 组合式 API 和 TypeScript 严格模式。
- 不使用 deprecated API。

---

### 7. 开发建议（来自需求提出者）

1. **数据结构设计**：建议将 `content` 字段设计为纯文本，同时保留结构化数据在 `rawData` 中，便于后续扩展（如点击显示详情）。合并事件应单独处理，避免丢失原始信息。
2. **合并策略**：定义清晰的合并规则，并在日志模块中实现合并检测函数。可考虑将合并功能设为可配置（是否开启）。
3. **筛选分类**：为每个事件预先分配 `category`，避免筛选时动态判断类型，提高性能。
4. **主题切换**：使用 CSS 变量定义颜色，通过切换根节点类名实现主题变更。
5. **回合分组 UI**：可使用 `:style` 或 `:class` 为每个回合的第一个日志添加特殊样式（如顶部边距和背景色），或使用伪元素标识。
6. **清空日志**：清空后应重置回合计数，并通知战斗系统（如重置日志模块状态）。
