## 1. 背景与目标

### 1.1 背景

太初道枢按四大模块组织：封神榜（数据根源）→ 唤灵台（阵容战斗）→ 演劫台（游戏模块）→ 昊天镜（战斗分析）。依据《太初道枢总体设计.md》9.3 界面调整要求：顶部改为**模块 Tab 导航**（标题改「太初道枢」、唤灵台为默认模块），各模块界面与操作入口按归属收敛。

本次开发聚焦其中两个模块：

- **昊天镜**：战斗调试、回放与分析中心（照彻每一场战局）；
- **封神榜**：游戏数据后台管理（编定一切游戏法则）。

### 1.2 目标

1. 按用户提供的示例 HTML 的**功能清单与界面布局**完成两模块开发；
2. 两模块与唤灵台（现有主界面）以模块 Tab 并列共存，切换保活；
3. 数据闭环打通：封神榜数据 → 唤灵台/演劫台消费；唤灵台战局 → 昊天镜回放分析；昊天镜结论 → 封神榜调参。

### 1.3 非目标（本次不做）

- 演劫台（游戏模块）开发；
- 网络同步 / 多端联机；
- 表达式引擎动态解析公式（封神榜增强项，后续迭代）。

- 封神榜数据先落 IndexedDB，`configs/` JSON 作为**初始种子数据**在首次启动导入（保留文件手工维护能力）。

## 3. 总体技术方案

### 3.1 模块化框架（两模块共同底座）

改造 `BattleArena.vue`（M1 第一步，落实 9.3）：

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：太初道枢 | [封神榜][唤灵台][演劫台][昊天镜] | 操作按钮    │
├────────────────────────────────────────────────────────────┤
│ 内容区按 Tab 切换（v-show 保活）：                            │
│   唤灵台 = 参战 + 战场 + 监控 + 控制栏（默认）                │
│   昊天镜 = BattleAnalysisView（回放 + 调试日志 + 监控…）       │
│   封神榜 = 数据管理后台页面                                    │
│   演劫台 = 占位（规划中）                                     │
└────────────────────────────────────────────────────────────┘
```

- 顶栏操作按钮按模块收敛：封神榜（角色编辑/图鉴/场景管理…）、唤灵台（战斗规则）、昊天镜（调试控制/数据快照/战斗记录…）；
- `v-show` 保活，切 Tab 不销毁战场状态。

### 3.2 数据层

- **封神榜**：IndexedDB DB_VERSION 1 → 2，新增 store（actors/skills/buffs/enemies/scenes/formations/lineups/materials/meta），`onupgradeneeded` 迁移脚本（保留 recordings/snapshots）；提供 Promise 数据访问 API + `dataVersion` 版本戳 + 战斗快照生成器；
- **昊天镜**：读取 recordings/snapshots store，经 `ReplayEngine`/日志解析渲染，与战斗发生时数据一致（快照优先）。

### 3.3 分层

| 层 | 昊天镜 | 封神榜 |
| -- | ------ | ------ |
| presentation | BattleAnalysisView + 子组件（按示例 HTML 布局） | 后台管理页面（列表/表单/数据包/健康检查/操作日志） |
| application | 回放/分析用例编排（复用 BattleProjection） | 数据访问 API、校验服务、导入导出用例 |
| domain | 复用 replay/logs/combat-record | 数据实体类型与校验规则 |
| infrastructure | 复用 BattleLogManager/TriggerEventBus | IndexedDB v2 存储 + 迁移脚本 |

```
M0 前置 ── 示例 HTML 到位 → BattleArena 模块化 Tab（标题/导航/按钮收敛）
```

- 每里程碑结束做一次 `npm run typecheck` + `npm run test` + 手测。

## 7. 风险与注意事项

| 风险 | 应对 |
| ---- | ---- |
| 示例 HTML 与现有组件布局差异较大 | 示例到位后先做差异对照表，明确"沿用现有 / 按示例重做" |
| 对话框 → 页面化迁移的状态与生命周期（v-show 保活） | 复用全局 Store（battleStore/debugStore），组件不持有战斗状态 |
| GameDataProcessor 显式静态导入 configs | lineups 等新配置需显式 import 并在类型契约中补齐 |
| 场景难度结构变更（enemyIds/lineupId）影响现有读取逻辑 | 兼容优先：`enemyIds` 缺省时回退 `lineupId` 展开，双形态解析 |
| IndexedDB 迁移失败导致旧数据丢失 | 迁移脚本幂等 + 迁移前自动导出备份（封神榜数据包） |
| 封神榜 CRUD 与 configs 种子数据同步 | 首次启动导入种子；后续以 IndexedDB 为准，configs 仅作种子源 |
