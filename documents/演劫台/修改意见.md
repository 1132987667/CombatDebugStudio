### 3.2 装备穿戴（含对比可视化）

**操作路径**：
1. 点击背包中的装备卡片 → 打开 `ItemDetailDrawer`
2. 详情区显示：
   - 基础属性（如攻击 +15）
   - **当前已装备的同部位装备**（若存在）：名称 + 属性值
   - **差值可视化**：绿色向上箭头（↑+10）或红色向下箭头（↓-5）
3. 点击「穿戴」：
   - 若槽位为空：直接穿上，背包减少 1 件
   - 若槽位有装备：旧装备卸下放入背包，新装备穿上
4. 穿戴成功后：
   - 通知「已装备 玄铁剑」
   - 抽屉底部出现「前往装备面板查看」按钮（点击切换至装备 Tab）
   - 背包列表自动刷新（移除已穿戴物品）

**差值可视化规则**：
- 对于每个属性（攻击/防御/速度），计算新装备 - 旧装备
- 正数：绿色 + 向上箭头 ↑
- 负数：红色 + 向下箭头 ↓
- 零：灰色 「—」
- 显示格式：`攻击 +15 → +5（↑+10）`

**数据流**：
```
点击「穿戴」→ packStore.wearItem(itemId, slot)
  → 调用 equipStore.wear(itemId)
    → equipStore 检查当前槽位
    → 若有旧装备，调用 packStore.addItem(oldItemId)
    → 调用 packStore.removeItem(itemId)
    → 更新 equipStore.slots[slot] = newItem
    → 触发 battleStore 属性重算（属性变更事件）
    → 持久化保存 equipStore + packStore
  → 通知成功
  → 可选：切换 Tab 到装备面板
```

### 3.3 坊市购买（含批量、刷新、限购）

**操作路径**：
1. 进入坊市页签，商品列表加载
2. 每个商品行显示：名称、类型、单价、库存、限购标签（「每日限购 3」）
3. 玩家选择数量（默认 1，点击 +/- 或手动输入）
4. 点击「购买」：
   - 前置校验：货币 ≥ 单价 × 数量；背包有足够空间
   - 若商品为限购，检查今日已购次数 < 限购数
   - 若库存不足，提示「库存不足」
5. 校验通过：
   - 扣除货币，增加背包物品
   - 若限购，记录今日购买次数（持久化）
   - 更新商品库存（若非无限）
   - 通知「购买成功，获得 灵石 ×10」

**坊市刷新机制**：
- 每个商品可独立设置 `resetType`：`'daily'`、`'weekly'`、`'never'`
- 所有限购商品在重置时恢复库存和购买次数
- 界面顶部显示距离下次重置的倒计时（如「距刷新还有 12:34:56」）
- 手动刷新按钮：消耗 10 灵石，冷却 10 分钟，立即重置所有限购商品（需策划确认是否允许）

**数据流**：
```
购买请求 → packStore.buyShopGood(goodId, quantity)
  → 检查货币、背包容量、限购、库存
  → 扣除货币 (playerStore)
  → 增加背包物品 (packStore.addItem)
  → 若限购，记录今日购买次数 (packStore.shopPurchaseHistory)
  → 减少库存 (shopGoods 中该商品 stock--)
  → 持久化保存 packStore + playerStore + shopHistory
  → 通知成功
```

### 3.4 仓库存取（含扩容规则）

**操作路径**：
1. 点击仓库格子：
   - **空且未锁定**：弹出「存入」对话框，显示背包物品列表供选择
   - **有物品**：弹出「取出」对话框，可选择部分或全部取出
   - **锁定**：提示「需灵石扩容解锁」
2. 存入/取出操作：选择数量，确认后执行
3. 底部「扩容」按钮：
   - 显示当前扩容消耗（灵石）和下一档消耗预览
   - 点击消耗灵石，增加 4 个新格子（一排）
   - 扩容消耗递增：50 → 100 → 200 → 400 → 800 …（可配置）
   - 扩容后格子立即显示为空位，响应式更新

**数据流**：
```
存入：packStore.moveToStorage(itemId, count)
  → packStore.removeItem(itemId, count)
  → storage[index] = { itemId, count }
  → 持久化保存

取出：packStore.moveToPack(storageIndex, count)
  → storage[index].count -= count（若为0则清空）
  → packStore.addItem(itemId, count)
  → 持久化保存

扩容：packStore.expandStorage()
  → 检查 playerStore.jade >= cost
  → 扣除灵石，新增 4 个空位（{ itemId: null, count: 0, locked: false }）
  → 持久化保存
```


## 五、数据持久化策略

### 5.1 触发时机

- **自动保存**：每次 `addItem`、`removeItem`、`moveToStorage`、`moveToPack`、`buyGood`、`expandStorage` 操作完成后，立即触发持久化
- **定期保存**：每 30 秒自动保存一次（防意外丢失）
- **退出保存**：页面卸载前（`beforeunload` 事件）强制保存

### 5.2 存储方式

- 使用 `persistentStorage`（IndexedDB）存储快照
- Key 固定为 `'pack:state'`
- 快照包含 `version` 字段，用于未来数据迁移

### 5.3 保存失败处理

- 保存失败时，调用 `notificationStore.toast('数据保存失败，请检查存储空间', 'error')`
- 本地状态保持不变，允许玩家继续操作，但会持续重试保存（最多 3 次）

### 5.4 启动加载

- 页面加载时，优先读取 IndexedDB 中的 `pack:state`
- 若无存档，从 `configs/xiyou/items.json` 生成初始背包物品（如初始丹药、少量材料）
- 若存档版本低于当前版本，执行迁移逻辑（`migratePackState`）

**交互流程**：

```

    │
    ▼

    │
    ├── 点击快捷格中的物品
    │       │
    │       ▼
    │   确认使用（无需二次确认，战斗中节奏优先）
    │       │
    │       ├── 消耗品（丹药/符箓）
    │       │   ├── 数量 −1
    │       │   ├── 效果生效 → BattleService 注入 BuffSystem
    │       │   │   ├── 回复丹 → requestHeal(targetId, value)
    │       │   │   ├── 符箓·护体 → addBuff(targetId, 'buff_shield_talisman')
    │       │   │   └── 解毒散 → cleanse(targetId, ['poison'])
    │       │   └── 消耗 1 个行动回合（通过 BattleService 标记）
    │       │
    │       ├── 永久丹药
    │       │   ├── 数量 −1
    │       │   ├── 永久属性提升 → setAttributeBase + recalcAll
    │       │   └── 不消耗行动回合
    │       │
    │       └── 晶球
    │           ├── 数量 −1
    │           ├── 打开晶球 → 随机获得物品入背包
    │           └── 不消耗行动回合
    │
    ├── 点击背包消耗品列表中的物品
    │       → 装入空快捷格（若已满则替换选中格）
    │
    └── 点击 [×] 或浮层外 → 关闭浮层
```

**行动回合消耗规则**：

| 物品类型 | 消耗回合 | 理由 |
|----------|----------|------|

| 符箓 | 是 | 等价于一次行动 |
| 永久丹药 | 否 | 场外使用 |
| 晶球 | 否 | 非战斗行为 |

## 九、性能方案

### 9.1 虚拟滚动

背包物品网格（可能 100+ 条目）采用虚拟滚动：

```typescript
// 复用 haotian 模块的 useVirtualList composable 模式
const { scrollRef, visible, measure, offsetOf, totalHeight } = useVirtualList({
  items: () => filteredItems.value,
  estimate: 72,   // 单行卡片预估高度
  gap: 8,
  padding: 8,
})
```

触发条件：`filteredItems.length > 50` 时启用，否则普通渲染。

### 9.2 防抖与节流

| 操作 | 策略 | 延迟 |
|------|------|------|
| 搜索输入 | 防抖 | 300ms |
| IDB 写入 | 防抖 | 500ms |
| 排序切换 | 即时 | 0 |
| 批量操作 | 即时 | 0 |

### 9.3 渲染优化

- 物品卡片使用 `v-memo="[item.count, item.rarity, selected]"` 减少无效重渲染
- 品质色通过 CSS 变量（`--r-color`）切换，不触发重排
- 详情弹窗使用 `<Teleport to="body">` + `v-if`（非 `v-show`），关闭时销毁 DOM

## 十一、状态管理（packStore Actions）

| Action | 触发 | 副作用 |
|--------|------|--------|
| `useItem(itemId, count)` | 使用物品 | 数量 −N；效果生效；toast |
| `addItem(itemId, count)` | 获得物品 | 数量 +N；IDB 写入 |
| `discardItem(itemId, count)` | 丢弃物品 | 数量 −N；toast |

| `moveToInventory(slotIdx, count)` | 取回背包 | 仓库 −N；背包 +N；toast |
| `expandStorage()` | 扩容 | 灵石扣减；capacity +6；toast |
| `purchase(goodId, count)` | 购买商品 | 货币扣减；库存 −N；背包 +N；toast |
| `setQuickSlot(slotIdx, itemId)` | 设置快捷栏 | quickSlots 更新；IDB 写入 |
| `useInBattle(slotIdx)` | 战斗中使用 | 数量 −1；效果注入 BattleService；回合标记 |

## 十二、边界与异常处理

| 场景 | 处理 |
|------|------|
| 背包为空 | EmptyState "行囊空空如也，去战斗获取物资吧" |
| 搜索无结果 | EmptyState "未找到「关键词」相关物品" + [清除搜索] |
| 仓库已满时存入 | toast 警告 + [扩容] 快捷入口 |
| 货币不足购买 | 购买按钮禁用 + 红色差额提示 |
| 库存为 0 | 商品行 opacity 0.5 + "已售罄" 标签 |
| 限购已满 | "已达上限" 标签替代购买按钮 |
| 丢弃任务物品 | 按钮禁用 + tooltip "任务物品不可丢弃" |
| 使用数量为 0 | 使用按钮禁用 |
| 战斗中非消耗品 | 快捷栏不显示非消耗品 |
| IDB 写入失败 | console.error + 内存状态不回滚（下次重试） |
| items.json 加载失败 | 兜底空数组 + EmptyState |
| 永久丹药在非战斗态使用 | 直接生效（无需战斗） |
| 回复丹在非战斗态使用 | 按钮禁用 + 提示"仅战斗中可用" |
