﻿﻿﻿﻿﻿﻿﻿### 3.2 装备穿戴（含对比可视化）

**操作路径**：
1. 点击背包中的装备卡片 → 打开 `ItemDetailDrawer`
2. 详情区显示：
   - 基础属性（如攻击 +15）
   - **当前已装备的同部位装备**（若存在）：名称 + 属性值
   - **差值可视化**：绿色向上箭头（↑+10）或红色向下箭头（↓-5）
3. 点击「穿戴」：
   - 若槽位为空：直接穿上，背包减少 1 件
   - 若槽位有装备：旧装备卸下放入背包，新装备穿上
4. 穿戴成功后：
   - 通知「已装备 玄铁剑」
   - 抽屉底部出现「前往装备面板查看」按钮（点击切换至装备 Tab）
   - 背包列表自动刷新（移除已穿戴物品）

**差值可视化规则**：
- 对于每个属性（攻击/防御/速度），计算新装备 - 旧装备
- 正数：绿色 + 向上箭头 ↑
- 负数：红色 + 向下箭头 ↓
- 零：灰色 「—」
- 显示格式：`攻击 +15 → +5（↑+10）`

**数据流**：
```
点击「穿戴」→ packStore.wearItem(itemId, slot)
  → 调用 equipStore.wear(itemId)
    → equipStore 检查当前槽位
    → 若有旧装备，调用 packStore.addItem(oldItemId)
    → 调用 packStore.removeItem(itemId)
    → 更新 equipStore.slots[slot] = newItem
    → 触发 battleStore 属性重算（属性变更事件）
    → 持久化保存 equipStore + packStore
  → 通知成功
  → 可选：切换 Tab 到装备面板
```

### 3.3 坊市购买（含批量、刷新、限购）

**操作路径**：
1. 进入坊市页签，商品列表加载
2. 每个商品行显示：名称、类型、单价、库存、限购标签（「每日限购 3」）
3. 玩家选择数量（默认 1，点击 +/- 或手动输入）
4. 点击「购买」：
   - 前置校验：货币 ≥ 单价 × 数量；背包有足够空间
   - 若商品为限购，检查今日已购次数 < 限购数
   - 若库存不足，提示「库存不足」
5. 校验通过：
   - 扣除货币，增加背包物品
   - 若限购，记录今日购买次数（持久化）
   - 更新商品库存（若非无限）
   - 通知「购买成功，消耗 金钱 × 数量」

**坊市刷新机制**：
- 每个商品可独立设置 `resetType`：`'daily'`、`'weekly'`、`'never'`
- 所有限购商品在重置时恢复库存和购买次数
- 界面顶部显示距离下次重置的倒计时（如「距刷新还有 12:34:56」）
- 手动刷新按钮：消耗 一定数量金钱，再次刷新所需金钱x2，立即重置所有限购商品（需策划确认是否允许）

**数据流**：
```
购买请求 → packStore.buyShopGood(goodId, quantity)
  → 检查货币、背包容量、限购、库存
  → 扣除货币 (playerStore)
  → 增加背包物品 (packStore.addItem)
  → 若限购，记录今日购买次数 (packStore.shopPurchaseHistory)
  → 减少库存 (shopGoods 中该商品 stock--)
  → 持久化保存 packStore + playerStore + shopHistory
  → 通知成功
```

### 3.4 仓库存取（多仓库：可材料建造、可改名、每仓独立扩容）

仓库模型从「单仓 + 格子扩容」升级为**可建造多座仓库**（上限 5 座）：刷宝玩法下不同类物品（药材 / 材料 / 装备 / 收藏）分仓存放，避免一仓塞满就全线告急。

**操作路径**：
1. 仓库页顶部为**仓库切换条**：每座仓库一个页签（仓名 + 已用/容量），点击切换当前仓；另有 [建造仓库] / [改名] 按钮
2. 点击当前仓格子：
   - **空格**：弹出「存入」对话框，显示背包物品列表供选择（存入当前仓）
   - **有物品**：弹出「仓库物品」对话框，可选 [取回背包] 或 [转移到其他仓]（TacticalSelect 选目标仓）
3. [建造仓库]：显示下一座建造成本（材料清单）与上限提示，材料不足置灰；点击后 **ConfirmDialog 二次确认**（材料为不可逆消耗），确认后新仓自动成为当前仓
4. [改名]：Dialog 输入仓名（trim 后非空、上限 8 字、**不与其他仓重名**）
5. [扩容]（作用于**当前仓**）：显示该仓下一次扩容消耗（金钱）；点击后 **ConfirmDialog 二次确认**（金钱为不可逆消耗），确认后扣钱，该仓 +6 格
   - 扩容消耗递增：50 → 100 → 200 → 400（可配置）
   - 单仓上限 36 格（初始 12 + 最多 4 次扩容），**每座仓库各自独立扩容**
6. 背包侧 [存入仓库]：单仓时直接存入；**多仓时先弹「目标仓选择」**（列出各仓名与剩余空位，已满仓库置灰不可选）——这是"不同物品放不同仓"的主路径

**数据流**：
```
存入仓库：packStore.moveToStorage(itemId[, warehouseId])
  → 目标仓首个空位 = { itemId, count }（整组存入；缺省 warehouseId = 当前仓）
  → 多仓时由 UI 弹目标仓选择后传入 warehouseId（单仓直接透传当前仓）
  → 背包删除该物品
  → 持久化保存

取回背包：packStore.moveToInventory(slotIdx[, warehouseId])
  → 该格清空，数量回背包
  → 持久化保存

仓库间直接转移：packStore.transferWarehouseItem(fromId, slotIdx, toId)
  → 目标仓首个空位 = 源格 { itemId, count }（整格转移）
  → 源格清空；目标仓满 / 同仓 / 非法仓则拒绝
  → 持久化保存

建造：packStore.buildWarehouse()
  → 校验上限（5 座）与材料（buildCost()）
  → 扣除材料，push 新仓（12 格空仓），切换为当前仓
  → 持久化保存

改名：packStore.renameWarehouse(id, name)
  → trim 后非空，超长截断 8 字

扩容：packStore.expandStorage([warehouseId])
  → 检查 currency.money >= expandCost(warehouseId)
  → 扣除金钱，该仓 +6 格（单仓上限 36）
  → 持久化保存
```

**建造成本（递增，源自 `configs/xiyou/pack.json` → `warehouseBuild.levels`）**：

| 目标座数 | 材料消耗 |
|---------|---------|
| 第 2 座 | 桃木 ×20、粗石 ×10 |
| 第 3 座 | 桃木 ×40、粗石 ×20、铜精 ×10 |
| 第 4 座 | 松木 ×40、铁精 ×20、铜精 ×20 |
| 第 5 座 | 松木 ×80、铁精 ×40、玄铁 ×5 |


## 五、数据持久化策略

### 5.1 触发时机

- **自动保存**：每次 `addItem`、`removeItem`、`moveToStorage`、`moveToInventory`、`buildWarehouse`、`transferWarehouseItem`、`renameWarehouse`、`expandStorage`、购买等操作完成后，防抖 500ms 触发持久化
- **退出保存**：页面卸载前（`beforeunload` 事件）强制保存

### 5.2 存储方式

- 使用 `persistentStorage`（IndexedDB）存储快照
- 落库位置：封神榜 `xiyou` 表，文档 id 固定为 `pack_runtime`
- 快照包含 `version` 字段，用于数据迁移；**当前版本 `PACK_SNAPSHOT_VERSION = 7`**
- v7 快照的仓库结构为多仓嵌套（替代 v6 及更早的扁平单仓 `storage`）：

```ts
{
  version: 7,
  inventory: Record<string, number>,     // 背包（非装备按 id 计数）
  warehouses: Array<{                    // 多仓库：slots 长度即该仓容量
    id: string                           // 首仓固定 'wh_main'
    name: string
    slots: Array<{ itemId: string | null; count: number }>
  }>,
  activeWarehouseId: string,             // 当前操作仓（失效时回退首仓）
  quickSlots: (string | null)[],
  currency: { money: number; xianyuan: number },
  // …装备实例 / 穿戴 / 药园 / 坊市等字段
}
```

### 5.3 保存失败处理

- 保存失败时，调用 `notificationStore.toast('行囊数据保存失败', 'error')`
- 本地状态保持不变，允许玩家继续操作

### 5.4 启动加载

- 页面加载时，优先读取 IndexedDB 中的 `pack_runtime`
- 若无存档，从 `configs/xiyou/pack.json` 生成初始背包与**首仓 `wh_main`**（12 格，含 storageCells 初始物资）
- 若存档版本低于当前版本，执行迁移逻辑：
  - **v6 → v7**：旧档的扁平 `storage` 数组包裹为 `warehouses[0]`（`id = 'wh_main'`、`name = '主仓库'`）；快照已带 `warehouses` 则不重复包裹（幂等）

### 3.1 战斗中使用物品 — 快捷栏

**入口**：战斗禅台（BattleZen）底部技能灵台右侧，新增「行囊」按钮（SVG 包袱图标），点击弹出快捷栏浮层。

```
┌─────────────────────────────────────────────┐
│  快捷栏（最多 4 格）                    [×]  │
│                                             │
│  [格1:回复丹×3] [格2:解毒散×1] [格3:空] [格4:空] │
│                                             │
│  ── 背包消耗品（点击装入快捷栏）──           │
```

**交互流程**：

```
战斗中点击「行囊」按钮
    │
    ▼
弹出快捷栏浮层（不暂停战斗，overlay 半透明）
    │
    ├── 点击快捷格中的物品
    │       │
    │       ▼
    │   确认使用（无需二次确认，战斗中节奏优先）
    │       │
    │       ├── 消耗品（丹药/符箓）
    │       │   ├── 数量 −1
    │       │   ├── 效果生效 → BattleService 注入 BuffSystem
    │       │   │   ├── 回复丹 → requestHeal(targetId, value)
    │       │   │   ├── 符箓·护体 → addBuff(targetId, 'buff_shield_talisman')

    │       │
    │       ├── 永久丹药
    │       │   ├── 数量 −1
    │       │   ├── 永久属性提升 → setAttributeBase + recalcAll
    │       │   └── 不消耗行动回合
    │       │
    │       └── 晶球
    │           ├── 数量 −1
    │           ├── 打开晶球 → 随机获得物品入背包
    │           └── 不消耗行动回合
    │
    ├── 点击背包消耗品列表中的物品
    │       → 装入空快捷格（若已满则替换选中格）
    │
    └── 点击 [×] 或浮层外 → 关闭浮层
```

**行动回合消耗规则**：

| 物品类型 | 消耗回合 | 理由 |
|----------|----------|------|

| 符箓 | 是 | 等价于一次行动 |
| 永久丹药 | 否 | 场外使用 |
| 晶球 | 否 | 非战斗行为 |

```
    │   上限 = min(库存, floor(余额 / 单价))
    │
    ├── 总价实时计算：单价 × 数量
    │
    ├── 余额校验（实时）
    │   ├── 足够 → [确认购买] 可点击（primary 色）
    │   └── 不足 → [确认购买] 禁用 + 红色文字 "差额 XXX"
    │
    ▼
点击 [确认购买]
    │
    ├── 成功
    │   ├── 货币扣减（数字滚动动画 400ms）
    │   ├── 库存 −N
    │   ├── 背包物品 +N（packStore.addItem）
    │   ├── toast "购买了 回复丹 ×2"
    │   └── 购买区收起
    │
    └── 失败
        ├── 库存不足 → toast "库存不足"
        ├── 余额不足 → toast "余额不足"
        └── 限购已满 → toast "已达购买上限"
```

### 6.3 背包 ⇄ 仓库 / 仓库 ⇄ 仓库 转移

```
切换当前仓：仓库页顶部切换条点击页签 → switchActiveWarehouse(id)

方式一：背包物品详情/右键 [存入仓库]
        ├── 单仓 → 直接存入当前仓
        └── 多仓 → 弹「目标仓选择」（各仓名 + 剩余空位，满仓置灰）→ 选定后存入
方式二：仓库页点击空格 → 弹出背包物品选择列表（存入当前仓）→ 确认
方式三：仓库页点击有物品的格子 → 弹出「仓库物品」对话框
        ├── [取回背包] → moveToInventory(slotIdx, 当前仓)
        └── [转移到其他仓] → 选择目标仓（多仓时显示 TacticalSelect）
              ├── 目标仓有空位 → transferWarehouseItem(fromId, slotIdx, toId) → toast
              └── 目标仓已满 → toast "「XX」已满，无法转移"（源格保持不动）
```

### 6.4 仓库建造与扩容

```
建造（仓库页顶栏 [建造仓库]）
    │
    ▼
展示下一座材料清单（buildCost()）；已达 5 座上限 → 按钮禁用
    │
    ▼
ConfirmDialog "消耗 桃木×20 + 粗石×10 建造一座新仓库？"（材料不可逆消耗）
    │
    ├── 确认 + 材料足够 → 扣除材料 → push 新仓（12 格空仓）→ 自动切换为当前仓 → toast
    └── 材料不足 → toast "材料不足：缺「XX」×N"（不扣料）

扩容（仓库页顶栏 [扩容]，作用于当前仓）
    │
    ▼
ConfirmDialog "消耗 金钱 ×50 扩容 6 格？"
    │
    ├── 金钱足够 → 扣减 → 该仓 slots +6 → 新格子入场动画
    └── 金钱不足 → toast "金钱不足"

每座仓库独立扩容，单仓上限 36 格（初始 12 + 最多扩容 4 次 × 6 格）。
扩容消耗按「该仓已扩容次数」取档：50 → 100 → 200 → 400（第 4 档封顶）。
建造上限：5 座（configs/xiyou/pack.json → warehouseBuild.maxCount）。
```

### 6.5 搜索与排序

```
搜索：
├── 输入框在二级 Tabs 右侧
├── 300ms 防抖
├── 匹配范围：name + description + type
└── 空结果 → EmptyState "未找到「关键词」相关物品"

排序（TacticalSelect 下拉）：
├── 默认（按 type 分组）
├── 品质降序
├── 品质升序
├── 名称
└── 数量降序
```

### 6.6 批量操作

```
背包页长按/右键物品卡片 → 进入多选模式
    │
    ├── 底部浮出操作栏：[批量存入仓库] [批量丢弃] [取消]
    │
    ├── [批量存入仓库]
    │   ├── 仓库空位 ≥ 选中数 → 全部转移 → toast
    │   └── 空位不足 → 转移前 N 个 → toast "部分存入，仓库已满"

```

## 九、性能方案

### 9.1 虚拟滚动

背包物品网格（可能 100+ 条目）采用虚拟滚动：

```typescript
// 复用 haotian 模块的 useVirtualList composable 模式
const { scrollRef, visible, measure, offsetOf, totalHeight } = useVirtualList({
  items: () => filteredItems.value,
  estimate: 72,   // 单行卡片预估高度
  gap: 8,
  padding: 8,
})
```

触发条件：`filteredItems.length > 50` 时启用，否则普通渲染。

### 9.2 防抖与节流

| 操作 | 策略 | 延迟 |
|------|------|------|
| 搜索输入 | 防抖 | 300ms |
| IDB 写入 | 防抖 | 500ms |
| 排序切换 | 即时 | 0 |
| 批量操作 | 即时 | 0 |

### 9.3 渲染优化

- 物品卡片使用 `v-memo="[item.count, item.rarity, selected]"` 减少无效重渲染
- 品质色通过 CSS 变量（`--r-color`）切换，不触发重排
- 详情弹窗使用 `<Teleport to="body">` + `v-if`（非 `v-show`），关闭时销毁 DOM

## 十一、状态管理（packStore Actions）

| Action | 触发 | 副作用 |
|--------|------|--------|
| `useItem(itemId, count)` | 使用物品 | 数量 −N；效果生效；toast |
| `addItem(itemId, count)` | 获得物品 | 数量 +N；IDB 写入 |
| `discardItem(itemId, count)` | 丢弃物品 | 数量 −N；toast |
| `moveToStorage(itemId, warehouseId?)` | 存入仓库 | 背包清空该物品；目标仓（缺省=当前仓）首个空位 +N；toast |
| `moveToInventory(slotIdx, warehouseId?)` | 取回背包 | 该仓指定格清空；背包 +N；toast |
| `transferWarehouseItem(fromId, slotIdx, toId)` | 仓库间直接转移 | 目标仓首个空位接收整格；源格清空；目标仓满/同仓/非法仓则拒绝 |
| `buildCost()` | 建造成本查询 | 返回下一座材料清单（`XiyouRecipeMaterial[]`）；已达上限返回 `null` |
| `buildWarehouse()` | 建造仓库 | 校验上限 + 材料；扣料；push 新仓（12 格）；切换为当前仓；toast |
| `switchActiveWarehouse(id)` | 切换当前仓 | `activeWarehouseId` 更新（id 不存在返回 false） |
| `renameWarehouse(id, name)` | 仓库改名 | trim 非空、截断 8 字；IDB 写入 |
| `expandCost(warehouseId?)` | 扩容成本查询 | 按该仓已扩容次数返回档位金额（默认 50/100/200/400） |
| `expandStorage(warehouseId?)` | 扩容当前仓 | 金钱扣减；该仓 slots +6（上限 36）；toast |
| `purchase(goodId, count)` | 购买商品 | 货币扣减；库存 −N；背包 +N；toast |
| `setQuickSlot(slotIdx, itemId)` | 设置快捷栏 | quickSlots 更新；IDB 写入 |
| `useInBattle(slotIdx)` | 战斗中使用 | 数量 −1；效果注入 BattleService；回合标记 |

## 十二、边界与异常处理

| 场景 | 处理 |
|------|------|
| 背包为空 | EmptyState "行囊空空如也，去战斗获取物资吧" |
| 搜索无结果 | EmptyState "未找到「关键词」相关物品" + [清除搜索] |
| 全部仓库已满时存入 | toast 警告 + 详情内 [仓库已满 · 扩容] 快捷入口 + 引导扩容/建造新仓 |
| 建造材料不足 | toast "材料不足：缺「XX」×N"，不扣料、不新增仓（按钮已置灰，另有二次确认兜底） |
| 仓库已达 5 座上限 | [建造仓库] 禁用 + toast "仓库已达上限（5 座）" |
| 目标仓已满时转移 | toast "「XX」已满，无法转移"，源格保持不动 |
| 目标仓与源仓相同 | 直接拒绝（不产生操作、无 toast） |
| 仓库改名为空 | 拒绝（trim 后非空校验），保持原名 |
| 扩容已达单仓上限 36 | toast "仓库已达上限"，不扣金钱 |
| 货币不足购买 | 购买按钮禁用 + 红色差额提示 |
| 库存为 0 | 商品行 opacity 0.5 + "已售罄" 标签 |
| 限购已满 | "已达上限" 标签替代购买按钮 |
| 丢弃任务物品 | 按钮禁用 + tooltip "任务物品不可丢弃" |
| 使用数量为 0 | 使用按钮禁用 |
| 战斗中非消耗品 | 快捷栏不显示非消耗品 |
| IDB 写入失败 | console.error + 内存状态不回滚（下次重试） |
| items.json 加载失败 | 兜底空数组 + EmptyState |
| 永久丹药在非战斗态使用 | 直接生效（无需战斗） |
| 回复丹在非战斗态使用 | 按钮禁用 + 提示"仅战斗中可用" |
