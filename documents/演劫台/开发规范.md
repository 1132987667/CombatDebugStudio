# 斗战西游开发规则说明

> **文档性质**：开发约束规范——斗战西游模块开发期间必须遵循的强制规则与禁止事项。
> **适用范围**：`src/presentation/modules/yanjie/games/xiyou/`、`configs/xiyou/`、封神榜 `xiyou` 数据域相关改动。
> **前置阅读**：《ONBOARDING.md》（架构总览）、《统一战斗系统文档.md》（战斗规则最终裁决）、《演劫台需求整合规格.md》（需求来源）、《西游斗战.md》（游戏蓝本）。

---

## 一、架构约束

### 1.1 分层依赖方向（不可逆）

```
presentation（UI）→ application（编排）→ domain（引擎）→ infrastructure（基础设施）
```

- 斗战西游的 UI 组件**只允许**依赖 `application/` 层提供的服务接口。
- **禁止**在 `games/xiyou/` 内直接 import `domain/battle/`、`domain/buff/`、`domain/skill/` 的内部实现。
- **禁止**在 `games/xiyou/` 内直接操作 IndexedDB，必须经 `GameDataApi` 或封神榜数据服务。

### 1.2 目录归属

| 内容 | 归属目录 | 说明 |
|---|---|---|
| 斗战西游 UI 组件 | `src/presentation/modules/yanjie/games/xiyou/` | 游戏专属，不污染公共组件 |
| 斗战西游配置数据 | `configs/xiyou/*.json` | 种子数据，运行时以 IndexedDB 为权威 |
| 斗战西游数据域 | 封神榜 `xiyou` store | 经 `GameDataApi.listXiyouData` 读取 |
| 共享 UI 组件 | `src/presentation/components/` | Dialog / Tabs / Button 等，不复制 |
| 战斗引擎 | `src/domain/battle/` | **只读消费，禁止修改** |

### 1.3 战斗引擎的使用边界

斗战西游**消费**战斗引擎，**不修改**战斗引擎：

- ✅ 通过 `BattleRuleManager` 配置战斗规则参数（`configs/params/`）
- ✅ 通过 `ParticipantStats.addModifier()` 注入装备/成长属性加成
- ✅ 通过技能配置（`configs/skills/`）定义技能步骤
- ✅ 通过 Buff 配置（`configs/buffs/`）定义状态效果
- ❌ 禁止修改 `DamageCalculator` 的 16 步伤害管线
- ❌ 禁止修改 `TurnManager` 的回合阶段顺序
- ❌ 禁止修改 `BuffSystem` 的叠加/驱散核心逻辑
- ❌ 禁止在 `games/xiyou/` 内 fork 或复制引擎代码

若战斗引擎行为不满足斗战西游需求，应通过以下途径解决：
1. `configs/params/` 调整规则参数
2. 新增 Buff 原子效果（`domain/buff/atomic/effects/`）
3. 新增技能步骤类型（需评审后修改 `SkillExecutor`）
4. 提出引擎扩展点需求，经评审后在引擎层实现

## 二、数据层规则

### 2.1 数据权威源

```
configs/xiyou/*.json（种子）──首次启动导入──▶ IndexedDB xiyou store（运行时唯一权威）
```

- 运行时**禁止**直接读取 `configs/xiyou/` 下的 JSON 文件作为数据源。
- 所有数据读写必须经 `GameDataApi`（Promise 接口）或 `mock.ts` 中的 `loadXiyouData()` 异步加载。
- 修改 `configs/xiyou/` 种子文件后，需重置种子标记或手动触发重新导入。

### 2.2 数据域隔离

- 斗战西游专属数据存入 `xiyou` store，**禁止**写入共享 store（actors / skills / buffs 等）。
- 共享 store 中的数据（如通用技能、通用 Buff）可被斗战西游**读取**，但**禁止**在斗战西游业务逻辑中修改。
- 装备实例数据（强化等级、附魔、词条）存入 `xiyou` store 的装备子域，**不**写入共享 `equipment` store。

### 2.3 引用完整性

- 斗战西游数据引用共享数据时（如技能引用 Buff、装备引用材料），必须确保被引用实体存在。
- 新增数据域字段时，需在封神榜 `REFERENCE_RULES` 中注册引用关系。
- 删除任何实体前，必须检查反向引用。

## 三、斗战西游业务规则

### 3.1 装备系统四维度

装备系统严格按四个独立维度设计，**禁止**混淆：

| 维度 | 含义 | 来源 |
|---|---|---|
| 阶位（凡/玄/地/天/仙） | 决定基础属性区间与成长上限 | 场景材料、关卡进度 |
| 品质（凡/精/超/绝/神） | 决定属性系数与词条数量 | 制造、技艺、特殊材料 |
| 星级（0-3 星） | 提升基础属性，长线追求 | 同名装备消耗 |
| 锻造状态 | 强化等级 / 附魔槽 / 洗练状态 | 玩家后续养成操作 |

### 3.2 数值上限

- 所有战斗相关数值（气血、攻击、防御、伤害）**不得超过 10000**。
- 百分比属性上限：暴击率 ≤ 100%，暴击伤害 ≤ 500%。

### 3.3 回合结算轴（不可乱序）

每回合严格按 5 阶段结算，斗战西游的子系统逻辑**必须**挂载到对应阶段：

| 阶段 | 内容 | 斗战西游挂载点 |
|---|---|---|
| Phase 1 回合开始 | 能量恢复、Buff 递减、DOT 结算 | 装备被动触发、丹药持续效果 |
| Phase 2 行动判定 | 控制判定、速度排序 | 装备速度加成、流派先手被动 |
| Phase 3 行动执行 | 技能释放、伤害结算 | 装备词条触发（暴击/连击） |
| Phase 4 行动后 | 被动触发、反击、吸血 | 套装效果、附魔触发 |
| Phase 5 回合结束 | 状态清理、能量结算 | 装备冷却递减 |

### 3.4 资源闭环

每个物品**必须**至少进入以下一种循环，**禁止**出现"只能卖钱"的材料：

```
制造循环：材料 → 装备制作
强化循环：晶球/异矿/灵水/灵气 → 装备强化
炼丹循环：液体/毒物/灵水 → 丹药合成
任务循环：任务物品 → 奖励
经济循环：杂物/碎银 → 金钱
升星循环：重复装备 → 升星
传说循环：BOSS 专属材料 → 传说装备
```

### 3.5 经济控制

- 强化金钱消耗按阶位递增：凡品 20×等级、玄品 50×等级、地品 100×等级、天品 150×等级、仙品 200×等级。
- 洗练消耗固定 5000 金钱/次。
- 九转金丹背包堆叠上限 5，全存档最多服用 10 颗。
- 天品/仙品装备**不可**传承。

## 四、UI / UX 规则

### 4.1 水墨风格强制约束

- **禁止**使用任何形式的图片、图标、特殊字体。
- 交互反馈以墨晕、边框变化、淡入淡出为主。

### 4.2 通用 UI 禁止项

- **禁止**使用 emoji（包括装饰性 emoji 和控制类符号 ⏮ ⏪ ▶ ⏸ ⚡ 等）。
- 图标一律使用内联 SVG 线条。
- 文本大小**不得低于** `--font-size-md`。
- 交互元素必须有可见焦点环（2-4px）。
- 图标按钮必须有 `aria-label` 或 `title`。
- 实时内容（战斗日志、toast）使用 `aria-live`。

### 4.3 布局约束

- 斗战西游游戏本体占满演劫台舞台区域（`.yj-game-stage`），内部自包含 flex column。
- 顶部导航栏（`.xy-topbar`）显示：游戏名、货币、当前场景、玩家等级。
- 主体三栏：左侧场景卷轴 / 中央战斗区 / 右侧功能菜单。

## 五、代码规范（石匠守则）

### 5.1 决策阶梯（写代码前必须逐级自问）

1. 这真的需要写吗？（YAGNI）
2. 代码库里是不是已经有了？复用已有的工具/模式，不重写。
3. 标准库能做吗？用它。
4. 原生平台能力够吗？用它。
5. 已安装的依赖能解决吗？用它。
6. 能一行搞定吗？写一行。
7. 只有到这一步：写能工作的最小代码。

### 5.2 强制规则

- **不写没人要求的抽象层。**
- **不引入可避免的新依赖。**
- **不写没人要的样板代码。**
- **删除优先于添加。乏味优先于聪明。最少文件原则。**
- **最短可用 diff 胜出**——但前提是理解了问题。
- **质疑复杂需求**："你真的需要 X 吗，还是 Y 就够了？"
- **所有思考过程必须使用中文。**

### 5.3 Bug 修复原则

- **修根因，不修表象。**
- grep 碰到的函数的**每个调用方**，修共享函数一次。
- 只修报告里提到的那条路径会留下另一个调用方继续坏着。

### 5.4 纯函数测试要求

- 纯函数逻辑（如概率计算、属性换算、品质判定）**必须**留可运行的 Vitest 测试。
- 不用框架 fixture，直接断言输入/输出。
- 新增纯逻辑先写能失败的最小断言，再改实现。

## 六、测试与验收

### 6.1 每阶段闭环验收

| 阶段 | 验收标准 |
|---|---|
| 战斗闭环 | 关卡可推、掉落入账、经验正确 |
| 装备闭环 | 穿戴/强化/附魔/洗练可用，属性正确反映到战斗 |
| 成长闭环 | 升级/技能点/流派选择可用，属性增长正确 |
| 经营闭环 | 制造/炼丹/技艺可用，材料消耗正确 |
| 经济闭环 | 金钱产出/消耗平衡，无通胀漏洞 |

### 6.2 回归护栏

- 每次改动后必须通过：`npm run typecheck` + `npm run test`。
- 涉及数值改动时，必须运行 `node scripts/balance-check.cjs` 确认 TTK 断言通过。
- 涉及战斗逻辑时，必须在唤灵台手动验证一场完整战斗。

### 6.3 禁止的验收方式

- ❌ "看起来没问题"
- ❌ "应该可以"
- ❌ 只测正向路径不测边界

## 七、文件与编码规范

### 7.1 文件编码

- `documents/` 下的 `.md` 文档：**必须 UTF-8 带 BOM**（文件头 `EF BB BF`）。
- `src/` 下的 `.ts` / `.vue` / `.scss` 文件：UTF-8 无 BOM。
- `configs/` 下的 `.json` 文件：UTF-8 无 BOM。
- **禁止**文件编码错乱（乱码）。写文件前确认目标文件编码，写入后保持原样。

### 7.2 命名规范

- 斗战西游专属 ID 前缀：`xiyou_`（如 `xiyou_quest_001`、`xiyou_recipe_zhujian`）。
- 装备实例 ID 前缀：`eq_`。
- 材料 ID 前缀：`mat_`。
- 配方 ID 前缀：`recipe_`。
- 禁止使用拼音缩写、无意义 ID、乱码 ID。

### 7.3 配置数据格式

- `configs/xiyou/` 下每份 JSON 必须包含 `updatedAt` 字段。
- 种子导入幂等标记：`cds:xiyou-seed-v1`。
- 新增配置域时，必须在封神榜 schema 中注册对应的 FieldSchema。

## 八、禁止事项清单（红线）

| # | 禁止事项 | 原因 |
|---|---|---|
| 1 | 修改 `domain/battle/` 核心引擎代码 | 引擎为全游戏共享，改动影响面不可控 |
| 2 | 在斗战西游内 fork 引擎逻辑 | 导致引擎修复无法同步 |
| 3 | 直接读写 IndexedDB（绕过 GameDataApi） | 破坏数据层抽象与版本管理 |
| 4 | 在 UI 组件中硬编码数值 | 数值必须走配置/封神榜，一处定义 |
| 5 | 使用图片、emoji、特殊字体 | 违反水墨风格约束 |
| 6 | 引入新的 npm 依赖（未经评审） | 违反石匠守则 |
| 7 | 跳过 `npm run typecheck` 提交代码 | 类型安全是底线 |
| 8 | 在共享 store 中写入斗战西游专属数据 | 破坏数据域隔离 |
| 9 | 战斗数值超过 10000 | 违反数值上限约束 |
| 10 | 创建"只能卖钱"的物品 | 违反资源闭环原则 |
| 11 | 在 `games/xiyou/` 外创建斗战西游专属文件 | 破坏目录归属 |
| 12 | 复制 `presentation/components/` 的共享组件到游戏目录 | 应直接 import 复用 |

## 九、开发流程

### 9.1 新功能开发步骤

```
1. 阅读需求（西游斗战.md / 设计稿补充-*.md）
2. 确认数据模型（是否需要新增配置域 / store 字段）
3. 确认引擎消费方式（走 params / Buff / 技能步骤 / Modifier）
4. 编写配置数据（configs/xiyou/）
5. 实现 UI 组件（games/xiyou/）
6. 接入数据层（GameDataApi / loadXiyouData）
7. 编写测试（纯函数 + 集成）
8. 运行 typecheck + test + balance-check
9. 手动验收（唤灵台战斗验证）
```

### 9.2 改动前必做

- 读任务、读它碰到的代码、把真实流程从头到尾跟一遍。
- grep 所有调用方，确认影响面。
- 确认改动是否收敛在 `games/xiyou/` 内。

### 9.3 改动后必做

- `npm run typecheck` 零报错
- `npm run test` 全绿
- 涉及数值：`node scripts/balance-check.cjs` 通过
- 涉及 UI：手动检查焦点、对比度、aria 属性

## 十、版本与文档

- 斗战西游当前版本：`0.2.0`（框架展示阶段）。
- 每次功能性改动后，更新 `xiyou.scss` 头部注释中的版本说明。
- 设计决策必须写入 `documents/演劫台/` 对应文档，**禁止**只存在于代码注释中。
- 本文档（开发规则）随项目演进更新，修订时递增版本号并记录变更日志。

> **一句话总结**：斗战西游是战斗引擎的**消费者**，不是修改者；是封神榜数据的**使用者**，不是绕过者；是水墨风格的**表达者**，不是破坏者。所有改动收敛于 `games/xiyou/`，所有数据经 `GameDataApi`，所有数值不超 10000，所有 UI 不用图片。
