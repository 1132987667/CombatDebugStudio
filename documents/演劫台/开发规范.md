# 斗战西游开发规则说明

> **文档性质**：开发约束规范——斗战西游模块开发期间必须遵循的强制规则与禁止事项。
> **适用范围**：`src/presentation/modules/yanjie/xiyou/`、`configs/xiyou/`、封神榜 `xiyou` 数据域相关改动。
> **前置阅读**：《ONBOARDING.md》（架构总览）。
> **权威口径声明**：游戏设计内容（装备四维度、强化/洗练/升星消耗公式、属性上限、物品目录、掉落、资源闭环）一律以《新需求/完整项目说明.md》（下称 PRD）为权威，本文不维护副本；通用工程守则（决策阶梯、最小 diff、bug 修根因、文件编码 BOM 规则、UI 禁 emoji / 字号下限等）以根目录 `AGENTS.md` 为权威，本文同样不重复。

---

## 一、架构约束

### 1.1 分层依赖方向（不可逆）

```
presentation（UI）→ application（编排）→ domain（引擎）→ infrastructure（基础设施）
```

- 斗战西游的 UI 组件**只允许**依赖 `application/` 层提供的服务接口。
- **禁止**在 `xiyou/` 内直接 import `domain/battle/`、`domain/buff/`、`domain/skill/` 的内部实现。
- **禁止**在 `xiyou/` 内直接操作 IndexedDB，必须经 `GameDataApi` 或封神榜数据服务。

### 1.2 目录归属

| 内容 | 归属目录 | 说明 |
|---|---|---|
| 斗战西游 UI 组件 | `src/presentation/modules/yanjie/xiyou/` | 游戏专属，不污染公共组件 |
| 斗战西游配置数据 | `configs/xiyou/*.json` | 种子数据，运行时以 IndexedDB 为权威 |
| 斗战西游数据域 | 封神榜 `xiyou` store | 经 `GameDataApi.listXiyouData` 读取 |
| 共享 UI 组件 | `src/presentation/components/` | Dialog / Tabs / Button 等，不复制 |
| 战斗引擎 | `src/domain/battle/` | **只读消费，禁止修改** |

### 1.3 战斗引擎的使用边界

斗战西游**消费**战斗引擎，**不修改**战斗引擎：

- ✅ 通过 `BattleRuleManager` 配置战斗规则参数（`configs/params/`）
- ✅ 通过 `ParticipantStats.addModifier()` 注入装备/成长属性加成
- ✅ 通过技能配置（`configs/skills/`）定义技能步骤
- ✅ 通过 Buff 配置（`configs/buffs/`）定义状态效果
- ❌ 禁止修改 `DamageCalculator` 的 16 步伤害管线
- ❌ 禁止修改 `TurnManager` 的回合阶段顺序
- ❌ 禁止修改 `BuffSystem` 的叠加/驱散核心逻辑
- ❌ 禁止在 `xiyou/` 内 fork 或复制引擎代码

若战斗引擎行为不满足斗战西游需求，应通过以下途径解决：
1. `configs/params/` 调整规则参数
2. 新增 Buff 原子效果（`domain/buff/atomic/effects/`）
3. 新增技能步骤类型（需评审后修改 `SkillExecutor`）
4. 提出引擎扩展点需求，经评审后在引擎层实现

## 二、数据层规则

### 2.1 数据权威源

```
configs/xiyou/*.json（种子）──首次启动导入──▶ IndexedDB xiyou store（运行时唯一权威）
```

- 运行时**禁止**直接读取 `configs/xiyou/` 下的 JSON 文件作为数据源。
- 所有数据读写必须经 `GameDataApi`（Promise 接口）或 `mock.ts` 中的 `loadXiyouData()` 异步加载。
- 修改 `configs/xiyou/` 种子文件后，需重置种子标记或手动触发重新导入。

### 2.2 数据域隔离

- 斗战西游专属数据存入 `xiyou` store，**禁止**写入共享 store（actors / skills / buffs 等）。
- 共享 store 中的数据（如通用技能、通用 Buff）可被斗战西游**读取**，但**禁止**在斗战西游业务逻辑中修改。
- 装备实例数据（强化等级、词条）存入 `xiyou` store 的装备子域，**不**写入共享 `equipment` store。

### 2.3 引用完整性

- 斗战西游数据引用共享数据时（如技能引用 Buff、装备引用材料），必须确保被引用实体存在。
- 新增数据域字段时，需在封神榜 `REFERENCE_RULES` 中注册引用关系。
- 删除任何实体前，必须检查反向引用。

| 主题 | PRD 锚点 |

PRD 之外、本文单独维护的两条硬口径：

- 九转金丹：背包堆叠上限 5，全存档最多服用 10 颗。
- 天品/仙品装备**不可**传承。

### 回合结算轴（不可乱序）

每回合严格按 5 阶段结算，斗战西游的子系统逻辑**必须**挂载到对应阶段（引擎 `TurnManager` 阶段顺序不可修改，见 §1.3）：

| 阶段 | 内容 | 斗战西游挂载点 |
|---|---|---|
| Phase 1 回合开始 | 能量恢复、Buff 递减、DOT 结算 | 装备被动触发、丹药持续效果 |
| Phase 2 行动判定 | 控制判定、速度排序 | 装备速度加成、流派先手被动 |
| Phase 3 行动执行 | 技能释放、伤害结算 | 装备词条触发（暴击/连击） |
| Phase 4 行动后 | 被动触发、反击、吸血 | 套装效果 |
| Phase 5 回合结束 | 状态清理、能量结算 | 装备冷却递减 |

## 四、UI / UX 规则

通用 UI 禁止项（emoji / 图片 / 特殊字体、`--font-size-md` 字号下限）见 `AGENTS.md`。斗战西游特有补充：

- 交互元素必须有可见焦点环（2-4px）。
- 图标按钮必须有 `aria-label` 或 `title`。
- 实时内容（战斗日志、toast）使用 `aria-live`。

### 布局约束

- 斗战西游游戏本体占满演劫台舞台区域（`.yj-game-stage`），内部自包含 flex column。
- 顶部导航栏（`.xy-topbar`）显示：游戏名、货币、当前场景、玩家等级。
- 主体三栏：左侧场景卷轴 / 中央战斗区 / 右侧功能菜单。

## 五、测试与验收

### 5.1 每阶段闭环验收

| 阶段 | 验收标准 |
|---|---|
| 战斗闭环 | 关卡可推、掉落入账、经验正确 |
| 装备闭环 | 穿戴/强化/洗练可用，属性正确反映到战斗 |
| 成长闭环 | 升级/技能点/流派选择可用，属性增长正确 |
| 经营闭环 | 制造/炼丹/技艺可用，材料消耗正确 |
| 经济闭环 | 金钱产出/消耗平衡，无通胀漏洞 |

### 5.2 回归护栏

- 每次改动后必须通过：`npm run typecheck` + `npm run test`（AGENTS.md 底线）。
- 涉及数值改动时，必须运行 `node scripts/generate-enemy-design.cjs` 确认 TTK 断言通过。
- 涉及战斗逻辑时，必须在唤灵台手动验证一场完整战斗。
- 禁止"看起来没问题 / 应该可以"式验收；只测正向路径不测边界等于没测。

## 六、命名与配置格式

### 6.1 ID 命名

- 静态物品（装备/材料/丹药/图纸/法宝神器等）前缀一律以 PRD「附录 · 物品 ID 命名规范速查」为准，禁止自造。
- PRD 未覆盖的运行时 ID 前缀：
  - 斗战西游专属 ID：`xiyou_`（如 `xiyou_quest_001`、`xiyou_recipe_zhujian`）。
  - 装备实例 ID：`eq_`；配方 ID：`recipe_`。
- 禁止使用拼音缩写、无意义 ID、乱码 ID。

### 6.2 配置数据格式

- `configs/xiyou/` 下每份 JSON 必须包含 `updatedAt` 字段。
- 种子导入幂等标记：`cds:xiyou-seed-v1`。
- 新增配置域时，必须在封神榜 schema 中注册对应的 FieldSchema。

## 七、红线速查（工程侧）

| # | 禁止事项 | 原因 |
|---|---|---|
| 1 | 修改 `domain/battle/` 核心引擎代码，或在游戏内 fork 引擎逻辑 | 引擎为全游戏共享，改动影响面不可控 |
| 2 | 直接读写 IndexedDB（绕过 GameDataApi） | 破坏数据层抽象与版本管理 |
| 3 | 在 UI 组件中硬编码数值 | 数值必须走配置/封神榜，一处定义 |
| 4 | 在共享 store 中写入斗战西游专属数据 | 破坏数据域隔离 |
| 5 | 在 `xiyou/` 外创建斗战西游专属文件 | 破坏目录归属 |
| 6 | 复制 `presentation/components/` 的共享组件到游戏目录 | 应直接 import 复用 |

业务红线（数值上限、资源闭环等）以 PRD 为准，工程守则红线（依赖、编码、验收）以 AGENTS.md 为准，不在此重复。

## 八、开发流程

### 8.1 新功能开发步骤

```
1. 阅读需求（《新需求/完整项目说明.md》及《新需求/》下专题文档）
2. 确认数据模型（是否需要新增配置域 / store 字段）
3. 确认引擎消费方式（走 params / Buff / 技能步骤 / Modifier）
4. 编写配置数据（configs/xiyou/）
5. 实现 UI 组件（xiyou/）
6. 接入数据层（GameDataApi / loadXiyouData）
7. 编写测试（纯函数 + 集成）
8. 运行 typecheck + test + generate-enemy-design
9. 手动验收（唤灵台战斗验证）
```

### 8.2 改动前 / 改动后必做

- 改动前：读任务、读它碰到的代码、把真实流程从头到尾跟一遍；grep 所有调用方确认影响面；确认改动收敛在 `xiyou/` 内。
- 改动后：按 §5.2 回归护栏执行；涉及 UI 时手动检查焦点、对比度、aria 属性。

> **一句话总结**：斗战西游是战斗引擎的**消费者**，不是修改者；是封神榜数据的**使用者**，不是绕过者；是水墨风格的**表达者**，不是破坏者。所有改动收敛于 `xiyou/`，所有数据经 `GameDataApi`，游戏数值口径以 PRD 为权威。
