### P1：最小可玩闭环（1-2 周）

> 原则：先跑通一条完整路径，再扩展宽度。

**选择一条最小闭环**：

```
玩家进入关卡 1（小花山）
→ 击败花妖（掉落桃木×2）
→ 洞府制造竹剑（桃木×3 + 铜精×1）
→ 装备竹剑（攻击+12）
→ 词缀生成（凡品 1 条词条）
→ 强化竹剑（+1，消耗一阶灿金晶球）
→ 再次挑战关卡 1 困难
```

**需要实现的最小代码集**：

| 模块 | 最小实现 | 不做什么 |
|---|---|---|
| 装备数据加载 | 从 equipment.json 读取 | 不做动态生成 |
| 制造系统 | 检查材料 → 扣材料 → 生成装备实例 | 不做图纸解锁（默认全解锁） |
| 词缀生成 | 按阶位区间随机 1 条 | 不做洗炼/保底 |
| 装备穿戴 | 替换槽位，重算属性 | 不做套装 |
| 强化 | 消耗晶球 + 金钱，属性 ×(1+5%) | 不做失败/保护 |
| 分解 | 返还材料 | 不做魂玉 |

### P4：风险管控

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| 配置数据量过大，手工维护出错 | 高 | 高 | 用脚本生成基础数据，手工只改特殊条目 |
| 词缀数值在减法公式下失衡 | 中 | 高 | P2 数值验证必须先行 |
| 天品/仙品材料掉落率导致玩家卡关 | 中 | 中 | 设计保底计数器（连续 N 次未掉落则必掉） |
| 装备系统与现有战斗引擎接口不兼容 | 中 | 高 | 先读 BattleEntity 的属性接口，确认装备属性注入方式 |
| 物品 ID 命名冲突 | 低 | 中 | 建立 ID 命名规范文档，健康检查覆盖 |
