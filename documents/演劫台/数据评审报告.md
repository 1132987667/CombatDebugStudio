## 三、P1 问题（需修复，种子导入前必须处理）

### P1-1：`buff_ctrl_slow` 的 `controlType: "slow"` 不在合法列表

**位置**：`enemy-buffs.json` → `buff_ctrl_slow`

**现象**：
```json
"controlType": "slow"
```

**问题**：合法 controlType 列表为 `stun / silence / freeze / sleep / bind / confusion`，不含 `slow`。引擎 `BuffConfigResolver` 解析未知 controlType 时会抛错或静默跳过。

**修复方案**：移除 `controlType` 和 `controlPriority` 字段，将 `category` 从 `"control"` 改为 `"modifier"`。减速效果已通过 `attributes.speed: -30%` 实现，无需 controlType 标记。

```json
{
  "id": "buff_ctrl_slow",
  "name": "减速",
  "polarity": "negative",
  "category": "modifier",
  "duration": 2,
  "maxStacks": 1,
  "stackRule": "REFRESH",
  "dispellable": true,
  "cleanseable": true,
  "tags": ["debuff", "slow"],
  "attributes": {
    "speed": { "value": -30, "type": "PERCENTAGE" }
  },
  "description": "速度-30%，持续2回合。"
}
```

### P1-2：`buff_block_up` 引用了不存在的属性 `blockRate`

**位置**：`enemy-buffs.json` → `buff_block_up`

**现象**：
```json
"attributes": {
  "blockRate": { "value": 15, "type": "ADDITIVE" }
}
```

**问题**：标准属性列表（`attributes.json`）中无 `blockRate`。引擎属性重算管线无法识别该 key，会被静默忽略。词缀系统中格挡率是概率属性（归词缀管），不走 attributes 修正。

**修复方案（二选一）**：

- **方案 A（推荐）**：将 `buff_block_up` 改为 effects 型 Buff，使用 `reflect` 或自定义原子效果：
```json
{
  "id": "buff_block_up",
  "name": "格挡强化",
  "polarity": "positive",
  "category": "modifier",
  "duration": 2,
  "maxStacks": 2,
  "stackRule": "LIMITED",
  "dispellable": true,
  "cleanseable": false,
  "tags": ["modifier", "block"],
  "effects": [
    { "type": "block_rate_up", "value": 15 }
  ],
  "description": "格挡率+15%，最多2层。"
}
```
（需确认引擎 `AtomicEffectType` 是否支持 `block_rate_up`，若不支持则走方案 B）

- **方案 B**：暂时移除 `buff_block_up`（当前无技能引用该 Buff），待词缀系统对接后再补。

### P2-3：普通敌人技能差异化不足

**位置**：`enemy-skills.json` 全部 75 个普通敌人技能

**现象**：同一大场景内的普通敌人技能效果高度相似（仅倍率和附加 Buff 概率有微小差异），缺乏基于敌人主题的机制差异。

**影响**：不影响功能，但降低战斗体验多样性。

**建议**：后续迭代中为部分普通敌人增加机制差异：
- 水属性敌人：攻击后有概率使目标减速（已部分实现）
- 金属性敌人：攻击附带破甲（降防）
- 火属性敌人：攻击附带灼烧（已部分实现）
- 土属性敌人：攻击附带眩晕（低概率）
