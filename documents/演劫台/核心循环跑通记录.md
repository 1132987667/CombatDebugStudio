## 1. 背景与目标

依据《开发计划》定义的最小核心闭环：

```
玩家进入关卡 1 → 击败敌人（掉落材料）
→ 洞府制造竹剑（桃木 + 铜精）
→ 装备竹剑（攻击加成）→ 词缀生成（凡品 1 条）
→ 强化竹剑（+1，消耗强化材料与金钱）
→ 再次挑战（数值优势体现）
```

跑通此路径视为"第一步完成"。验收标准见开发计划 §5（V01-V10）。

## 3. 改造内容（分四批）

### 批 1 · 装备实例化核心（W04/W05/W06/W15/V05/V06/V09）

- **packStore 引入装备实例模型**：`GearInstance { instanceId, itemId, enhance, quality, affixes }`
  - 装备不再按 id 计数，制造/掉落/初始持有均实例化，穿戴上扣背包一件
  - `craftEquipment(itemId)`：校验材料 → 扣材料 → 按品质 roll 词缀（凡 1 / 精 2 / 超 3 / 绝 4 / 神 5 条）→ 入背包
  - `equipInstance / unequip`：背包 ⇄ 槽位
  - `enhanceGear(slot)`：扣材料 + 金钱 → 成功率判定 → 强化 +1（失败只扣消耗），强化上限按阶位
  - `instanceStats / equippedStats`：基础属性 × 品质系数 × 强化倍率 + 词缀，供战斗注入与面板重算
  - 存档扩展 `gearInstances + equipped`（v1 旧档自动迁移：itemId → 裸实例）
- **玩家属性面板叠加装备加成**（BattleRoster）：面板数值 = 基础 + 加点 + 装备（与战斗主角同口径）
- EquipPanel / EnhancePanel / CharacterPanel 接线实例模型，强化面板从演示态改为真实生效

### 批 2 · 战斗经济闭环（W16/V02/V01/V18）

- **playerStore 增加经济接口**：
  - `gainExp(amount)`：经验累计 → 升级循环（重算属性、回满血能量），返回升级次数
  - `gainCurrency(unit, amount)`：金币入账
- **BattleZen 战斗结算**：胜利 → `markSceneCleared` 解锁链 + 经验/金币入账 + 掉落入包 → `emit('result')`
- **掉落/奖励数据源修正**：`dropsForScene / rewardForScene` 改读 `configs/enemies/enemies.json`（按敌人 id 关联，修复 scene_1_1 花妖掉落断裂）
- **战斗结算弹窗** `BattleResultDialog`：胜负 / 经验 / 金币 / 升级 / 掉落列表，返回关卡

### 批 3 · 难度与敌人数据（W09/W13/W14/V08）

- **`buildEnemyTeam`**：敌方参战者改读 `configs/enemies/enemies.json`（stats/drops 按 id 关联），替代硬编码公式
- **难度倍率**（R19）：简单 1 / 普通 1.5 / 困难 2，作用于主要数值属性
- **通关解锁链** `markSceneCleared`：胜利解锁本关与 `unlockCondition.sceneId` 指向的后续关卡
  - NOTE：`clear_boss` 前置（boss_major_*）当前无 BOSS 场景，保持锁定
  - TODO(P2)：enemies.json skillIds 引用的技能（skill_enemy_s1_1_a_s1 等 168 个）在 configs/skills 未定义，暂留空走引擎普攻兜底；技能数据补齐后注入 skills.small/passive 即可生效

### 批 4 · configs 引用断裂修复（健康检查 238 → 0）

- **技能 buff 引用 178 项**：seed 合并 `configs/xiyou/enemy-buffs.json` 进 buffs 表（SEED_FLAG 升 v17，强制已 seed 浏览器重导）
- **scenes 掉落引用 29 项**：scenes.json 的 `drops.materials` 9 个 id 拼写/后缀修正（mat_danshui_yu → mat_danshuiyu 等）
- **词条强校验 31 项**：`getSchoolNames` 兼容 `{ schools: [...] }` 包裹结构（此前恒为空集导致流派误报）
