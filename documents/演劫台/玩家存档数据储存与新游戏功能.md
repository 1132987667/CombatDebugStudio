## 2. 需求背景

当前演劫台游戏进度依赖浏览器 `localStorage` 进行简易序列化存储，存在以下问题：

1. **无版本迁移机制**：存档结构变更（如装备槽位从 8 槽迁移至 6 槽）时，旧档无法自动适配；
2. **无完整性校验**：存档损坏或字段缺失时直接崩溃，无降级恢复能力；
3. **无"新游戏"入口**：玩家无法主动重置进度、开启新存档，只能手动清除浏览器数据；
4. **存储容量受限**：`localStorage` 上限约 5MB，随装备实例与任务数据增长存在溢出风险。

本需求旨在建立**结构化、可迁移、防丢失**的存档体系，并在设置界面提供"新游戏"操作入口。

## 4. 存档数据结构（Schema v2.0.0）

```typescript
interface SaveData {
  meta: {
    version: string          // 当前为 "2.0.0"
    save_time: number        // Unix 时间戳
    play_time: number        // 累计游玩秒数
    checksum?: string        // 完整性校验值（P1）
  }

  player: {
    level: number
    exp: number
    hp_max: number
    energy_max: number
    base_atk: [number, number]
    gold: number
    pills_eaten: Record<string, number>  // 丹药服用记录（防超限）
    statBonuses?: Record<string, number> // 加点分配
  }

  progress: {
    max_scene: number
    current_scene: number
    current_difficulty: 'simple' | 'normal' | 'hard'
    unlocked_scenes: number[]
    unlocked_difficulties: Record<string, string[]>
    boss_killed: string[]
    hidden_boss_killed: string[]
    great_boss_defeated: string[]
    final_boss_defeated: boolean
  }

  inventory: {
    materials: Record<string, number>    // 材料ID: 数量
    equipments: string[]                 // 装备实例ID列表
    elixirs: Record<string, number>      // 丹药ID: 数量
    misc: Record<string, number>         // 杂物ID: 数量
  }

  equipment: {
    weapon: string | null
    armor: string | null
    helmet: string | null
    boots: string | null
    charm: string | null
    ring: string | null
    // 法宝 / 神器为独立类型（P2）
    treasure?: string | null
    artifact?: string | null
  }

  craft: {
    weapon_level: number
    weapon_exp: number
    armor_level: number
    armor_exp: number
    accessory_level: number
    accessory_exp: number
  }

  skills: {
    passive: string | null
    minor1: string | null
    minor2: string | null
    major: string | null
  }

  battle_stats: {
    total_battles: number
    total_wins: number
    total_losses: number
    scene_battle_count: Record<string, number>
  }

  quests: {
    active: string[]
    completed: string[]
  }
}
```

## 5. 存档储存方案

### 5.1 存储后端选型

| 层级 | 实现 | 说明 |
|------|------|------|
| 主存储 | `IndexedDbStorage`（复用 CombatDebugStudio 已有实现） | DB 名称：`xiyou_game_save`，store：`saves` |
| 降级 | `localStorage`（key：`xiyou_save`） | IndexedDB 不可用时回退 |
| 端口抽象 | `IPersistentStorage` 接口 | 领域层不直接依赖具体存储实现 |

### 5.2 存储键约定

| 键名 | 用途 |
|------|------|
| `save:main` | 主存档（手动 / 自动共用，手动覆盖自动） |
| `save:auto` | 自动存档备份（独立于手动，防误覆盖） |
| `save:export_{timestamp}` | 导出记录索引（P2） |

### 5.3 自动存档触发时机

| 触发点 | 说明 |
|--------|------|
| 定时器 | 每 30 秒执行一次 |
| 战斗结束 | 胜负结算完成后 |
| 装备变更 | 穿戴 / 卸下 / 强化 / 升星后 |
| 场景切换 | 进入新场景或切换难度后 |
| 任务完成 | 领取奖励后 |
| 页面卸载 | `beforeunload` 事件兜底 |

### 5.4 版本迁移

```typescript
// 迁移注册表（按版本号升序执行）
const MIGRATIONS: Record<string, (old: any) => SaveData> = {
  '1.0.0_to_2.0.0': migrateEquipmentSlots,  // 8槽 → 6槽
  // 未来版本在此追加
}
```

**迁移规则（v1.x → v2.0.0）**：

| 旧字段 | 新字段 | 规则 |
|--------|--------|------|
| `necklace` + `crown` | `helmet` | 取品质较高者；若两者均为空则 null |
| `belt` | `boots` | 直接映射 |
| `bracelet` | `charm` | 直接映射 |
| `weapon` | `weapon` | 保持不变 |
| `armor` | `armor` | 保持不变 |
| `ring` | `ring` | 保持不变 |

### 6.3 新游戏重置逻辑（resetGame）

```typescript
function resetGame(): void {
  // 1. 停止所有定时器（自动存档、战斗循环）
  stopAllTimers()

  // 2. 清除存储
  indexedDbStorage.remove(STORE.SAVES, 'save:main')
  indexedDbStorage.remove(STORE.SAVES, 'save:auto')
  localStorage.removeItem('xiyou_save')
  localStorage.removeItem('xiyou_save_auto')

  // 3. 重置运行时状态为初始值
  gameState = createInitialGameState()

  // 4. 重置 UI
  renderAll()
  closeAllModals()

  // 5. 显示引导提示
  showToast('新游戏已开始')
  showOnboarding()  // 首次进入引导（若已实现）
}
```

## 7. 存档加载流程

```
页面加载
    │
    ▼
尝试读取 IndexedDB 'save:main'
    │
    ├── 存在 → 校验 checksum（P1）
    │       │
    │       ├── 校验通过 → 检查 meta.version
    │       │       │
    │       │       ├── version === 当前版本 → 直接加载
    │       │       └── version < 当前版本 → 执行迁移链 → 加载
    │       │
    │       └── 校验失败 → 尝试读取 'save:auto' 备份
    │               │
    │               ├── 备份可用 → 加载备份 + 提示"主存档异常，已恢复备份"
    │               └── 备份不可用 → 创建新存档 + 提示"存档损坏，已重置"
    │
    └── 不存在 → 尝试读取 localStorage 'xiyou_save'（旧版兼容）
            │
            ├── 存在 → 迁移至 IndexedDB → 加载
            └── 不存在 → 创建初始存档
```

## 8. 存档导出 / 导入（P1）

### 8.1 导出

```typescript
function exportSave(): void {
  const data = JSON.stringify(gameState, null, 2)
  const blob = new Blob([data], { type: 'application/json' })
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = `xiyou_save_${Date.now()}.json`
  a.click()
  URL.revokeObjectURL(url)
}
```

### 8.2 导入

- 文件选择器（`<input type="file" accept=".json">`）
- 解析 JSON → 校验 `meta.version` 字段存在性
- 执行迁移（若版本低于当前）
- 校验必填字段完整性（player / progress / inventory / equipment）
- 写入 IndexedDB → 刷新 UI
- 校验失败时提示具体缺失字段，拒绝导入

## 11. 约束与注意事项

1. **编码规范**：`documents/` 下产出的 `.md` 文件必须 UTF-8 带 BOM；源代码 UTF-8 无 BOM；
2. **UI 规范**：禁用 emoji；字号不低于 `--font-size-md`；按钮文案使用中文；
3. **石匠守则**：复用已有 `IndexedDbStorage` 与 `IPersistentStorage` 端口，不新建存储抽象；复用 `Checksum.ts`，不重写校验算法；
4. **兼容性**：旧版 `localStorage` 存档（key: `xiyou_save`）首次加载时静默迁移至 IndexedDB，迁移完成后删除旧键；
5. **性能**：存档序列化/反序列化应在 50ms 内完成（典型存档体积 < 200KB）；
6. **安全**：导出文件不含任何用户隐私信息；存档校验仅防意外损坏，不作为反作弊手段。
