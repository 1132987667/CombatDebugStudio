## 五、调整清单（按优先级）

> 决策阶梯：本模块定位是**演劫台下的可视化演示沙盒**，不是成品游戏。四面板已能完整展示数据与结构，多数"养成循环/经济系统/装备实例化"交互对沙盒目标无增量价值，按 YAGNI 砍掉（见上表 🗑 项），不实现。

| 优先级 | 调整项 | 说明 |
|--------|--------|------|
| P0 | 打通"装备/修为 → 战斗属性"数据流 | 沙盒核心价值是"改数据 → 看战斗变化"。让 `buildBattleTeams` 从 reactive 的 `gearSlots/realms/playerParty` 读取并响应变化，`syncTeams()` 后重拉 | 
| P0 | 统一品质体系 | items.json 数字 5 档 与 pack.json 中文 4 档二选一。推荐全量走 items.json 数字档，pack.json 改为数字 rarity 或删除（§3.1 双轨冲突） |
| P1 | 装备槽位数据与文档对齐 | 6 槽 vs 旧版 8 部位：以数据为准（6 槽），修改旧版文档描述 |
| P2 | 背包卡片补 count | 若需显示数量，给 items.json 条目补 count 字段；否则维持不显示（当前无消费链路，不显示更诚实） |
| P2 | 伙伴 skills 字段 | 若战斗联动（P0）需要伙伴被动进战斗，再补 `XiyouMate.skills`；否则不补 |

## 六、验收标准

1. **P0-数据流**：在装备面板改任意槽位（换/卸/强化数值），进入战斗后 `ParticipantCard` 属性随之变化，且 `battleStore.syncTeams()` 被触发。
2. **P0-品质统一**：`rg -n "rarity" configs/xiyou/` 结果只剩数字 1-5 一种形态；背包内所有品质色一致映射 `xy-q--` 类。
3. **P1-槽位对齐**：装备面板与 `equip.json` 槽位数一致（6），文档不再出现 8 部位。
4. **不回归**：`npm run typecheck` 通过；四个面板展示与现状一致。
