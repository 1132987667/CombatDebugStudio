> **文档性质**：设计决策文档——词缀系统最终规则与完整词缀库。
> **版本**：v3.1（2026-08-11）
> **适用范围**：`configs/xiyou/affixes.json`、封神榜 `xiyou_affixes` 数据域、`src/shared/utils/affix.ts`、`src/shared/constants/affix.ts`
> **前置阅读**：《设计稿补充-词缀.md》（原典）、《统一战斗系统文档.md》（战斗规则）、《数值体系搭建指南.md》§D1b（五行攻击已删、五行抗性保留）、《设计稿补充-装备.md》（装备词条，与词缀不混用）

## 0. 设计原则

```text
1. 词缀只作为敌人难度标签。
2. 词缀只做属性修正，不承载具体能力机制。
3. 概率/百分比属性（吸血率、反伤率、格挡率、连击率、反击率等）
   可作为词缀属性修正——引擎每次结算时读取判定。
4. 有独立生命周期的持续效果（中毒 DOT、护盾、控制状态、净化）
   交给 Buff 系统——有施加/持续/移除事件。
5. 词缀不与玩家装备词条混用。
6. 增益词缀作用于敌人，只做正面修正（增强敌人）。
7. 减益词缀作用于玩家（唯一的"负面"方向）。
8. 词缀的"性格"通过「选择增强哪些属性」体现，不通过「增强A削弱B」体现。
   不增强某属性本身就是该敌人的相对弱点，无需显式削弱。
9. 五行攻击属性已从引擎删除（设计决策 D1b），词缀中不出现五行攻击修正。
   五行相关词缀统一为「五行抗性」（对应 fireRes/waterRes/metalRes/woodRes/earthRes）。
10. 同一敌人不附加同名词缀。
11. 同一 conflict_group 的词缀不共存。
12. 天命词缀为 BOSS 专属，不参与随机。
13. 词缀数量随场景/爬塔层数递增，不锁死为固定 1 个。
```

## 2. 词缀字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一 ID，前缀 `affix_yao_{tier}_{seq}` / `affix_mandate_{seq}` / `affix_jie_{seq}` |
| name | string | 词缀名称 |
| tier | number | 档位 1-5（劫数为 0） |
| tier_name | string | 妖气/妖性/妖道/妖圣/天命/劫数 |
| target | string | enemy / player |
| category | string | 攻伐/守御/生存/资源/控制/五行/削弱 |
| personality | string | 性格标签（驱动 AI 策略与 UI 展示） |
| modifiers | array | 属性修正数组（支持多条） |
| modifiers[].attribute | string | 修正属性字段（必须存在于 `attributes.json`） |
| modifiers[].value | number | 修正数值（百分比） |
| modifiers[].calc | string | add 加算 / multiply 乘算 |
| weight | number | 随机权重（天命为 0，不参与随机） |
| conflict_group | string | 冲突组，同组不共存 |
| allowed | array | guardian / boss / elite / tower |
| scene_range | array | 推荐关卡 [min, max] |
| exclusive_boss | string/null | 天命专属：绑定 BOSS ID |
| description | string | 描述 |

## 10. 冲突规则

```text
1. 同名词缀不共存。
2. 同一 conflict_group 不共存。
3. 天命词缀与任何随机词缀不共存（天命独占）。
4. 四档妖圣同一敌人最多 1 条。
5. 劫数词缀与增益词缀互不冲突（方向不同）。
6. 五行单体抗性词缀（火灵/水灵/木灵/金灵/土灵）与五行轮转/混元归一不共存。
7. 多词缀时，各词缀 conflict_group 不可重复。
8. 冲突时重新随机（最多重试 3 次，超出放弃该词缀位）。
```

## 11. 词缀生成逻辑

```javascript
function generateAffixes(enemyType, sceneIndex, difficulty, towerFloor) {
  const affixes = [];
  const usedGroups = new Set();

  const plan = resolveAffixPlan(enemyType, sceneIndex, difficulty, towerFloor);

  // 天命独占
  if (plan.hasMandate) {
    affixes.push(getMandateByBoss(enemyType));
    return affixes;
  }

  // 增益词缀
  for (let i = 0; i < plan.buffCount; i++) {
    const pool = getAffixPool('enemy', plan.buffTier, sceneIndex);
    const picked = randomPickByWeight(pool, usedGroups);
    if (picked) {
      affixes.push(picked);
      picked.modifiers.forEach(m => usedGroups.add(picked.conflict_group));
    }
  }

  // 劫数词缀
  if (plan.hasDebuff) {
    affixes.push(randomPickByWeight(getAffixPool('player', 0), new Set()));
  }

  return affixes;
}
```

## 12. 五行抗性与克制矩阵的分工

```text
克制矩阵（elementMatrix）：阵营相性，单位级，由 faction 决定。
  例：火阵营打木阵营 ×1.2。

五行抗性（fireRes / waterRes / metalRes / woodRes / earthRes）：
  属性级减免，可培养。词缀修正的是这一层。
  例：敌人有「火灵护体」→ fireRes +60% → 玩家火系技能伤害 ×0.4。

两者并存的策略意义：
  火克木是天理（克制矩阵），但木阵营敌人可以堆 fireRes 反制（五行抗性词缀）。
  「克制是天赋，抗性是修行。」
```

### 五行抗性上限

```text
五行抗性上限：80%（保留 20% 克制穿透空间）。
词缀修正后若超过 80%，钳制为 80%。
```

## 14. 引擎接入

### 14.1 数据流

```text
configs/xiyou/affixes.json（种子）
  → IndexedDB xiyou_affixes store（运行时权威）
  → GameDataApi.listAffixes()（Promise 读取）
  → AffixGenerator.generate()（战斗初始化时调用）
  → ParticipantStats.addModifier()（注入属性修正）
```

### 14.2 注入方式

```typescript
// 增益词缀：PERCENTAGE 修饰符
participantStats.addModifier({
  sourceType: ModifierSourceType.AFFIX,
  sourceName: `词缀·${affix.name}`,
  attribute: modifier.attribute,
  value: modifier.value,
  type: ModifierType.PERCENTAGE,
})

// 劫数词缀：作用于玩家阵营全体
for (const player of playerTeam) {
  player.stats.addModifier({
    sourceType: ModifierSourceType.AFFIX,
    sourceName: `劫数·${debuff.name}`,
    attribute: debuff.attribute,
    value: debuff.value, // 负值
    type: ModifierType.PERCENTAGE,
  })
}
```

### 14.3 五行抗性注入

```typescript
// 火灵护体：fireRes +60%
// 对应属性字段：fireRes（已存在于 attributes.json）
// 引擎伤害管线第 10 步「元素抗性」消费此值
participantStats.addModifier({
  sourceType: ModifierSourceType.AFFIX,
  sourceName: `词缀·火灵护体`,
  attribute: 'fireRes',
  value: 60,
  type: ModifierType.PERCENTAGE,
})
```

### 14.4 吸血率/反伤率/格挡率消费

```text
吸血率（lifestealRate）：
  伤害管线结算后，攻击者恢复 = 实际伤害 × lifestealRate%。
  走触发器 on_damage_dealt。

反伤率（reflectDamagePercent）：
  受击时，攻击者受到 = 原始伤害 × reflectDamagePercent%。
  走触发器 reflect_damage。已有实现。

格挡率（blockRate）：
  伤害管线第 1 步命中判定后，额外判定格挡。
  格挡成功：伤害 ×0.5。
  走触发器 on_hit_received。

连击率（comboRate）：
  攻击结算后，判定是否追加一次攻击。
  走触发器 on_attack_landed。

反击率（counterRate）：
  受击后，判定是否立即反击。
  走触发器 on_hit_received。
```
