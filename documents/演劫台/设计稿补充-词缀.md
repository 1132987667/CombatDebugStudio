# 《西游斗战》完整词缀库设计稿

## 0. 词缀库设计原则

词缀库严格遵循以下原则：

```text
1. 词缀只作为敌人难度标签。
2. 词缀只做属性修正，不承载具体能力机制。
3. 吸血、反伤、格挡、中毒、净化等具体能力交给 Buff 系统。
4. 词缀不与玩家装备词条混用。
5. 增益词缀作用于敌人。
6. 减益词缀作用于玩家。
7. 同一敌人不附加同名词缀。
8. 建议同一敌人不附加同一 conflict_group 的词缀，避免同类修正过度叠加。
```

---

# 1. 词缀库总览

本词缀库基于知识库原典整理，共包含 **55 条正式词缀**：

| 分类 | 数量 | 作用对象 | 定位 |
|---|---:|---|---|
| 减益一档 | 8 | 玩家 | BOSS 对玩家的削弱 |
| 增益一档 | 8 | 敌人 | 前期 / 低难词缀 |
| 增益二档 | 12 | 敌人 | 中期词缀 |
| 增益三档 | 15 | 敌人 | 后期词缀 |
| 增益四档 | 12 | 敌人 | 终局传说词缀 |
| 合计 | 55 | - | 可直接作为正式词缀池 |

---

# 2. 词缀字段说明

每条词缀建议使用以下字段：

| 字段 | 说明 |
|---|---|
| id | 词缀唯一 ID |
| name | 词缀名称 |
| tier | 词缀档位，1-4 |
| quality | 品质：common / rare / epic / legendary |
| target | 作用对象：enemy / player |
| category | 功能分类：削弱 / 攻伐 / 守御 / 生存 / 资源 / 控制 / 五行 |
| modifier | 修正属性字段 |
| value | 修正数值 |
| calc | 计算方式：add 加算 / multiply 乘算 |
| weight | 随机权重 |
| conflict_group | 冲突组，同组建议不共存 |
| allowed | 可附加对象：guardian / boss |
| scene_range | 推荐出现关卡范围 |
| description | 描述 |

# 9. 词缀分配规则

## 9.1 基础规则

```text
每个难度的第 3 个敌人，即守护者，固定附加 1 个增益词缀。
BOSS 固定附加 1 个增益词缀 + 1 个减益词缀。
增益词缀从对应档位中随机选取。
减益词缀只从减益一档词缀池中选取。
同一敌人不重复附加同名词缀。
同一 conflict_group 不建议同时出现。
```

---

## 9.2 档位推荐分布

| 关卡范围 | 简单难度 | 普通难度 | 困难难度 | 守护者 | BOSS |
|---:|---|---|---|---|---|
| 1-3 | 无或一档 | 一档 | 一档 | 一档 | 一档增益 + 一档减益 |
| 4-6 | 一档 | 一档 / 二档 | 二档 | 二档 | 二档增益 + 一档减益 |
| 7-9 | 一档 / 二档 | 二档 | 三档 | 三档 | 三档增益 + 一档减益 |
| 10 | 二档 | 三档 | 三档 / 四档 | 三档或四档 | 四档增益 + 一档减益 |

---

## 9.3 权重建议

| 词缀档位 | 推荐权重 |
|---|---:|
| 一档 | 100 |
| 二档 | 80 |
| 三档 | 50 |
| 四档 | 20 |
| 减益一档 | 100 |

如果希望四档词缀更稀有，可将四档权重降至：

```text
10 或 5
```

# 10. 词缀生成伪代码

```javascript
function generateAffixes(enemyType, sceneIndex, difficulty) {
  const affixes = [];

  if (enemyType === "guardian") {
    const buffTier = getGuardianBuffTier(sceneIndex, difficulty);
    const buffPool = getAffixPool("enemy", buffTier);
    affixes.push(randomPickByWeight(buffPool));
  }

  if (enemyType === "boss") {
    const buffTier = getBossBuffTier(sceneIndex, difficulty);
    const buffPool = getAffixPool("enemy", buffTier);
    const debuffPool = getAffixPool("player", 1);

    affixes.push(randomPickByWeight(buffPool));
    affixes.push(randomPickByWeight(debuffPool));
  }

  return removeConflictAffixes(affixes);
}
```

# 11. 冲突处理建议

为避免敌人属性过度膨胀，建议执行以下冲突规则：

```text
1. 同名词缀不能共存。
2. 同一 conflict_group 不能共存。
3. 增益四档词缀同一敌人最多出现 1 条。
4. BOSS 的增益词缀和减益词缀互不冲突。
5. 五行类词缀可以与其他类型词缀共存。
6. 若随机结果发生冲突，则重新随机一次。
```

示例：

```text
蛮力和破军都属于 enemy_atk_pct 冲突组。
因此同一个守护者不应同时拥有蛮力和破军。
```

# 13. 最终建议

正式开发建议优先使用：

```text
原典 55 条词缀库
```

原因：

```text
1. 完全符合知识库设定。
2. 数量适中，不会造成配置负担。
3. 覆盖攻伐、守御、生存、资源、控制、削弱、五行等方向。
4. 适合守护者与 BOSS 的词缀生成规则。
```

如果后续需要增强刷子感，再逐步加入：

```text
资源类扩展
控制类扩展
五行四档扩展
攻伐 / 守御补全扩展
```

这样既能保证当前系统稳定，又能为后续词缀怪、困难词缀、终局 BOSS 词缀留下扩展空间。
