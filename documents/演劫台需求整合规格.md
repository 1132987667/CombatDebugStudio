## 2. 整合原则

1. **引擎不重建**：战斗公式/技能/AI/元素矩阵/Buff 在 CombatDebugStudio 已完整实现（`DamageCalculator` 等），SOLO-DEMO 的战斗类需求只做"验证与补齐"，不做二次开发。
2. **数据域复用**：敌人/场景/阵型/技能/Buff/材料/装备已入封神榜数据域（IndexedDB 14 store），演劫台只消费，不重复建模。
3. **新增集中在"成长与经营"**：演劫台真正要新建的是 SOLO-DEMO 已验证的成长循环（境界/命数/轮回/飞升）、养成（装备/功法/洞天/炼丹/炼器）、剧情（任务/对话/势力/世界）、内容（关卡/敌人势力/副本/成就）。
4. **吸收教训**：SOLO-DEMO 最大的失败是"数据先行、链路断裂"（40 任务配 3 对话、十余处悬空 dispatch、商店买不了）。演劫台开发**每张需求单必须带验收标准**，杜绝同款事故。

## 4. 成长循环归一化（SOLO-DEMO → 封神榜）

SOLO-DEMO 的成长主轴是"**等级 → 境界 → 命数 → 轮回 → 飞升**"，演劫台保留这条**五层成长体验**，但归一化到 4v4 队伍 + 五行 + 扁平属性：

| 成长层 | SOLO-DEMO（原始） | 演劫台（归一） |
| --- | --- | --- |
| 等级 | 单人 100 级，每级 4 自由点 + 自动分配 | **每个上阵角色独立等级**（guardian 五人组），等级成长走职业曲线（数值框架 D3） |
| 境界 | 16 境界（凡人→大罗），突破给属性点 | 归一为封神榜境界：保留"境界 = 成长阶段"概念，奖励改为角色基础属性，数值表需重定（见 §7 Q2） |
| 命数 | 5 命，等级上限 100+命数×100 | **简化**：并入境界系统，不单设命数（避免双重置叠加） |
| 轮回（逆轮溯真） | 小重置：等级回 1、保留灵蕴，全属性+1%、等级增幅+4% | 归一为"**小队重置**"：等级/装备重置，保留灵蕴之魂（角色碎片/成长材料），全队属性 % 加成 |
| 飞升（万象归墟） | 大重置：基础转核心 100%、物品获取翻倍 | 归一为"**飞升**"：保留洞天/功法，队伍属性转化倍率提升，解锁新内容（新章/新境界） |
| 天赋 | 1 棵树 9 节点 | 保留"天赋 = 差异化 build"，改为每角色天赋盘，效果走乘区（独立乘区连乘已拍板） |

**关键归一决定**：
- **命数并入境界**（演劫台简化，避免两套重置逻辑叠加，这是 SOLO-DEMO 里最混乱的部分）；
- **轮回/飞升作用于"整个队伍"而非单人**（4v4 阵容养成，重置时整队回退，全队共享 % 加成）；
- 灵蕴之魂/本源之魂 → 演劫台"轮回货币/飞升货币"，由封神榜资源域定义。

## 5. 题材归一（敌人势力 + 元素）

### 5.1 敌人势力 → 封神榜敌人标签

SOLO-DEMO 的三大势力（机械古修/异神血肉/噬魂妖国）设计优秀，是"针对配装"的差异化来源。归一化到封神榜（现有敌人是花妖/虾蟹/岩妖等五行系）：

| SOLO-DEMO 势力 | 特性 | 弱点 | 演劫台映射 |
| --- | --- | --- | --- |
| 机械古修 | 高物防、低法防、免疫流血/中毒、护盾 | 弱雷 | 映射为敌人 **tag**（如 `mechanical`），五行缺雷 → 弱**金**（金系技能破甲克制） |
| 异神血肉 | 高回复、自带吸血、高血 | 弱火 | 敌人 tag `flesh`，弱**火** |
| 噬魂妖国 | 高闪避、高爆发、腐蚀 | 弱物理 | 敌人 tag `soul`，弱**物理**（走 attack 无元素加成） |

- 实现：敌人 JSON 加 `tags` 字段；战斗读取 tag 判断免疫（复用 Buff 免疫体系，见数值框架 §3 tag 免疫）；
- 弱点 = 元素克制矩阵（`configs` elements 表）里的系数，五行内闭环。

### 5.2 元素归一

| 8 元素（SOLO-DEMO） | 五行（演劫台） | 处理 |
| --- | --- | --- |
| 金/木/水/火/土 | 金/木/水/火/土 | 保留，附加效果（破甲/缠绕/冰冻/灼烧/眩晕）归入五行技能效果 |
| 雷/风/冰 | — | **删除**：并入五行（雷→金，风→木，冰→水），或做成技能特效非独立元素 |

## 8. 演劫台开发路线（与 SOLO-DEMO 需求单对照）

| 阶段 | 内容 | 吸收的 SOLO-DEMO 需求 | 验收 |
| --- | --- | --- | --- |
| E1 地基 | 演劫台模块框架（Tab 页/路由/存档接入） | R30/R38 | 演劫台 Tab 可进入，存档可用 |
| E2 战斗闭环 | 复用引擎跑通 4v4 关卡推图（复用场景/敌人/阵容） | R02/R03/R04/R19/R22 | 关卡可推，奖励结算 |
| E3 成长 | 队伍养成 + 境界 + 天赋 + 轮回/飞升 | R01/R20/R21/R27/R28/R29 | 五层成长全可用 |
| E4 装备 | 装备养成闭环 | R05/R13~R17 | 穿戴/强化/洗练/套装可用 |
| E5 经营 | 洞天 + 种植 + 炼丹 + 炼器 + 离线 | R07/R08/R11/R12/R25 | 经营闭环 + 离线收益 |
| E6 剧情 | 任务 + 对话 + 势力 + 商店 | R06/R09/R10/R18/R33/R34 | 主线可推进，剧情连贯 |
| E7 内容 | 敌人势力特性 + 副本/成就/宠物（P3） | R23/R35/R36/R37 | 内容可扩展 |

**关键经验（从 SOLO-DEMO 吸取）**：
1. **每阶段必须闭环**：SOLO-DEMO 的教训是"数据先行、链路断裂"——E2 就要求"关卡可推、奖励入账"再进入 E3，不允许先把 40 个任务数据建好却无运行时推进；
2. **悬空调用零容忍**：验收前跑 `npm run typecheck` + 静态检查无未定义 dispatch/commit；
3. **数值一处定义**：境界/轮回奖励走配置表（封神榜数据域），不写死在组件。

## 9. 一句话总结

> **演劫台 = CombatDebugStudio 引擎（4v4/五行/已拍板数值）× 封神榜数据域（消费）× SOLO-DEMO 系统设计（成长/装备/经营/剧情五层玩法）。**
> 不迁移 SOLO-DEMO 代码，吸收它的系统设计、玩法结构与"链路断裂"教训，按演劫台现有架构归一落地。
