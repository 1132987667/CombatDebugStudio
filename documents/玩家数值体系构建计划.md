# 玩家数值体系构建计划

> **状态**：方案已定（2026-08-31），待开工。决策 D1（SAP 六维模型 + 900 总属性点）与 D2（新权重表）已确认；执行节奏按"先出方案不改码"，M1-M4 待确认后推进。
> **已定决策**：
> - **D1**：玩家成长采用 SAP 六维模型（对齐 HTML/数值文档，与属性定义表 SAP 度量衡闭环）。每级 12 固定属性点 + 4 自由属性点 = 16 点/级，50 级 = 800，+ 丹药 100 = **900 默认等级总属性点**。
> - **D2**：养成权重以策划新表为准（等级120 / 装备240 / 流派60 / 宠物60 / 坐骑60 / 法宝60 / 神器60，总 660），且**后续很大可能变化 → 必须数据化写入 JSON**，不可硬编码。
> - **D5**：装备数值公式已定（核心:附加 = 2:1，单位基数 = 900/6/3/50 = 1，浮动 50%~110%），详见 §3.7。

## 一、背景与目标

### 1.1 背景

策划提供了一份数据管理后台原型（HTML）与一份《斗战西游》数值逻辑梳理文档。核心诉求是：**玩家构造该游戏的数值体系的过程要在封神榜里体现出来**——不是简单地把原型里的表格搬进来，而是把"从 SAP 度量衡 → 玩家成长 → 各系统投放 → 来源审计 → 战斗公式结算"这条构建链路在后台里可见、可编辑、可审计。

**执行节奏**：先出方案不改码。本文为方案文档，M1-M4 待确认后推进。

### 1.2 目标

1. 在封神榜建立**玩家成长配置**（初始属性 / 每级成长 / 自由属性点 / 属性点转化 / 等级经验），对齐 HTML「玩家配置」模块与 PRD §18/§19；
2. 建立**属性定义表**（SAP 价值倍数 / 属性层级 L1-L4 / 归属系统），对齐 HTML「属性定义」模块；
3. 建立**来源审计视图**（属性 × 系统投放矩阵），对齐 HTML「来源审计」模块；
4. 调整封神榜侧栏菜单排序，让"玩家构建数值体系的过程"成为导航主线。

### 1.3 非目标（本期不做）

- 不重写封神榜通用 CRUD（DataTable / EntityDrawer / FieldEditor 已能承载新表）；
- 不实现宠物 / 坐骑 / 流派 / 法宝 / 神器的独立数据表（现有 `xiyou` 单文档已承载，拆表成本高收益低，见 §5 决策点 D3）；
- 不改战斗引擎公式（公式在代码中，FormulasView 保持只读参考页）；
- 不做《数值逻辑梳理》中战斗公式（暴击溢出转化 / 连击衰减 / 反伤上限等）的引擎落地，本期只落配置与审计。

## 三、方案设计：玩家构建数值体系的闭环

### 3.1 构建链路（导航主线）

```
① 度量衡      属性定义（SAP 价值倍数 / L1-L4 层级 / 归属系统）
     ↓
② 玩家成长    玩家配置（初始属性 → 每级成长 → 自由点 → 转化 → 预览）
     ↓
③ 系统投放    装备 / 词条池 / 宠物 / 坐骑 / 流派 / 法宝 / 神器
     ↓
④ 来源审计    属性 × 系统投放矩阵（主 / 副 / 禁止来源）
     ↓
⑤ 公式结算    属性与公式（只读参考页，公式在代码中）
```

### 3.3 玩家配置（新系统视图 PlayerConfigView）

对齐 HTML「玩家配置」交互，数据落 `params` 域（新增 `player_config` 条目，复用 BattleParamData.data）：

```ts
interface PlayerConfig {
  id: 'player_config'
  maxLevel: 50
  expFormula: 'round(50 × L^1.35 + 60 × L)'
  base: { hp: 60; atk: 15; def: 10; hit: 10; dodge: 10; speed: 10 }   // 对齐 PRD §19
  // 每级固定成长（合计 = 12 属性点）：
  //   hp24/12 + atk8/2 + def4/2 + hit3/2 + dodge3/2 + speed2/2 = 2+4+2+1.5+1.5+1 = 12
  growth: { hp: 24; atk: 8; def: 4; hit: 3; dodge: 3; speed: 2 }
  freePointsPerLevel: 4                                              // 每级 4 自由属性点
  conversion: { hp: 12; atk: 2; def: 2; hit: 2; dodge: 2; speed: 2 }  // 1 SAP 定义
  /** 丹药带来的额外属性点（计入等级总属性点） */
  pillBonusPoints: 100
  currentLevel: 1      // 仅预览用
}
```

> **总量校验**：每级 16 属性点（12 固定 + 4 自由）× 50 级 = 800，+ 丹药 100 = **900 等级总属性点**（与 §2.3 权重表、装备公式单位基数一致）。

视图三块：
- **成长配置**：初始属性 / 每级成长 / 自由点 / 转化率（表单）
- **经验公式**：maxLevel + 公式展示 + 一键填充 expTable（复用 ExpGoldView 思路）
- **属性预览**：`base + (L-1)×growth + 自由点×转化` 实时计算，标注 SAP 总量

纯配置 + 纯计算，不依赖引擎，改动面最小。预览计算逻辑做成纯函数放 `domain/fengshen/`（对齐 exp-reward.ts 模式），可单测。

### 3.6 系统预算（params 域 system_budget，数据化）

8 大系统权重表作为数据写入 `params` 域 `system_budget` 条目（策划可能频繁调整，必须 JSON 数据化，禁止硬编码）：

```ts
interface SystemBudgetEntry {
  system: 'level' | 'equipment' | 'school' | 'pet' | 'mount' | 'talent' | 'artifact' | 'relic'
  label: string        // 等级 / 装备 / 流派树 / 宠物 / 坐骑 / 法宝 / 神器
  totalSap?: number    // 等级域总属性点（900 = 800 成长 + 100 丹药）
  weight: number       // 预算权重（120 / 240 / 60 ...）
  note?: string        // 备注（如装备：100% × 强化15(1.6) × 满级升星(1.25)）
}
```

来源审计顶部从该条目读取权重展示；改动权重只改 JSON，不碰代码。

### 3.7 装备数值公式（已定 D5）

策划新设定：装备基础属性按"核心 2 : 附加 1"权重投放，单位基数锚定等级总属性点：

```
单位基数 = 等级总属性点 900 ÷ 6 部位 ÷ 3 权重和（核心2+附加1）÷ 满级50 = 1
装备属性值 = 单位基数 × 装备等级 × 属性权重（核心2/附加1） × 品阶权重 × 属性转化系数
浮动范围 = 50% ~ 110%
```

示例（10 级仙品剑）：核心攻击 `1×10×2×1.0×2=40` → [20,44]；附加命中 `1×10×1×1.0×2=20` → [10,22]。

> 该公式随策划调整可能性大，作为数据（公式模板）落 `params` 域，供装备配置页展示与后续生成校验；本期不做装备属性生成逻辑，仅存档。

## 五、已定决策

### D1：玩家成长模型 —— ✅ 已定：SAP 六维模型（900 总属性点）

采用 HTML/数值文档六维模型，并按策划 2026-08-31 设定更新总量：

```ts
base:       { hp: 60, atk: 15, def: 10, hit: 10, dodge: 10, speed: 10 }
// 每级固定成长 = 12 属性点（hp24/12 + atk8/2 + def4/2 + hit3/2 + dodge3/2 + speed2/2 = 12）
growth:     { hp: 24, atk: 8,  def: 4,  hit: 3,  dodge: 3,  speed: 2 }
freePointsPerLevel: 4                        // 每级 4 自由属性点
conversion: { hp: 12, atk: 2,  def: 2,  hit: 2,  dodge: 2,  speed: 2 }   // 1 SAP = 12血 = 2攻 = 2防 = 2命中 = 2闪避 = 2速度
pillBonusPoints: 100                          // 丹药额外属性点
expFormula: 'round(50 × L^1.35 + 60 × L)'
maxLevel: 50
```

**总量校验**：每级 16 属性点（12 固定 + 4 自由）× 50 级 = 800，+ 丹药 100 = **900 等级总属性点**（权重仍 120）。

与属性定义表的 SAP 度量衡天然一致，来源审计可闭环。演劫台数据链切换列为后续任务（本期 PlayerConfigView 独立于演劫台 `player.json`，不强制联动）。

### D2：养成权重 —— ✅ 已定：策划新表（数据化）

以 §2.3 策划新表为准（等级总属性点 900、权重 120/240/60...，总 660），**写入 `params` 域 `system_budget` JSON**，后续策划改动只改配置。

### D5：装备数值公式 —— ✅ 已定
