## 八、遗留项（不强改，天花板与建议路径）

1. **`BuffConfigResolver` stackRule 缺省值怪象**（已加 HACK 注释）：缺省写 `'LIMITED'`（大写字符串），而 `StackRule.LIMITED = 'limited'`；buffs.json 121/142 条无 stackRule 走此缺省，`BuffSystem` 叠层 switch（REFRESH/LIMITED）不会命中该值。**疑似潜伏 bug**（叠层上限逻辑可能未按 LIMITED 生效），修正会改变现网行为，须先确认策划语义再统一。
2. **`attributeSync.ts` REVERSE_BONUS_ATTR_MAP 疑似笔误**：`speedBonus → speedBonus` 自映射（其余三条均为 bonus→主属性），速度加成的反向同步当前是空操作。按红线未改，建议确认后改为 `ATTRIBUTE_CODE.speed`。
3. **JSON import 断言（约 40 处 `as unknown as`）**：configs JSON → 类型断言（xiyouData/debugActions/caveLogic/battle/ConfigDataSource/seed 等）属持久化形态宽容点，保留。天花板：数据结构漂移时编译期无感；建议路径：统一 `loadJson<T>(raw, guard)` 守卫收口后一次性消除（牵动面大，未在本次执行）。
4. **`unified-attrs.ts` SHORT_TO_CODE**：demo 旧存档兼容层，`RES→'resist'` 为码表外遗留值，值侧保留 string（已加宽容点注释）。
5. **calculation-utils / combat-record 的 extraValues 链**：源头为 configs 技能 JSON 自由键（历史键宽容），输出端保留 string + 消费点窄化断言，强收为假收敛。
6. **`battleStore.ts:615` `false as unknown as F` 泛型兜底、`save-bridge.ts` 动态键写档**：牵动泛型签名/存档写入路径，保留。
7. **文案分歧清单**（键集相同、值刻意不同，收敛时不得统一）：skillType「大招(schema/EDP) vs 大技能(DataTable)」、「被动 vs 被动技能(SkillTypeName)」；category「属性(schema/EDP) vs 属性修正(DataTable)」；装备阶位 t4/t5「四阶/五阶(schema/EDP) vs 天品/仙品(GearDetailDialog，xiyou 文案域)」；damageReduction 三名并存（见 §六-2）。
