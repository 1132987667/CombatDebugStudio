# 常用提示词

## 语句 1：从第一性原理出发，评审上个回答的方案

```
上下文：上个回答的方案是指在本次会话中，针对我上一个请求给出的具体方案。
- 如果这是新会话，先告诉我"上个回答的方案"具体指什么，我们确认后再开始
- 如果方案涉及多个文件或步骤，一一点名

从第一性原理出发评审该方案。

具体要求：
1. 回到最基本的公理：提示词/方案的唯一目的是让 AI 在最少交互回合内产出正确代码改动
2. 针对每条公理，用三列表示：
   | 公理 | 方案的实际表现 | 是否符合（✅/❌）|
3. 至少列出 4 条公理
4. 评审完毕后，给出一个保留/修改/废弃的建议
```

## 语句 2：对抗式评审上个回答的方案

```


对抗式评审该方案。

具体要求：
1. 假设你的目标是让这个方案失败，攻击它的设计缺陷
2. 至少列出 4 种攻击角度，按攻击的成功概率从高到低排列
3. 每个攻击必须包含：
   - 攻击点：方案中哪个具体设计有问题
   - 攻击方式：你会怎么利用这个缺陷让方案失效
   - 真实场景：举一个具体例子说明攻击如何生效
4. 每个攻击用三行以内说完，不要展开大段论述
5. 评审完毕后，给出该方案在对抗视角下的脆弱性评级（低/中/高）
```

## 语句 3：根据以上评审意见给出新的修改方案

```

- 你现在要基于这前几轮评审的结论来回应

1. 把前几轮评审发现的每个缺陷列出来，标记状态（已采纳/已驳斥/部分采纳）
2. 对于已采纳的缺陷，给出具体的新方案来解决它
3. 对于已驳斥的缺陷，说明为什么原方案是正确的
4. 最终产出物必须写入文件，路径按我的要求指定

输出格式：
## 缺陷清单
| 缺陷 | 来源（评审1/评审2） | 状态 | 解决方案 |
|------|-------------------|------|---------|

## 修改方案
```
