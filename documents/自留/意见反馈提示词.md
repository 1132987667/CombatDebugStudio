【数据导出格式要求】 导出不能只是把表 dump 成 JSON，须同时满足以下对格式的硬性要求（这也是你评估现状、提出建议时的基准）：

- 自描述：包内必须携带 schema 元信息——每张表的列名（中英文）、字段类型、单位、枚举取值、是否必填；做到脱离代码、脱离本系统也能读懂任一字段的含义。
- 语义显式：数值必须标明口径（百分比 / 绝对值 / 区间 / 每级成长），"0.15"要能一眼看出是 15% 还是 0.15 点；区间字段导出为明确的 min/max，不靠约定俗成。
- 引用可解析：外键字段导出时附带被引用实体的可读名（id + 名称），而非裸 id；并给出引用方向，便于顺藤摸瓜。
- 范围自证：meta 必须写明本次导出覆盖哪些表、各表条数、筛选条件、增量基线版本，以及来源（IndexedDB 版本 / configs 重载点）、导出人、导出时间与可选备注。
- 稳定可复现：字段顺序、行序稳定，同一数据版本两次导出逐字节一致，便于版本间 diff 与归档比对。
- 双轨交付：面向程序的 JSON（利于引擎直接消费）+ 面向策划与评审的表格报表（CSV/XLSX 或可读汇总），二者同源、可互相印证。
- 可校验可预览：包内含校验信息（条目数、校验和），导入前先给出差异预览与影响面（新增 / 覆盖 / 删除 / 引用断裂）再落库。
- 工程规范：UTF-8 编码、统一换行符、杜绝乱码；超出单包体积上限时支持分包，并用包间清单关联。
