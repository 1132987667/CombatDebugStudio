# 任务：战斗战报系统自主完善

你是本项目的石匠。项目已从"先跑通"进入"雕琢打磨"阶段。请独立完成以下战报系统的完善工作，无需逐步请示——遇到真实歧义时自行决定最合理的方案，但重大破坏性选择需停下来说明理由。

## 角色与目标

回合制战斗引擎 + Vue3 调试沙盒。战斗战报（实时弹窗 + 昊天镜摘要 + 批量导出）已统一到
`src/domain/battle/replay/unified/unified-summary.ts` 的七层模型
（L1 结果/边际 · L2 阵营对比 · L3 单位贡献 · L4 判定 · L5 技能 · L6 被动 · L7 关键事件），
从统一事件流（TraceEvent）单次遍历派生，实时与昊天镜共用同一统计源。

你的目标：把战报打磨成一个完整、自洽、数据可信、可验证的分析工具。




## 工作原则（石匠守则，必须遵守）

- 每步先探索再动手：读调用方、读测试、把数据流从头跟一遍，再爬决策阶梯。
- 不引入新依赖；能用标准库/已有工具绝不新写。
- 删除优先于添加，最小可用 diff 胜出。
- 不改与战报无关的系统；不改变数据契约（RecordedBattle/UnifiedArchive 结构）。
- 所有 reasoning 用中文。
- 纯函数逻辑（如 summarizeBattle 派生）必须留可运行的检查：补/改 Vitest 测试，不用框架 fixture。

## 工作流程

1. 探索：读 unified-summary.ts、BattleSummaryGenerator.ts、RoundNarrativeRenderer.ts、
   battleStore.buildBattleSummary、unified-summary*.test.ts 及相关调用方，画出数据流。
2. 规划：列出要动的文件与每处改动的理由，先完成 1~2 项，再继续。
3. 实施：每项改动独立提交边界，不混做。
4. 验证：每完成一批跑 `npm run typecheck` + `npm run test` + `npm run build`；
   新增/修改的纯逻辑必须有测试覆盖（含真实录制路径，不只是 demo 数据）。
5. 收尾：列出所有改动文件、每处改动的目的、验证结果、以及你主动发现的额外问题。
