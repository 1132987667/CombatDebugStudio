## 6. 附录：未落地项设计要点（开工输入）

> 本附录从两份源文档提取，只保留**开工所需**的设计要点（数据结构 / 阈值 / 约束 / 验收）；已落地项不在此列（以代码为准）。**状态仍以 §2 为准**，本附录只是设计参考。

### B0 · 引用服务底座

- 改动集中在 `src/application/service/DataIntegrityService.ts` 一个文件。
- 目标：一次遍历建 `Map<表, Map<id, 实体>>` + `Map<表, Set<id>>`；`elements` 文档型单独建 id 集。
- `runHealthCheck` / `scanDuplicateRefs` / `assertDeletable` / `findReferencing` / `validateOnSave` 改读索引，不再各自 `listAll`；`existsIn` 由逐条 `get` 改为 Set 命中。
- 索引生命周期：**单次调用内构建复用**（不做跨调用缓存 + 失效链）。
- 复杂度改善：`O(规则数 × 全表)` → `O(表数 × 全表)`。
- 验收：`tests/unit/fengshen-data.test.ts` 全绿，无断言变化（纯等价重构）。

### B1a · 影响面推演

- 现有 `findReferencing` 三个盲区：① 只覆盖声明式 `REFERENCE_RULES`；② 无二级引用；③ 点开才扫。
- 目标：直接 / 间接分层的引用树；前置到编辑抽屉，改动**之前**提示"本次改动将影响 N 个实体"。
- 边界：仅声明式引用；公式类软引用（装备公式、属性公式）登记为已知盲区。

### B1b · 属性中心

- 同一语义属性散落在 6 处，口径各异，需**新建**"属性出现规则表" + 6 个提取器：

| 位置 | 字段形态 |
|---|---|
| `attributes` | `code` 字符串 |
| `player_config` | MAP 键 |
| `system_distribution` | 区间 / 公式 |
| `equipment_affixes.valueRange` | `{min, max}` |
| `affixes.statModifiers` | 数组元素 `attribute` |
| `growth.perLevel` | MAP 键 |

- 每行显示：表名 + 行 ID + 该处值 + 口径标签（基准值 / 派生值 / 引用值），可点击跳转。
- 注意：现有 `refIndex` 是 id→中文名翻译字典，**不能**复用为引用图。

### B2 · 交付闭环

- 导入 dry-run：按当前策略输出「新增 / 覆盖 / 跳过」三份清单（含字段级 diff），确认后再落库；`overwrite` 执行前自动导一份当前快照兜底。
- `overwrite` 语义澄清：只清**包内清单里**的表，包里未带的表原样保留（极易被误读为整库重置）。
- 导出 meta 补：导出人 / 用途 / 覆盖范围 / 目标消费方。
- 双源漂移检查：库内 vs `configs/` 同名表对比，列出被手改 / 新增 / 删除；操作分级为「仅看差异 / 仅重载差异表 / 全量重置」。
- 快照（源自规划 §3.6）：

```ts
interface ValueSnapshot {
  id: string                    // snap_<timestamp>
  label: string                 // 策划命名，如「9.15 平衡版」
  createdAt: number
  tables: Record<string, unknown>   // 仅 params 域结构化表深拷贝
}
interface SnapshotDiffResult {
  added: Array<{ table: string; key: string }>
  removed: Array<{ table: string; key: string }>
  changed: Array<{
    table: string; key: string; field: string
    before: number; after: number
    deltaPercent: number        // |Δ| > 10% 时 UI 高亮
    sapImpact?: number          // 仅六维属性换算
  }>
}
```

- 存储：IndexedDB（复用 `IPersistentStorage`），保留最近 20 份 + 溢出提示；只快照 params 域（估 < 1MB/份），不快照全量 xiyou/装备表（它们有 `configs/` JSON 作版本真相）。
- 回滚 = 用 `tables` 覆盖对应表并写操作日志（`OperationLogEntry` 已有）；对比粒度：表 → 行 → 字段三级下钻。
- 包 vs 包 diff：按表 / 按 ID 输出「新增 / 删除 / 字段变更」三色，可导出。

### B3 · 校验与体检

- 敌人曲线规则（源自规划 §3.5，每条输出一个 `ValidationIssue`）：

| 规则 | 判定 | 级别 |
|---|---|---|
| 等级-属性曲线偏离 | vs `enemyMeanStatsByLevel`（`data-insight.ts` 已有）偏离 > ±40% / > ±100% | warn / error |
| 秒杀 / 永动机 | TTK < 1 回合 或 > 30 回合 | error |
| 经验 / 金钱曲线 | vs `enemy_reward_table` 同级基准偏离 > ±30% | warn |
| 异常字面值 | 属性值 ≥ 10000 且等级 ≤ 10 | error |

- 平衡性校验（源自规划 §3.9）：`BalanceReport { systemDeviations[], uncoveredAttributes[], outOfRangeAffixes[], pillOverCap, balanceScore }`。`AuditView` 已有预算权重条 + 词条频次，增量是 **SAP 口径折算 + 偏差判定**（>10% warn / >50% error），不重建展示。
- 数值体检报表（建议 11）：每系统「预算 vs 实际投放」达成条；每属性区间覆盖率直方图（统计落在配置区间外 / 边界上的实体数）；装备按公式**模拟出的**六维分布（静态表已无频次可统计）；一键导出带表头说明、生成时间、`dataVersion` 的 CSV / Markdown。
- 异常值预警（建议 14）：同分组（同 `role` 敌人 / 同 `slot` 装备）算均值与方差，±3σ 外标「建议复核」而非硬拦截；规则配置化挂到校验注册表，避免每加一条就改代码。

### B4 · 模拟线

- TTK 曲线：满配玩家 vs 各等级敌人均值装，期望击杀回合数折线；健康区间默认 3~8 回合，区间外标红（秒杀怪 = 投放过量，打不死 = 投放不足）。
- 胜率蒙特卡洛：同装配模拟 N 场（默认 200，上限 2000），固定种子，输出胜率 + 回合数直方图，分「碾压 / 健康 / 胶着 / 翻车」四档。
- 压制矩阵：等级（1~50）× 品阶（t1~t5）网格，每格填 TTK / 胜率热力色。
- A/B 对拼：两套玩家配置互打 200 场。
- 养成瓶颈分析：逐个移除某系统投放再模拟，胜率跌幅最大者即当前瓶颈。
- 数据结构：

```ts
interface BattleSimulateRequest {
  playerConfig: PlayerGrowthConfig
  equippedSkills?: string[]
  enemySelector:
    | { kind: 'single'; enemyId: string }
    | { kind: 'byScene'; sceneId: string }
    | { kind: 'byLevel'; from: number; to: number }
  runs: number          // 默认 200，上限 2000
  maxRounds: number     // 默认 50
  seed?: number
}
interface BattleSimulateReport {
  seed: number
  perLevel: Array<{
    level: number
    ttk: number
    winRate: number
    roundsHistogram: Record<number, number>
    status: 'stomp' | 'healthy' | 'close' | 'losing'
  }>
  bottlenecks?: Array<{ system: string; winRateDrop: number }>
}
```

- 实现约束（关键）：`domain/fengshen/battle-simulator.ts` **只做编排**（装配 → 循环 → 聚合），结算全部调用现有 `BattleSystem`，禁止复制结算公式；种子经 `battleData.rng` 注入（第 i 场用 `seed + i` 派生），不引入第二套随机源；浏览器侧与单测同装配链路（`tests/unit/lianji-battle-sim.test.ts` 为先例）；分帧调度（每帧 10 场）+ 进度条，**单场 > 5ms 再上 Web Worker**（不预先优化）。
- 性能预算：200 场 × ≤50 回合，目标 < 2s（< 1s 更佳）。
- 战力估算（源自规划 §3.10）：**不自建战力公式**，退化为本批输出的汇总视图——战力 = 模拟胜率 × 1000 归一化；推荐挑战关卡 = 胜率落在 60%~90% 的场景。
- 数值溯源（建议 15）：选中实体 + 属性，输出完整推导链（基础值 → 成长 → 词条 → Buff → 最终），并支持反向提问「若把 X 改成 Y，谁会变」——把影响面 + 公式引用 + 运行时模拟串起来的收口。

### 验收口径（源自规划 §八）

标注「自动」= vitest 断言随功能落地交付；「人工」= 浏览器实操验收。

| 项 | 验收标准 | 方式 |
|---|---|---|
| 系统投放 | 配 3 条属性规则、实时显示偏差 | 人工 + 自动 |
| 装备生成 | 固定种子生成 100 件 50 级仙品武器，核心属性在公式区间内；同种子二次生成逐字节一致 | 自动 |
| 属性上限 | 构造超标属性 → error 拦截保存 + quickFix 钳回 | 自动 |
| 校验分级 | error / warn / info 三级各构造一条，HealthView 分类 / 过滤 / 跳转正确 | 人工 + 自动 |
| 战斗模拟 | 固定种子跑 200 场，TTK / 胜率输出且分帧不卡（> 200ms/帧即不合格）；与 `lianji-battle-sim` 同配置读数一致 | 自动 + 人工 |
| 消耗品 | 丹药提供 12 点属性、使用等级 50、总点数不超上限 | 自动 |
| 平衡性 | 一键校验输出报告，偏差 > 15% 的系统标红 | 自动 |
| 敌人校验 | 发现 99999 血 1 级怪并标 error | 自动 |
| 快照对比 | 差异高亮无遗漏；回滚后各表与快照逐字段一致 | 自动 |
| 经验曲线 | 曲线上正确出现节点标注与累计经验序列，与表数据一致 | 人工 + 自动 |
| 掉落模拟 | 固定种子模拟 1 万次，统计结果与理论值偏差 < 5% | 自动 |
| 战力估算 | 估算读数与模拟胜率换算值一致（同一数据源，无第二公式） | 自动 |

**回归底线**：全量测试相对当前基线无新增失败（已知存量失败与 flaky 不计入；不写死测试文件数）。

### 贯穿项与开放问题

- 校验分级（规划 §5.5，注册表已落地）：`error` 拦截保存 / `warn` 保存后提示 / `info` 仅展示；`HealthView` 即统一面板。执行时机 = 手动全量校验 + 保存前仅跑 error 级。
- Seeded RNG（规划 §5.6，已落地）：配置生成侧（装备生成 / 掉落模拟）禁止直接 `Math.random()`，种子回填到报告。
- 公式模式边界（规划 §九）：`formula` 用有限模板白名单（`linear` / `poly`），拒绝 `eval` 字符串；分段函数需求出现再加。
- TTK 健康区间（规划 §九）：3~8 回合是否符合「变强 → 碾压 → 再变强」定位待策划确认；碾压期（前 20 级）可能刻意 < 3 回合，建议按等级段可配。
- 压制矩阵敌人取样（规划 §九）：用同等级均值怪还是 Boss？建议双轨都出。
- 快照范围（规划 §九）：是否纳入 params 域以外的表（装备 / 敌人改动频繁时）。
- 模拟场数（规划 §九）：默认 200（±7%）/ 矩阵视图 1000（±3%），耗时差 5 倍，让策划按需选。
