## 1. 项目总览

**太初道枢**是万物法则的源头——「太初」为混沌初开、道法之始，「道枢」为运转一切法则的枢纽。整个系统围绕一套**回合制战斗引擎**展开，以四大模块承载从**数据编定 → 阵容调配 → 实战对局 → 战局分析**的完整闭环：

```
封神榜（定法） → 唤灵台（布阵） → 演劫台（应劫） → 昊天镜（洞悉）
    ↑                                                 │
    └───────────────── 调参反馈 ←─────────────────────┘
```

- **封神榜** 是数据根源：编定角色、技能、Buff 等一切游戏法则；
- **唤灵台** 是当前系统主界面：从封神榜唤请仙灵、搭配阵容、驱动回合制战斗运转；
- **演劫台** 是游戏模块：用封神榜所定数据开启真实回合制对局，实战应验战力与规则；
- **昊天镜** 是战斗分析：照彻演劫台与唤灵台中的每一场战局，调试、检验、分析全过程。

## 2. 命名体系

| 模块   | 类别       | 名称释义                                     | 功能定位                 |
| ------ | ---------- | -------------------------------------------- | ------------------------ |

| 唤灵台 | 阵容战斗   | 登台做法，点将入阵                           | 从封神榜中唤请仙灵，搭配阵容，驱动回合制战斗的运转 |
| 演劫台 | 游戏模块   | 以身入劫，实战应验                           | 利用封神榜所定数据，开启一场真实的回合制对局，亲手验证战力与规则 |
| 昊天镜 | 战斗分析   | 回光溯影，洞悉玄机                           | 照彻演劫台与唤灵台中的每一场战局，调试、检验、分析战斗全过程 |

**模块关系要点**

- 封神榜是唯一的数据源头，唤灵台与演劫台只消费其数据，不自行改数据；
- 唤灵台与演劫台共享同一套战斗引擎（`domain/battle`），各自产出战斗记录；
- 昊天镜消费两处产出的战斗记录，其分析结论反馈回封神榜用于调参。

## 3. 封神榜 — 后台数据管理

> **定万物命格，掌仙班位阶。** 在此编定角色、技能、Buff 等一切游戏法则，乃太初道枢的数据根源。

### 3.1 定位

封神榜是**游戏数据的编定与管理系统**，定义「这个世界里存在什么」。所有被唤灵台、演劫台使用的角色、技能、Buff、敌人、场景、阵型、材料，均在此处确立。数据以 `configs/` 下的 JSON 配置为存储形态，以代码中的类型定义（`src/shared/types/`）为契约。

### 3.2 数据内容（榜单条目）

| 数据域     | 配置文件                      | 内容说明                                                     |
| ---------- | ----------------------------- | ------------------------------------------------------------ |
| 角色       | （CharacterEditor 编辑态）    | 基础属性（等级、气血、攻击、防御、速度、暴击率/伤、各百分比加成）、能量机制、技能绑定 |
| 技能       | `configs/skills/`             | 主动技能（消耗、冷却、目标选择、步骤编排、伤害/治疗计算配置）与被动技能（触发条件、效果） |
| Buff/效果  | `configs/buffs/`、`configs/effects/` | 原子效果（属性修正、持续伤害、治疗、护盾、控制、免疫、光环、触发）+ 自包含脚本（`domain/buff/scripts/`） |
| 敌人       | `configs/enemies/`            | 敌人属性、技能、掉落物（材料/消耗品 + 概率）                  |
| 场景       | `configs/scenes/`             | 场景背景、多难度敌人配置、所需等级、通关奖励（经验/金币）；难度编组可直接列敌人，也可引用预设阵容（含角色 + 阵型） |
| 阵型       | `configs/formations/`         | 站位布局（前排/后排）、阵型增益 Buff、前排保护规则            |
| 预设阵容   | `configs/lineups/`            | 角色组合 + 阵型绑定 + 阵营（我方/敌方） + 用途标签，供场景难度引用与唤灵台一键布阵 |
| 材料       | `configs/materials/`          | 材料与消耗品（稀有度、描述、使用效果）                        |
| 装备       | `configs/materials/`（待拆分独立域） | 部位（武器/防具/饰品）、属性加成、穿戴等级门槛、阵营限制（当前混于材料中，缺加成字段） |
| 阵营元素克制 | （待建）                    | 阵营/元素定义（火/水/木/土/金）与两两克制系数，战斗模块读取影响伤害/命中修正 |
| 成长曲线   | （待建）                      | 角色升级的每级属性增量与经验表，供演劫台养成                 |
| 掉落组     | （待建，演进项）              | 一组物品 + 掉落概率，供敌人引用，替代敌人内嵌 drops          |
| 战斗规则参数 | `configs/params/`           | 伤害倍率、暴击概率、Buff 上限、默认冷却、平衡性系数、校验与调试开关（BattleRulesDialog 参数待收拢） |
| 全局参数   | `configs/params/`             | 全局规则（Buff 上限、默认冷却、平衡性系数）、校验与调试开关   |

### 3.3 功能清单

- **角色管理**：编辑角色属性、查看属性详情与公式、重置角色
- **技能管理**：编定技能步骤（造成伤害 / 施加 Buff / 治疗 / 召唤等）、伤害计算配置（基础值 + 属性比率）、目标选择策略
- **Buff 管理**：编定效果时长、叠加规则、生效时机；支持代码脚本级自定义 Buff（自包含脚本模式）
- **敌人与掉落管理**：编定敌人属性、技能组、掉落概率表
- **场景管理**：配置关卡难度、敌人编组、通关奖励、进入等级门槛；难度编组支持两种形态——直接列敌人（`enemyIds`）或引用预设阵容（`lineupId`，含角色 + 阵型）
- **阵型管理**：配置站位与阵型增益
- **预设阵容管理**：编定角色组合、绑定阵型、标注阵营（我方/敌方）与用途标签，供场景难度引用与唤灵台一键布阵
- **装备管理**：编定装备部位、属性加成、穿戴门槛，供角色装配与演劫台养成（当前混于材料域，待独立）
- **阵营元素克制管理**：编定阵营/元素克制系数，战斗模块读取修正伤害/命中（当前数据未建模）
- **成长曲线管理**：编定角色升级的每级属性增量与经验表（当前仅编辑器枚举文本）
- **战斗规则参数管理**：集中管理伤害倍率、暴击概率等调参参数，收拢 BattleRulesDialog 与计算器中的可调值
- **掉落组管理**（演进项）：编定物品组 + 概率供敌人引用，替代敌人内嵌 drops
- **图鉴**：以只读图鉴形式总览已编定的角色、技能、Buff、敌人、物品（当前实现形态）

### 3.4 现状与规划

- ✅ **已实现**：`configs/` 全量数据 + 类型契约；预设阵容示例（`configs/lineups/lineups.json`）已建；角色编辑对话框（`CharacterEditor.vue`）、图鉴对话框（`CompendiumDialog.vue`）、场景管理对话框（`SceneManagementDialog.vue`）承担部分编辑/浏览职能
- 🚧 **规划中**：独立的后台管理页面形态（完整的 CRUD、数据校验、版本管理），目前数据以 JSON 文件手工维护；场景难度引用预设阵容（`lineupId`）的读取逻辑待接入；装备（混于材料）、阵营克制、成长曲线、战斗规则参数、掉落组五个数据域待补充建模

## 4. 唤灵台 — 阵容战斗

> **登台做法，点将入阵。** 从封神榜中唤请仙灵，搭配阵容，驱动回合制战斗的运转。

唤灵台是**当前系统的主界面**，即 `BattleArena.vue` 承载的整页应用。它把封神榜编定的角色唤请上场、排布阵容，驱动战斗引擎跑完一场回合制战斗。这里强调的是「操作与验证」：随时可打、可停、可调。

│ （角色选择、  │  （角色卡、技能、动画、    │  （角色监控：      │

### 4.3 功能清单

- **参战面板**（`ParticipantPanel.vue`）：勾选启用/禁用角色、点击头像查看属性、拖拽调整出战顺序

- **战斗控制**（`ControlBar.vue`）：开始/结束/重置战斗、暂停/继续、自动战斗、倍速调节

- **战斗规则设置**（`BattleRulesDialog.vue`）：调整伤害倍率、暴击概率等规则参数
- **场景切换**：从已配置场景载入敌人编组开战（难度编组可为直接敌人列表或预设阵容）
- **预设阵容布阵**：参战面板可从封神榜预设阵容（`configs/lineups/`）一键点将入阵，自动套用阵型站位与增益
- **快捷键**：键盘操作支持（`KeybindManager`）

### 4.4 现状与规划

- ✅ **已实现**：完整的单页战斗界面（`BattleArena.vue`），战斗引擎全流程可用（编队 → 开始 → AI 决策 → 技能执行 → 伤害计算 → Buff 生效 → 结束判定）

## 5. 演劫台 — 游戏模块

> **以身入劫，实战应验。** 利用封神榜所定数据，开启一场真实的回合制对局，亲手验证战力与规则。

### 5.1 定位

演劫台是把封神榜数据**做成"一款游戏"**的模块：玩家不再是调试者，而是入劫者。它提供关卡推进、队伍养成、掉落收集、奖励结算等游戏化体验，底层复用同一套回合制战斗引擎与数据。唤灵台侧重「调试沙盒式验证」，演劫台侧重「产品化对局」。

### 5.2 规划功能清单

- **关卡（劫）推进**：按封神榜场景配置逐劫闯关，含难度分级（易/普/难）、进入等级门槛、通关奖励结算；敌方编组由场景定义，可直接列敌人或引用预设阵容（角色 + 阵型）
- **队伍养成**：角色等级成长、基础属性随等级成长、经验获取
- **阵容搭配**：复用唤灵台的出战选择与阵型增益规则
- **战斗对局**：复用战斗引擎，玩家手动操作或自动战斗，AI 驱动敌方
- **掉落收集**：战后按敌人掉落表（`drops`：材料/消耗品 + 概率）结算战利品
- **资源管理**：金币、材料、消耗品（`materials/`）的获取与使用
- **战局留痕**：每场对局自动产出战斗记录，供昊天镜照彻分析
- **存档**：队伍进度、背包、关卡进度的持久化（基于现有 IndexedDB 存储层）

### 5.3 现状与规划

- 🟡 **数据雏形已就绪**：`configs/scenes/`（难度、奖励、所需等级）、`configs/enemies/`（掉落）、`configs/materials/`（材料与消耗品）、`configs/formations/`（阵型）已按游戏化数据建模，只待模块开发
- 🚧 **规划中**：完整模块尚未开发，是四模块中唯一的新建模块

## 6. 昊天镜 — 战斗分析

> **回光溯影，洞悉玄机。** 照彻演劫台与唤灵台中的每一场战局，调试、检验、分析战斗全过程。

### 6.1 定位

昊天镜是**战斗调试、回放与分析中心**，消费唤灵台与演劫台产出的战斗记录。它让开发者/玩家回到战局中任何一刻，逐帧查看伤害链路、Buff 流转、状态变化，是「验证规则正确性」与「定位战斗问题」的核心工具。

### 6.2 功能清单

- **战斗录制与回放**：战斗中自动录制行动记录（`BattleRecorder`），回放引擎（`ReplayEngine` + `BattleReplay.vue`）重现整场战局，逐行动查看攻击/技能/伤害/治疗详情
- **调试日志**（`DebugLogDialog.vue` + `TraceLogTree.vue`）：以树形断点视图检视战斗事件链路（伤害计算、Buff 判定、AI 决策）
- **调试控制面板**（`DebugControlDialog.vue`）：按模块分类的调试动作——状态修改（气血/能量/属性/Buff 施加与移除）、动画调试（爆点样式切换）、数据生成（批量战斗数据供统计分析）、流程控制
- **数据快照**（`DataSnapshotDialog.vue`）：导出/检视战斗关键节点数据
- **实时角色监控**（`BattleDashboard.vue`）：战斗中选中角色，实时查看核心/进阶/情境/隐藏层级属性、属性加成、Buff、技能信息
- **战斗结算摘要**：战后胜负判定、伤害统计、战斗概览
- **日志体系**：日志收集 → 解析 → 渲染三层架构，支持分类过滤、层级过滤

### 6.3 现状与规划

- ✅ **已实现**：录制/回放、调试日志树、调试控制面板、数据快照、实时监控、结算摘要均已在唤灵台页面中以对话框/面板形态落地
- 🚧 **规划中**：升级为独立模块页面，聚合回放、日志、快照为统一分析工作台

## 7. 模块间数据流

```
┌────────────┐   configs/ JSON + 类型契约   ┌────────────┐
│   封神榜    │ ────────────────────────────→ │   唤灵台    │
│ （数据根源） │                              │ （阵容战斗） │
└────────────┘                              └─────┬──────┘
      ▲                                           │ 战斗记录
      │                                           ▼
      │                                   ┌────────────┐
      │  调参反馈（分析结论 → 修订数据）      │   昊天镜    │
      │                                   │ （战斗分析） │
      │                                   └────────────┘
      │                                           ▲
┌─────┴────────────┐                              │ 战斗记录
│     演劫台       │ ─────────────────────────────┘
│   （游戏模块）    │
└──────────────────┘
```

1. **封神榜 → 唤灵台 / 演劫台**：提供全部游戏数据（角色、技能、Buff、敌人、场景、阵型、材料、装备、阵营克制、成长曲线、掉落组、规则参数），只读消费；
2. **唤灵台 / 演劫台 → 昊天镜**：各自跑出的战斗被录制为战斗记录，统一送入昊天镜；
3. **昊天镜 → 封神榜**：分析结论（伤害不平衡、Buff 过强、规则 bug）驱动封神榜数据修订，形成闭环。

三处技术共享：同一套 `domain/` 战斗引擎、同一套 `configs/` 数据源、同一套事件/日志/存储基础设施。

## 8. 技术架构

沿用 DDD 四层架构，依赖方向由外向内，领域层不依赖任何外层代码：

| 层             | 内容                                                         | 承担模块职能                     |
| -------------- | ------------------------------------------------------------ | -------------------------------- |
| presentation/  | Vue 组件 / Pinia Store / Composable / 样式                   | 四模块 UI（唤灵台为主界面）      |
| application/   | 用例编排：BattleFacade（服务门面）、BattleProjection（投影层）、BattleDataGenerator | 四模块业务编排、UI 快照桥接     |
| domain/        | 战斗引擎（回合/AI/技能/伤害/Buff/规则/录制/回放）、属性系统、Buff 脚本、端口接口 | 战斗规则与数据法则（封神榜根基） |
| infrastructure/| DI 容器、事件总线（Battle/Trigger/UI）、日志（BattleLogManager）、存储（IndexedDB + 迁移）、动画调度、快捷键 | 四模块共用的底座                 |

数据契约：`configs/` JSON ↔ `src/shared/types/` 类型定义；领域实体 → 投影层（`BattleProjection` + `participantMapper`）→ UI 纯数据快照（`UIParticipantSnapshot`），Vue 组件不直接绑定领域实体。

- **M4 · 昊天一统**：回放、日志、快照聚合为统一分析工作台，分析结论回流封神榜
