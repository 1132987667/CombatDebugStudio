## 0. 设计前提与定位

在谈属性之前，先定游戏形态，否则所有数值都是空中楼阁。

### 0.1 产品定位（演劫台）

| 维度 | 设定 | 依据 |
| ---- | ---- | ---- |
| 品类 | 封神题材·仙灵收集·回合制 | 五行元素克制（金木水火土）是核心特色 |
| 对战形态 | 我方 4 人阵 vs 敌方编组 | 现有引擎 4v4、yaotu 五人组原型 |
| 核心循环 | 闯关 → 得材料/经验 → 养成 → 变强 → 闯更难关 | 演劫台定位（§5） |
| 存档模式 | 单机优先，IndexedDB 本地存档 | 现有存储层 |
| 内容体量 | 中小型：角色 ~30、关卡 ~10 章 × 多难度、技能 ~80 | 现阶段 configs 规模 |

> 单机 + 本地存档 = **数值以"可玩性"而非"付费坑"为目标**，养成节奏求稳不求急。

### 0.2 核心设计原则

1. **属性可见即所用**：玩家面板上每个数字都参与某个战斗公式；引擎内部可以有隐藏/上下文属性（如 `damageDealt`），但**玩家面板只展示有明确意义的属性**。
2. **属性收敛**：现有 `attributes.json` 的 60+ 属性，产品化需收敛为 ~20 个玩家可感知属性 + 一批引擎内部派生属性（含 tag 免疫，见《数值体系搭建指南》§3）。
3. **成长有预算**：任何属性的总成长 = 各养成子系统供给之和，系统设计时**先定预算占比**，再做内容，避免"某个子系统一家独大"。
4. **防御永远可破防**：减法防御公式下（`damage - defense`），任何等级的敌人防御必须低于玩家最低攻击 × 0.85（沿用现有平衡脚本断言），否则出现"打 1 点"的体验事故。
5. **TTK 可验收**：任何数值改动后能跑通"TTK 模拟"验收（1v1 约 6~12 回合，4v4 约 4~10 回合），不靠手感。

## 1. 玩家属性怎么设计（属性体系）

### 1.1 属性分层模型

把属性按"玩家可感知程度"分成四层，是收敛 60+ 属性的总纲：

```
┌────────────────────────────────────────────────────┐
│ 显示层（玩家面板，~15 个）                            │
│   白板属性 × 4 + 概率属性 × 4 + 元素属性 × 7 + 机制 × 2  │
├────────────────────────────────────────────────────┤
│ 公式层（引擎消费，显示层属性的运算来源）               │
│   加法/百分比/独立乘/最终乘 四类修饰符                │
├────────────────────────────────────────────────────┤
│ 派生层（由白板换算得出，不直接配置）                  │
│   effectiveDefense / 防御系数 / 暴击期望等            │
├────────────────────────────────────────────────────┤
│ 隐藏层（引擎内部，不展示）                           │
│   tag 免疫 · damageDealt/damageTaken 上下文 · 布尔免疫 │
└────────────────────────────────────────────────────┘
```

> 对应现有 `ParticipantStats` 的四段式计算管线（`base → 百分比 → 独立乘 → 最终乘`），
> 显示层属性 = 白板（base + 加算）走百分比/乘区后的最终值。

### 1.2 玩家面板属性清单（推荐）

| 组 | 属性 | 引擎 code | 说明 | 参与公式 |
| ---- | ---- | ---- | ---- | ---- |
| 白板（随等级成长） | 气血 | `maxHealth` | 生存基线 | 伤害结算 |
| | 攻击 | `attack` | 伤害基线 | 基础伤害 `attack × (1±15%)` |
| | 防御 | `defense` | 减法减免 | `damage - defense` |
| | 速度 | `speed` | 行动顺序 | 回合排序 |
| 概率（靠养成/词条） | 暴击率 | `critRate` | 默认 10% | 暴击判定 |
| | 暴击伤害 | `critDamage` | 默认 125% | 暴击倍率 |
| | 命中率 | `hit` | 默认 90% | 命中判定 |
| | 闪避率 | `dodge` | 默认 10% | 命中判定（引擎门控） |
| 元素（五行特色） | 五行抗性 ×5 | `metalRes`…`earthRes` | 对应元素减伤 | 元素抗性环节 |
| | 元素伤害加成 | `fireSkillDmgBonus` 等（按角色所属元素取 1 个） | 所属元素增伤 | 来源方加成 |
| 机制 | 最大能量 | `maxEnergy` | 固定 200 | 技能释放 |
| | 治疗加成 | `healReceived` | 受疗修正 | 治疗结算 |

**面板总计 ~16 个**。其余全部降级到隐藏层或删除。

### 1.3 建议从面板降级/删除的属性（收敛清单）

现有 `attributes.json` 中以下属性**不进玩家面板**：

| 处理 | 属性 | 理由 |
| ---- | ---- | ---- |
| 收敛为 tag 免疫 | `slowImmune` `stunResist` `knockbackResist` `poisonResist` `bleedResist` `burnImmune` | 布尔免疫 → `immunities: ["stun"]`（见《搭建指南》§3.5） |
| 降为隐藏/上下文 | `damageDealt` `damageTaken` | 技能链计算临时值，战斗中变化，不展示 |
| 降为隐藏/保留 | `damageReduction` `damageTakenIncrease` `damageBoost` `trueDamageRate` | 参与公式但玩家难以理解，留在引擎层，仅调试面板展示 |
| 降为隐藏/保留 | `normalAtkDmgReduction` `skillDmgReduction` `critDmgTakenReduction` `physicalSkillDmgBonus` `damageToLowHp` `damageToDemon` `demonDamage` | 专项加成，属技能设计细节，不进主面板 |
| 降为隐藏/保留 | `comboRate` `counterRate` `reflectDamagePercent` `shield` `controlSuccessRate` `controlDurationReduction` `debuffImmunityRate` `poisonRes` `webSuccessRate` `burnDuration` `fireDamage` `fireDamageTaken` `waterDamageTaken` `lightningDamageTaken` `hpRegenPercent` `hpRegenFlat` `skillCooldown` | 机制属性，由 Buff/装备供给，调试面板可见 |
| 删除 | `currentHealth` `currentEnergy` | 运行时状态（`isRuntimeState`），不是"可养成属性"，面板显示但不在属性列表 |
| 待定 | `waterAtk` `fireAtk` `metalAtk` `woodAtk` `earthAtk` 五行攻击 | **决策点 D1**（见 §6），建议不拆 5 个攻击 |

### 1.4 属性数值规范

| 规范项 | 约定 | 依据 |
| ---- | ---- | ---- |
| 数值范围 | 遵循 `attributes.json` 的 `range` 字段 | 封神榜校验（§4.2） |
| 百分比表达 | `isPercentage` 属性 UI 统一 % 显示，引擎内部 100 = 100% | 现有 `critRate` 模型 |
| 小数处理 | 伤害 `floor` 取整；属性值 `round(value, 2)` | `DamageCalculator`/`ParticipantStats` |
| 上限约束 | 暴击/命中/闪避/免伤硬上限（见下） | 防数值失控 |

**概率类硬上限建议**：

| 属性 | 上限 | 理由 |
| ---- | ---- | ---- |
| 暴击率 | 100% | 超出无意义 |
| 命中率 | 100% | 同 |
| 闪避率 | 75% | 现有 range 已定，保留 25% 必中空间 |
| 免伤率 | 90% | 防无限减伤 |
| 元素抗性 | 80% | 五行克制需保留穿透空间 |

## 2. 怎么成长（等级与成长曲线）

### 2.1 成长来源总览

玩家角色的成长只有一条主轴线——**等级**，其余养成子系统（§3）挂在其上做乘区放大：

```
白板属性(基础值)
  └─ 每升 1 级：白板 += 成长曲线每级增量（线性/分段）
  └─ 装备：在 base+加算 上加固定值（ADDITIVE）
  └─ 突破/升星：百分比加成（PERCENTAGE）
  └─ 阵型/天赋：独立乘区/最终乘区（MULTIPLICATIVE/FINAL）
```

### 2.2 等级体系

| 决策 | 推荐 | 理由 |
| ---- | ---- | ---- |
| 等级上限 | 50（现 schema 允许 1–99，取 50 控量） | 中小型内容，等级段太长会稀释每级成长感 |
| 升级经验 | 每级线性递增：`exp(L) = 100 × L` | 前期快后期慢，节奏自然 |
| 等级影响 | 仅白板属性成长；不做等级压制（决策点 D2 已拍板） | 减法公式下等级压制会放大破防问题 |

### 2.3 成长曲线设计（核心交付物）

**设计方法**：五份职业模板各一条曲线，互有侧重。以现有 yaotu 五兄弟为原型（数值来自 `balance-check.cjs`）：

| 职业原型 | 现有角色 | 定位 | 曲线侧重 |
| ---- | ---- | ---- | ---- |
| 输出 | yaotu_fire（hp350/atk70） | 高攻低防 | 攻↑↑ 血↓ 防↓ |
| 暴击/均衡 | yaotu_gold（hp430/atk58） | 攻守兼备 | 攻↑ 血↑ 防↑ |
| 速度/控制 | yaotu_water（hp390/atk48） | 先手压制 | 速↑↑ |
| 治疗/持续 | yaotu_wood（hp410/atk52） | 续航 | 血↑ 速↑ |
| 坦克 | yaotu_earth（hp520/atk40/def25） | 高血高防 | 血↑↑ 防↑↑ 攻↓↓ |

**推荐曲线形式（决策点 D3 已拍板）**：`模板系数（连续成长）+ 里程碑表（离散奖励）`——
每级增量 = `基础增量 × 成长系数`，五职业各一套系数；10/20/30/40/50 级里程碑表表达特殊等级奖励（解锁技能、+5% 暴击等）：

```jsonc
// configs/params/curves.json （D3 拍板形态）
{
  "player": {
    "maxLevel": 50,
    "templates": {
      "attacker": { "hp": 8, "atk": 6, "def": 3, "spd": 2.5 },
      "tank":     { "hp": 14, "atk": 2.5, "def": 6, "spd": 1.5 },
      "healer":   { "hp": 10, "atk": 3, "def": 3.5, "spd": 2.5 },
      "speedster":{ "hp": 9, "atk": 4, "def": 3, "spd": 3.5 },
      "balanced": { "hp": 11, "atk": 4, "def": 4, "spd": 2 }
    }
  },
  "milestones": {
    "10": { "unlockSkill": true },
    "20": { "bonus": { "critRate": 5 } },
    "30": { "unlockSkill": true },
    "40": { "bonus": { "critRate": 5 } },
    "50": { "bonus": { "attackBonus": 20 } }
  },
  "enemy": {
    "hp":  { "base": 80, "perLevel": 11 },
    "atk": { "base": 10, "perLevel": 2.0 },
    "def": { "base": 1,  "perLevel": 0.9 },
    "spd": { "base": 10, "perLevel": 1.2 }
  }
}
```

> 敌人曲线沿用现有 `rebalance-enemies.cjs` 的线性公式（HP=80+11(L-1) 等）。
> 玩家曲线 = 职业模板系数 × 等级，等级 1 时与敌人同段位、随等级拉开差距（主角团定位）。

### 2.4 成长曲线与敌人曲线的关系（关键约束）

玩家 vs 敌人的相对强度直接决定战斗体验，用**等级差模型**看：

| 玩家等级 vs 敌人等级 | 体验 | 约束 |
| ---- | ---- | ---- |
| 玩家 -3 ~ 0 | 有挑战 | TTK ≈ 8~12 回合 |
| 玩家 = 敌人 | 正常 | TTK ≈ 6~10 回合 |
| 玩家 +1 ~ +3 | 碾压 | TTK ≈ 3~5 回合 |

**必须满足**：任何等级下 `敌人def < 我方最低攻击 × 0.85`（破防约束），
以及 4v4 我方 vs 场景敌方 TTK ∈ [4, 10]（现有 `balance-check.cjs` 断言，沿用为验收标准）。

## 3. 多个子系统怎么养成（养成体系）

### 3.1 子系统总览

演劫台规划 5 个养成子系统 + 2 个组合系统，按"投入产出比稳定→爆发"排序：

| # | 子系统 | 对应现有数据 | 养成内容 | 产出 | 占比建议 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 1 | **角色等级** | 角色 `level` + 成长曲线 | 经验 | 白板四维成长 | 40% |
| 2 | **装备** | `configs/equipment/equipment.json`（36 件，独立域已有） | 穿戴+强化+进阶 | 固定值+随机词条（D7） | 25% |
| 3 | **技能升级** | `skills` 的 `levelValue` | 技能书 | 技能倍率/效果 | 15% |
| 4 | **突破/升星** | 待建（碎片） | 同名碎片/突破石 | 百分比加成+解锁上限 | 15% |
| 5 | **天赋/命盘** | 待建 | 天赋点/道具 | 差异化乘区 | 5% |
| 组合 | **阵型/羁绊** | `formations` + `lineups` | 组队配置 | 全员增益 | — |
| 组合 | **五行克制** | 元素矩阵（待建） | 阵容元素搭配 | 克制系数 | — |

> 占比 = 该子系统对"白板四维最终值"的理论贡献权重（决策点 D4 已拍板：40/25/15/15/5 + 投放阶段模型）。
> 装备 + 技能 + 突破 + 天赋 ≈ 60%，保证"练级之外有养成"；
> 角色等级 40% 保证"练级永远有用"。

**D4 配套：资源投放阶段模型**（占比的落地形态——决定玩家每天把精力花在哪）：

```
前期（1~15级）  等级 60% 装备 10%   —— 没装备可给，升级是唯一主线
中期（16~30级） 等级 40% 装备 30%   —— 装备/技能/突破陆续开放
后期（31~50级） 等级 25% 装备 35%   —— 装备强化与突破收尾，天赋入场
```

### 3.2 子系统详细设计

#### 子系统 1：角色等级（经验）

| 项 | 设计 |
| ---- | ---- |
| 升级方式 | 关卡通关给经验，或经验道具（`materials` 消耗品） |
| 产出 | 白板四维按 §2.3 曲线增长 |
| 上限 | 50 级 |
| 防呆 | 满级后经验道具转为回收资源 |

#### 子系统 2：装备（穿戴 + 强化 + 进阶）

从 `materials` 拆分出独立装备域（规格说明书 §3.6 已规划）：

| 项 | 设计 |
| ---- | ---- |
| 部位 | weapon / armor / accessory × 3 件 |
| 稀有度 | 1~5 星（现有 `rarity` 字段） |
| 基础加成 | `{ attribute, modifierType, value }`：白板属性或百分比（复用 Buff 修饰符合并管线） |
| 穿戴门槛 | `requiredLevel`（现有字段） |
| 阵营限制 | `factionRestriction`（可选，如仅火系，与五行克制联动） |
| 强化 | 强化石（`materials`）→ 提升基础加成数值，设强化上限 |
| 进阶 | 进阶材料 → 稀有度/词条条数提升 |
| 随机词条（决策点 D7 已拍板） | 掉落带随机词条：词条数由稀有度定档（1~5 条），从 `affixes.json` 按部位子集抽取；新增"洗炼"消耗强化石重roll词条（保底，保留最高档） |
| 词条平衡 | TTK 校验用"无词条/满词条"两个端点，中间态不参与断言 |

**装备的修饰符落地**：装备 `stats` 转成 `Modifier`（`sourceType: 'equipment'`）塞进目标角色属性堆栈，
与 Buff 同一管线（现有 `ModifierSourceType.EQUIPMENT` 已存在）。装备脱换 → 修饰符增删 → 版本戳失效重算。

#### 子系统 3：技能升级

| 项 | 设计 |
| ---- | ---- |
| 升级材料 | 技能书（按稀有度分 3 档） |
| 产出 | 技能 `levelValue` 提升 → `calculation.extraValues` 的 `ratio` 上调（如 80% → 90% 攻击） |
| 上限 | 技能等级 1~10，与角色等级挂钩（`技能上限 = min(10, 角色等级/5)`） |
| 表达 | 技能描述按等级动态显示数值 |

> 技能数值 = `baseValue` + `attribute × ratio`（现有结构），升级只调 `ratio`，天然跟随攻击成长，不会脱节。

#### 子系统 4：突破/升星

| 项 | 设计 |
| ---- | ---- |
| 材料（决策点 D6 已拍板） | 角色碎片（关卡掉落为主 + 商店兑换保底，不做抽卡）+ 突破石（精英/Boss） |
| 产出 | 每星给全体白板 × 5% 百分比加成（PERCENTAGE 修饰符）；星级还解锁技能等级上限 |
| 上限 | 6 星 |
| 玩家感知 | 星级变化即时反映在面板百分比 |

#### 子系统 5：天赋/命盘（差异化，最低优先级）

| 项 | 设计 |
| ---- | ---- |
| 材料 | 天赋点（关卡首通/成就） |
| 产出 | 独立乘区/最终乘区修饰符（`MULTIPLICATIVE`/`FINAL`），构建流派（如"暴击流""连击流"） |
| 上限 | 每职业一棵树，节点 ~10 个 |

> **说明**：天赋系统优先级最低（占比仅 5%，决策点 D9 已拍板：MVP 后置）。先把 1~4 跑通。

#### 组合系统：阵型/羁绊

| 项 | 设计 |
| ---- | ---- |
| 阵型 | `formations` 站位 + 阵型增益 Buff（已有数据） |
| 羁绊 | 特定角色组合上阵触发额外增益（新数据，可后置） |

### 3.4 战力模型（可选）

> 战力 = 数值强度的一维化，供关卡门槛/自动战斗判断用。**决策点 D5 已拍板：MVP 后置**——
> 关卡门槛沿用 `scenes.requiredLevel`，不做 `power` 字段；以下公式留作后置参考。

```
战力 = HP × 0.5 + ATK × 1.2 + DEF × 0.8 + SPD × 1.5

```

权重可调，不参与战斗公式，仅作 UI 展示与关卡推荐。

## 4. 数值平衡框架

### 4.1 公式回顾（引擎已有，确认即可）

- 基础伤害 = `attack × (1 ± 15%)`（无 calculation 时）
- 技能伤害 = `baseValue + Σ(attribute × ratio)`
- 暴击倍率 = `critDamage / 100`
- 防御 = 减法：`damage - defense`（真实伤害跳过）
- 元素抗性/免伤/易伤 = 乘法区，按顺序叠乘
- 钳制：`[1, 9999]`

### 4.2 平衡目标（沿用现有断言，作为验收标准）

| 指标 | 目标 |
| ---- | ---- |
| yaotu 1v1 普攻 TTK | 6~12 回合 |
| 我方 4v4 vs 场景 | 4~10 回合，前期胜、后期有挑战 |
| 破防约束 | 任何敌人 `def < 我方最低攻击 × 0.85` |

### 4.3 平衡工具链（调参 → 验证 → 决策）

```
调整 curves.json / 装备 / 技能 ratio
        ↓
node scripts/rebalance-enemies.cjs   （按曲线重算敌人）
        ↓
node scripts/balance-check.cjs        （TTK 模拟，断言失败即回退）
        ↓
封神榜后台调 battle params            （伤害倍率等）
        ↓
昊天镜回放分析实际战局                （验证手感，反哺调参）
```

### 4.4 数值膨胀控制

1. **属性供给预算**（§3.1 占比）防止多子系统叠加失控；
2. **概率/免伤硬上限**（§1.4）防无限堆叠；
3. **钳制 `[1, 9999]`** 兜底伤害上下限；
4. **防御成长 < 攻击成长** 永续可破防（曲线设计约束）。
