### 2.2 等级体系

| 决策 | 推荐 | 理由 |
| ---- | ---- | ---- |
| 等级上限 | 50（现 schema 允许 1–99，取 50 控量） | 中小型内容，等级段太长会稀释每级成长感 |
| 等级影响 | 仅白板属性成长；不做等级压制（决策点 D2 已拍板） | 减法公式下等级压制会放大破防问题 |


### 2.4 成长曲线与敌人曲线的关系（关键约束）

玩家 vs 敌人的相对强度直接决定战斗体验，用**等级差模型**看：

| 玩家等级 vs 敌人等级 | 体验 | 约束 |
| ---- | ---- | ---- |
| 玩家 -3 ~ 0 | 有挑战 | TTK ≈ 8~12 回合 |
| 玩家 = 敌人 | 正常 | TTK ≈ 6~10 回合 |
| 玩家 +1 ~ +3 | 碾压 | TTK ≈ 3~5 回合 |

**必须满足**：任何等级下 `敌人def < 我方最低攻击 × 0.85`（破防约束），
以及 4v4 我方 vs 场景敌方 TTK ∈ [4, 10]（现有 `balance-check.cjs` 断言，沿用为验收标准）。

## 3. 多个子系统怎么养成（养成体系）

### 3.1 子系统总览

演劫台规划 5 个养成子系统 + 2 个组合系统，按"投入产出比稳定→爆发"排序：

| # | 子系统 | 对应现有数据 | 养成内容 | 产出 | 占比建议 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 1 | **角色等级** | 角色 `level` + 成长曲线 | 经验 | 白板四维成长 | 40% |
| 2 | **装备** | `configs/equipment/equipment.json`（36 件，独立域已有） | 穿戴+强化+进阶 | 固定值+随机词条（D7） | 25% |
| 3 | **技能升级** | `skills` 的 `levelValue` | 技能书 | 技能倍率/效果 | 15% |
| 4 | **突破/升星** | 待建（碎片） | 同名碎片/突破石 | 百分比加成+解锁上限 | 15% |
| 5 | **天赋/命盘** | 待建 | 天赋点/道具 | 差异化乘区 | 5% |
| 组合 | **阵型/羁绊** | `formations` + `lineups` | 组队配置 | 全员增益 | — |
| 组合 | **五行克制** | 元素矩阵（待建） | 阵容元素搭配 | 克制系数 | — |

> 占比 = 该子系统对"白板四维最终值"的理论贡献权重（决策点 D4 已拍板：40/25/15/15/5 + 投放阶段模型）。
> 装备 + 技能 + 突破 + 天赋 ≈ 60%，保证"练级之外有养成"；
> 角色等级 40% 保证"练级永远有用"。

**D4 配套：资源投放阶段模型**（占比的落地形态——决定玩家每天把精力花在哪）：

```
前期（1~15级）  等级 60% 装备 10%   —— 没装备可给，升级是唯一主线
中期（16~30级） 等级 40% 装备 30%   —— 装备/技能/突破陆续开放
后期（31~50级） 等级 25% 装备 35%   —— 装备强化与突破收尾，天赋入场
```

### 3.2 子系统详细设计

#### 子系统 1：角色等级（经验）

| 项 | 设计 |
| ---- | ---- |
| 升级方式 | 关卡通关给经验，或经验道具（`materials` 消耗品） |
| 产出 | 白板四维按 §2.3 曲线增长 |
| 上限 | 50 级 |
| 防呆 | 满级后经验道具转为回收资源 |

#### 子系统 2：装备（穿戴 + 强化 + 进阶）

从 `materials` 拆分出独立装备域（规格说明书 §3.6 已规划）：

| 项 | 设计 |
| ---- | ---- |
| 部位 | weapon / armor / accessory × 3 件 |
| 稀有度 | 1~5 星（现有 `rarity` 字段） |
| 基础加成 | `{ attribute, modifierType, value }`：白板属性或百分比（复用 Buff 修饰符合并管线） |
| 穿戴门槛 | `requiredLevel`（现有字段） |
| 阵营限制 | `factionRestriction`（可选，如仅火系，与五行克制联动） |
| 强化 | 强化石（`materials`）→ 提升基础加成数值，设强化上限 |
| 进阶 | 进阶材料 → 稀有度/词条条数提升 |
| 随机词条（决策点 D7 已拍板） | 掉落带随机词条：词条数由稀有度定档（1~5 条），从 `affixes.json` 按部位子集抽取；新增"洗炼"消耗强化石重roll词条（保底，保留最高档） |
| 词条平衡 | TTK 校验用"无词条/满词条"两个端点，中间态不参与断言 |

**装备的修饰符落地**：装备 `stats` 转成 `Modifier`（`sourceType: 'equipment'`）塞进目标角色属性堆栈，
与 Buff 同一管线（现有 `ModifierSourceType.EQUIPMENT` 已存在）。装备脱换 → 修饰符增删 → 版本戳失效重算。

#### 子系统 3：技能升级

| 项 | 设计 |
| ---- | ---- |
| 升级材料 | 技能书（按稀有度分 3 档） |
| 产出 | 技能 `levelValue` 提升 → `calculation.extraValues` 的 `ratio` 上调（如 80% → 90% 攻击） |
| 上限 | 技能等级 1~10，与角色等级挂钩（`技能上限 = min(10, 角色等级/5)`） |
| 表达 | 技能描述按等级动态显示数值 |

> 技能数值 = `baseValue` + `attribute × ratio`（现有结构），升级只调 `ratio`，天然跟随攻击成长，不会脱节。

#### 子系统 4：突破/升星

| 项 | 设计 |
| ---- | ---- |
| 材料（决策点 D6 已拍板） | 角色碎片（关卡掉落为主 + 商店兑换保底，不做抽卡）+ 突破石（精英/Boss） |
| 产出 | 每星给全体白板 × 5% 百分比加成（PERCENTAGE 修饰符）；星级还解锁技能等级上限 |
| 上限 | 6 星 |
| 玩家感知 | 星级变化即时反映在面板百分比 |

#### 子系统 5：天赋/命盘（差异化，最低优先级）

| 项 | 设计 |
| ---- | ---- |
| 材料 | 天赋点（关卡首通/成就） |
| 产出 | 独立乘区/最终乘区修饰符（`MULTIPLICATIVE`/`FINAL`），构建流派（如"暴击流""连击流"） |
| 上限 | 每职业一棵树，节点 ~10 个 |

> **说明**：天赋系统优先级最低（占比仅 5%，决策点 D9 已拍板：MVP 后置）。先把 1~4 跑通。

#### 组合系统：阵型/羁绊

| 项 | 设计 |
| ---- | ---- |
| 阵型 | `formations` 站位 + 阵型增益 Buff（已有数据） |
| 羁绊 | 特定角色组合上阵触发额外增益（新数据，可后置） |
| 产出 | 全员/同阵营增益（`PERCENTAGE` 修饰符，作用于全队） |

### 3.3 养成资源经济（资源流）

| 资源 | 产出子系统 | 来源 | 消耗 |
| ---- | ---- | ---- | ---- |
| 经验 | 角色等级 | 关卡通关、经验道具 | 升级 |
| 金币 | 通用货币 | 关卡、卖材料 | 强化/进阶 |
| 强化石 | 装备 | 关卡掉落、商店 | 装备强化 |
| 进阶材料 | 装备 | 精英/Boss 掉落 | 装备进阶 |
| 技能书 | 技能 | 关卡、商店 | 技能升级 |
| 角色碎片 | 突破 | 关卡掉落、商店兑底（D6 已拍板，不做抽卡） | 升星 |
| 突破石 | 突破 | 精英/Boss | 升星 |
| 天赋点 | 天赋 | 首通/成就 | 天赋解锁（D9：MVP 后置） |

**资源防溢出**：每种资源设"投入上限"（装备强化上限、技能满级、升星满星），
中后期重复产出转换为通用货币（回收率约 30%）。

### 3.4 战力模型（可选）

> 战力 = 数值强度的一维化，供关卡门槛/自动战斗判断用。**决策点 D5 已拍板：MVP 后置**——
> 关卡门槛沿用 `scenes.requiredLevel`，不做 `power` 字段；以下公式留作后置参考。

```
战力 = HP × 0.5 + ATK × 1.2 + DEF × 0.8 + SPD × 1.5
       + (暴击率/100) × 15 + (暴伤-100)/100 × 10
```

权重可调，不参与战斗公式，仅作 UI 展示与关卡推荐。

## 4. 数值平衡框架

### 4.1 公式回顾（引擎已有，确认即可）

- 基础伤害 = `attack × (1 ± 15%)`（无 calculation 时）
- 技能伤害 = `baseValue + Σ(attribute × ratio)`
- 暴击倍率 = `critDamage / 100`
- 防御 = 减法：`damage - defense`（真实伤害跳过）
- 元素抗性/免伤/易伤 = 乘法区，按顺序叠乘
- 钳制：`[1, 9999]`

### 4.2 平衡目标（沿用现有断言，作为验收标准）

| 指标 | 目标 |
| ---- | ---- |
| yaotu 1v1 普攻 TTK | 6~12 回合 |
| 我方 4v4 vs 场景 | 4~10 回合，前期胜、后期有挑战 |
| 破防约束 | 任何敌人 `def < 我方最低攻击 × 0.85` |

### 4.3 平衡工具链（调参 → 验证 → 决策）

```
调整 curves.json / 装备 / 技能 ratio
        ↓
node scripts/rebalance-enemies.cjs   （按曲线重算敌人）
        ↓
node scripts/balance-check.cjs        （TTK 模拟，断言失败即回退）
        ↓
封神榜后台调 battle params            （伤害倍率等）
        ↓
昊天镜回放分析实际战局                （验证手感，反哺调参）
```

### 4.4 数值膨胀控制

1. **属性供给预算**（§3.1 占比）防止多子系统叠加失控；
2. **概率/免伤硬上限**（§1.4）防无限堆叠；
3. **钳制 `[1, 9999]`** 兜底伤害上下限；
4. **防御成长 < 攻击成长** 永续可破防（曲线设计约束）。

## 附：一句话总结

> **玩家属性 = 收敛后的 16 个可见属性 + 隐藏层；成长 = 等级白板 × 职业曲线；
> 养成 = 等级/装备/技能/突破/天赋五个子系统按预算供给；平衡 = 曲线约束 + 硬上限 + TTK 验收闭环。**
