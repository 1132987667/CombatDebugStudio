## 1. 功能作用

唤灵台是**回合制战斗引擎的实时调试沙盒**，应用的默认模块（`BattleArena.vue:67` `activeModule = 'huanling'`，`v-show` 保活）。核心价值：为开发者提供一个**可视化、可干预、可观测**的战场，用于验证战斗机制（伤害公式、被动技能、Buff/Debuff、动画、AI）。

职责定位：

1. **编排战斗全生命周期**：配置阵容 → 发起战斗 → 手动/自动推进 → 结束 → 产出录制数据供昊天镜消费；
2. **提供调试干预手段**：角色编辑（注入 Buff/改写属性）、调试控制面板（胜负判定/满血/数据生成/动画测试）；
3. **实时监控战场**：右侧面板展示选中角色的属性/技能/状态，悬浮显示属性追溯与技能详情；
4. **战斗记录产出源**：每场真实战斗结束自动持久化录制（BattleRecorder → IndexedDB），供昊天镜「战斗记录」数据源回放/调试。

### 2.3 状态管理

- **`useBattleStore`（Pinia，`presentation/stores/battleStore.ts`）**：核心状态中枢。UI 态（rules/loading/autoPlayMode/animationState/quickMode）+ 业务态（battleService/双队伍/回合数/战斗激活态）+ **投影层快照表 `participants`**（UI 唯一数据源）。经 `battleService.on()` 注册 10 类事件，`destroy()` 统一清理。
- **`useFengshenStore`**：仅消费 `dataVersion`（联动刷新阵容数据）。
- **`useBattleAnimation`**：GSAP 动画注册与播放。

### 2.4 数据流

1. **数据来源**：引擎数据（敌人/技能/场景/阵容）走 `GameDataProcessor` 静态工具，底层 `IDataSource` 双实现——`ConfigDataSource`（configs JSON 兜底）与 `IdbDataSource`（IndexedDB，封神榜种子导入后 `BattleDataLoader.reload()` 预载切换）。管理数据（actors/lineups/affixes）经 `GameDataApi`（Promise 只读接口）读取。
2. **战斗发起**：`ParticipantPanel` 配置阵容 → `Huanling.startBattle` → `battleStore.startBattle()` → `BattleService.startBattle()` → `BattleSystem.initialize`（生成 battleId + randomSeed，BattleRecorder 开始记录）。
3. **UI 同步**：`TEAM_DATA_CHANGED` → `syncTeams` → 投影层 `BattleProjection` 刷新 `participants` 快照（BattleDashboard/BattleField 从快照读取，不直绑领域实体）。
4. **战斗记录产出**（供昊天镜）：`BattleRecorder` 内存维护 `RecordedBattle` → 结束时保存 IndexedDB RECORDINGS store（`saveKey = battle_recording_<battleId>_<时间戳>`，词牌名，checksum 校验，`maxRecordings=50` 裁剪）。昊天镜经 `UnifiedArchiveService.fromRecordedBattle` 归一化消费。

## 3. 设计细节

- **投影层解耦**：UI 组件统一从 `UIParticipantSnapshot` 纯数据快照读取，不直接绑定领域实体；`BattleProjection` 用 `queueMicrotask` 批处理 + 版本号去重，一回合多次属性变更只触发一次重渲染。
- **动画预算模型**（`BattleField.getActionBudget`）：固定时间预算，技能/飘字/特效按档位编排，`quickMode` 跳过动画。
- **战报单源**：实时战报弹窗与昊天镜摘要共用 `summarizeBattle`（`domain/battle/replay/unified/unified-summary.ts`），不维护第二套统计口径。
- **录制三路径**：正常结束（`BattleLifecycleManager.endBattle` + saveRecording）/ UI 主动结束（`Huanling.endBattle` 后补存）/ 手动「保存战斗记录」按钮；批量生成走 `BattleDataGenerator` headless 路径。
- **数据源切换**：封神榜任何写操作 → `dataVersion` 递增 → 非战斗激活时 `BattleDataLoader.reload()` 重载引擎数据源（战斗中不重载，防实体引用失效）。

## 5. 开发方向

1. **场景管理落地**：把内存空壳接 IndexedDB，与封神榜 scenes 数据域对齐（当前场景保存"刷新即失"）。
2. **调试结束路径统一**：立即胜负/强制结束走标准 `endBattle`，保证录制持久化与 BATTLE_SUMMARY 事件一致。
3. **默认阵容数据化**：已落地——默认阵容从封神榜预设阵容（lineups 表）读取，actor 归我方 / enemy 归敌方，无可用阵容回退取前两个敌人。
4. **与演劫台共享战斗入口**：唤灵台与演劫台共用同一套 `domain/battle` 引擎，后续可提取公共"开战流程"组合式函数，避免两处各写一套编排。
5. **消除 ponytail 标记**：按 AGENTS.md 约定逐步清理存量 `ponytail:` 注释。
