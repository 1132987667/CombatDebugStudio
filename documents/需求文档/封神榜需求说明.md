## 1. 功能作用

封神榜是**游戏数据的编定与管理系统**，太初道枢的**数据根源**（模块副标题「数据根源」，`ModuleHeader.vue` tab3）。

四条使命（规格说明书 §1.1）：

1. **定义**：完整 CRUD 编定一切游戏法则（角色、技能、Buff、敌人、场景、阵型、材料、装备、掉落、元素、成长、词缀、规则参数）；
2. **守护**：引用/数值/唯一性校验，杜绝坏数据流入战斗；
3. **供给**：以统一只读 Promise API 向其他模块供数，保证数据源唯一；
4. **留痕**：导入导出、版本迁移与操作日志，可备份可追溯。

存储策略：**IndexedDB 为主 + `configs/` JSON 仅作首次启动种子**，运行期 IDB 是唯一权威（`configs/` 保留手工维护能力）。

## 2. 现状实现

### 2.1 数据域清单（14 表 + meta）

侧栏 12 项导航（`Fengshen.vue:62-105`，`DOMAIN_GROUPS` 4 组）+ 2 个隐藏表（`enemies` 与角色一体经 actors 管理、`params` 由系统功能「战斗规则参数」复用渲染）：

| 分组 | 数据域 | 表名 |
|------|--------|------|
| 战斗核心 | 角色/敌人、技能、状态与 Buff | `actors` / `skills` / `buffs` |
| 世界编组 | 场景、阵型、预设阵容 | `scenes` / `formations` / `lineups` |
| 物品经济 | 材料、装备、掉落组 | `materials` / `equipment` / `drops` |
| 规则成长 | 阵营克制、成长曲线、词缀 | `elements` / `growth` / `affixes` |
| 隐藏 | 敌人（一体管理）、战斗规则参数 | `enemies` / `params` |

**schema 一份定义三用**（`src/domain/fengshen/schema.ts`：表单渲染 + 校验 + 列配置）。除 `elements` 外均含 `uniqueFields: ['name']`。引用规则注册表 `REFERENCE_RULES`（20 条）：保存校验、删除保护、健康检查、反向引用**共享同一规则表**，路径支持 `steps[].effectId` 数组遍历。

### 2.3 数据层（`src/infrastructure/adapters/storage/IndexedDbStorage.ts`）

- DB：`combat-debug-studio`，**DB_VERSION=3**——v1（recordings/snapshots）、v2（封神榜 14 表 + meta）、v3（新增 affixes 词缀表）。
- meta store：`dataVersion`（全局版本号）+ 操作日志 + 种子标记 `cds:fengshen-seed-v8`。
- 种子导入（`seed.ts`）：skills（6 份合并）/enemies（3 份）/scenes/formations/lineups/materials/equipment/drops/affixes 直接落表；`buffs` 表**合并 effects.json**；`actors` 从 `guardian_*` 敌人派生（id 一致、faction 按后缀映射、growth=growth_balanced）；`elements`/`growth`/`params` 新建种子。种子保证自洽（健康检查无断裂引用）。
- `dataVersion` 生命周期：写入口唯一（`FengshenDataService.save/remove` + `DataPackageService.importPackage`，两者共享 `onDataChanged`）→ 递增版本 → 未开战时重载引擎数据源。

### 2.4 数据源切换（封神榜改动 → 引擎可见）

1. **端口抽象** `IDataSource`（`getEnemies/getSkills/getScenes/getLineups`），双实现：`ConfigDataSource`（configs JSON 兜底）/ IDB 预载（`BattleDataLoader.reload()`）。
2. **启动编排**（`main.ts:18-38`）：`seedFengshenData` → `BattleDataLoader.reload()` → `GameDataApi.getElementMatrix()` → `DamageCalculator.setConfig({ elementMatrix })`（阵营克制注入）。任一失败回退 ConfigDataSource。
3. **运行期写操作联动**（`fengshenStore.ts:70-77`）：`onDataChanged` 中非战斗激活时重载；战斗中不重载（数据经快照冻结）。
4. **阵营克制纯函数** `resolveElementCoefficient`（faction 任一缺失恒 1.0），在 `DamageCalculator.ts:541-550` 消费。

## 3. 设计细节

- **Schema 驱动**：字段 schema 一份定义，同时驱动 FieldEditor 表单、校验、DataTable 列、健康检查——新增数据域只加 schema 与表名。
- **引用完整性**：`REFERENCE_RULES` 单一规则表支撑四件事（保存校验、删除保护、健康检查、反向引用），支持跨表（`lineups.roles[].roleId→actors+enemies`）与数组路径。
- **写路径唯一**：所有写操作（CRUD + 导入）收敛到两个服务（`FengshenDataService`/`DataPackageService`），统一 `bumpVersion` + 日志 + `onDataChanged`，杜绝旁路写入绕过版本戳。
- **种子幂等**：`cds:fengshen-seed-v8` 标记防重复导入；改 configs 种子需升 seed flag 才重导，改 store 结构需升 DB_VERSION（两个独立版本维度）。
- **删除保护**：被引用实体删除时按 `REFERENCE_RULES` 拦截（删除保护），健康检查暴露断裂引用。

## 5. 开发方向

1. **演劫台数据源接线**：把斗战西游从 mock 切到封神榜 IndexedDB——这是打通"封神榜 → 演劫台"数据闭环的最大缺口，也是演劫台从"演示框架"走向"真对局"的前提。
2. **Buff 域接入引擎**：让 `buffs` 表改动对引擎可见（当前效果走静态脚本），解决"封神榜改 Buff 战斗无感"的断层。
3. **数据包完整性**：修复 affixes 漏导出；补导入前自动备份。
4. **调参闭环**：`params` 表接入 `BattleRulesDialog` 与引擎计算器，实现"封神榜改数值 → 唤灵台即时生效"。
5. **快照生成器接线**：战斗记录附带不可变快照（装备/克制/规则参数冻结值），供昊天镜一致回放。
