# 战斗战报数据契约（消费侧）

> **文档性质**：战报统计层（`summarizeBattle`）对统一事件流（TraceEvent）的输入依赖声明——消费侧契约
> **版本**：v1.0（2026-08）
> **适用范围**：`src/domain/battle/replay/unified/unified-summary.ts`（消费方）与全部 trace 事件发射端（`TraceDamageLogger` / `BuffTraceLogger` / `HealCalculator` / `BattleExecutor` / `BattleSystem` / `PassiveSkillManager`）
> **说明**：本契约声明"统计层读取哪些事件、读哪些字段、按什么口径计入"。实时战报（`BattleSummaryDialog`）与昊天镜摘要（`SummaryDialog`）共用 `summarizeBattle` 单一统计源，**不维护第二套口径**。开发新 trace 事件发射点时对照 §3 检查清单，避免形态分叉。
> **约束力来源**：类型系统不对 `payload: Record<string, unknown>` 施加约束，本契约的约束力 = 本声明 + §5 测试锁定 + 代码评审纪律。

---

## §1 定位

战报七层模型（L1 结果/边际 · L2 阵营对比 · L3 单位贡献 · L4 判定 · L5 技能 · L6 被动 · L7 关键事件）**全部从统一事件流单次遍历派生**：

```
TraceEvent[] ──fromRecordedBattle──▶ UnifiedArchive ──summarizeBattle──▶ BattleSummary
                    (字段归一化 + HP 快照)              (单次遍历, 纯函数)
```

统计层不持有第二份累加状态；事件流中**没有的事件**就不会被统计。因此"发射端少发一个事件"等价于"战报少一项数据"——数据完整性由发射端负责。

---

## §2 事件契约表

统计层消费的事件 phase 与字段如下。**凡是列入本表的字段，发射端必须按"口径"栏发射；未列入的字段（如 `steps`/`rolls`/`chain`）统计层不读取，仅供调试检视器使用。**

### 2.1 `damage_calculation`（伤害计算）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `result` | ✓ | 最终伤害值（整数）。`final` 是旧别名，仅由 `normalizeTraceEvent` 迁移兼容，新发射端直接发 `result` | `TraceDamageLogger`；`BattleSystem` 补发（dot/trigger） |
| `skillName` | ✗ | 技能名。缺省归「未标记技能」 | `TraceDamageLogger`（读 `record.skillName`） |
| `crit` | ✗ | 对象 `{ rate, multiplier, triggered }`，仅 `triggered === true` 计暴击 | `TraceDamageLogger`（demo 存档为布尔 `true`，兼容） |
| `dodge` | ✗ | `true` = 闪避，计闪避不计命中/承伤 | `BattleExecutor.handleMissAttack` 补发 |
| `dot` | ✗ | `true` = 持续伤害。**计入承伤与 HP，不计命中/暴击/技能/输出** | `BattleSystem` 补发（`requestDamage(origin='dot')`） |
| `death` + `lethalMark` | ✗ | `true` = 最终死亡确认。**不计伤害**（伤害已由本次技能路径的 `damage_calculation` 统计），仅做击杀/存活标记 | `BattleSystem.runEndConditionCheck` 补发 |

**无 `sourceId` 的伤害事件**（触发器反伤/平摊/场地、系统伤害）：按 `hasSrc` 规则计入承伤与 HP，**不计命中/暴击率分母/技能使用/任何单位输出**。

### 2.2 `heal_calculation`（治疗计算）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `result` | ✓ | 治疗量。`final` 旧别名同上 | `HealCalculator`；`BattleSystem` 补发（HOT） |
| `hot` | ✗ | `true` = 持续治疗。**仅恢复 HP 模拟，不计技能表**（无来源，治疗量不入任何单位） | `BattleSystem` 补发（`requestDamage/requestHeal(origin='hot')`） |
| `skillName` | ✗ | 技能名（`context.record.skillName`）。`executeAction` 路径 record 为 undefined 时缺省 | `HealCalculator` |

### 2.3 `buff_lifecycle`（Buff 生命周期）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `action` | ✓ | 施加判定。**大小写不敏感归一为小写匹配**（真实路径发 `BuffAction.APPLY` 大写，demo 用小写 `apply`）；仅 `apply` 参与统计 | `BuffTraceLogger` |
| `resisted` | ✗ | `true` = 被抵抗，计目标 `resists`；缺省计 `buffsApplied`。**真实路径无此事件源**（BuffSystem 仅免疫、无 debuff 抵抗机制），恒缺省 | 仅 demo 存档形态 |
| `targetId` | ✓ | 被施加者，`buffsApplied`/`resists` 按 targetId 归属 | `BuffTraceLogger` |

### 2.4 `action_execution`（行动执行）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `sourceId` | ✓ | 行动者，计 `attacks`；同时计入全局判定 `attacks` | `BattleExecutor.executeParticipantAction` |

### 2.5 `battle_lifecycle`（战斗生命周期）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `action='revive'` + `hp` | 事件级 | 复活：恢复 `targetId` 单位 `alive=true` 并按 `hp` 恢复 HP 模拟（lethalMark 已把该单位标死） | `BattleExecutor` 复活结算 |

### 2.6 `passive_trigger`（被动触发）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `verdict='TRIGGERED'` | ✓ | 仅统计触发成功；`SKIPPED` 不计 | `PassiveSkillManager` |
| `passiveId` / `passiveName` / `owner` | ✓ | 按 `passiveId\|owner` 聚合次数 | `PassiveSkillManager` |

### 2.7 `turn_flow`（回合流转）

| 字段 | 必填 | 口径 | 发射点 |
|---|---|---|---|
| `turn` | ✓ | 取最大值作为战报回合数 | `BattleSystem` |

## §3 新发射端对齐检查清单

写新的 trace 事件发射点时，逐条对照：

1. **伤害值用 `result`**，不要用 `final`（`final` 仅 `normalizeTraceEvent` 迁移兼容旧档）
2. **伤害事件必须显式标记语义**：是 dot（`dot:true`）？闪避（`dodge:true`）？死亡确认（`lethalMark:true`）？无标记的伤害会被当作"普通命中"统计，**污染命中率分母与技能表**（`hasSrc` 规则只排除无来源，不排除有来源的非标记事件）
3. **无来源伤害（触发器/系统）不带 `sourceId`**，统计层自动按 `hasSrc` 排除命中/技能/输出
4. **`crit` 用对象 `{ rate, multiplier, triggered }`**，不要用布尔（demo 存档兼容布尔，新发射端统一对象形态）
5. **`buff_lifecycle.action` 用 `BuffAction` 枚举**（大写），统计层按小写归一匹配
6. **补发型事件（dot/HOT/trigger/lethalMark）必须在 `isEnabled(phase)` 门控内发射**，零成本关闭，且绝不双算——补发值必须来自已发生的实际扣血（如 `settleDamage` 返回值），不得重复累加
7. **复活必须发 `battle_lifecycle action='revive'`**，否则战报存活标记停留在阵亡

## §4 已知缺口与设计事实

以下项目**不是统计层 bug**，而是数据源不存在或领域机制缺失，统计层刻意不做伪造：

| 缺口 | 性质 | 处理 |
|---|---|---|
| `resists`（抵抗）恒 0 | BuffSystem 无 debuff 抵抗机制（仅免疫检查） | 昊天镜摘要按 `hasResisted` 动态隐藏列；「显示空指标」开关强制展示 |
| dot / 触发器伤害无来源 | 系统伤害无攻击方 | 计入承伤与 HP，不计任何单位输出（承伤 vs 输出不对账是预期） |
| HOT 治疗量不入单位 | 无来源治疗 | 仅恢复 HP 模拟 |
| 治疗 `skillName` 在 `executeAction` 路径缺失 | record 未携带 | 该路径治疗归「未标记技能」 |
| BerserkBuff 自残伤害不进战报 | `triggerEvent(DEAL_DAMAGE, { damagePercent })` 不带 `dot:true`，不补发事件 | 保持现状（即时自伤，无来源）；若需进入承伤，给 triggerEvent 数据加 `dot:true` |
| `dealDotDamage` 已修复（含根因） | 双重失效已修：① percent 原传入 `rawDamage` 参数位 → 修正为 `damagePercent` 位；② **根因**——JSON 配置触发器脚本的 `ctx.buffSystem` 从未注入（`emitTriggerEvent`/`executeTriggerScript` 构造的 ctx 不含它），`ctx.buffSystem?.requestDamage` 全部短路，`dealDotDamage`/`reflectDamage`/`shareDamage` 等脚本实际无效 → 两处调用点注入 `buffSystem: this`。`buff_strong_poison` 冗余 triggers 已移除（脚本单独驱动，避免双算） | 毒伤害经 dot 事件进入承伤/HP |

## §5 测试锁定

契约行为由以下测试锁定，改动统计层或发射端时须保证通过：

- `tests/unit/unified-summary.test.ts` — demo 存档口径（大小写、七层模型、胜负边际）
- `tests/unit/unified-summary-realdatapath.test.ts` — 真实形态（crit 对象、lethalMark、dot、buff 大小写、复活/触发器/HOT/治疗 skillName）
- `tests/unit/unified-summary-dot-realdatapath.test.ts` — dot/trigger 补发的真实战斗链路（`BattleSystem → traceCollector → fromRecordedBattle → summarizeBattle`）
