## 0. 背景与定位

`configs/enemies/enemies.json` 现有 180 只敌人（level 1~70，含 yaotu_* 五行护法与 test_* 靶子等沙盒实体 23 只；零引用旧怪 75 只归档 configs/expired/enemies-old-expired.json），数值由历史批次沉积而成：品阶之间的强度差、次级属性的等级曲线，都隐含在数据里而没有显式定义。本文档把这些隐式规律提炼为**「等级模板曲线 × 品阶系数」的生成模型**，使新敌人的生成有公式可依、有断言可验、与玩家成长（`computePlayerBase`）有明确对标关系。

模型定位是**离线生成管线的数值中枢**（对齐《数值体系搭建指南》§4.1 对 curves.json 的定位），运行时不做任何敌人属性缩放——运行时只做 `GameDataProcessor.enemyToParticipant()` 实例化与 `resolveAffixPlan()` 挂词缀。

## 1. 目标 / 非目标

**目标**

- G1 显式化：品阶强度差从「数据沉积」变为「系数矩阵」，每个公式有符号定义、参数来源、实数算例。
- G2 可再生：文档数值表由脚本现场拟合生成，配置改动 → 重跑 → 表格与断言同步更新。

### 2.2 现状勘察发现（本次设计的前提事实）

以下发现全部可由 `node scripts/generate-enemy-design.cjs` 的报告复现：

1. **品阶差异是隐式的**：`role` 字段只有 5 个取值（xiaoyao 75 / yaotu 25 / yaokui 5 / yaowang 8 / yaozun 11），但没有任何配置定义它们之间的强度关系。拟合显示同档位敌人相对等级曲线的倍率高度恒定（如妖魁血量系数在 L26~46 全部为 8.00±0.01），说明历史上存在模板化生成，只是规则从未显式化。
2. **离线重平衡管线已与数据脱节**：`scripts/rebalance-enemies.cjs` 与 `scripts/balance-check.cjs` 消费 `stats.currentHealth` 键和旧 id 体系（`enemy_001`/`boss_001`，存于 configs/expired/ 归档），而当前 enemies.json 血量键为 `maxHealth`、id 为 `enemy_s*_**` 风格。两脚本对当前数据已不可用（✅ 已按 §9 路径归档删除，平衡验证统一走本脚本的 A1~A8 断言）。
3. **奖励双轨脱节**：运行时真值是敌人内嵌的 `exp/money` 字段（演劫台 `rewardForEnemyById()` 直读），封神榜 `enemy_reward_table` 是管理域基准表。二者系统性偏离：敌人字段 ≈ 基准×roleMult 的 exp ×0.23~0.43、gold ×0.39~0.97（分档中位，见 §4 生成表）。
4. **升级击杀数阶梯 30/60/90（✅ 2026-09-23 已修）**：旧 `exp_table` 分段（300L/600L/900L）除以 `baseExp` 线性（10L）得每级所需同等级击杀数 L1~10 为 30 只、L31~50 为 90 只，跳变无平滑。`exp_table` 种子已改为 §19 公式生成（与 player.json 同式），现击杀数 11→25.7 只/级平滑爬升（§4 击杀数表）。
5. **经验公式双轨（✅ 2026-09-23 已合）**：旧 `exp_table` 种子（300L 分段手填）与 `player_config.expFormula`（`round(50×L^1.35+60×L)`）数值不一致。seed.ts `buildExpTable()` 已改为按同一公式生成，双轨合一。
6. **王级 BOSS 错标品阶**：`boss_king_*`（L65，3 只）`role` 标 `yaowang`，但其数值相对曲线的倍率（血 20.0/攻 1.89/防 1.70/速 1.90）全面超过妖尊档（16.0/1.83/1.60/1.71），实际是「妖王之上的王级」。模型以特殊档单独登记（§3.7）。
7. **终局 BOSS 剧情特化**：`boss_final_liuer`（L70）血量 24.0×、攻 1.33×、防 1.20×、速 0.48×——超肉低速的演出型 BOSS，`energyInit=50` 也为全表唯一特例。特殊档登记。
8. **普攻破防悬崖（旧模型专有，2026-09-23 重定标后已消失）**：旧曲线 def 独立成长，旧口径下模型防御越过「主角最低攻×0.85」后普攻被减法防御完全吞掉（小妖 L17 起即触发）。重定标后敌 def 占同等级玩家攻的 20%~34%（随档位递增），普攻下限 0.85×玩家攻 − 0.34×玩家攻 = 0.51×玩家攻 > 0 恒成立 → 悬崖在全等级域不再出现（§4 生成表 def 对标行）。
9. **对标口径是下界**：`computePlayerBase` 不含自由点（4 点/级 ×50 级 = 200 SAP）与装备预算（系统预算权重 240）。实际玩家强度高于对标基准，敌人对标比例应理解为「玩家裸等级口径」。

## 3. 生成模型

### 3.1 模型总公式

```
stats[attr](role, L) = round( Template[attr](L) × Coef[role][attr] )
```

- `Template`：等级模板曲线，等级维，只随 L 变化。
- `Coef`：品阶系数矩阵，档位维，只随 role 变化（逐维独立，见 §4 生成表——妖徒是防御特化、速度偏慢，不是四维均匀放大）。
- `round`：四舍五入取整，与现状数据口径一致。

### 3.2 等级模板曲线（配置权威，不自拟合）

血/攻/防/速四维模板来自 `configs/params/curves.json`（`type: linear`，`value = base + perLevel×(L−1)`）：

| 维度 | 曲线 | L1 | L30 | L70 |
| --- | --- | --- | --- | --- |
| maxHealth | 45 + 18×(L−1) = 0.75×SAPhp | 45 | 549 | 1287 |
| attack | 14.4 + 7.2×(L−1) = 0.90×SAPatk | 14.4 | 223.2 | 515.2 |
| defense | 3.2 + 1.6×(L−1) = 0.20×SAPatk | 3.2 | 49.6 | 113.6 |
| speed | 10 + 1.2×(L−1)（未重定标） | 10 | 44.8 | 92.8 |

> 2026-09-23 重定标：旧曲线（hp 80+11L / atk 10+2L / def 1+0.9L）相对旧玩家线（hp300/atk15+1）拟合，与 SAP 玩家线（hp60/atk16 起、+24/+8 每级）在减法防御下互为死锁。新曲线按小妖=基准档（coef 1.0）对齐 §25 系数带：hp = 0.75×玩家线（普通怪 2~3 回合全歼）、atk = 0.90×玩家攻线、def = 0.20×玩家攻线；speed 无平衡语义沿用旧值。

### 3.3 次级维度模板（小妖样本最小二乘拟合）

命中/闪避/暴击率/暴击伤害以小妖（基准档、最大样本 n=75）最小二乘拟合，其余档位相对小妖模板求系数。具体公式与系数见 §4 生成表。形状结论：`hit = 10 + 2×(L−1)`（与攻击曲线同形状）、`critRate ≈ 5 + 0.2×(L−1)`、`critDamage ≈ 120 + 0.5×(L−1)`、`dodge ≈ 2 + 0.8×(L−1)`；`maxEnergy = 150` 全体常量，`energyInit = 25`（终局 BOSS 特例 50）。命中与暴击的品阶差异在圆整噪声内（系数 ≈1.00~1.03），模型视为模板统一。

### 3.4 品阶系数矩阵

由脚本对各档位实数取「实数 ÷ 模板」中位数现场拟合（§4 生成表），**不是手工设定值**。档位语义解读：

| 档位 | role | 存在域 | 定位 |
| --- | --- | --- | --- |
| 小妖 | xiaoyao | L1~50 | 基准档（系数 ≡ 模板基准）；a/b/c 三尾缀同模板 |
| 妖徒 | yaotu | L2~50（偶数级） | 精英杂兵：血厚（2.93×）、攻强（1.33×）、慢速（0.89×） |
| 妖魁 | yaokui | L6~46（逢 10 附近） | 小 BOSS（boss_minor_*）：首次引入 phases 与词缀 |
| 妖王 | yaowang | L10~65 | 中 BOSS（boss_major_* / boss_king_*，后者实为 §3.7 王级档） |
| 妖尊 | yaozun | L55~70 | 大 BOSS（boss_achieve_* / boss_oldsoul_*） |

### 3.5 词缀池规则（affixPlan，现状拟合）

`affixPool = { buffTier, count }` 按档位与等级生成，`buffTier → 档位` 映射见 §2.1（5 = 天命，须绑定表命中）：

| 档位 | count | buffTier |
| --- | --- | --- |
| 小妖 | 0 | 0 |
| 妖徒 / 妖魁 | 1 | `clamp(ceil(L/20), 1, 3)` → yao_1（≤20）→ yao_2（22~40）→ yao_3（42+） |
| 妖王 | 1 | yao_3；boss_king_* 为天命（5） |
| 妖尊 | 2 | yao_4；终局为天命（5）、count 1 |

现状偏差：妖王 L10~30 三只实际填 `buffTier=5`（天命档），未命中绑定表时运行时等于无词缀——与 L40/50 的 yao_3 混用，属历史不一致，A8 断言对妖王档放行 {3,5}，其余档位严格对齐。

### 3.6 奖励对齐规则（设计口径，现状未对齐）

设计上敌人奖励应满足：

```
exp[min,max]  = [ baseExp(L) × roleMult[role], 1.5 × baseExp(L) × roleMult[role] ]   （圆整）
money[min,max] = [ goldMin(L) × roleMult[role], goldMax(L) × roleMult[role] ]        （圆整）
```

其中 `baseExp/goldMin/goldMax` 查 `enemy_reward_table`（线性插值），`roleMult` 见其 `roleMultiplier`（normal 1.0 / elite 1.15 / yaotu 1.2 / yaokui 2.0 / yaowang 3.0 / yaozun 5.0；xiaoyao 对应 normal）。**现状敌人字段与该口径存在 ×0.23~0.97 的系统性偏差（§4 生成表），本次只登记不修改**——修正需要同步演劫台结算与掉落经济，列为 §8 决策点。

### 3.7 特殊档与例外

- **王级**（`boss_king_*`，3 只）：role 字段标 yaowang 但系数全面超过妖尊档，模型按独立档位拟合（§4 生成表）。建议未来为敌人引入显式 `tier` 字段或改标 role（§8）。
- **沙盒/测试实体**：`yaotu_*` 五行护法（5 只，玩家侧沙盒角色、ACTORS 派生源）、`test_*` 战斗测试靶子（18 只，数值与测试断言绑定）——两者数值冻结，生成模型（A3/A8/重算）对其跳过，不参与拟合与重算。`boss_major_*` 五大场景 BOSS（已并入 enemies.json）2026-09-23 起为生成模型精确值（SAP 线 × 目标比例，个性因子 f=1），参与拟合与断言、不再冻结。
- **终局**（`boss_final_liuer`，1 只）：剧情演出特化（血 24.0×/攻 1.33×/防 1.20×/速 0.48×/energyInit 50），按独立档位登记，不参与品阶单调断言。

### 3.8 新敌人生成算法

```
function 生成敌人(role, L, {name, faction, skillIds, drops, ...}):
    assert role ∈ {xiaoyao,yaotu,yaokui,yaowang,yaozun} 且 L 在该档位存在域内
    stats.maxHealth  = round( (80 + 11×(L−1))  × Coef[role].maxHealth )
    stats.attack     = round( (10 + 2×(L−1))   × Coef[role].attack )
    stats.defense    = round( (1 + 0.9×(L−1))  × Coef[role].defense )
    stats.speed      = round( (10 + 1.2×(L−1)) × Coef[role].speed )
    stats.hit        = round( hit模板(L)  × Coef[role].hit )        // 系数≈1
    stats.dodge      = round( dodge模板(L) × Coef[role].dodge )
    stats.critRate   = round( critR模板(L) )                        // 不吃品阶系数
    stats.critDamage = round( critD模板(L) )
    stats.maxEnergy = 150; stats.energyInit = 25
    affixPool = affixPlan(role, L)                                  // §3.5
    exp/money = 奖励对齐规则(§3.6)                                   // 待现状对齐决策
    drops     = 等级段掉落组人工配置（模型不生成，约束：2~7 条、probability 0.05~0.9）
```

等级选择惯例（现状）：小妖逐级分布、妖徒占偶数级、BOSS 按「章节末（逢 10）/成就（55）/残魂（60）/王级（65）/终局（70）」锚点放置。

### 5.2 TTK 口径与有效域

模拟器与原 `balance-check.cjs`（已归档）同款：`伤害 = floor(攻 × (0.85+随机×0.3) − 防)`，最少 1 点；按速度序行动、攻击血量最低目标；确定性 LCG 随机（可复现）。我方基准为 SAP 裸线小队（`player.json` base + growth，不含加点/装备/丹药）。重定标后敌 def 恒 ≤ 0.34×玩家攻，普攻在全等级域有效（§2.2 发现 8 的悬崖已消失），TTK 断言覆盖 L10~L50 对局；模拟含我方减员（无技能/治疗），实测带比 §25 连续 dps 估算带偏长 ~1.5 倍。

### 5.3 玩家对标的解析性质

2026-09-23 重定标后敌人曲线与 SAP 玩家线同斜率（hp{45,18} = 0.75×SAPhp、atk{14.4,7.2} = 0.90×SAPatk、def{3.2,1.6} = 0.20×SAPatk），各档位对标比例恒定、不随等级漂移（小妖血 75%、妖徒 220%、妖魁 600%…，见 §4 生成表）。这不是缺陷而是线性同斜率模型的固有性质：等级维只提供「基础盘」，档位间强度差由品阶系数（BOSS 档 8~24×）、词缀（yao_4 = +80%）、阵容规模（BOSS 战多打少）与多系统养成预算（装备 240 权重等）弥补。若未来把玩家成长改为超线性或敌人曲线改为二次型，本节恒定比例需重新推导（曲线 `type` 字段已预留扩展点）。
