# 敌人生成设计（等级 × 品阶）

> 本文档的数值总表（§4）由 `scripts/generate-enemy-design.cjs` 从配置现场拟合生成：改 `configs/params/curves.json` 或 `configs/enemies/enemies.json` 后重跑 `node scripts/generate-enemy-design.cjs --write` 即再生，表格永不与配置脱节。脚本内置 8 组平衡断言（§5），断言不过则非零退出。

## 0. 背景与定位

`configs/enemies/enemies.json` 现有 124 只敌人（level 1~70），数值由历史批次沉积而成：品阶之间的强度差、次级属性的等级曲线，都隐含在数据里而没有显式定义。本文档把这些隐式规律提炼为**「等级模板曲线 × 品阶系数」的生成模型**，使新敌人的生成有公式可依、有断言可验、与玩家成长（`computePlayerBase`）有明确对标关系。

模型定位是**离线生成管线的数值中枢**（对齐《数值体系搭建指南》§4.1 对 curves.json 的定位），运行时不做任何敌人属性缩放——运行时只做 `GameDataProcessor.enemyToParticipant()` 实例化与 `resolveAffixPlan()` 挂词缀。

## 1. 目标 / 非目标

**目标**

- G1 显式化：品阶强度差从「数据沉积」变为「系数矩阵」，每个公式有符号定义、参数来源、实数算例。
- G2 可再生：文档数值表由脚本现场拟合生成，配置改动 → 重跑 → 表格与断言同步更新。
- G3 可检验：拟合度、单调性、玩家对标、TTK 节奏、奖励自洽全部脚本断言化，不靠人眼。
- G4 对标玩家：模型能回答「同级同品阶敌人是玩家的百分之几」，比例锚点来自 124 只实数反推，不是拍脑袋。

**非目标**

- 不修改任何现有源码、配置与既有脚本（`rebalance-enemies.cjs` 等的失配问题只登记不修，见 §2.2 与 §9）。
- 不做运行时敌人缩放/动态难度。
- 不开发封神榜新 UI 视图（衔接口径见 §6，列为后续工作）。
- 不重写 124 只敌人数据：模型对现状的拟合度以断言闸门守护（A3），个别手调怪以离群清单点名登记，不强行抹平。

### 2.2 现状勘察发现（本次设计的前提事实）

以下发现全部可由 `node scripts/generate-enemy-design.cjs` 的报告复现：

1. **品阶差异是隐式的**：`role` 字段只有 5 个取值（xiaoyao 75 / yaotu 25 / yaokui 5 / yaowang 8 / yaozun 11），但没有任何配置定义它们之间的强度关系。拟合显示同档位敌人相对等级曲线的倍率高度恒定（如妖魁血量系数在 L26~46 全部为 1.94±0.01），说明历史上存在模板化生成，只是规则从未显式化。
2. **离线重平衡管线已与数据脱节**：`scripts/rebalance-enemies.cjs` 与 `scripts/balance-check.cjs` 消费 `stats.currentHealth` 键和旧 id 体系（`enemy_001`/`boss_001`，存于 enemies-old.json），而当前 enemies.json 血量键为 `maxHealth`、id 为 `enemy_s*_**` 风格。两脚本对当前数据已不可用（本次不修，见 §9）。
3. **奖励双轨脱节**：运行时真值是敌人内嵌的 `exp/money` 字段（演劫台 `rewardForEnemyById()` 直读），封神榜 `enemy_reward_table` 是管理域基准表。二者系统性偏离：敌人字段 ≈ 基准×roleMult 的 exp ×0.23~0.43、gold ×0.39~0.97（分档中位，见 §4 生成表）。
4. **升级击杀数阶梯 30/60/90**：`exp_table` 分段（300L/600L/900L）除以 `baseExp` 线性（10L）得每级所需同等级击杀数：L1~10 为 30 只、L11~30 为 60 只、L31~50 为 90 只。31 级后 90 只/级明显偏肝，且阶梯跳变无平滑（§8 待确认）。
5. **经验公式双轨**：`player_config.expFormula`（`round(50×L^1.35+60×L)`，ExpGoldView「按公式填充」用）与 `exp_table` 种子（300L 分段手填）数值不一致。
6. **王级 BOSS 错标品阶**：`boss_king_*`（L65，3 只）`role` 标 `yaowang`，但其数值相对曲线的倍率（血 3.04/攻 4.12/防 6.31/速 1.90）全面超过妖尊档（2.71/3.67/5.64/1.71），实际是「妖王之上的王级」。模型以特殊档单独登记（§3.7）。
7. **终局 BOSS 剧情特化**：`boss_final_liuer`（L70）血量 9.54×、攻 0.48×、防 1.90×、速 0.48×——超肉低速的演出型 BOSS，`energyInit=50` 也为全表唯一特例。特殊档登记。
8. **普攻破防悬崖**：主角最低攻击×0.85 ≈ 34（yaotu_earth atk40），模型防御超过该值的首发等级：小妖 L17、妖徒 L13、妖魁 L10、妖王 L8、妖尊 L7。此后「普攻减法模型」失效，输出依赖技能倍率与装备成长——这是攻击模型的结构性边界（§5.3）。
9. **对标口径是下界**：`computePlayerBase` 不含自由点（4 点/级 ×50 级 = 200 SAP）与装备预算（系统预算权重 240）。实际玩家强度高于对标基准，敌人对标比例应理解为「玩家裸等级口径」。

## 3. 生成模型

### 3.1 模型总公式

```
stats[attr](role, L) = round( Template[attr](L) × Coef[role][attr] )
```

- `Template`：等级模板曲线，等级维，只随 L 变化。
- `Coef`：品阶系数矩阵，档位维，只随 role 变化（逐维独立，见 §4 生成表——妖徒是防御特化、速度偏慢，不是四维均匀放大）。
- `round`：四舍五入取整，与现状数据口径一致。

### 3.2 等级模板曲线（配置权威，不自拟合）

血/攻/防/速四维模板来自 `configs/params/curves.json`（`type: linear`，`value = base + perLevel×(L−1)`）：

| 维度 | 曲线 | L1 | L30 | L70 |
| --- | --- | --- | --- | --- |
| maxHealth | 80 + 11×(L−1) | 80 | 399 | 839 |
| attack | 10 + 2×(L−1) | 10 | 68 | 148 |
| defense | 1 + 0.9×(L−1) | 1 | 27.1 | 62.2 |
| speed | 10 + 1.2×(L−1) | 10 | 44.8 | 92.8 |

### 3.3 次级维度模板（小妖样本最小二乘拟合）

命中/闪避/暴击率/暴击伤害以小妖（基准档、最大样本 n=75）最小二乘拟合，其余档位相对小妖模板求系数。具体公式与系数见 §4 生成表。形状结论：`hit = 10 + 2×(L−1)`（与攻击曲线同形状）、`critRate ≈ 5 + 0.2×(L−1)`、`critDamage ≈ 120 + 0.5×(L−1)`、`dodge ≈ 2 + 0.8×(L−1)`；`maxEnergy = 150` 全体常量，`energyInit = 25`（终局 BOSS 特例 50）。命中与暴击的品阶差异在圆整噪声内（系数 ≈1.00~1.03），模型视为模板统一。

### 3.4 品阶系数矩阵

由脚本对各档位实数取「实数 ÷ 模板」中位数现场拟合（§4 生成表），**不是手工设定值**。档位语义解读：

| 档位 | role | 存在域 | 定位 |
| --- | --- | --- | --- |
| 小妖 | xiaoyao | L1~50 | 基准档（系数 ≡ 模板基准）；a/b/c 三尾缀同模板 |
| 妖徒 | yaotu | L2~50（偶数级） | 精英杂兵：防御特化（≈3.0×）、攻强（≈1.9×）、慢速（0.89×） |
| 妖魁 | yaokui | L6~46（逢 10 附近） | 小 BOSS（boss_minor_*）：首次引入 phases 与词缀 |
| 妖王 | yaowang | L10~65 | 中 BOSS（boss_major_* / boss_king_*，后者实为 §3.7 王级档） |
| 妖尊 | yaozun | L55~70 | 大 BOSS（boss_achieve_* / boss_hidden_*） |

### 3.5 词缀池规则（affixPlan，现状拟合）

`affixPool = { buffTier, count }` 按档位与等级生成，`buffTier → 档位` 映射见 §2.1（5 = 天命，须绑定表命中）：

| 档位 | count | buffTier |
| --- | --- | --- |
| 小妖 | 0 | 0 |
| 妖徒 / 妖魁 | 1 | `clamp(ceil(L/20), 1, 3)` → yao_1（≤20）→ yao_2（22~40）→ yao_3（42+） |
| 妖王 | 1 | yao_3；boss_king_* 为天命（5） |
| 妖尊 | 2 | yao_4；终局为天命（5）、count 1 |

现状偏差：妖王 L10~30 三只实际填 `buffTier=5`（天命档），未命中绑定表时运行时等于无词缀——与 L40/50 的 yao_3 混用，属历史不一致，A8 断言对妖王档放行 {3,5}，其余档位严格对齐。

### 3.6 奖励对齐规则（设计口径，现状未对齐）

设计上敌人奖励应满足：

```
exp[min,max]  = [ baseExp(L) × roleMult[role], 1.5 × baseExp(L) × roleMult[role] ]   （圆整）
money[min,max] = [ goldMin(L) × roleMult[role], goldMax(L) × roleMult[role] ]        （圆整）
```

其中 `baseExp/goldMin/goldMax` 查 `enemy_reward_table`（线性插值），`roleMult` 见其 `roleMultiplier`（normal 1.0 / elite 1.15 / yaotu 1.2 / yaokui 2.0 / yaowang 3.0 / yaozun 5.0；xiaoyao 对应 normal）。**现状敌人字段与该口径存在 ×0.23~0.97 的系统性偏差（§4 生成表），本次只登记不修改**——修正需要同步演劫台结算与掉落经济，列为 §8 决策点。

### 3.7 特殊档与例外

- **王级**（`boss_king_*`，3 只）：role 字段标 yaowang 但系数全面超过妖尊档，模型按独立档位拟合（§4 生成表）。建议未来为敌人引入显式 `tier` 字段或改标 role（§8）。
- **终局**（`boss_final_liuer`，1 只）：剧情演出特化（血 9.54×/攻 0.48×/防 1.90×/速 0.48×/energyInit 50），按独立档位登记，不参与品阶单调断言。

### 3.8 新敌人生成算法

```
function 生成敌人(role, L, {name, faction, skillIds, drops, ...}):
    assert role ∈ {xiaoyao,yaotu,yaokui,yaowang,yaozun} 且 L 在该档位存在域内
    stats.maxHealth  = round( (80 + 11×(L−1))  × Coef[role].maxHealth )
    stats.attack     = round( (10 + 2×(L−1))   × Coef[role].attack )
    stats.defense    = round( (1 + 0.9×(L−1))  × Coef[role].defense )
    stats.speed      = round( (10 + 1.2×(L−1)) × Coef[role].speed )
    stats.hit        = round( hit模板(L)  × Coef[role].hit )        // 系数≈1
    stats.dodge      = round( dodge模板(L) × Coef[role].dodge )
    stats.critRate   = round( critR模板(L) )                        // 不吃品阶系数
    stats.critDamage = round( critD模板(L) )
    stats.maxEnergy = 150; stats.energyInit = 25
    affixPool = affixPlan(role, L)                                  // §3.5
    exp/money = 奖励对齐规则(§3.6)                                   // 待现状对齐决策
    drops     = 等级段掉落组人工配置（模型不生成，约束：2~7 条、probability 0.05~0.9）
```

等级选择惯例（现状）：小妖逐级分布、妖徒占偶数级、BOSS 按「章节末（逢 10）/成就（55）/隐藏（60）/王级（65）/终局（70）」锚点放置。

### 5.2 TTK 口径与有效域

模拟器与 `balance-check.cjs` 同款：`伤害 = floor(攻 × (0.85+随机×0.3) − 防)`，最少 1 点；按速度序行动、攻击血量最低目标；确定性 LCG 随机（可复现）。我方基准为 enemies-old.json 的 `yaotu_*` 五只（L10 固定值）。**有效域到 L15 左右**：模型妖徒 L13 起防御超过主角最低攻×0.85（§2.2 发现 8），此后普攻减法模型打不动高防单位——真实战斗靠技能倍率、词缀与装备成长补输出，脚本的 TTK 断言因此只覆盖 L5~L10 对局，L15+ 的强度验证需要接引擎级模拟（§9）。

### 5.3 玩家对标的解析性质

血量对标比例随等级单调衰减并有解析极限：`lim(L→∞) 敌人血量/玩家血量 = 11/24 ≈ 46%`（敌人血成长 11/级 ÷ 玩家 24/级），攻击极限 `2/8 = 25%`。这不是缺陷而是线性模型的固有性质：等级维只提供「基础盘」，后期强度差由品阶系数（BOSS 档 2.7~9.5×）、词缀（yao_4 = +80%）、阵容规模（BOSS 战多打少）与多系统养成预算（装备 240 权重等）弥补。若未来把玩家成长改为超线性或敌人曲线改为二次型，本节极限值需重新推导（曲线 `type` 字段已预留扩展点）。
