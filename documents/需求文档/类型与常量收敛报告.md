## 三、保留的宽容点及理由（均已带注释）

| 位置 | 宽容形态 | 理由 |

| `DataIntegrityService.ts` 实体 | `Record<string, unknown>` | 跨全部异构表通用校验器，结构由 schema 驱动运行时解析（文件头补 NOTE） |

| `save-bridge.ts` 存档词缀 attribute | `as GearAffix['attribute']` | 历史持久化字符串（SaveEquipmentInstance 宽容键域），写入时由 configs 生成（HACK 注释注明） |

## 四、遗留项（天花板与建议路径）

1. **属性码→中文名多源并存（最大遗留）**：`attribute-codes.generated.ts` AttributeMetaMap（引擎权威）、`attribute-dictionary.ts`（策划维度字典）、`AffixRuleView` ALL_ATTRS（65 项编辑器选项）三源并存，且存在文案别名（ALL_ATTRS 的 hitValue 叫「命中值」，字典叫「命中」）。**天花板**：强行归一会改变界面文案（违反本次红线）。**建议路径**：先拍板各场景文案口径 → ALL_ATTRS 改为从字典派生 + per-view 别名覆盖表 → 字典与 generated 以生成脚本合一。
2. **items.json 类型三副本 / scenes 双副本 / bosses 双副本**（ItemData/XiyouItemDef/XiyouCatalogItem；SceneData/XiyouScene；两个 BossRow）。**天花板**：用户同期正在迁移 items.json（装备迁出、结构变动中），现在归一必然撞车。**建议路径**：待 items.json 迁移落定后，XiyouCatalogItem 删除改引 ItemData、XiyouScene 与 SceneData 二选一（desc/background 改名需同步模板）。
3. **双码系并存**：品阶 t1~t5 ↔ 拼音五档（fan/xuan/di/tian/xian）、命中 hitValue ↔ 个体权重短码 hit。本次已用 `GearTier`/`AffixQualityCode`/TIER_KEY 换算表/INDIVIDUAL_WEIGHT_CODES 把两套码显式化。**天花板**：configs 侧为策划历史口径，引擎单方面统一会造成配置不兼容。**建议路径**：下次 configs 大版本时统一为单一码系，换算表即删除点。
4. **稀/品级双体系**：`Item.ts` rarityNames（1-4 普通/稀有/史诗/传说）与 `xiyou/quality.ts` RARITY_NAMES（1-5 凡/玄/地/天/仙）并存，fengshen/types 注释混用两套口径。**建议路径**：Item 侧旧体系仅剩 2 个消费方，确认无存档依赖后并入 quality.ts 体系。
5. **技能类型文案漂移**：`DataTable.vue:280` 的 type 标签写「大技能」、`schema.ts` SKILL_TYPE_VALUE_LABEL 写「大招」（同为 ultimate 的展示文案）。**天花板**：归一会改其中一处界面文案，触碰本次红线。**建议路径**：策划拍板统一文案后，DataTable 删本地行改引 SKILL_TYPE_VALUE_LABEL 并补 material/consumable 两个物品域键（或拆两表）。
6. **基线存量失败（非本次引入，甄别记录）**：任务开始时 3 失败——attributes.json 新增 luck 未同步字典/展示配置（fengshen-attribute-dictionary / attribute-display 两测）、role-grades 倍率口径漂移（代码 1.1/1.3 vs 测试期望 1.15/2.0）。执行期间用户修复了前两类；quality.test.ts（pack.json→items.json 迁移中）与 lianji-battle-sim 为非确定性偶发（单独跑稳定通过、复跑全量即过），最终验证 1176/1176 全绿。
7. **并行开发调和记录**：执行期间用户在同批文件活跃开发（新提交 00b5ad28 含 items.json 装备迁出、EquipmentData.value 新增、validators 新目录等），types.ts 的 AffixRuleConfig 收紧被用户审阅后有意回退（附理由注释），本次尊重该决策并调和了 gear-generate 的混合状态； ParticipantCard.vue 的自导入坏行（致 SFC 编译失败、4 个测试无法收集）已顺手修复。
8. **`BuffConfigResolver` stackRule 缺省值怪象（疑似潜伏 bug）**：缺省写 `'LIMITED'`（大写字符串），而 `StackRule.LIMITED = 'limited'`；buffs.json 121/142 条无 stackRule 走此缺省，`BuffSystem` 叠层 switch（REFRESH/LIMITED）不会命中该值，叠层上限逻辑可能未按 LIMITED 生效。修正会改变现网行为，须先确认策划语义再统一（已加 HACK 注释）。
9. **`attributeSync.ts` REVERSE_BONUS_ATTR_MAP 疑似笔误**：`speedBonus → speedBonus` 自映射（其余三条均为 bonus→主属性），速度加成的反向同步当前是空操作。按红线未改，确认后应改为 `ATTRIBUTE_CODE.speed`。
10. **其余宽容点补录**：`unified-attrs.ts` SHORT_TO_CODE 的 `RES→'resist'`（demo 旧存档兼容层，码表外遗留值）；calculation-utils / combat-record 的 extraValues 链（源头为技能 JSON 自由键，输出端 string + 消费点窄化断言，强收为假收敛）；`battleStore.ts` 的 `false as unknown as F` 泛型兜底与 `save-bridge.ts` 动态键写档。文案分歧全清单（键集相同、值刻意不同，收敛时不得统一）：skillType「大招(schema/EDP) vs 大技能(DataTable)」、category「属性 vs 属性修正」、装备阶位 t4/t5「四阶/五阶 vs 天品/仙品」、damageReduction 三名并存。
