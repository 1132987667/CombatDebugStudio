# 练器图谱改造需求文档

> 定位：洞府·打造（ForgePanel）解锁判定与图谱体系的收敛改造。
> 原则遵循 AGENTS.md：删除优先于添加、最少文件、最短可用 diff、理解问题后再动手。
> 状态：待评审 / 待实现。

## 一、需求背景与目标

### 1.1 现状

当前「打造装备」按 **图谱（blueprintId）** 判定解锁，逻辑在 `packStore.blueprintUnlocked`：

- 装备无 `blueprintId` → 直接可造
- `tier === 't1'` → 默认解锁
- 其余 → 需背包持有对应 `bp_*` 图纸（不消耗）

装备数据在 `configs/equipment/equipment.json`，每条可打造装备均带 `blueprintId` 与 `materials`（材料权威在本表）。

### 1.2 问题

1. **普通装备被图谱重复卡门槛。** t2/t3 装备的材料本身来自高阶关卡（材料即进度），图谱叠加成第二道门槛，造成「材料齐了却被一张纸卡住」的挫败感，且无收藏价值。
2. **掉落图谱体系断裂。** `enemies.json` / `bosses.json` 掉落的图纸是 `recipe_weapon_t1` ~ `recipe_armor_t7` 这一套，而装备 `blueprintId` 引用的是 `bp_t1_eq` ~ `bp_immortal_04` 另一套。**两套完全脱节**：BOSS 掉的图纸对制造系统没有任何作用；反之保留图谱的装备所需的 `bp_legend_*` / `bp_immortal_*` 图纸当前没有对应掉落来源。
3. **图鉴不展示合成方式。** `ItemDetail.vue` 只显示描述/属性/效果，玩家查不到「这件东西怎么获得/用什么材料合成」。

### 1.3 目标

- 普通装备（t1/t2/t3）**免图谱**：材料满足即可打造，图鉴可见合成方式。
- 稀有装备（特殊 sp / 传说 legend / 仙品 immortal）**保留图谱**：图纸是击败对应强敌的凭证，有仪式感。
- 图鉴展示**所有可合成物品**的合成方式（材料 + 是否需要图谱 + 获取途径）。
- 清理断裂的 `recipe_*` 图纸数据与掉落引用。

## 二、图谱适用范围（免图谱 / 需图谱清单）

| 类别 | 判定 | 说明 |
|---|---|---|
| 一阶装备（t1，bp_t1_*） | 免图谱 | 材料即门槛；新手期无门槛 |
| 二阶装备（t2，bp_t2_*） | 免图谱 | 材料来自关卡 3-5，材料即门槛 |
| 三阶装备（t3，bp_t3_*） | 免图谱 | 材料来自关卡 6-9，材料即门槛 |
| 特殊装备（sp，bp_sp_01/02/03） | 需图谱 | 三件特殊装备各自对应一张独立图纸，妖尊 专属，图纸=击败凭证 |
| 传说装备（legend/t4，bp_legend_*） | 需图谱 | BOSS 首杀专属，图纸有仪式感 |
| 仙品装备（immortal/t5，bp_immortal_*） | 需图谱 | 最终 BOSS，图纸是终局解锁 |
| 丹药 / 符箓 / 碎片合成 / 药园 | 免图谱 | 现状即无 blueprintId，材料驱动 |

**判定实现**：免图谱的装备**删除 `blueprintId` 字段**（数据即真相），保留图谱的装备保留。解锁逻辑收敛为「无 blueprintId → 直接可造」，无需前缀/tier 特判。

## 三、功能改动明细

### 3.1 解锁判定（`src/presentation/stores/packStore.ts`）

现状 `blueprintUnlocked`（约 630 行）：

```ts
function blueprintUnlocked(itemId: string): boolean {
  const g = gearById(itemId)
  if (!g?.blueprintId) return true
  if (g.tier === 't1') return true
  return (inventory.value[g.blueprintId] ?? 0) > 0
}
```

改为：

```ts
function blueprintUnlocked(itemId: string): boolean {
  const g = gearById(itemId)
  if (!g?.blueprintId) return true
  return (inventory.value[g.blueprintId] ?? 0) > 0
}
```

- 删除 `tier === 't1'` 特判分支（t1 删 blueprintId 后自然落入无图谱分支）。
- `craftEquipment`（约 641 行）中「图纸解锁校验 → 材料校验 → 扣材料」流程不变，仅解锁判定随上述简化。

### 3.2 打造面板（`src/presentation/modules/yanjie/xiyou/components/cave/ForgePanel.vue`）

- `unlockedOf(r)` 继续走 `pack.blueprintUnlocked(g.id)`，无需改动逻辑；普通装备将恒为解锁。
- 未解锁卡片（仅 sp/legend/immortal 会命中）保留 `is-locked` 样式与「需「XX」解锁」提示（`blueprintNameOf` 仅在保留图谱装备上非空）。
- 普通装备卡片不再出现锁图标，材料满足即可选中并铸造。
- 材料不足的「不足」标签保留，作为普通装备的主要限制反馈。

### 3.3 图鉴合成方式展示

#### 3.3.1 数据源扩展（`src/presentation/composables/useCompendium.ts`）

现状物品图鉴数据来自 `GameDataProcessor.getMaterialsData()`，经 `deriveMaterials` 白名单过滤（木材/矿石/…/货币），**不含装备、图纸**。

改造：

- 物品列表数据源**合并可打造装备**：`equipmentCatalog.filter((g) => g.craftable)` 并入 `CompendiumItem[]`，字段对齐（id/name/type=slot/rarity/description/stats/slot）。
- `CompendiumItem` 增加合成信息字段（可选，图鉴可空安全）：
  - `recipeMaterials?: { itemId: string; count: number }[]`
  - `blueprintId?: string`（需图谱的装备才有）
  - `craftType?: 'forge' | 'alchemy' | 'talisman' | 'fragment'`（合成方式类别）

数据来源映射：

| 物品类别 | 合成信息来源 |
|---|---|
| 可打造装备 | `equipment.json` 的 `materials` / `blueprintId` |
| 丹药 | `cave.json` 的 `alchemyRecipes` |
| 符箓 | `cave.json` 的 `talismanRecipes` |
| 碎片合成 | `caveLogic.FRAGMENT_RULES` |
| 药园产出 | `cave.json` 的 `gardenCrops` |

#### 3.3.2 详情展示（`src/presentation/components/ItemDetail.vue`）

新增「合成方式」区块，展示：

- 合成类别（打造 / 炼丹 / 符箓 / 碎片合成 / 种植）
- 所需材料（名称 × 数量，引用 `caveLogic.itemName`）
- 图谱需求（若 `blueprintId` 存在：显示「需「XX图纸」解锁」；否则显示「无需图谱」）
- 材料不足时的缺项提示（可复用打造面板的 `is-low` 语义，图鉴仅展示不交互）

> NOTE: 图鉴物品列表来自封神榜 IDB（`GameDataProcessor.getMaterialsData`），封神榜写操作后 `refresh()` 已触发，装备合并需保证同一数据源内一致（从 `configs/equipment` 或 IDB EQUIPMENT 表二选一，避免双源漂移）。

## 四、验收标准

1. t1/t2/t3 普通装备：背包材料满足即可在打造面板选中并铸造，无锁提示；材料不足时提示「不足」。
2. sp/legend/immortal 装备：未持有对应 `bp_*` 图纸时卡片锁定并提示「需「XX」解锁」；持有后材料满足即可造，图纸不消耗。
3. 图鉴中任意可合成物品可见合成方式（材料清单 + 是否需要图谱）。
4. `npm run test` 全绿；`npm run typecheck` 通过。
5. `recipe_*` 与 `bp_t*_*` 图纸条目、掉落引用在 `items.json` / `enemies.json` / `bosses.json` / `cave.json` / `equipment.json` 中全部清除，无遗留引用（`rg "recipe_weapon|recipe_armor|bp_t[123]_"` 应仅命中保留的 sp/legend/immortal 图谱）。
6. 封神榜 IDB 健康检查无断裂引用（`fengshen-data.test.ts` 覆盖）。
