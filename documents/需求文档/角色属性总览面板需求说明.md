# 角色属性总览面板 需求说明

> 版本：v0.1（草案）｜创建：2026-09-01｜状态：待评审
> 关联：`documents/属性监控显示设计.md`（单属性四层来源拆解，本面板 tooltip 复用）、`src/presentation/config/attributeDisplay.ts`（分层/分组 schema）、`src/shared/types/projection.ts`（投影快照）

## 0. 背景与定位

当前角色属性展示散落三处，且各自只渲染少量字段，没有统一的「全量属性 + 分层 + 折叠」组件：

| 组件 | 模块 | 现状 |
| --- | --- | --- |
| `RoleAttrsPanel.vue` | 昊天镜（回放） | 只读事件目标/行动角色，展示快照里携带的少量属性 |
| `CharacterPanel.vue` | 演劫台（西游养成） | 硬编码 coreAttrs/bonusAttrs 两组，非全量 |
| `EntityDetailPanel.vue` | 封神榜 | 实体详情内嵌，展示口径不一 |

本需求要新增一个**可复用的「角色属性总览面板」组件**：一次性呈现单个角色的全部属性（需求方口径「64 项」，见 §8 待确认），按**业务分组 + 展示层级**双维度组织，支持分组展开/收起与折叠态记忆，每项可悬浮查看四层来源拆解。

它不重复实现属性计算或修饰符拆解——数值来自投影快照，四层拆解来自既有 tooltip 设计，本组件只负责「怎么把一堆属性看得清楚」。

## 1. 目标 / 非目标

**目标**
- G1 单组件渲染一个角色的全量属性当前值，不遗漏、不硬编码属性清单（清单由元数据 + 展示配置驱动）。
- G2 分层呈现：`core` 常显、`advanced`/`situational` 默认折叠可展开、`hidden`（气血/能量/护盾）走独立条状区，不进网格。
- G3 分组呈现：进攻 / 防御 / 元素 / 控制 / 通用 五组，每组标题可折叠。
- G4 提供「全部展开 / 全部收起」，折叠与过滤状态可记忆（刷新后保持）。
- G5 任一属性行悬浮显示四层来源（复用 `AttributeTooltip.vue`）。
- G6 过滤：按名称/代码搜索、只看非零、只看已配置分组。

**非目标**
- N1 不做属性/成长配置的编辑（那是封神榜 `PlayerConfigView.vue` 的职责）。
- N2 不做战斗结算、不做属性推演（回放态的 `attribute_recalc` 推演由调用方完成，本组件只接收推演后的快照）。
- N3 不改动领域层（`domain/attribute`、`domain/battle`）。

## 2. 数据来源与架构约束（关键，决定可行性）

**铁律（见 AGENTS.md）**：UI 一律从投影快照 `UIParticipantSnapshot` 读取，不直接绑定领域实体。

**现状与缺口**
- 领域层全量属性值在 `ParticipantStats`（`src/domain/battle/entity/ParticipantStats.ts`）：`Map<AttributeCode, AttributeValue>`，其中 `AttributeValue = { value, base, modifiers[], isPercentage, breakdown? }`——这才是「64/98 项」的真正全量来源。
- 但 `UIParticipantSnapshot`（`src/shared/types/projection.ts`）目前只暴露 9 个数值字段（attack / defense / speed / critRate / critDamage + currentHealth / maxHealth / currentEnergy / maxEnergy + shield）。
- **结论：必须先扩展投影层，本组件才有数据可读。** 这是本需求唯一的、但最重要的前置依赖。

**对投影层的要求（前置任务 P0）**
- `UIParticipantSnapshot` 新增只读字段 `attributes: Record<AttributeCode, AttributeSnapshotItem>`。
- `AttributeSnapshotItem = { value: number; base: number; isPercentage: boolean }`；debug 模式下可附 `breakdown`（复用 `CalculationBreakdown`）供 tooltip 展开，非 debug 省略以控制快照体积。
- 由 `participantMapper`（`src/application/projection/participantMapper.ts`）在生成快照时，从实体 `ParticipantStats` 全量导出。
- 快照仍遵守「纯数据、无 getter、无领域引用」原则；属性数量增加后，用版本戳（`version`）做增量更新，避免每帧重建整个 map。

**元数据来源（只读，无需改）**
- 名称 / 描述 / 是否百分比 / 是否 runtimeState：`AttributeMetaMap`（由 `configs/attributes/attributes.json` 经 `npm run generate:attributes` 生成，当前 **98 个 code，其中 3 个 isRuntimeState**）。
- 分组 / 展示层级：`src/presentation/config/attributeDisplay.ts`（见 §3）。

## 3. 分层模型（两维正交，复用已有 schema）

两个维度互相独立：一个属性同时具有「属于哪个组」和「属于哪个展示层级」。

### 3.1 展示层级 `DisplayTier`（决定默认可见性与折叠）

沿用 `attributeDisplay.ts` 已定义的四层：

| tier | 语义 | 本面板默认呈现 |
| --- | --- | --- |
| `core` | 攻击/防御/暴击等关键项 | 常显，所在组默认展开 |
| `advanced` | 暴击承伤减免、命中/闪避值等进阶项 | 所在组默认折叠，可展开 |
| `situational` | 五行抗性、特殊伤害加成等情境项 | 归入折叠区，命中当前敌人特征时高亮 |
| `hidden` | 血量/能量/护盾等运行时状态 | 不进网格，交由组件顶部条状区单独渲染 |

> **缺口**：`ATTRIBUTE_DISPLAY_CONFIG` 目前只显式配置了 41 个 code，其余走 `getAttributeDisplayConfig` 的默认值 `{ displayTier:'advanced', group:'utility' }`。这会让大量属性被「静默归类」。**要求：补全所有可展示 code 的显式配置**，让每一项的层级/分组是策划明确决定的，而非默认兜底。

### 3.2 业务分组 `group`（决定分区标题）

沿用 `defense / offense / elemental / control / utility` 五组，组标题映射中文：进攻 / 防御 / 元素 / 控制 / 通用。

## 4. 交互规格

- **4.1 分组手风琴**：每个 `group` 一个可点击标题，前缀 SVG chevron（禁 emoji），带 `aria-expanded`。
- **4.2 默认展开策略**：含 `core` 属性的组默认展开；纯 `advanced`/`situational` 的组默认收起。
- **4.3 全局开关**：工具条「全部展开 / 全部收起」。
- **4.4 状态记忆**：折叠态、过滤条件持久化到 `localStorage`，作用域按 §8 待确认（默认建议「全局」）。刷新后恢复。
- **4.5 悬浮明细**：属性行 hover → `AttributeTooltip.vue`，展示基础数值/属性加成/独立乘区/最终乘区四层（数据来自 `breakdown`，仅 debug 开关开启时有值；无值时 tooltip 只显示当前值与描述）。
- **4.6 过滤**：搜索框（匹配 displayName 或 code）、「只看非零值」开关、「只看已配置层级」开关（排除落入默认兜底的项，用于发现 §3.1 缺口）。
- **4.7 差异对比（增强，可后置）**：可选 `baseline` 属性快照，行内以红/绿 delta 显示相对基线的变化，复用技能系统「差异计算器」思路。非首版必须。

## 5. 组件契约

**位置**：`src/presentation/components/AttributeBoard.vue`（跨模块复用，不放单一模块内）。

**Props**
```ts
interface AttributeBoardProps {
  /** 全量属性快照（来自扩展后的 UIParticipantSnapshot.attributes），必填 */
  attributes: Record<string, AttributeSnapshotItem>
  /** 顶部条状区（气血/能量/护盾）所需运行时值，可选 */
  vitals?: { currentHealth: number; maxHealth: number; currentEnergy: number; maxEnergy: number; shield: number }
  /** 角色名/等级，仅用于头部展示 */
  subject?: { name: string; level?: number }
  /** 紧凑模式（弹窗/侧栏窄容器用） */
  variant?: 'full' | 'compact'
  /** 是否悬浮显示四层明细 */
  showBreakdown?: boolean
  /** diff 模式基线快照 */
  baseline?: Record<string, AttributeSnapshotItem>
}
```

**Events**：`select?(code)`（父级想要点击某个属性做联动时用，可后置）。

**Slots**：`header` / `footer`（预留，允许各模块塞自己的操作）。

**渲染输入不是 code 列表，而是「数据里存在哪些属性」**——组件遍历传入的 `attributes` 键集，逐个查展示配置归类；不硬编码任何属性数组（满足 G1、遵守「复用而非重写」）。

## 6. 视觉与无障碍约束

- 文字不小于 `--font-size-md`（AGENTS.md 明令禁止更小）。
- 禁止 emoji；折叠/筛选图标一律 SVG 或矢量字符。
- 数值右对齐、等宽字体 `--font-family-mono`；百分比项统一后缀 `%`（由 `isPercentage` 决定）。
- 折叠控件键盘可操作（Enter/Space），焦点可见。
- 分组卡片复用现有设计 token，风格与 `RoleAttrsPanel` / 封神榜面板一致，不新造一套样式。

## 7. 验收标准（DoD）

- A1 传入含全部非 runtime 属性的快照，组件按五组分区渲染，`hidden` 项出现在顶部条状区而非网格。
- A2 `core` 所在组默认展开、其余默认收起；「全部展开/收起」生效；折叠与过滤状态刷新后保持。
- A3 hover 任一属性，debug 开启时显示四层来源明细，关闭时只显示值+描述，不报错。
- A4 搜索/只看非零/只看已配置 三个过滤可组合生效。
- A5 无 emoji、无小于 `--font-size-md` 的字号；折叠控件可纯键盘操作。
- A6 领域层零 diff；组件仅依赖扩展后的 `UIParticipantSnapshot`（不 import `domain/battle` 实体）。
- A7 有一个可运行检查（无框架也可）：把「code → {group, tier, defaultCollapsed}」抽成纯函数 `resolveAttributeLayout()`，用断言覆盖：已知 code 命中显式配置、未知 code 落默认、`hidden` 被排除出网格。放 `tests/unit/`。

## 8. 待确认（Open questions，评审时定）

- **Q1「64 项」口径**：当前注册表 98 个 code，扣 3 个 runtimeState 得 95 个可配置项，仍非 64。64 是否为「剔除系数类（health/attack/…Coefficient）、派生重复项（finalAttack/finalDefense）后的可展示集」？请给出确切清单或筛选规则，否则本面板首版按「全部非 runtime 属性」渲染。
- **Q2 首个接入入口**：先替换昊天镜 `RoleAttrsPanel`（回放场景数据最全），还是先在封神榜新建独立「角色属性」调试视图？
- **Q3 明细形态**：四层来源是「仅 tooltip 悬浮」，还是要支持「行内就地展开」？（后者信息密度更高但更占空间）
- **Q4 折叠记忆作用域**：全局共用一套 / 按角色 / 按模块各一套。
- **Q5 diff（§4.7）是否纳入首版**：建议后置，先交付纯总览 + 折叠 + tooltip。

## 9. 落地拆分（供排期参考，非本文档承诺）

3. **P2 组件主体**：`AttributeBoard.vue` 分组手风琴 + 折叠记忆 + 过滤 + tooltip 接入。
4. **P3 接入入口**：按 Q2 选定的模块接入，替换旧的零散展示。
5. **P4（可选）**：diff 模式。
