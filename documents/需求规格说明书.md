## 1. 项目概述

### 1.1 项目背景

CombatDebugStudio 是一个基于 Web 的**回合制战斗引擎**，同时附带一套**可视化调试沙盒**。核心引擎（`src/domain/` + `src/application/`）作为独立库发布，不依赖 Vue；调试沙盒（`src/presentation/`）基于 Vue 3 构建，为引擎提供可视化交互界面。

系统支持多种战斗场景配置、智能敌人 AI、完整的 Buff/减益效果系统，以及战斗回放和调试功能。

### 1.2 项目目标

1. 提供**优秀的回合制战斗引擎核心**——类型安全、测试覆盖、干净无残留的代码
2. 支持**易扩展的插件化架构**——自包含 Buff 脚本、DI 容器、Port 接口、全局气血周期钩子
3. 支持多种战斗场景和敌人配置
4. 实现智能战斗 AI 决策系统
5. 提供可视化调试和监控界面
6. 支持战斗过程回放和分析

### 1.3 目标用户

- 游戏开发人员
- 战斗系统测试工程师
- 游戏设计师
- 独立游戏开发者

### 2.4 扩展性设计

> 本系统以 **「易扩展」为第一公民**。扩展点设计贯穿所有层次。

#### 2.4.1 扩展点全景

```
┌─────────────────────────────────────────────────────────────────┐
│                   扩展方式一览                                     │
├─────────────────────────────────────────────────────────────────┤
│  ① 自包含 Buff 脚本       → 写一个 .ts 文件，导出 BUFF_ID + 类    │
│  ② DI 容器注册/替换服务   → container.register('key', instance)   │
│  ③ Port 接口注入          → setLogger(myLogger) / setStorage()    │
│  ④ 气血周期钩子           → onBeforeTurn / onAfterTurn / ...      │
│  ⑤ Buff 模板工厂          → BuffTemplateGenerator.createXxx()     │
└─────────────────────────────────────────────────────────────────┘
```

#### 2.4.2 自包含 Buff 脚本（最常用的扩展方式）

每个 Buff 脚本是一个独立的 TypeScript 文件，通过静态成员自描述：

```typescript
export const BUFF_ID = 'buff_my_effect'

export class MyEffectBuff extends BaseBuffScript {
  static readonly BUFF_ID = 'buff_my_effect'

  // 可选：自包含配置，无需外部 JSON
  static readonly CONFIG: ScriptBuffConfig = {
    id: 'buff_my_effect',
    name: '我的效果',
    category: StatusCategory.COMBAT,
    maxStack: 3,
    duration: 3,
    selfContained: true,
  }

  onApply(context: BuffContext): void {
    /* ... */
  }
  onRemove(context: BuffContext): void {
    /* ... */
  }
}
```

放入 `domain/buff/scripts/` 后，`BuffScriptLoader` 通过 `import.meta.glob` **自动扫描并注册**，无需修改任何配置文件。

#### 2.4.3 DI 容器注入

DI 容器（`Container.ts`）支持注册实例和工厂，**已在 `src/index.ts` 导出**：

```typescript
import { Container } from 'game-system'

const container = Container.getInstance()
container.register('MyService', new MyService())
container.registerFactory('Logger', () => new CustomLogger(), true)
```

#### 3.2.1 基础属性（16项）

| 属性                                                  | 说明            | 范围     |
| ----------------------------------------------------- | --------------- | -------- |

#### 3.2.2 能量系统规则

- 初始能量：30点
- 回合开始恢复：15点
- 小技能消耗：50能量（冷却2回合）
- 大技能/终极技消耗：150能量（冷却5回合）
- 受击回复：12点（每回合最多3次）
- 被动技能：无消耗

### 3.3 战斗计算公式

- **基础伤害**：`random(minAttack, maxAttack)`
- **防御减免**：`DEFENSE_EFFECTIVENESS = 0.5`，`DEFENSE_DENOMINATOR = 500`
- **最终伤害**：`基础伤害 × (1 - 防御减免)`，向下取整
- **暴击伤害**：`最终伤害 × critDamage / 100`
- **命中判定**：`random(0, 100) < (命中率 - 目标闪避率)`
- **暴击判定**：`random(0, 1) < critRate`

### 3.4 Buff系统

#### 3.4.1 Buff 脚本架构（扩展性核心）

所有 Buff 采用**自包含脚本模式**，每个脚本类通过静态 `CONFIG` 字段提供元数据，框架自动读取并注册。脚本位于 `domain/buff/scripts/` 下：

- `combat/` — 战斗 Buff（AttackUp、DefenseUp、Poison、Stun 等）
- `support/` — 辅助 Buff（Shield、HealOverTime 等）
- `base/` — 模板基类（BaseBuffScript、AttributeBuffTemplate、BuffTemplateGenerator）

**注册流程：**

```
脚本文件放入 scripts/ → BuffScriptLoader (import.meta.glob 自动扫描)
                       → BuffScriptRegistry.register(buffId, factory, metadata, config)
                       → BuffSystem 通过 registry.get(buffId) 延迟实例化
```

**两种配置模式：**

| 模式                      | 说明                                           | 适用场景                |
| ------------------------- | ---------------------------------------------- | ----------------------- |
| **自包含 CONFIG**（推荐） | 脚本类内定义 `static CONFIG: ScriptBuffConfig` | 独立 Buff，无需外部依赖 |
| JSON 配置                 | `configs/buffs/buffs.json` 中定义              | 数据驱动，需运行时调整  |

### 3.6 AI系统

#### 3.6.2 优先级策略

1. 治疗技能（血量低于阈值时）

- 高能量（≥70%）：使用大技能
- 中能量（50%-70%）：均衡使用
- 低能量（<50%）：普通攻击

## 7. 验收标准

### 7.1 功能验收

- 战斗流程完整执行（创建 → 回合循环 → 结算）
- 伤害符合计算公式
- Buff 正确应用、移除、叠加
- AI 自主决策（技能选择、目标选择）
- 调试面板实时显示属性变化
- 回放历史战斗（含状态跳转）

### 7.2 扩展性验收

- 新增一个 Buff 脚本只需 1 个 `.ts` 文件，放入 `scripts/` 目录后自动注册生效
- DI 容器在 `src/index.ts` 导出，外部可 `container.register()` 和 `container.resolve()`
- `ILogger` 可通过 `setLogger()` 注入自定义实现
- `onBattleStart` / `onBeforeTurn` / `onAfterTurn` / `onBattleEnd` 四个钩子可注册且正确触发
- 有自动化测试验证上述四种扩展方式

### 7.3 界面验收

- 布局正确显示
- 点击正常响应
- 动画平滑播放
- 符合设计规范
