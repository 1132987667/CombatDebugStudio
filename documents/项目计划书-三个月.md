# 三个月项目计划书 — CombatDebugStudio

> 制定日期：2026-07-09
> 定位：一个优秀易扩展的回合制战斗引擎 + 可视化调试沙盒
> 基于代码库全量扫描（106 commits，151 文件重构，1 个 failed 测试，43 处 console.log，60+ 处 any 类型）

---

## 项目诊断摘要

| 项目 | 现状 |
|------|------|
| 定位 | **优秀易扩展的**回合制战斗引擎 + 可视化调试沙盒（Vue 3 库模式 SPA） |
| 架构 | 清晰的 DDD 四层（domain / application / infrastructure / presentation），DI 容器 |
| 开发状态 | 单人开发，处于激进重构期（最近 10 次提交改 151 文件，删 34K 行） |
| 测试 | 38 个测试，**1 个 Failed**（BattleE2E: 期望 ACTIVE 得到 PREPARING） |
| 类型安全 | `strict: false`，60+ 处 `any`码 |
| 未完成功能 | 护盾系统（2 个 TODO）、BuffContext 角色缓存（1 个 TODO） |
| 魔法数字 | `Math.random() * 20 + 10` 等硬编码回退伤害 5 处 |
| 文档 | 有中文设计文档，但已滞后于代码重构 |

### 扩展性现状（新增）

| 维度 | 现状 | 差距 |
|------|------|------|
| Buff 脚本注册 | `import.meta.glob` 自动扫描 + 手动注册，有 CONFIG 模式但**仅 BerserkBuff 实现** | 13/15 脚本未接入 CONFIG 模式 |
| DI 容器 | 注册/工厂/单例完备，但**未在 `index.ts` 导出** | 外部使用者无法利用 |
| Port 接口 | 仅有 `ILogger`（已集成）+ `IStorage`（定义但未使用） | 覆盖面窄 |
| 插件/扩展点 | **无正式插件系统**，无全局生命周期钩子 | 扩展能力全靠约定而非机制 |
| 扩展性测试 | 零 | 无人验证外部能否扩展 |
| 扩展文档 | 无 | 无人知道怎么扩展 |

---

## 阶段划分总览

```
月 1 ── 止血与加固 ─────────────────────────────────── 稳定基础，还技术债，清理 API 面
月 2 ── 扩展性基建 ─────────────────────────────────── 让引擎真正可扩展
月 3 ── 打磨与发布 ─────────────────────────────────── 体验 + 文档 + 发布
```

> ✅ 调整说明：月 2 主题从「功能完备」改为「扩展性基建」，因为护盾/Buff/技能本身就是扩展性的展示窗，而新加的生命周期钩子、Port 集成、CONFIG 统一才是让引擎「易扩展」的骨架。

## 「优秀易扩展」在这个项目里的具体含义

```
┌─────────────────────────────────────────────────┐
│                 优秀易扩展                          │
├─────────────┬───────────────────────────────────┤
│  优秀 =      │  易扩展 =                          │
│  · 类型安全   │  · Buff 脚本自包含 CONFIG，无需改 JSON │

│  · 性能基线   │  · 文档 + 示例覆盖三种扩展方式        │
└─────────────┴───────────────────────────────────┘
```

## 关键假设

1. **单人全职投入**，每周有效开发时间 20-25 小时
2. **开发者对 TypeScript、Vue 3、回合制游戏逻辑有一定熟悉度**
3. **三个月后需要交付**一个可被外部使用的库/工具，而非持续内部迭代
4. **开发环境已就绪**（Node.js、npm、Git）

如果以上假设与实际情况不符，请告诉我调整范围。
