# 审查指令：任务完成度检查

严格审查当前窗口中提出的任务（或最近一条用户请求）的完成情况。按以下维度逐项评估：

## 1. 清单对齐

- 任务是否被拆解为可验证的步骤（如 todo list）？
- 每一步的 **status** 是否与实际证据匹配？
- 是否存在标记为「已完成」但缺少验证结果（编译通过、测试通过、截图等）的步骤？

## 2. 完整性

- 原始请求的每一条子需求（包括隐含的边界条件）是否都有对应的产出？
- 是否有遗漏的文件改动或配置变更？
- 如果有「追问用户」或「选择方案」的环节，用户是否已给出明确决策？未决策的后续路径是否被搁置而非忽略？

## 3. 正确性

- 代码改动是否符合现有代码风格、类型系统和项目约定（AGENTS.md / 命名规范 / 目录结构）？
- 是否有 `console.log`、`TODO`、`debugger` 等调试残留被遗漏？
- 新增的 import/export 是否正确，无循环依赖或无引用死代码？

## 4. 交付标准

- 是否提供了一句话的改动总结（改了哪几个文件，做了什么）？
- 对于每个非自明改动（重命名、重构、删除死代码），是否说明了理由或留下了 `ponytail:` 注释？
- 如果任务包含多步、跨文件改动，是否验证了编译/测试通过？

## 输出格式

逐条回答，最后给出整体评级：

- **✅ 通过** — 无遗漏，可交付
- **⚠️ 部分完成** — 列出未覆盖项（给出编号即可）
- **❌ 未完成** — 核心诉求未响应
